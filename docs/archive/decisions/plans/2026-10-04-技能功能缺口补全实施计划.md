## 2. 实施策略与需先收口的细节

采用“先契约和可恢复执行，后生产接线与操作体验”的顺序。按页面逐按钮补接口容易重复定义事实；一次性重写所有模块则扩大回归。按用户操作链交付小批闭环，每批包含真实命令、持久化、失败恢复、界面反馈与测试。

| 事项 | 本计划采用的边界 | 首批交付前需明确的细节 |
| --- | --- | --- |
| 草稿 | 已确认编辑保护与草稿不改变当前主体；建议草稿持久化到库内专用位置，按主体／相对文件／基准内容身份隔离 | 跨重启恢复、保存／丢弃后的清理及基准已变化时的恢复策略。建议保留到明确保存或丢弃，不设静默超时删除；写入失败保持当前输入并允许重试 |
| 版本采用 | 编辑覆盖、来源采用、历史恢复共用执行边界；全部受管链接跟随当前版本，独立副本不改写 | 查明现有消费者与旧记录的实际身份、迁移／恢复兼容；不根据 fixture 的 pinned 字段新增固定版本能力 |
| 版本比较 | 先补按确切版本读取与文件级变化说明；不会把当前正文当历史正文 | 逐行 Diff 为可选扩展，不影响安全恢复的必需交付；若纳入，再明确规模、长文件、窄屏和无障碍要求 |
| 独立分支 | 按操作模型 §17.1，收回统一“编辑保存→创建新 Skill”流程 | 旧入口、命令兼容及错误提示清理；不新增第二创建流程 |
| 忽略更新 | 若提供，只记录某来源／通道／具体候选；关闭窗口不写决定，新候选重新提醒 | 精确候选身份与过期规则，是否纳入首期。未纳入时明确缺项，不能以“保持本地”冒充持久化忽略 |
| 安全门禁 | 确定性检查对应实际内容，AI 独立可选，不自动扩大授权 | 沿用已确认门禁；FB-003 等尚未裁决的警告分级不在此计划擅改 |

以上是实施建议与范围边界，不将未裁决细节写成既有产品规则。第 0 阶段将确认的细节更新到权威规范，再发布可供实施的契约。

## 4. 工作包与验收标准

### K0：把审查发现变为可实施契约

- 为每个高风险发现补能触发实际缺陷的失败测试，记录成功／拒绝／取消／重复／恢复／权限路径。复用修改追溯跨报告只跟踪一次。
- 明确现有 SkillId、内容／版本身份、物理目标、消费者集合、来源候选及元数据修订依据。预览引用精确快照，提交重新核验范围与身份；过期时重新预览。
- 版本、删除、继承共用现有操作日志／恢复基础设施，先检查其适配能力。输出结果区分完成、部分完成、受限、失败、待恢复，不新增关系分类。
- 契约落在 `crates/skillhub-core/src/api/{command,query}.rs`、相关模型和现有应用服务；持久化变更在 storage 中明确迁移与旧数据策略。绑定由后端统一生成。
- 交付：权威规范增量、DTO／命令／查询说明、故障矩阵、受影响消费点、每包文件清单和 RED 证据；不提前以 stub 成功供 UI 放行。

### K1：统一可恢复版本采用及检查事实（P1）

- 锚点：`crates/skillhub-application/src/lib.rs` 版本／内容命令、`skillhub-storage/src/library/layout.rs`、`version_store`、数据库版本登记与 portable manifest；前端 `skill-detail/nativeApi.ts`、`VersionTimeline.tsx`、`SecurityResults.tsx`。
- 编辑覆盖、来源采用、历史恢复共同协调不可变版本、当前指针、可见目录、portable、DB 与消费者验证。复用现有服务，不借此重构整个应用 facade。
- 保留可恢复备份直到必需提交完成；文件系统与 DB 无法做单一事务时，记录阶段、恢复材料与幂等操作身份。补偿失败进入恢复中心，不能只恢复指针后宣称回退成功。
- 影响来自真实受管／未接管／共享消费者，去除 affected/pinned/rerunsBasicCheck 硬编码。检查绑定精确内容版本；复用同版本结果应显示原时间，不称刚执行。
- 补按确切历史版本读取文件的只读查询，版本路径与身份校验沿用存储边界；比较结果明确文件级范围，历史正文不得回退读当前版本。版本命名继续独立，不触发内容采用。
- 测试：无变化不造版本；旧版本保留；身份／权限变化；目录替换、manifest、DB、检查每阶段失败；补偿再失败；重启恢复；重复提交；共享目标单次核验；列表／详情／文件／安全同版本。
- 完成标准：任何结果都能解释当前版本和恢复状态，原文件与未接管独立副本不被改写。

### K2：共享回收与主体删除恢复（P1）

- 锚点：`skillhub-core/src/application/removal_service.rs`、应用 RemovalBackend／治理 facade、存储关系与操作日志；前端 `relationships/governance/nativeApi.ts`、影响组件、`removal/nativeApi.ts`。
- 回收预览携共享目标及完整消费者，用户决定进入真实提交契约；后端基于最新事实强制校验，不固定发 remove_owned_target。共享实体只执行一次，关系结果按消费者如实展示。
- 影响未完成、读取失败、目标身份未知或预览过期时禁止破坏性提交；前后端都守边界。仅结束关系与移除目标分别执行，不删未知替换物。
- 多目标删除提供稳定操作身份、逐项结果和恢复状态。已完成项不重复破坏，失败项重新核身份后续跑；主体清理只在关系处置达到合法完成条件后执行。
- 测试：两消费者共用一目标；两种决定；查询失败；预览后新增消费者／替换目标；第二项文件失败；文件成功但 DB 失败；重复、重启和恢复；保留原文件／独立副本。
- 完成标准：失败后用户知道哪些完成、哪些待恢复，并能安全继续；没有旧准备态导致的永久重试死锁。

### K3：完整导出扫描与预览绑定（P1/P2）

- 锚点：`skillhub-storage/src/export/mod.rs`、应用导出准备／提交、`DataProtectionPage.tsx` 与 native facade。
- 安全扫描使用确切主体与版本 manifest 的全部实际打包文件，发现包含相对路径与可读说明；覆盖配置、脚本等资源。读取失败／无法可靠扫描依既有安全策略阻断或明确受限，禁止把漏扫说成无风险。
- 预览绑定主体、版本、格式、目录和敏感决定；任一输入改变使旧预览失效，提交核快照。遵循既有权限和输出路径校验，取消不产生最终包，失败产物可识别清理。
- 测试：正文无敏感词而 `.env`／配置含虚拟凭据；历史版本；不可读／越界资源；预览后换主体／范围／目录；候选内容变化；取消／重复／输出占用。
- 完成标准：展示并确认的范围等于实际导出范围，所有被打包内容都经过对应安全检查。

### K4：正式草稿、校验、保存及离开保护（P1）

- 锚点：`features/markdown/{api,nativeApi,MarkdownEditor,MarkdownWorkspace}.ts(x)`、Rust 内容读取／保存与新增草稿适配、相关查询。
- 补齐生产 save/read/discard draft、Markdown 校验与明确错误契约，不再依赖 unavailable facade。草稿不切当前版本、不写回原始来源。
- 在工作区统一脏状态，覆盖 tab、文件、相邻 Skill、路由返回和关闭；保留／丢弃／取消共用一个流程，异步草稿失败不清空输入，不靠 debounce 保证安全。
- 保存先检查真实身份与声明，再调用 K1 版本采用；若运行时名称发生不受支持变化，明确阻断，不静默重命名。
- 测试：快速切换／关闭、恢复草稿、基准变化、草稿读写失败、校验错误／警告按既定门禁、readonly／权限、取消、stale identity 与重复保存。
- 完成标准：用户输入可恢复，覆盖保存真正产生可核验版本，各视图刷新而无需点击通知。

### K5：创建新 Skill、复用修改与替换继承（P1/P2）

- 锚点：SaveMarkdownAsCopy 命令、来源追溯模型／repository、统一派发与回收服务；Markdown 编辑保存结果、ProvenancePanel 和图谱。
- 请求携原主体、起始版本、用户命名、替换继承／不继承及明确目标集合。新主体不自动绑定原网络来源，持久化独立“复用修改”追溯，原主体和未选关系保持。
- 替换继承经 K2 与既有派发安全流程真正替换并验证目标；共享实体去重、真实名称占用核验，不复制关系账目。主体创建／追溯／继承失败有明确可恢复边界。
- 结果返回新主体／版本／可读名称和逐项目标结果；UI 提供定位入口，刷新库、追溯、图谱和对应关系。
- 测试：两种继承、取消、同名占用、共享目标、权限拒绝、部分替换失败／恢复、重复提交、原主体不变、新来源不自动继承、重启追溯。
- 完成标准：新主体、上游依据和实际使用关系能够互相核验，成功文案只描述已落账事实。

### K6：来源身份、候选及采用闭环（P1/P2）

- 锚点：source 查询／命令／repository、远端获取；`SourceRelinkPanel.tsx`、`SourceUpdatePanel.tsx`、相关 nativeApi。
- 自由文本转为查找→候选验证→关联／解除的真实流程，记录完整仓库／分支或发布／目录坐标。失败不覆盖原关联，来源解除不删除主体或导入存证。
- 明确已有通道选择；远端失败不静默改通道。候选绑定真实内容身份，采用经过 K1 同一预览、检查、执行与恢复，保留本地旧版本。
- 移除来源更新里的独立分支假能力，指向统一编辑新建流程。若纳入忽略本次更新，按具体候选持久化，不把取消当决定，不永久关闭更新。
- 成功刷新来源、版本、摘要、库、insights 和安全；失败及无变化状态分离。
- 测试：多候选／错误目录、失效来源、权限／网络失败、候选变化、关联与解除、保持当前／忽略／取消、新候选再提醒、采用失败恢复与重启。

### K7：画像、真实 insights、组合和安全呈现（P1/P2）

- 锚点：元数据命令／repository、`skills/nativeApi.ts`、`skill-detail/nativeApi.ts`、MetadataPanel、InsightPanels、组合 API、安全 presenter。
- 元数据使用后端原子字段 patch 或等价可证明并发安全策略；Escape 明确取消且阻止后续 blur 提交。编辑失败保留输入，别名不改运行时身份。
- 取消与字段并发的独立修复可在第 1 阶段提前交付，避免等全部投影工作完成；仍需先确认字段契约及统一前端文件所有权。
- 统一用途回退、译文作为用途的显式保存、翻译错误与无译文。AI 入口展示配置状态和实际发送范围，网络／AI 请求只在明确意图内执行。
- combinations、dependencies、externalChanges 查询真实事实，未支持／失败不能返回伪空集；操作历史转统一可读 presenter。详情组合操作共用抽屉真实流程，试用继续核跨页与重启事实。
- 安全查询用具体版本键；内容变化刷新，旧结果可作为旧版本历史但不能显示为当前结论。发现项解释事实、影响与下一步，未知规则可读且不等于低风险。
- 测试：交错并发 patch、Escape／blur、译文错误、用途回退、AI 未配置／权限取消、组合新增移除与重启、insights 查询失败、版本切换旧检查不可冒用。

### K8：冻结前端的生产入口、导航与可读反馈（P2）

- 锚点：DetailHeader、SkillDetailPage、DetailSectionNav、SkillQuickDrawer、图谱导航、版本／目标 presenter、中英翻译。
- 在冻结槽位内补详情头派发、导出、条件性的转集中管理、删除；准确携 Skill／关系／物理目标上下文，治理动作仍在关系治理统一执行。
- 保留图谱／列表筛选、选中项、抽屉及返回上下文，前后项继承合法导航 state；失效项显示可读解释。验证 returnTo 为内部合法路径。
- 版本无命名显示可读序号／时间／未命名；目标未知不裸露内部 ID，也不让未知影响放行。另建成功可直接定位新主体，所有入口错误有明确下一步。
- 测试：头部条件门控、精确深链／返回／相邻项、目标失效、长值、窄屏、键盘、焦点恢复、减少动效与主题；原型详情 31／抽屉 10 持续通过。

### K9：本地资源、外部应用与接管适配（P2）

- 锚点：MarkdownRenderer／Workspace／nativeApi、Rust 文件读取、Windows/macOS 平台适配与既有治理导航。
- 本地资源以精确 Skill／版本根解析，拒绝目录逃逸、危险 scheme 和指向根外的链接；错误结束 aria-busy 并提供可读说明，继续遵守远程图片策略。资源查询和前端缓存键携实际版本身份（缺省解析当前，历史读取显式指定），Markdown 与图片来自同一版本，切换／保存后不得沿用旧版本缓存。
- 打开默认／所选应用和目录使用既有受控平台适配器，不执行未经校验的任意命令；失败和权限拒绝留在原页面可处理。
- requestTakeover 跳转既有身份／共享／权限预览流程，不以 mock 状态宣称已接管。外部只读／内置／插件等限制依据真实能力。
- 测试：合法资源、缺失、越界、符号链接、权限、默认应用缺失、取消选择、外部只读及治理跳转；Windows/macOS 真机分别验收。

## 5. 执行组织与文件所有权

下一轮团队固定为主代理加两个执行代理，两个执行代理均为 Luna / max；不新增审查代理。主代理统筹产品裁决与契约，维护当前四份开发文档，串行整合、独立复核各阶段成果并负责最终验收。

| 角色 | 职责与文件边界 |
| --- | --- |
| 主代理（统筹与复核） | 明确未裁决的产品边界并更新权威规范；维护当前四份开发文档；分配 K0—K10 与文件所有权；独立检查权限、身份、影响预览、持久化、失败恢复、生成契约和生产 adapter 测试；负责冲突整合、全量检查及最终平台验收。 |
| A：后端契约与执行 | 负责 core DTO／命令／查询、应用执行与恢复、数据库／文件／portable 存储和迁移、生成绑定、后端定向测试。共享应用 facade 与绑定由 A 作为单一写入所有者；绑定必须用生成工具更新。 |
| B：前端与体验 | 负责冻结规范内的抽屉／详情接线、体验呈现、导航／刷新、i18n 与浏览器自动化；消费已明确的生成契约，不手写重复绑定或自行定义后端规则。前端实施前加载 frontend-design；React 同时遵循 vercel-react-best-practices。 |

A 与 B 在主代理明确的接口／文件边界下并行，涉及共享文件时先约定唯一写入方；A 先交可生成并可测试的契约，B 可并行完成基于当前契约的只读盘点、RED 测试与不触碰共享 DTO 的准备，契约提交后再接线。K0 由主代理主持收口，A/B 各自提供执行面证据和失败测试；遇到未裁决的真实产品选择时报告主代理决策并同步规范，不暂停所有独立工作，也不自行扩大范围。

每阶段由主代理承担独立复核；Critical／Important 问题退回原执行者修复后才整合，不额外设 review agent。重型 CI／E2E 由主代理串行协调。遵循用户对分支、推送和 worktree 清理的单独交接指令，保留用户数据和恢复材料。

## 6. 测试与最终完成标准（K10）

每包 TDD：先真实失败证据，再最小实现，最后必要重构。不降低断言、删测试、假成功或任意延时。前端实施前加载 frontend-design；React 同时遵循 vercel-react-best-practices。

| 层级 | 验证内容与命令 |
| --- | --- |
| 契约与持久化 | 定向 `cargo test -p <相关crate> --test <实际测试文件>`；优先扩展 facade、undeploy_delete、export_redesign、version_store 等既有用例，并增加跨阶段故障／恢复测试 |
| 生成绑定 | 临时设置 `SKILLHUB_WRITE_BINDINGS=1`，运行 `cargo test -p skillhub-desktop generate_bindings`，随后清除临时变量；检查生成差异，禁止手写 bindings.ts |
| 前端定向 | `pnpm --dir apps/desktop exec vitest run <受影响测试>`；覆盖真实 native mapper、组件取消／错误和跨页刷新；必要 check／build |
| 浏览器 | 按实际配置运行受影响 Markdown、drawer/detail、治理、来源、导出等 E2E；新增缺口用例。mock 验证页面契约，另用真实应用 facade＋临时库验证原生持久化，二者分别记录 |
| 最终整合 | `git diff --check`、`pnpm ci:local`、`pnpm test:e2e`、`pnpm verify:release`、`pnpm test:release`、`node scripts/verify_atomic_test_catalog.mjs`；在最终代码整合上记录结果 |
| Windows/macOS | 按 [完整操作链清单](../../development/人工验收清单-2026-10-05.md) 执行隔离素材流程，记录版本、截图／日志、实际文件与关系及清理；权限／共享／链接／占用／重启恢复分别验 |

完成必须同时满足：

1. K1—K9 所有已确认必需能力完成，P1 无遗留；可选项明确范围和状态，不以隐藏入口冒充已实现。
2. 成功、失败、取消、重复、恢复、权限限制有适用测试；生产 facade 贯通真实应用域及持久化，不以 mock 通过代替。
3. 版本／文件／portable／DB／检查／关系各消费面一致；原文件保护及共享目标结果可核验。
4. 最终全量与发布检查无新增失败，详情／抽屉原型回归持续通过；不把旧数量当新增测试必须保持的数量。
5. 当前开发状态、自动化说明、完成度矩阵更新；真实验收后更新人工清单和矩阵。平台未验或恢复风险未解时明确阻塞发布，不能声明完整交付。
