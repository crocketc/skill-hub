# SkillHub 前端体验与视觉系统升级设计规格

> 日期：2026-09-11  
> 状态：待实施  
> 适用范围：SkillHub 桌面端 React 前端  
> 配套计划：`docs/superpowers/plans/2026-09-11-skillhub-frontend-experience-refresh-goal.md`

## 1. 目标

本轮升级解决以下问题：

- 设置页输入框、下拉框、开关和供应商配置缺少统一、可信的产品级外观。
- 设置页嵌套两列栅格在中小窗口中连续压缩内容。
- 发现页以大块空白容器和普通列表呈现结果，缺少适合浏览的 Skill 小卡片。
- Skill 库表格密度过高，现有卡片信息层级不足。
- 页面标题、状态、图标、焦点、滚动和响应式规则不统一。
- 多个页面仍以相同圆角卡片承载不同层级的信息，降低辨识度。

目标体验是“本地 Skill 档案工作台”：普通用户可以快速识别对象、状态、来源和下一步操作；专业用户仍可访问表格、路径、版本和完整技术信息。

## 2. 不可破坏条件

1. 完整保留以下 9 个预设主题的标识、名称、顺序和视觉性格：
   - `moss-neutral`
   - `spring-signal`
   - `terracotta`
   - `codex-light`
   - `ocean-cobalt`
   - `sakura`
   - `aurora`
   - `roast`
   - `grok-night`
2. 保留 `system/light/dark` 到默认浅色、深色主题的映射，以及现有持久化键和值。
3. 不修改业务规则、Rust 后端、数据库、生成绑定、网络策略、凭据存储和安全边界。
4. LLM 的“服务可达”和“模型可用”仍是两级结果，不得合并成单一成功状态。
5. AI 能力默认关闭，不能绕过确定性安全检查。
6. 不新增 Git 同步、OAuth、远端设备、NAS 功能或其他超出当前本地优先范围的能力。
7. 保留现有 Agent 品牌 SVG、来源与许可证；CoMate 继续使用文字回退，不伪造 Logo。
8. 不使用 `transition: all`，不通过隐藏溢出、降低断言、删除测试或任意延时掩盖问题。

## 3. 视觉方向

### 3.1 设计语言

- 页面是工作台，不是营销页；内容左对齐，正文行宽控制在约 `72ch`。
- Skill、Agent、项目和供应商是实体，可以使用卡片。
- 普通设置、说明和流程步骤使用分区、表单行、分隔线和状态区域，不默认套卡片。
- 唯一强化的视觉线索是“来源 → 本地库 → 部署目标”的关系轨迹。
- 不使用装饰性玻璃、通用渐变、悬停上浮或大面积阴影制造“高级感”。
- `aurora` 的渐变只保留为主题特征或主题预览，不扩散到所有主按钮。

### 3.2 主题语义角色

9 个主题继续提供各自原始颜色，同时统一暴露以下语义角色：

- 画布：`--ui-canvas`
- 表面：`--ui-surface`
- 次级表面：`--ui-surface-subtle`
- 正文：`--ui-ink`
- 次级正文：`--ui-ink-muted`
- 强调：`--ui-accent`
- 边界：`--ui-border-subtle`、`--ui-border`、`--ui-border-strong`
- 控件：`--ui-control-background`、`--ui-control-border`、`--ui-control-border-hover`、`--ui-control-placeholder`
- 交互：`--ui-hover-surface`、`--ui-pressed-surface`、`--ui-selected-surface`、`--ui-selected-border`
- 禁用：`--ui-disabled-background`、`--ui-disabled-text`、`--ui-disabled-border`
- 图标：`--ui-icon`、`--ui-icon-muted`、`--ui-icon-on-accent`
- 焦点：`--ui-focus`
- 状态：成功、警告、危险、信息各自提供前景、背景、边界和反色文字。

迁移期间保留现有 `--color-*` 变量作为兼容别名。业务页面不得写死某个主题的十六进制颜色。

### 3.3 排版、间距与形状

- 不引入在线字体。使用 macOS/Windows 本地优先字体栈；路径、哈希和 API 值使用现有等宽字体。
- 字级：12 / 14 / 16 / 18 / 22 / 28px。
- 正文行高 1.5，标题行高 1.25。
- 间距采用 4px 基准：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px。
- 控件标准高度 40px，紧凑型 32px，重要主操作 44px。
- 标签圆角 4px，输入和按钮 6px，实体卡片 10px，抽屉和对话框 14px。
- 胶囊形只用于状态徽标；表单和普通分区不用阴影。
- 实体卡片最多使用一级浅阴影；抽屉和对话框才能使用更明显阴影。

## 4. 基础组件规范

### 4.1 表单

- `Field` 统一标签、帮助文字、错误文字、必填状态、`id`、`htmlFor` 和 `aria-describedby`。
- `Input`、`Select` 明确设置背景、文字、边界、占位符和焦点，保证 Windows 深色模式可读。
- 输入字段提供有意义的 `name`、正确的 `type/inputMode` 和合适的 `autocomplete`。
- 提交失败时错误紧邻字段，并聚焦第一个无效字段。
- Checkbox 与文字共享点击区域；Switch 只用于立即生效的二元设置。
- Button 加载时保留原动作文字，增加不重复朗读的加载标识和 `aria-busy`。

### 4.2 图标

- 按钮内图标 16px，导航 20px，提示 24px，实体或品牌标识 32–40px。
- 普通图标使用一致的 1.75–2px 线宽、圆角端点和 `currentColor`。
- 品牌 Logo 保持原色；外围底色和边界通过主题语义色适配。
- 图标按钮的可点击区域至少 40×40px，并具有明确的 `aria-label`。
- 装饰图标使用 `aria-hidden="true"`；状态始终使用“图标＋文字”，不能只靠颜色。
- 全站统一搜索、导入、部署、更新、恢复、删除、外部打开、成功、警告和失败的图标映射。
- 替换 `⌂`、`↗`、`⭳`、`⇣`、`✎`、`×`、`⌄`、`⌃` 等用作正式操作的字体字符。
- T0 不新增第三方图标依赖，优先建立本地 SVG 注册表。

### 4.3 页面与弹层

- AppShell 只提供一个主内容 `main`，并提供可聚焦的 Skip Link。
- 顶栏负责一级路由 `h1`；页面内容从 `h2` 开始。没有顶栏的详情页可显式使用 `h1`。
- 页面只保留一个主要滚动所有者；内部滚动只用于编辑器、表格或明确的长列表。
- Drawer/Dialog 打开后正确设置焦点、限制焦点范围、支持 Escape，并在关闭后恢复触发器焦点。
- Sticky 区域不得遮挡焦点、最后一行内容或主要操作。
- 响应式判断优先基于内容容器，不只使用浏览器视口宽度。

## 5. 核心页面设计

### 5.1 设置与 LLM

```text
┌ 分区导航 ┐ ┌ 当前分区 ───────────────────────────┐
│ 通用     │ │ 分区说明                            │
│ 数据保护 │ │ ─────────────────────────────────── │
│ 网络与AI │ │ 完整宽度表单行 / 供应商实体列表     │
│ 自动化   │ │                                     │
│ 技能库   │ │ 新增/编辑进入抽屉，不挤压当前页面   │
│ 应用更新 │ │                                     │
└──────────┘ └─────────────────────────────────────┘
```

- 1280/1440px 使用左侧分区导航；800/1024px 使用顶部紧凑分区选择器。
- 右侧内容始终单列，不恢复嵌套两列设置栅格。
- LLM 供应商采用完整宽度实体行/卡片；新增和编辑放入抽屉。
- 供应商显示类型、端点、模型、启用、默认、凭据状态和最近连接结果。
- 删除供应商需要确认；取消后焦点返回触发器。
- 两级连接结果分别显示服务状态、模型状态、延迟和可理解的错误处理建议。

### 5.2 发现 Skill

```text
发现 Skill
[本机] [在线] [仓库] [lock]
[搜索____________________] [来源，可选] [搜索]
[AI 搜索辅助]                              [普通导入]

┌ Skill ──────┐ ┌ Skill ──────┐ ┌ Skill ──────┐
│ 来源图标 名称│ │ 来源图标 名称│ │ 来源图标 名称│
│ 来源 / 仓库  │ │ 来源 / 仓库  │ │ 来源 / 仓库  │
│ 最多三行说明 │ │ 最多三行说明 │ │ 最多三行说明 │
│ 元数据 / 状态│ │ 元数据 / 状态│ │ 元数据 / 状态│
│ 查看  下载导入│ │ 已在库        │ │ 不可安装      │
└──────────────┘ └──────────────┘ └──────────────┘
```

- 内容宽度 ≥1180px 为 3 列，760–1179px 为 2 列，低于 760px 为 1 列。
- 800px 应用窗口在展开侧栏后通常进入单列。
- 卡片最小宽度约 280px，操作区稳定在底部。
- 不把整张卡片做成可点击按钮；标题、链接和操作保持独立语义。
- 不伪造后端没有提供的作者、评分、兼容性或描述。
- 搜索中、空结果、失败、离线、已在库、不可安装、AI 扩展命中和 AI 回退分别展示。

### 5.3 Skill 库

- 普通用户默认使用增强卡片视图；表格保留为专业模式。
- 卡片展示名称、用途、来源、版本、部署目标、风险和升级状态。
- 筛选栏优先展示搜索和当前生效条件；次要筛选在窄窗口折叠。
- 表格支持列选择或优先列，不依赖难发现的双层横向滚动。
- 快速抽屉继续保留筛选、选择和返回上下文。

### 5.4 其他页面

- 概览：一个首要指标＋紧凑统计；避免所有数据使用同形指标卡。
- Skill 详情：重组为身份、状态、正文、关系和生命周期，减少九个章节同形平铺。
- Agent/项目：使用实体卡片和详情页；注册/编辑进入抽屉，不挤压主列表。
- 待处理/操作记录/恢复：围绕“风险—影响—下一步”组织，批量操作不遮挡焦点。
- 初始化/重新发现：统一步骤名称、完成状态和底部操作区，保留所有业务分支。
- 导入/部署/移除：统一“选择 → 预览影响 → 执行 → 结果”，不改现有状态机。
- Markdown 工作区：保守迁移，只统一基础控件、状态、图片尺寸占位和主题表现。

## 7. 全局验收矩阵

- 尺寸：800/1024/1280/1440px × 600/720/900px。
- 内容：简体中文、英文、120 字符名称、长 Windows/macOS 路径、空/单条/50+ 条目。
- 主题：9 个主题全部完成 token、控件、对比度和核心页面检查。
- 状态：加载、空、失败、取消、重复、权限受限、恢复、部分成功。
- 键盘：Tab 顺序、可见焦点、弹层焦点限制和恢复、标签页方向键。
- 图标：装饰图标隐藏、操作图标有名称、状态不只靠颜色。
- 布局：无根级横向滚动、无文字逐字压缩、无操作栏覆盖、无不可发现的双重滚动。
- 动效：遵循系统减少动态效果；动画只使用明确属性，且可被用户操作打断。
- React 性能：继续满足 300 Skill 场景；避免新增串行请求、无效重渲染和大范围动态导入，性能优化必须有前后证据。
- 人工：Windows/macOS 原生下拉框、系统缩放、字体、滚动条、暗色阴影和屏幕阅读器体验。
