# 未决事项产品裁决（2026-10-05）

> 本文是六项未决事项的**产品规则权威表述**（规范收口），由[裁决建议](../plans/2026-10-05-未决事项裁决建议.md)（背景/选项/裁决过程）与[实施计划](../plans/2026-10-05-未决事项实施计划.md)（源码落点与实施口径）支撑。实施以本文为行为依据；与旧讨论冲突时以本文为准。全部规则基于确定性安全检查，AI 仅辅助解释、不参与任何放行/分级判定。

## 1. 导入安全分级与预警状态（FB-003）

- 导入基础检查的发现分三级：**危险级**（critical/error 类确定性规则）、**警告级**（warning 类）、**放行级**（无发现）。规则集逐条标注产品级，分级只基于确定性规则。
- **危险级不拦截**：导入时向用户展示该 Skill 的具体风险明细，由用户显式决策**仍要导入 / 不导入**。决策粒度为**单个 Skill**，不牵连整批导入任务（其他 Skill 正常导入）。
- **警告级不拦截**：直接导入，无需逐项决策，但以聚合说明告知。
- **预警状态**：危险级"仍要导入"与全部警告级导入后，该 Skill 进入预警状态：**不可派发**，加入待办交用户处理。处理方式三选：
  - **完全信任**：解除预警，恢复可派发等操作；决定**留痕**（记录来源、时间、绑定内容版本）。
  - **不信任（删除）**：走既有删除流程（含影响确认），删除该 Skill。
  - **稍后处理**：留在待办，期间持续不可派发。
- 预警与信任记录**绑定内容版本**：同版本不重复提示；版本内容变化后重新进入预警。
- 留痕可追溯：导入时"仍要导入"与待办"完全信任"的决定均在安全页可见（来源/时间/版本）。
- 派发被预警拒绝时，错误说明必须直接给出处理入口指引（详情安全页/待办），不留死胡同。
- 交互口径（2026-10-05 定稿）：危险级决策在导入向导处置环节内联完成（与冲突处置同一次评审、一次提交），否弃"导入后补决策"。

## 2. 导入检查记录（FB-006）

- 导入时的基础检查结果**登记为该内容版本的首次基础检查记录**，标注来源"导入时检查"（trigger=import）。
- 导入后列表/详情/安全页显示真实检查状态，重启保留。
- 升级前旧导入的 Skill 缺记录的**如实显示缺记录**并引导重查，不伪造历史通过。
- **同版本不覆盖已有检查结果**：该版本已有任何检查记录时不新增导入记录（以最新记录为准的既有语义不变）。
- 检查记录持久化失败时导入整体失败，不假通过。

## 3. 批内冲突处置（FB-007）

- 冲突分析新增**"批内"分组**（现仅对比"批 vs 库内已有"）：
  - 同内容同来源（明显重复）：建议合并为一个、其余跳过。
  - 同名不同内容：要求用户**逐个显式处置**，不给静默默认、未处置则提交被拒。处置选项："独立命名"（填写新名称，贯穿导入校验，与批内及库内均不冲突）或"跳过"。
- 提交期库或批内组成再变化时，重新确认。
- "独立命名"第一期即提供最小可用实现；后补的仅是增强体验（推荐名称、批量重命名）。

## 4. 删除级联清理草稿（跟进 4）

- 删除主体（含批量删除，即逐主体同一流程）时**一并删除该主体在 `drafts/` 下的全部编辑草稿**。
- 删除确认中**仅当存在草稿时**说明"将同时删除未完成的编辑草稿"，并在影响清单列出草稿数量；一次确认完成，不残留孤儿草稿。
- 这是"保留用户原文件"边界的已裁决例外：草稿属主体私有数据，随主体删除；删除操作既有回滚窗口内一并可回滚。

## 5. 备份不含草稿的明确说明（跟进 5）

- 备份范围暂不纳入未保存的编辑草稿（维持现状）。
- 备份操作区说明与备份完成反馈中**明确提示**"备份不包含未保存的编辑草稿，编辑中的内容请先保存"。
- 草稿纳入备份/恢复列为后续增强（需处理恢复草稿与恢复后库版本的匹配），按需排期。

## 6. 来源更新守卫式快速重试（跟进 6）

- 来源更新执行失败后，失败记录保留用户决定；同一预览在事实未变时可**按原决定直接重试，免重新预览**。
- 重试前系统**重核事实**（本地当前内容指针、上游内容与原预览一致）：一致则直接执行；不一致（上游更新、本地改动、过期）则预览失效，**落回重新预览**再确认。重核通过等价于原预览的事实保证。
- 前端如实呈现两类失败："可按原决定重试（系统会先核验一致性）"与"内容已变化，需重新预览"。
