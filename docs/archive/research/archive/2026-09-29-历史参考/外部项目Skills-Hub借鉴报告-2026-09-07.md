# 外部项目 Skills Hub 借鉴报告

> 对比对象：`/Users/chengcheng/skills-hub`（外部项目，以下称“参考项目”）与当前 SkillHub。
> 结论范围：**只记录参考项目中更值得采用的能力、交互或实现细节**；当前项目已经具备同等或更完整能力的部分不列入。本报告是方案与实现边界说明，不直接引入第三方代码。

## 结论摘要

当前项目的核心是面向普通用户的**纯本地** Skill（技能）管理，不应把跨设备 Git（版本控制）同步纳入近期路线图。参考项目中值得保留的是它处理高风险文件操作的局部原则：先预览、暂存后原子替换、遇冲突不覆盖、删除可恢复、状态与错误可理解。

近期最值得吸收的是“**精选优先的在线发现**”和“**可单独配置的扫描来源**”。当前项目已有 `skills.sh`（技能市场）在线搜索及导入向导，因此不应重复建设搜索；应补足精选目录、离线回退和来源控制。

| 优先级 | 借鉴项 | 预期价值 | 推荐方式 |
| --- | --- | --- | --- |
| P1 | 精选 Skill 目录 + 搜索结果分层 | 降低首次发现优质 Skill 的成本 | 在现有在线发现页上增量实现 |
| P1 | 扫描来源控制与“发现待导入”提示 | 明确扫描范围，避免导入噪声 | 在发现页/设置页增加持久化配置 |
| P2 | 本地高风险操作的状态反馈与可恢复性 | 让导入、更新、迁移和恢复更可理解、可回退 | 复用现有本地工作流，局部增强 |

## P2：本地高风险操作的安全与状态反馈

### 借鉴点

参考项目的跨设备同步不适合当前产品定位；但其中对高风险文件操作的处理值得拆出并用于本地流程。核心价值是把“即将发生什么、是否安全、失败后怎么办”显式建模，而不是让用户面对一次不可解释的文件写入。

参考实现证据：

- `src/components/skills/deviceSyncState.ts` 将页面状态限定为“健康、有变更、失败、冲突、进行中”，并定义确定的优先级（第 115–218 行）。该状态表达可移植到本地导入、上游更新、集中库迁移和恢复。
- `src-tauri/src/core/device_sync/text_merge.rs` 对不大于 1 MiB 的 UTF-8（统一码转换格式）文本做三方合并；二进制、大文件、混合换行或冲突一律转人工处理，而非强行覆盖（第 5–82 行）。
- 其文件替换路径会先写入暂存目录、校验后再激活替换；该思想适合本地集中库迁移、恢复和受管副本更新。

### 产品边界

- 只增强当前本地导入、上游更新、集中库迁移、备份恢复、部署核对和安全解除部署；不新增设备、远端仓库、Git、OAuth（授权）、网络调度或跨设备状态。
- 对要覆盖、删除或迁移的本地内容，必须先给出影响预览；存在外部修改或内容冲突时停止自动写入，要求用户选择处理方式。
- 当前项目规划的“网络存储”是下一大版本的独立方向，优先考虑 NAS（网络附加存储）/SMB（服务器消息块）等挂载目录作为本地文件系统路径；具体连接、授权与同步体验届时重新设计，不能由本报告的 Git 同步方案替代。

### 建议局部模型

| 概念 | 关键字段 | 目的 |
| --- | --- | --- |
| `LocalChangePreview` | 操作类型、受影响 Skill、文件增删改、风险项 | 让用户先看计划再执行 |
| `LocalConflict` | 路径、基线/当前/候选内容、可选决策 | 支持保留当前、采用候选、外部处理 |
| `LocalOperationRun` | 开始/结束时间、阶段、稳定错误码、结果摘要 | 提供可审计历史和可操作错误 |
| `RecoverableDeletion` | 删除前快照、到期时间、恢复状态 | 与现有备份和恢复能力衔接 |

涉及内容比对时必须使用当前项目已有的稳定 Skill/版本标识和内容哈希，不以显示名称匹配；否则重命名会被误判为删除加新增。

### 本地文件操作算法（应借鉴，不能直接搬代码）

```text
锁定本地操作
  → 扫描并校验当前文件状态
  → 与候选内容或备份快照比较，生成预览
  → 无冲突：写入暂存目录并校验哈希
  → 原子替换目标；记录 LocalOperationRun
  → 有冲突：保存 LocalConflict；不改目标；界面转“需处理”
```

具体规则：

- 只对有共同基线、UTF-8 且不超过 1 MiB 的本地文本尝试三方合并；合并结果仍要过哈希和路径边界校验。
- 二进制文件、超过上限的文件、符号链接语义冲突、删除与编辑并发、或任何未验证快照，全部进入人工冲突，不推测用户意图。
- 提交前写入暂存目录，校验完成后再原子替换；失败时保留原集中库和诊断信息。
- 删除先进入应用回收站并设保留期；当前项目已有备份、恢复和卸载影响评估，应复用这些能力而不是维护第二套不可恢复删除。
- 操作前后通过当前部署服务做“重新核对”；外部修改不能被静默覆盖。

### 前端设计规格

| 状态 | 页面主体 | 主操作 | 必须呈现的信息 |
| --- | --- | --- | --- |
| 预览 | 影响摘要卡 | 继续、返回修改 | 新增/修改/删除分别计数，受影响 Skill 列表 |
| 进行中 | 当前阶段与不可重复提交状态 | 取消（可取消时） | 正在写入的范围与安全提示 |
| 冲突 | 冲突置顶 | 逐项决策 | 基线/当前/候选差异，明确“不会自动覆盖” |
| 完成 | 结果摘要与后续操作 | 打开详情、恢复或关闭 | 成功、跳过、失败分别计数 |
| 失败 | 错误卡与本次操作记录 | 重试、查看详情 | 稳定错误码、阶段、恢复建议，不能只显示原始异常 |

参考项目可借鉴的细节是：状态机有确定优先级（进行中 > 冲突 > 失败 > 有变更/预览 > 完成），且按失败类型给出具体下一步。这些能显著减少普通用户在本地高风险操作上的误判。

### 当前项目的接入位置

- `crates/skillhub-core`：补强本地变更预览、冲突决策与可恢复删除模型。
- `crates/skillhub-application`：复用现有导入、更新、备份恢复用例，统一预览/执行两阶段和操作记录。
- `crates/skillhub-adapters`：复用路径校验、链接处理、内容扫描和暂存替换原则，不引入 Git 适配器。
- `crates/skillhub-storage`：复用现有备份、版本和操作记录，按需补充本地冲突快照。
- `apps/desktop/src/features/import`、`skill-detail`、`backup`：在既有流程内展示预览、冲突和可恢复结果，不新增“设备同步”页面。

### 必须先写的测试

1. 同一文件的非重叠文本修改可自动合并，重叠编辑必须生成冲突。
2. 二进制、超限文件、混合换行、哈希不匹配均不得自动合并。
3. 预览、暂存或原子替换任一步失败不会修改集中库；失败可恢复。
4. 删除与本地修改、同名不同 ID、重命名、路径穿越、符号链接均有确定结果。
5. 并发操作、权限不足、磁盘空间不足和冲突时，重复提交被阻止并有准确恢复提示。
6. 操作后的本机部署重新核对不覆盖独立的工具端改动。

## P1：精选优先的在线 Skill 发现

### 借鉴点

当前项目已有在线搜索和受控导入；参考项目的增量优势在于把“精选目录”和“关键词搜索”放进同一浏览体验：无搜索时先呈现精选项；输入关键词后同时显示命中的精选项与去重后的网络结果；每张卡展示来源、摘要、星标/安装量，并明确已安装状态。

其后端还把精选清单设计成“远端更新 → 本地缓存 → 内置兜底”的三级来源：远端加载失败时仍返回缓存或随应用发布的静态列表，而不是使发现页不可用。参考依据为 `src-tauri/src/core/featured_skills.rs` 第 7–13、44–103 行；前端分层与已安装去重在 `src/components/skills/ExplorePage.tsx` 第 58–76、118–218 行。

### 推荐实现

在当前“在线发现”模块内增加“推荐”区，而不是新增平行入口：

1. 发布一份仓库内、可审查的 `featured-skills.json`，字段仅含名称、简介、来源 URL、分类、维护日期和展示排序；不要将其等同于安全背书。
2. 启动或打开页面时按“签名/校验过的远端清单 → 上次验证缓存 → 内置清单”读取；界面显式标明来源与最后更新时间。
3. 搜索结果分为“推荐匹配”和“在线结果”，按规范化的 `来源 + Skill 标识` 去重，已在库中的项显示“已导入”并可跳转详情。
4. 用户点击安装仍必须进入现有导入、扫描、安全检查和冲突决策流程；推荐卡绝不绕过当前项目的安全边界。

### 前端细节

- 复用当前发现页的独立子页与导入向导；顶部使用一个搜索框，下面先显示推荐网格，再显示在线结果网格。
- 卡片只承担“识别、可信线索、安装入口”三件事：名称、两行摘要、来源、分类、维护度/热度和安装状态。不要在卡片内塞入部署目标或安全检查结果。
- 搜索为空时保留推荐内容；搜索中使用骨架或明确加载状态；网络不可用时保留已验证的推荐清单并显示轻量提示。
- 参考项目 `docs/assets/explore-online-skills.png` 的双区卡片布局和卡片右上角即时安装状态可直接作为视觉参考；颜色、字体、组件仍应沿用当前项目设计系统。

### 验收条件

- 断网、远端 5xx（服务器错误）、无缓存三种场景均有不同且准确的状态。
- 精选与搜索结果去重；已导入 Skill 不显示可重复安装操作。
- 任何推荐项安装均完整经过当前导入安全检查；伪造 URL、重定向和非受支持来源仍被拒绝。
- 清单升级、缓存过期、字段缺失和本地化文案都有测试。

## P1：可配置扫描来源与待导入提醒

### 借鉴点

参考项目把“扫描哪些目录以发现可导入 Skill”和“向哪些工具部署 Skill”明确分为两套配置。用户可逐个开关扫描来源，保存后重新扫描；主列表在发现候选时给出醒目的“发现待导入”横幅，并提供“调整扫描范围”和“审查并导入”两个并列操作。

参考依据：`src/components/skills/modals/DiscoveryScanModal.tsx` 第 26–123 行实现可访问的逐项开关、已启用计数及“保存并重新扫描”；`src/components/skills/SkillsList.tsx` 第 85–117 行实现待导入横幅。该模式对拥有多个 Agent（智能体）和自定义目录的用户尤其有价值。

### 推荐实现

- 在当前发现模块增加持久化的 `DiscoverySource` 配置：唯一键、显示名、经过脱敏的路径提示、来源类型、启用状态和上次扫描结果。
- 部署目标继续保持独立；关闭扫描某个 Agent 目录不能停用该 Agent 的部署，也不能删除已导入内容。
- 扫描结果只收集包含 `SKILL.md` 的有效目录，并沿用当前扫描器的真实目录、符号链接和边界校验规则。
- 在库页顶部仅当存在新候选时显示横幅；横幅不直接导入，而是进入当前候选选择与冲突处理工作流。

### 前端细节

- 设置弹窗按“来源名称 + 路径 + 开关”单行排列，顶部显示“已启用 X/Y”，底部主按钮为“保存并重新扫描”。
- 待导入横幅应使用与普通信息通知不同的强调色；右侧保持两个动作：次级“扫描设置”、主操作“审查候选”。
- 重新扫描期间禁用重复提交，完成后将焦点和结果摘要返回横幅，满足键盘与读屏器（screen reader）可用性。

### 验收条件

- 配置跨重启保存；关闭来源后不扫描也不删除历史候选的审计记录。
- 用户设置、默认来源和自定义目录重复时按规范化真实路径去重。
- 扫描结果有来源归属；候选目录失效、无读取权限和软链接越界都能显示可操作错误。

## 实施顺序与取舍

1. P1 的精选目录和扫描来源控制可独立实施，改动集中在发现读模型与现有发现页。
2. P2 在现有导入、上游更新、集中库迁移和恢复流程中逐步补强预览、原子替换、冲突与恢复，不新增同步子域。
3. 网络存储留待下一大版本：以 NAS/SMB 等挂载目录的本地路径支持为起点，届时根据需求单独设计，不预设 Git 同步为实现方案。

不建议复制参考项目的单体页面状态、手写 Tauri DTO（数据传输对象）或其硬编码工具目录表。当前项目已有更适合长期维护的分层、绑定生成、路径安全和导入检查机制；借鉴应保持在上述能力和交互契约层。
