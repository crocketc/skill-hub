## 3. 联网复检发现（与文档冲突或可补充）

### 3.1 P0 — 直接冲突，建议必须修订

**① OpenAI Codex（§5.1，第 150 行表格 + 第 180 行章节）**

文档写：「`~/.codex/skills` 不是 OpenAI 官方文档列出的 Codex 本地 Skill 加载目录」

OpenAI 官方 Codex 文档（Skills 章节）明确列出三档作用域：

- Built-in：Codex 安装目录
- **User：`~/.codex/skills/`**
- **Project：`{cwd}/.codex/skills/`**

且官方 API 示例路径即为 `/Users/me/.codex/skills/skill-creator/SKILL.md`，`skills/config/write` 也以该路径为参数。同时 Codex 仍读取 `~/.agents/skills`（跨平台）。两者并存，官方文档未说明同名优先级。

→ 建议改为：Codex 同时支持 `.agents/skills`（跨平台）与 `.codex/skills`（原生），并列列出，同名优先级标「未公开」。

**② Google Antigravity（§5.9，第 160 行表格 + 第 266 行章节）**

| 项 | 文档现值 | 官方/真机实际值 |
|---|---|---|
| 全局目录 | `~/.gemini/config/skills` | `~/.gemini/antigravity/global_skills/`（Windows: `C:\Users\<user>\.gemini\antigravity\global_skills\`） |
| 项目目录 | `.agents/skills` | **`.agent/skills/`（单数）** |
| 兼容目录 | 兼容 `.agent/skills` | 即为官方项目目录，非兼容项 |

本机 `~/.gemini/config` 不存在；`~/.gemini/antigravity/` 下同时有 `skills`（3 个）和 `global_skills`（2 个）两个目录，两者关系官方未说明，需标为待验证。

→ 建议：全局目录改 `~/.gemini/antigravity/global_skills/`，项目目录改 `.agent/skills/`，并把 `~/.gemini/antigravity/skills` 列为「存在但用途未公开」。

**③ Kimi Code（§5.14，第 165 行表格 + 第 316 行章节）**

开源仓库文档（moonshotai.github.io/kimi-cli）已改为「品牌组 + 通用组」双组机制，与官网产品文档（kimi.com/code/docs）表述不同：

- 品牌组（默认互斥选一）：`~/.kimi/skills/` > `~/.claude/skills/` > `~/.codex/skills/`
- 通用组（互斥选一）：`~/.config/agents/skills/`（推荐）> `~/.agents/skills/`
- `merge_all_available_skills = true`（默认）时品牌组全部加载并按 kimi > claude > codex 解析同名
- 项目级同构：`.kimi/skills/`、`.claude/skills/`、`.codex/skills/` + `.agents/skills/`

官方产品文档仍写 `$KIMI_CODE_HOME/skills`（默认 `~/.kimi-code/skills`）。

→ 建议：两套表述并列记录，标注「官方产品文档与开源仓库文档存在分歧，待实测」。关键点：**Kimi Code 会读取 Claude 和 Codex 的 Skill 目录**，这对 SkillHub 的重复检测影响很大。

**④ ZCode（§5.15，第 166 行表格 + 第 326 行章节）**

文档写项目级「UI 支持项目导入，实际目录未公开」。官方 Skill 文档已公开：

- 用户级：`~/.zcode/skills/<name>/SKILL.md`
- **工作区级：`<workspace>/.zcode/skills/<name>/SKILL.md`**

另有明确的格式限制（description 上限 1024 字符、body 超 100KB 截断、每轮注入 metadata 且有共享预算上限、超限降级为仅名称）和官方点名的可导入外部 Agent：Claude Code、Codex CLI、OpenClaw、Augment、Windsurf。

→ 建议：补上工作区级目录；补上格式限制（对 SkillHub 的兼容性检查有意义）；把 ZCode 从「部分适配候选」升为「完整适配候选」。

**⑤ 通义灵码 / Qoder CN（§5.11，第 286 行章节）**

文档写 IDE 用户级 `~/.lingma/skills`。本机 `~/.lingma` 下只有 `tmp` 和 `vscode`，无 `skills` 子目录；而 `~/.qoder/skills` 存在且有 3 个 Skill。

→ 建议：保留官方目录表述，但标注「本机未生成，需确认 IDE 版是否实际落盘至此」。

### 3.2 P1 — 可补充的新证据

- **Cursor（第 155 行 + §5.4）**：官方明确「for compatibility, Cursor 也加载 Claude 与 Codex 目录：`.claude/skills/`、`.codex/skills/`、`~/.claude/skills/`、`~/.codex/skills/`」，并支持子目录递归（`.cursor/skills/shipping/deploy-staging/SKILL.md`）、frontmatter `paths` 字段限定作用范围。内置目录 `~/.cursor/skills-cursor/` 官方明确警告不得修改。→ 建议补内置目录（只读）与兼容目录清单。
- **TraeCode（§5.10）**：中国版内置目录 `~/.trae-cn/builtin_skills/`（5 个：TRAE-code-review、TRAE-debugger、TRAE-generate-mini-app、TRAE-security-review、_shared）；全球版 `~/.trae/skills` 与国内版 `~/.trae-cn/skills` 并存，需按版本拆分 profile。
