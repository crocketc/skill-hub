# SkillHub 发布版本与需求基线差异审查

审查日期：2026-09-02  
发布版本：`v0.1.0`（提交 `0bda666`）  
当前开发基线：`main`（提交 `3027ac1`）

## 结论

发布版本不能视为“需求文档中所有功能已经完成”。当前情况是：领域层、ApplicationFacade、部分桌面页面和自动化测试已经完成，但生产路由仍有多处使用 `unavailable` facade，初始化向导也没有接入启动门禁和真实本机操作。

## 证据摘要

- `apps/desktop/src/app/router.tsx` 中，Skill 库和 Skill 详情使用 native facade。
- Agent、项目、安全结果、待处理、操作进度、恢复和设置路由仍使用 `unavailable...Facade`。
- `/initialize` 路由存在，但 `BootstrapGate` 始终直接渲染 `AppShell`，没有依据首次初始化状态自动跳转。
- `OnboardingWizard` 默认没有注入集中库路径、完成初始化和 Agent 发现的 native operations，因此安装后不会形成可执行的首次使用闭环。
- 需求要求首次启动展示集中库位置、发现 Agent、只读扫描已有 Skill、允许跳过并可从设置重新进入；这些要求尚未全部在生产桌面端兑现。

## 为什么已发布版本看起来“不完整”

当前发布节奏先发布了一个早期版本，验证构建、更新和底层业务能力；部分 UI 以预览数据或 unavailable facade 保留，避免伪造真实数据。自动化测试通过只能证明契约和组件行为，不代表每个页面都已经接入本机数据库和文件系统。

## 建议的后续开发顺序

1. **首次启动初始化闭环**：启动状态、默认集中库路径、向导自动进入、跳过/完成持久化、设置页重新进入。
2. **生产路由 facade 接入**：优先 Agent、项目、设置、待处理和安全结果页，消除用户可见的 unavailable 页面。
3. **导入/部署/删除桌面联调**：从页面操作到真实数据库、文件系统和操作结果完整跑通。
4. **备份/恢复/导出/卸载桌面验收**：补齐入口、进度、错误和恢复反馈。
5. **签名更新和真机验收**：在生产资产具备后验证更新安装、自动重启和回滚。

## 范围说明

本审查不扩大原需求：网络存储/云盘、运行时 Hook、LLM 使用证据等仍按需求文档中的后续或实验范围处理。此文件属于个人开发资料，仅在本地维护。
