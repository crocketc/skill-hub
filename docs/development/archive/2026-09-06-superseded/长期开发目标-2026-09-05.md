## 环境坑（前一个 Agent 实测得出，直接照做）

**MSVC 链接**：沙箱内 `cargo test` 链接失败（link.exe 被 /usr/bin/link 遮蔽、缺 LIB/INCLUDE、沙箱拦截 cl.exe）。做法：
```bash
MSVC="/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/VC/Tools/MSVC/14.44.35207"
export PATH="$MSVC/bin/Hostx64/x64:$PATH"
export LIB="C:\\Program Files (x86)\\Microsoft Visual Studio\\2022\\BuildTools\\VC\\Tools\\MSVC\\14.44.35207\\lib\\x64;C:\\Program Files (x86)\\Windows Kits\\10\\Lib\\10.0.26100.0\\um\\x64;C:\\Program Files (x86)\\Windows Kits\\10\\Lib\\10.0.26100.0\\ucrt\\x64"
export INCLUDE="C:\\Program Files (x86)\\Microsoft Visual Studio\\2022\\BuildTools\\VC\\Tools\\MSVC\\14.44.35207\\include;C:\\Program Files (x86)\\Windows Kits\\10\\Include\\10.0.26100.0\\um;C:\\Program Files (x86)\\Windows Kits\\10\\Include\\10.0.26100.0\\ucrt;C:\\Program Files (x86)\\Windows Kits\\10\\Include\\10.0.26100.0\\shared"
CARGO_INCREMENTAL=0 <cargo 命令>
```
必要时对 cargo 命令禁用沙箱（dangerouslyDisableSandbox）。

**Git ref 丢失**：沙箱可能丢弃 `.git/refs` 写入——commit 成功但 HEAD 解析失败。每次提交后立即 `git rev-parse HEAD`；失败则取完整 40 位 SHA，用 **Write 工具**写入 `.git/refs/heads/feat/v0.2.0-product-completion`，再验证。**push 必须禁用沙箱**。

## 并行开发规则（子代理，最多 3 个）

为节约时间，**无直接依赖且文件集不相交**的任务用子代理（Agent 工具）并行开发：

- **并发上限 3 个子代理**；不指定 model 参数（继承主代理模型）。
- **只把任务实现体交给子代理**：子代理负责写代码 + 写测试 + 跑测试验证，**不做 git commit/push**（避免 ref 丢失问题与竞态）——完成后由主代理审查 diff、补齐共享文件、统一提交推送。
- **共享热点文件归主代理**：`i18n/*/common.json`、`api/bindings.ts`、`app/router.tsx`、`styles/base.css` 由主代理统一编辑/合并；子代理的任务范围只含自己的 feature 目录与测试文件。子代理需要新 i18n 键/bindings 时，在产出说明里列出键名与值，由主代理落盘。
- 子代理指令必须**自包含**：带上环境坑（MSVC 配方、ref 问题）、TDD 约束、相关契约形状与安全基线（发现模块任务必须附规格 §4/§6 的常量与校验要求）。
- 并行分组示例（文件集互不相交时才启动）：
  - Q1（Rust adapters）∥ Q3（OnboardingWizard 完成页）∥ Q4（操作框架）三者可并行；
  - Q2 依赖 Q1 的适配决策但文件不同，可在 Q1 完成后与 Q4/Q5 的余量并行；
  - Q5 依赖 Q4 的框架，必须串行；Q7~Q8 均依赖各自契约，互相可并行。
- 主代理在并行期间负责：审查子代理产出、处理共享文件、跑全量验证、提交推送、维护队列状态。任何子代理产出不可用时：放弃该产出重做或降级，不要阻塞队列。
