# SkillHub 人工验收重构与缺陷修复交接

日期：2026-09-09  
当前分支：`feat/v0.2.0-product-completion`  
原代码冻结基线：`27042e6`  
交接原因：现有 22 条人工验收项颗粒度过粗，部分条目同时覆盖多个功能、分支和平台事实；首轮 Windows 源码验收已发现多项问题，继续按旧清单执行会导致结果和问题无法准确对应。

## 1. 当前决定

- 暂停继续执行旧版人工验收清单。
- 不在本次交接中修改业务代码、重构测试或修复缺陷。
- 下一位 Agent 应以《需求文档》《产品与交互设计》《用户故事》为上游依据，以 v0.2.0 实际功能范围为版本边界，重新建立原子测试体系。
- 能稳定自动化的用例必须进入 Rust、前端组件/集成或 Playwright 测试；只有依赖真实设备、系统集成或人工视觉判断的用例留在人工验收清单。
- 用户提出过“恢复出厂设置并删除全部数据”，随后明确撤回。保持现有需求：不提供危险的一键清空数据，不实现该功能。
- 完整大模型接入属于下一版本规划，不计入 v0.2.0 发布阻塞；不得用无行为的按钮伪装已支持能力。

## 3. 验收体系重构目标

建立三层结构：

1. 原子测试目录：覆盖全部用户故事及全局验收规则，是需求追溯的权威入口。
2. 自动化测试说明：记录可自动化用例、测试层级、测试文件、命令和结果。
3. 人工验收清单：只保留真实设备必须人工执行的原子用例，并提供逐条结果记录。

每条原子测试用例至少包含：

| 字段 | 要求 |
|---|---|
| 用例编号 | 稳定唯一编号，例如 `TC-US001-01` |
| 用户故事 | 对应 `US-001～US-062`；横向规则可关联多个故事 |
| 版本归属 | `v0.2.0`、`下一版本`、`后续大版本`或`明确不做` |
| 前置条件 | 最小、可重复、不得依赖个人真实数据 |
| 操作链路 | 一个闭环或一个分支，不混合无关断言 |
| 预期结果 | 可观察、可判定，不使用“正常”“符合预期”等空泛表述 |
| 测试类型 | Rust、前端组件/集成、Playwright、Windows 人工、macOS 人工、签名包人工 |
| 自动化证据 | 已有测试文件/用例名，或明确标记“缺失待补” |
| 执行结果 | 待执行、通过、失败、阻塞、不适用 |
| 证据/问题编号 | 截图、日志、真实文件证据和独立问题 ID |

原子拆分原则：

- 成功、失败、取消、重复、恢复、权限受限分别成用例。
- Windows 与 macOS 只有在系统行为确实不同时才拆分；共享业务逻辑优先自动化一次。
- 一个用例可以验证一个完整闭环，例如“导入成功后文件落盘且重启仍可见”；不得同时夹带概览刷新、批量结果样式等其他问题。
- 视觉、文案和业务事实分开；路径/权限/链接等系统事实与页面状态分开。
- 已实现但缺测试、设计已定义但未实现、下一版本能力必须分开标记。

## 4. 推荐执行顺序

1. 解析 62 条用户故事中的每条 Given/When/Then，并补入 10 条全局验收规则产生的横向用例。
2. 对每条用例做 v0.2.0 范围判定；不得因为设计文档存在就默认代码已实现。
3. 建立现有自动化测试到原子用例的反向索引，验证测试断言而非仅凭文件名判断覆盖。
4. 将可自动化但缺失的项目列为测试债务，按 TDD 先补失败测试。
5. 重写人工验收清单，只保留安装/卸载、真实文件选择器、真实权限、链接、缩放、减少动效、签名更新、跨设备恢复及必要视觉判断。
6. 将首轮验收记录拆成独立问题，完成复现和根因调查后再修复。
7. 修复后运行相关测试，再运行仓库规定的格式、静态检查、类型检查、构建和发布检查。
8. 用新清单重新执行 Windows 验收；问题收口后再执行 macOS 与正式安装/签名更新验收。

## 5. 首轮验收问题清单

以下内容来自用户填写的旧人工验收记录。原文仍保存在《人工验收清单》，本节只做可执行拆分，不宣称根因已确认。

### QA-001 批量删除交互与反馈

- 现象：删除所选 Skill 后，批量影响/候选处理界面覆盖技能库；批量删除还要求输入 `FORCE DELETE`；成功结果逐条铺开；数量较多时缺少清晰的执行中反馈。
- 用户期望：保留必要的影响预览和二次点击确认，不要求输入文本；执行中给出状态；结束后返回技能库；结果先显示成功/失败数量，只展开失败项；删除动作进入操作记录与恢复。
- 需求边界：删除前仍必须重新扫描部署、引用、依赖和未知外部引用；有部署关系时仍需逐项选择处理方式，不能简化成无影响预览的直接删除。
- 代码入口：`apps/desktop/src/features/removal/BatchRemovalImpactDialog.tsx`、`apps/desktop/src/features/skills/SkillLibraryPage.tsx`、`crates/skillhub-core/src/application/removal_service.rs`。
- 测试入口：删除/解除部署相关前端测试、`crates/skillhub-core/tests/undeploy_delete.rs`、应用层 removal 测试。

### QA-002 初始化自定义集中库进入死路

- 现象：在“新建集中库”选择其他目录并“保存并重启”后，提示集中库初始化完成后不能更换根目录，无法进入下一步；返回后仍选中该目录，继续不可用；选择目录按钮置灰；使用已有集中库也不能继续。
- 初步证据：`LibraryStep.tsx` 在存在 `customLibraryPath` 时禁用重新选择按钮；`OnboardingWizard.tsx` 先持久化根目录再调用重启，失败后仍保留所选状态。必须继续追踪后端 `set_library_root` 与初始化状态，确认真正根因后修复。
- 代码入口：`apps/desktop/src/features/onboarding/LibraryStep.tsx`、`OnboardingWizard.tsx`、对应 native API 和 Tauri 命令。
- 测试入口：`OnboardingWizard.test.tsx`、`OnboardingBranches.test.tsx`、`tests/e2e/onboarding.spec.ts`。

### QA-003 本地批量导入来源选择被意外清空

- 现象：取消一个默认扫描来源后再选择本地目录，其他已选默认来源被清空。
- 期望：扫描来源多选与手动追加目录共存；手动目录追加到当前选择，不替换已有选择。
- 代码入口：`apps/desktop/src/features/import/SourceInput.tsx`、`ImportWizard.tsx` 和目录选择适配层。
- 测试入口：`SourceInput.test.tsx`、`ImportWizard.test.tsx`、`tests/e2e/import-deploy.spec.ts`。

### QA-004 本地批量导入来源区域交互冗余

- 现象：解析本地路径后额外显示“类型/本地路径/目标”描述块，与候选区域重复；缺少明确的全不选和全部移除入口。
- 期望：本地批量导入以候选来源/候选 Skill 区域为主；全选按钮可明确切换或增加全不选；手动追加来源可单独移除并支持全部移除。
- 注意：来源描述块对 URL、Git、npx 等来源仍可能有价值，不能未经需求确认全局删除；应按来源类型设计。

### QA-005 导入结果信息密度过高

- 现象：成功项全部逐条展示。
- 期望：先显示成功、失败、跳过和待处理数量；默认只展开失败/待处理项，成功明细可按需查看。
- 代码入口：`apps/desktop/src/features/import/ImportSummary.tsx`。

### QA-006 导入后概览仍显示零

- 现象：技能已出现在技能库，但概览统计仍为 0。
- 调查要求：区分“概览 React Query 缓存未失效”“bootstrap 快照未重新查询”“后端快照统计未更新”三类原因；先复现并记录导入完成前后查询结果，再修复数据源头。
- 代码入口：导入完成缓存失效逻辑、`apps/desktop/src/features/overview/OverviewPage.tsx`、bootstrap snapshot 查询与后端统计。

### QA-007 快速抽屉别名和备注保存失败或不刷新

- 现象：抽屉修改别名/备注后重新打开为空，列表不显示更新。
- 初步证据：`SkillQuickDrawer.tsx` 对保存失败执行 `catch(() => undefined)`，用户看不到失败；还需核对 native facade、后端持久化及相关 Query 缓存失效。
- 代码入口：`apps/desktop/src/features/skills/SkillQuickDrawer.tsx`、技能 native API、元数据存储层。

### QA-008 完整详情元数据无法保存

- 现象：编辑别名、用途说明、标签、备注后提示“未能保存，草稿已保留”。
- 调查要求：读取原始结构化错误和 Tauri/Rust 日志，追踪字段映射、命令结果及持久化；不得只隐藏错误提示。
- 代码入口：`apps/desktop/src/features/skill-detail/MetadataPanel.tsx`、`SkillDetailPage.tsx`、对应 native API 和应用层命令。

### QA-009 原始描述未读取 Frontmatter `description`

- 现象：快速抽屉未显示 `SKILL.md` 头部的 `description`。
- 调查要求：检查导入解析、元数据落库、详情查询和前端映射四层，确定字段在哪一层丢失。

### QA-010 版本展示疑似使用内容哈希

- 现象：抽屉和详情中的版本像哈希值，不符合普通用户理解。
- 目标规则待与现有需求核对：本地首次导入需使用可读版本；远程来源存在可信版本时保留来源版本；内容哈希只作为技术身份或完整性证据，不作为主要版本标签。
- 注意：不要仅在前端截断或伪造 `1.0`；需确认版本领域模型、来源版本和更新比较语义。

### QA-011 Markdown 编辑器与预览区域重叠

- 现象：进入编辑后源码与预览不是稳定左右分栏，出现重叠。
- 代码入口：`apps/desktop/src/features/markdown/MarkdownWorkspace.tsx` 及相关样式。
- 测试要求：至少覆盖常见桌面宽度和小窗口边界；真实系统缩放保留人工验证。

### QA-012 Markdown 工作区长内容无限拉高

- 现象：长 `SKILL.md` 持续撑高页面。
- 期望：工作区有合理的桌面高度约束，源码和预览区域独立滚动；不能影响页面主要操作和可访问性。

### QA-013 Markdown 保存行为与所有权提示不清

- 现象：只有“保存并创建副本”，用户希望可保存原文。
- 需求边界：用户自有或 SkillHub 管理内容允许显式保存并形成新版本；只读、内置、插件和未接管外部内容只能复制导入或接管。下一位 Agent 应先核对当前对象的所有权映射，再按权限显示“保存”或“保存为副本”，不能对所有对象统一开放原文覆盖。

### QA-014 品牌图标未按素材映射

- 现象：用户期望已有素材的品牌使用对应 Logo，未识别品牌继续使用颜色标签和大写首字母。
- 调查要求：先盘点现有 Logo 素材及品牌 ID 映射；仅对有明确素材和身份映射的 Agent 替换，保留未知品牌回退。
- 代码/测试入口：`BrandLogo`、`BrandTag` 及其测试、项目静态资源目录。

### QA-015 翻译入口

- 用户建议在 Markdown 阅读/源码/编辑之外增加翻译入口。
- 当前决定：完整 LLM 接入属于下一版本。v0.2.0 不新增无行为按钮；现有设计中的描述翻译与完整内容翻译也要区分，下一版本需求澄清后再实现。

## 6. 自动化与人工的判定规则

优先自动化：

- 领域规则、路径边界、所有权、状态转换、冲突决策和部分失败语义。
- 数据持久化、操作记录、版本、备份/恢复完整性和查询刷新。
- 前端按钮状态、表单校验、成功/失败/取消反馈、缓存失效、导航上下文和国际化键。
- 浏览器可稳定模拟的完整流程、键盘操作、窗口尺寸和长文本布局。
- 300 Skill 性能基准中不依赖真实系统 API 的部分。

保留人工：

- Windows/macOS 安装、卸载、首次启动、签名、公证、系统安全提示和真实更新包。
- 原生目录选择器、系统凭据存储、真实无权限/只读目录、符号链接/目录联接。
- 系统缩放、减少动效、原生窗口行为、文件管理器可见结果。
- 跨设备备份介质和真实恢复。
- 需要人判断的信息层级、视觉遮挡、文案可理解性和品牌识别。

## 7. 工作约束

- 行为变更必须 TDD：先补最小失败测试，再实现，再重构。
- 每个问题独立定位根因和提交；不得把多个猜测性修复捆绑。
- 不降低断言、不删除测试、不增加任意延时掩盖问题。
- 不使用真实用户 Skill、凭证或个人目录作为测试夹具。
- 保留用户当前未提交内容；当前 `apps/desktop/src-tauri/Cargo.toml` 存在 `tauri` 的空 `features = []` 变更，功能修复前应判断是否必要，不要擅自覆盖。
- 修复 UI 前先核对需求与所有权/数据安全规则；用户验收建议不自动等价于已批准的范围变更。
