- **最多 3 个子代理同时执行不冲突的任务**。第 4 个任务必须等前 3 个中有人释放槽位。

### 4.2 文件边界规则（决定"能否并行"的唯一标准）

- 可并行：文件集合完全不重叠，且不触碰上一节列出的公共文件。
- 不可并行直接合并：两个任务都要改 `api/query.rs`、`api/command.rs`、`relationship_governance_service.rs`、`AppShell.tsx`、`router.tsx` 或 `common.json`。此时二者必须用**独立 worktree**，且合并顺序固定（先冻规则/契约，后消费），后合并的一方必须 rebase 并把文案改为已冻结的词汇表。
- 页面并行期对 `common.json` 各自使用独立命名空间（如 `relationships.graph.*`、`relationships.decisions.*`、`relationships.governance.*`），由 Task 10 统一排序、去重、键集对称审计。
- 每个并行实现单元使用**独立 worktree**（`git worktree add`），任务级复审通过后再合入阶段基线；合入后立即删除 worktree 与临时分支。

### 4.3 每个子代理的固定工作流（七步，不可跳）

1. **加载技能**（见 §5），把本次任务点名要用的技能读进来再动手。
2. **在任务账本登记**：`.superpowers/sdd/2026-09-16-skill-relationship-module-and-unified-execution-implementation-plan/`（该目录已被 `.gitignore` 忽略，只作过程账本，不入库），写 `task-N-brief.md`（任务简报：范围、文件集、验收命令、不可触碰边界）。
3. **先写失败测试**并确认变红（把红灯输出贴进账本）。禁止先写实现再补测试。
4. **最小实现**转绿；然后重构。禁止超出计划范围的顺带改动。
5. **定向测试 + 自检**：跑本 Task 的定向命令，再跑受影响 crate/包的检查。前端改动必须过 `pnpm check:frontend`；Rust 改动必须过 `cargo fmt` 与相关 crate 的 `clippy -D warnings`。
6. **独立复审**：审查者必须**不是**实现者（由另一个子代理或主代理担任），双轴审查（Standards 轴 + Spec 轴：是否符合设计与计划）。BLOCKER 必须修复后复核；MINOR 记录处置结论。复审 diff 存进账本目录。
7. **合并 + 提交**：`git diff --check` 干净后提交（英文动词开头），随后删除 worktree/临时分支。

### 4.4 子代理返回给主代理时必须包含

修改文件清单、验证命令与结果（真实输出，不是"应该通过"）、提交哈希、未解决问题、对公共文件的变更请求（若有）。主代理负责核对实际改动，不采信"我改好了"的口头结论。
