### 本轮记录的执行注意

- **workspace clippy 是整合门禁**：K 批次多轮只跑定向 test/check 时，8 处 clippy 违规（derivable_impls、clone_on_copy、needless_borrows、collapsible_if、result_large_err、await_holding_lock、unnecessary_lazy_evaluations 等）累积到 K10 才暴露。教训：每批整合后立即 `cargo clippy --workspace --all-targets --all-features -- -D warnings`。`await_holding_lock` 不识别显式 `drop()`（词法范围检查），用块作用域包裹；`result_large_err` 按函数 `#[allow]` 并注释辩护。
- **E2E 与用户 5174 预览服务共存**：正式 config `reuseExistingServer:false` + `--strictPort` 会因端口占用直接失败。端口被用户 vite dev 占用时，使用仓库外会话临时配置（`testDir` 指向对应工作树 `tests/e2e`，`webServer.url` 指向 5174，`reuseExistingServer:true`）复用现有服务——dev 服务读磁盘实时代码，等同当前工作树状态；不杀用户进程、不改正式配置。端口空闲时照常用 `pnpm test:e2e`。
- **并行负载偶发**：并行 cargo/vitest 首轮偶发失败（facade_import_conflicts、vitest 超时）；隔离重跑全绿即定性环境负载，不降低断言、不增加任意延时。
- **i18n 校验**：`node /tmp/i18n-check.mjs` 类相对路径脚本必须从 `apps/desktop` 运行；vitest 亦必须 `cd apps/desktop` 后运行。

## 自动化命令

| 用途 | 命令与注意事项 |
| --- | --- |
| Rust 单元／集成 | 定向 `cargo test -p <crate> --test <测试文件>`；全仓 `cargo test --locked --workspace` |
| Rust lint 门禁 | `cargo clippy --workspace --all-targets --all-features -- -D warnings`（每批整合后必跑）；`cargo fmt --all -- --check` |
| 前端单测 | 全量 `pnpm test:frontend`；定向 `pnpm --dir apps/desktop exec vitest run <受影响测试>`。必须在 `apps/desktop` 下运行 vitest，从仓库根会解析到无 jsdom 配置的 vitest |
| 前端检查与构建 | `pnpm check:frontend`（ESLint 与 TypeScript）、`pnpm build:frontend`、`pnpm --dir apps/desktop check` |
| 浏览器 E2E | 必须用根目录脚本 `pnpm test:e2e <spec>`（带 `--config=tests/e2e/playwright.config.ts`）。直接 `npx playwright test` 不加载 baseURL，会大面积报「Cannot navigate to invalid URL」——是调用方式错误，不是产品缺陷。端口被 5174 用户预览服务占用时按上方"共存"方式处理 |
| 发布检查 | `pnpm verify:release`、`pnpm test:release`、`node scripts/verify_atomic_test_catalog.mjs`、`node scripts/verify_frontend_lifecycle_scripts.mjs` |
| 生成绑定 | 临时设置 `SKILLHUB_WRITE_BINDINGS=1` 运行 `cargo test -p skillhub-desktop generate_bindings`，完成后移除该临时变量并核对生成差异；绑定只能由生成工具更新，不手写 bindings.ts |
| Windows release 构建 | `pnpm --dir apps/desktop tauri build --no-bundle`（产物 `target/release/skillhub-desktop.exe`，不提交 Git，供真机验收使用） |
| 本地 CI | `pnpm ci:local` 十项：fmt、deny、clippy、Rust 全仓、冻结安装、生命周期、audit、check、前端单测、构建（保留既有 chunk 提示；通过步骤静默，失败才输出） |
| 空白检查 | 最终整合提交前 `git diff --check` |

## 覆盖范围与验证边界

自动化覆盖：

- Rust core／application／storage 的领域、facade、存储与迁移测试；K1—K6 新增的 RED/GREEN 行为测试（版本采用一致性恢复与补偿、共享消费者确认／回收、多目标失败继续与逐项恢复、导出全资产敏感扫描与预览绑定、草稿校验、另存血缘与替换继承确认门、来源身份校验与预览绑定采纳、忽略候选持久化）。
- 六项裁决实施的行为测试：导入安全分级与逐条依据（product_level）、prepare 提前扫描与 security_decision 门禁（危险级缺省拒该 Skill 不牵连整批）、0028 security_alerts 迁移与派发双重门禁（get_deployment_plan/revalidate）、trust_skill_security 幂等与同版本防复活、AI 调用次数恒 0 的边界钉住、basic-v1 误报回归素材、analyze_import_batch 批内分组与同名显式处置（未处置拒提交、批组成守卫）、导入检查 trigger=import 登记、删除级联草稿、备份说明、守卫式重试留痕。
- 前端组件与 nativeApi 契约单测；DEV 预览路由与 mock 门面下的浏览器 E2E（页面契约与几何），已对齐 K3 两段导出、K5 另存对话框／确认门、K6 预览绑定流、六项的安全决策区/预警徽标/待办信任三选/派发拦截（security-alert-workflows 专项 spec）与批内冲突处置链路。
- 发布检查与原子测试目录一致性校验。

自动化不能证明：

- 真实桌面通过。浏览器预览、预览 HTTP 200、自动化通过均不代表 Windows/macOS 桌面通过；人工验收只按[人工验收清单](人工验收清单-2026-10-05.md)执行并记录。
- 原生文件与权限事实。真实用户目录与 Agent 文件保护、真实权限／只读目录、跨卷行为、真实窗口／主题视觉、长路径与批量耗时、通知中心人工可读性不在自动化覆盖内。Windows 目录联接与 macOS 符号链接的真实落盘与权限取证需真机：能力不足的环境中原生链接场景由守卫提前跳过（本轮 Windows 全量 E2E 中此类跳过如实计入 skipped，不记为通过），测试命令成功不等于原生场景实际运行。
- mock 与真实持久化分开记录。E2E／浏览器测试使用 DEV 预览路由与 mock 门面，只证明前端契约与几何，不能证明原生 IPC 与数据库的真实往返；生产链路由真实应用域＋临时库持久化测试分别验证与记录（K1—K6 与六项实施的 facade 级测试属此类），两者都不替代桌面人工验收。
- FB-003／FB-006／FB-007 与跟进三项已实施并有自动化覆盖，但真实桌面链路仍需人工验收：真实导入素材的分级呈现与单 Skill 决策、预警状态在真实库/待办/派发三处的一致性、信任后同版本重扫、批内冲突在真实多来源批次中的分组、导入检查记录的重启持久化，分别按人工清单流程 C、F、V1/V2 验证，不以全量绿色推定关闭。
- 部分真机时序无法由自动化稳定制造：DEV-101 真实进程崩溃时序按流程 I 真机验收；自定义 Agent 真实登记（原生文件选择器授权）、真实目录替换后的身份变化拦截、部署／解除落盘属流程 L 真机范围。

## 验证纪律

- 行为变更采用 TDD：先写失败测试，再实现最小行为，最后重构；不降低断言、不删除测试、不假成功、不增加任意延时。
- 开发阶段按影响范围定向验证；**每批整合后立即跑 workspace clippy 与 fmt**（本轮教训：定向测试不查 lint，违规会累积到全量门禁才暴露）。
- 相关测试通过且代码未再变化时，不重复运行同一套测试；出现新改动、失败或未解决风险时，再补充必要验证。回报须写明本轮测试范围、结果与尚未验证的边界，定向通过不得写成全量通过。
- 发布前必须在最终整合提交上执行全量验证：`pnpm ci:local`、`pnpm test:e2e`、发布检查与 `git diff --check`，并处理失败。本轮已在 `19d1601c` 完成；后续任何代码变更都必须重新执行，不得继承本轮结果。
- 新变更必须自行验证并记录当次结果，不继承历史绿色结果；归档中旧日期的结果不再代表当前代码状态。
