# SkillHub Task4 技能库工作台设计

> 日期：2026-08-25

> 状态：用户已确认交互与视觉方向，等待书面规格复核

## 1. 目标与范围

本规格定义 Plan07 Task4 的技能库默认工作台、保存视图、批量选择和 Skill 快速抽屉。实现遵守 `docs/产品与交互设计.md` 的列表、抽屉和完整详情三级信息架构，并延续已确认的桌面壳层与九套完整主题。

Task4 只实现前端页面与可注入数据边界，不修改 Rust 合约，不提前实现 Task5 的完整详情页、Task7 的统一导入流程或 Task9 的部署、安全、删除和恢复提交工作流。

## 2. Design Read

`Design Read: local developer tool · restrained, precise, scannable · register=product · SOUL=5 · SPECTACLE=1 · DENSITY=9 · hero-engine=none`

技能库是面向 100–300 个本地 Skill 的高频工作台。界面优先保证扫描速度、可恢复上下文和批量操作范围的真实性，不采用营销式大标题、装饰性动效、卡片瀑布流或命令行优先的隐藏交互。

本页面沿用当前主题的语义令牌。主题切换只改变完整配色，不改变表格、筛选器、抽屉或控件造型。

## 3. 已确认的页面方向

采用用户选择的 A「平衡型工作台」：

- 保存视图横向排列在表格上方。
- 搜索与组合筛选形成第二层工具栏。
- 表格在抽屉关闭时占满内容区宽度。
- 快速抽屉覆盖内容区，不挤压或重新计算列表布局。
- 选择后使用底部浮动批量操作栏，不在每行堆叠重复操作按钮。

技能库默认采用紧凑密度，目标行高为 36–40px。该决定只覆盖技能库默认值，不修改其他页面已经采用的标准密度；用户仍可在“列与密度”中切换标准或舒适密度。

## 4. 页面信息架构

页面从上到下分为五层：

1. 页面上下文：技能总数、当前数据来源状态和页面级操作。
2. 保存视图：内置视图、用户保存视图和保存当前条件入口。
3. 查询工具栏：全文搜索、组合筛选、视图切换、列与密度设置。
4. 高密度表格：排序、分页、单选、多选和行级抽屉入口。
5. 选择状态：当前页选择或全部筛选结果选择后的浮动批量栏。

保存视图保持单行。超出可用宽度的用户视图进入“更多视图”，避免压缩搜索和表格首屏。保存视图只保存筛选、排序、列和密度，不复制 Skill，也不保存当前页码或批量选择。

## 5. 表格模型

### 5.1 默认列

默认紧凑视图显示：

- 选择。
- 名称和显示别名。
- 我的用途说明。
- 标签和生命周期。
- Agent 与项目部署摘要。
- 当前版本和可升级提示。
- 基础安全检查、AI 安全检查和待处理摘要。

数字与数量右对齐并使用等宽数字；文本左对齐；状态使用文字或图标配合颜色。未知、未检查和无数据不得表现为失败。

### 5.2 可选列

用户可显示、隐藏和调整顺序的扩展列包括原始说明、描述译文、来源、所有权、许可证、调用方式、运行要求和声明信息。选择列与名称列不可隐藏。

### 5.3 分页与密度

- 默认每页 25 项，可切换 10、25、50 或 100 项。
- 页脚显示总数和当前范围，例如“共 80 项，当前显示 1–25”。
- 紧凑、标准和舒适三档密度共享相同字段和语义，不因密度改变业务内容。
- 25 项分页表不使用虚拟滚动，避免增加键盘和屏幕阅读器复杂度。

## 6. 行交互与上下文恢复

- 点击行正文打开快速抽屉。
- 点击复选框只改变批量选择，不打开抽屉。
- 不使用双击作为必要操作。
- 键盘聚焦行后按 Enter 打开抽屉。
- 关闭抽屉后焦点返回原行；原行不可用时返回表格容器。
- 打开、关闭或切换抽屉对象时保留筛选、排序、分页、列、选择和列表滚动位置。
- 筛选、排序、页码、保存视图和当前抽屉 Skill 写入 URL 查询参数，支持返回与刷新恢复。
- 批量选择保存在当前技能库路由状态中，不写入 URL，也不进入保存视图。

## 7. 批量选择模型

选择状态使用显式联合类型：

1. `none`：未选择。
2. `explicit`：保存已选择的具体 Skill ID，可跨分页保留。
3. `all_filtered`：保存当前筛选快照和少量排除 ID，不预先载入全部筛选结果 ID。

用户选择当前页面后，界面显示“已选择当前页面 25 项”，并提供“选择全部 80 个筛选结果”。进入 `all_filtered` 后显示“已选择全部 80 项”。

筛选条件发生变化时，`all_filtered` 选择失效并清除，同时通过 `aria-live="polite"` 说明原因；具体 ID 选择只保留仍属于新结果集的对象。批量操作栏必须显示选择范围，不能把高风险对象隐藏在一个总数中。

Task4 只产生类型化批量操作意图并展示选择范围。没有真实命令契约的部署、删除或安全处理不得显示伪成功状态，其准备、确认和逐项结果由 Task9 实现。

## 8. 快速抽屉

### 8.1 尺寸与布局

用户选择 B「加宽」作为默认值：

- 默认宽度目标为 620–720px，根据工作区宽度约束在安全范围内。
- 同时提供标准、加宽和近全屏三档。
- 用户可拖动调整宽度；最终宽度按用户全局记忆。
- 抽屉内部使用两列模块布局；空间不足时退化为单列。
- 抽屉内部独立滚动，标题、主要操作、高风险摘要和完整详情入口保持可见。

### 8.2 固定模块

以下内容不可隐藏：

- 名称、显示别名和说明。
- 主要操作。
- 高风险和待处理摘要。
- 完整详情入口。

### 8.3 可配置模块

以下模块可显示、隐藏和调整顺序：

- Agent 与项目关系。
- 版本与更新。
- 来源与许可证。
- 基础与 AI 安全检查。
- 调用方式、运行要求和声明信息。
- 依赖与语义重复。
- 外部变更。
- 有可靠数据时的使用证据摘要。

配置按用户全局保存，不为每个 Skill 建立独立布局。固定模块在配置界面显示为不可隐藏，并提供恢复默认。

## 9. 前端数据边界

### 9.1 当前契约缺口

现有 Specta 绑定只提供 `SearchQuery -> SearchHit[]`，其中包含 Skill ID、名称、排序分值和匹配字段。它不能提供 Task4 所需的目录分页、完整表格列、Skill 保存视图、列/密度偏好或抽屉偏好。

Task4 不手工扩展生成绑定，也不使用搜索结果猜测目录数据。

### 9.2 Facade

新增可注入 `SkillLibraryFacade`，页面只消费下列前端模型：

- `SkillPage`：行、总数、当前范围和分页信息。
- `SkillLibraryQuery`：搜索、筛选、排序、页码、页容量和当前视图。
- `SavedSkillView`：名称、查询条件、排序、列和密度。
- `SkillTablePreferences`：列顺序、显示状态和密度。
- `SkillDrawerPreferences`：档位、像素宽度、模块顺序和显示状态。
- 类型化保存、更新、恢复偏好和批量意图方法。

测试和视觉验收注入确定性的 Mock Facade。正式桌面路由使用 `UnavailableSkillLibraryFacade`；真实查询合约未冻结前，页面显示明确的数据不可用状态，不伪造用户 Skill。

以后接入 Rust 时，新实现必须通过 Specta 生成类型并完整校验漂移；页面组件和测试不需要更换交互模型。

## 10. 数据加载与状态

分页数据、保存视图和偏好通过 React Query 并行加载，避免串行瀑布。各状态分别表达：

- 首次加载：使用与紧凑行同高的骨架表格，预留最终布局空间。
- 无 Skill：解释集中库为空，并指向后续统一导入入口。
- 无筛选结果：显示当前条件未匹配并提供清除筛选。
- Facade 不可用：说明目录数据接口尚未接入，不显示伪数据。
- 查询失败：保留查询上下文，显示错误和重试。
- 偏好保存失败：保持当前临时设置，提示未持久化并允许重试或恢复默认。

尚未实现的导入、完整详情和高风险工作流只保留清晰的边界，不得模拟提交成功。

## 11. 组件边界

- `SkillLibraryPage.tsx`：组合页面查询状态、选择状态和抽屉状态。
- `SkillTable.tsx`：TanStack Table 列、排序、分页、键盘行交互和选择。
- `SkillFilters.tsx`：搜索、组合筛选、结果数和清除条件。
- `SavedViews.tsx`：内置视图、用户视图、溢出和未保存变更提示。
- `SkillQuickDrawer.tsx`：抽屉固定区域、模块区域、宽度和焦点恢复。
- `drawerModules.ts`：固定模块与可选模块注册表、顺序和可见性规则。
- `api.ts`：Facade、前端模型、Mock/Unavailable 实现和 React Query 适配。

TanStack Table 负责列、排序和行模型，不负责远端数据获取。页面不定义内联组件，不把所有偏好合并为一个巨型状态对象；简单派生值在渲染期间计算，昂贵行模型交给 TanStack Table。

## 12. 动效与可访问性

- 普通模式只对抽屉使用短时位移与透明度反馈；不得使用装饰性循环、弹跳或弹性动画。
- 减少动态效果时抽屉直接进入终态，不使用位移。
- 表头排序使用 `aria-sort`；复选框名称区分当前行、当前页和全部筛选结果。
- 保存视图、筛选器、密度和分页均可通过键盘操作并具有可见焦点。
- 选择范围变化、筛选导致的选择清除和偏好保存结果使用适度的 live region。
- 中英文资源键保持完全一致；用户可见文案不直接写死在组件中。
- 所有九套主题复用同一结构并分别保证正文、辅助文字、状态和焦点对比度。

## 13. TDD 与验收

TDD 先覆盖用户行为并观察预期失败，再实现最小功能。至少覆盖：

- 当前页选择与全部筛选结果选择的区别。
- `all_filtered` 的筛选快照、排除项和筛选变化处理。
- 保存视图只保存查询、排序、列和密度。
- 默认紧凑密度和密度切换。
- 选择列、名称列及抽屉固定模块不可隐藏。
- 抽屉模块排序、恢复默认和偏好保存失败。
- 标准、加宽、近全屏和拖动宽度记忆。
- 行点击、复选框隔离、Enter 打开和关闭焦点恢复。
- URL 查询状态恢复与抽屉切换时的列表上下文保持。
- 加载、空、无筛选结果、错误和 Facade 不可用状态。
- 中英文文案和减少动态效果。

Task4 验收命令：

```text
pnpm --dir apps/desktop test --run src/features/skills
pnpm --dir apps/desktop test --run
pnpm --dir apps/desktop check
pnpm --dir apps/desktop build
```

完成后在桌面窗口中检查中性苔和 Grok 夜主题、中文与英文、紧凑表格、全部筛选结果选择、加宽抽屉、宽度拖动、键盘焦点和减少动态效果。
