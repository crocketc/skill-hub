# SkillHub 应用内更新功能设计

## 1. 目标与范围

为普通用户提供不依赖 GitHub 页面操作的应用更新体验：SkillHub 在应用内检查版本、下载适配当前平台的安装包、验证完整性，并在用户明确确认后启动系统安装程序。

本设计不尝试绕过 Windows SmartScreen、Windows Smart App Control 或 macOS Gatekeeper。未签名/未公证构建仍可能出现系统安全提示，SkillHub 只负责提供清晰说明和安全校验。

V1 不包含：静默安装、强制升级、后台常驻更新服务、任意第三方下载源、平台开发者证书购买或公证流程。V1 只保留一次更新启动失败后的受控回滚，不做长期多版本回滚管理。

## 2. 用户体验

### 2.1 普通用户流程

1. 应用按设置执行后台检查，或用户在设置页手动检查。
2. 发现新版本后展示版本号、发布日期、更新说明、文件大小和当前平台。
3. 用户点击“下载更新”，应用内显示进度和取消操作。
4. 下载完成后校验版本、文件大小、SHA-256 和更新签名。
5. 校验通过后显示“立即安装”；用户确认后退出当前版本并启动更新器。
6. 更新器完成替换后自动启动新版本；新版本完成启动自检后记录更新成功。
7. 下载、校验、安装或启动自检失败时保留/恢复上一版本，不影响 Skill 数据。

GitHub 只作为后台发布源；用户不需要打开 GitHub。下载失败时可提供“打开官方发布页”作为备用操作。

### 2.2 设置项

- 自动检查更新：开启/关闭。
- 启动时检查：开启/关闭；检查不得阻塞主界面启动。
- 检查频率：每天一次、每周一次、仅手动。
- 接收预览版：默认关闭，V1 可只保留配置占位，不提供预览版发布流程。

默认值：自动检查开启、启动检查不阻塞、最短检查间隔 24 小时、不接收预览版。

## 3. 发布清单与下载源

### 3.1 固定来源

应用只信任预配置的官方发布仓库和 HTTPS 地址。发布清单至少包含：

- 应用版本和发布时间；
- 更新说明；
- 平台和架构；
- 安装包名称、大小和下载地址；
- SHA-256；
- Tauri 更新签名（启用签名更新时）。

不接受用户输入的下载 URL，不把任意网页内容解析为更新清单。应用更新查询应复用现有 GitHub Release 适配器和网络关闭策略，并使用缓存避免频繁请求。

### 3.2 平台文件

- Windows 首次安装：x64 和 ARM64 当前用户 NSIS 安装包；应用内更新使用对应的 Tauri 更新器包。
- macOS 首次安装：Intel、Apple Silicon 和 Universal DMG；应用内更新使用对应的 `.app.tar.gz` 更新器包。

平台不匹配的文件不得展示为可安装选项。DMG 只用于 macOS 首次安装和手动下载，不作为应用内自动更新包。

## 4. 状态与错误

更新状态与下载状态分开保存，至少覆盖：

- 未检查、检查中、无更新、有更新；
- 下载中、下载取消、下载失败；
- 校验中、校验失败、已准备安装；
- 用户取消安装、启动安装失败、等待重启。

错误必须使用结构化错误码和可操作建议，不把网络错误、校验错误和平台不匹配混为“更新失败”。

安全失败处理：

- HTTPS、官方仓库、版本格式或平台字段校验失败：拒绝下载；
- SHA-256 或签名不匹配：删除临时包并要求重新检查；
- 下载中断：保留当前版本，临时文件可清理或稍后续传；
- 安装程序启动失败：保留已下载包供用户重试，不替换当前程序。

## 5. 安全与平台边界

- V1 默认只在用户点击后下载和安装，不静默执行。
- 安装包由 Windows/macOS 系统负责最终执行；SkillHub 不修改系统安全策略。
- 未签名 Windows 构建可能触发 SmartScreen，Smart App Control 可能阻止未签名文件。
- 未公证或仅 ad-hoc 签名的 macOS 构建可能触发 Gatekeeper。
- 获得平台签名和公证后，可复用本设计增加更可靠的自动安装，但不改变固定来源、哈希/签名校验和用户确认原则。

## 6. 组件与职责

### 应用层

- 更新检查服务：读取策略、缓存和当前版本，调用发布适配器。
- 下载服务：按已选平台资产下载到应用临时目录，提供进度和取消。
- 校验服务：验证清单字段、大小、SHA-256 和更新签名。
- 安装协调器：仅在用户确认后启动本地安装器，并返回启动结果。

### 桌面层

- 提供当前平台/架构、临时目录和启动本地安装包能力。
- 不向前端暴露任意进程执行入口。

### 前端

- 更新提示、详情、下载进度、校验失败和安装确认界面。
- 普通模式隐藏实现细节；开发者选项可查看来源、版本、哈希和错误码。

## 7. 数据流

```text
检查策略 → 发布清单 → 官方版本筛选 → 用户确认下载
        → 临时文件下载 → 哈希/签名校验 → 用户确认安装
        → 系统安装器 → 重启后重新检查当前版本
```

检查结果可缓存；安装包和临时凭据不得写入 SkillHub 数据库，也不得进入日志或备份包。

## 8. 测试要求

- 版本比较、预览版过滤和检查频率。
- 官方仓库/HTTPS/平台架构字段校验。
- 网络关闭、超时、429、缓存命中和缓存过期。
- 下载取消、断点或失败后的清理与重试。
- SHA-256 正确、错误和包大小不一致。
- 签名正确、缺失和不匹配。
- 用户取消安装、安装器启动失败和当前版本保持不变。
- Windows 安装完成后的自动重启，以及 macOS 更新完成后的自动重新拉起。
- 新版本首次启动超时/崩溃时恢复上一版本并自动重新打开；恢复失败时提供重新下载安装包。
- Windows/macOS 平台资产选择。
- 更新策略持久化和重启后状态恢复。
- 不执行任意 URL、任意命令或未确认安装。

## 9. 分阶段建议

### V1

应用内检查、应用内下载、完整性校验、用户确认后启动更新器；安装完成后自动重新打开软件。默认不强制、不静默，系统安全确认仍由 Windows/macOS 负责。

### 后续版本

在获得 Windows 代码签名和 macOS Developer ID/公证后，降低系统安全提示并增强自动安装稳定性；仍保持用户可见、可取消和可追溯。V1 的启动自检回滚只覆盖应用程序，不回滚用户 Skill 数据。

## 10. 明确不承诺的事项

- 不承诺消除 SmartScreen 或 Gatekeeper 提示。
- 不承诺未签名构建在所有企业策略下可安装。
- 不承诺第三方客户端或外部安全软件接受安装包。
- 不把“下载成功”当作“安装成功”或“平台已信任”。
