## A. 准备与记录规则

### A0. 自动化与人工验收分流

每条验收项新增一个执行标签：

- `[浏览器自动化]`：只依赖页面 DOM、路由、表单、键盘操作、布局、文案、前端状态和可注入的固定数据。使用 `pnpm test:e2e` 或对应 Playwright 用例。
- `[混合]`：页面流程可以先用浏览器自动化验证；真实数据、Rust/Tauri IPC、数据库、文件产物或网络结果必须再做桌面人工取证。自动化通过只能记录为“自动化通过”，不能直接把人工项标为通过。
- `[桌面人工]`：依赖 Tauri 原生命令、系统目录选择器/系统浏览器、真实文件系统副作用、真实网络切换、权限/占用故障、签名更新包或 Agent 实际目录。不得用预览页或 mock 结果代替。

当前指南的默认分流如下：

| 指南范围 | 浏览器自动化先验收 | 仍需桌面人工验收 |
| --- | --- | --- |
| `1v`~`1cc` 修复回归 | 布局、路由、文案、筛选、确认框、国际化、状态展示 | 目录选择器、真实来源更新、版本/文件写入、系统浏览器、真实部署和导出产物 |
| `1d`~`1r` 功能批次 | 页面流程、空态、加载/取消、错误展示、导航和可注入数据下的交互 | 真实仓库下载、lock 文件、数据库持久化、后台原生操作、文件权限和导出/备份结果 |
| `1s`~`1u` 来源更新 | 结果分组、批量汇总、错误文案和按钮状态 | Git 来源记录、远端仓库变化、断网、真实上游下载和版本创建 |
| `P0-02`~`P0-05` 核心流程 | 页面可达性、表单校验、预检/确认交互和结果呈现 | 本地目录扫描、导入物化、部署/解除部署、删除保护、安全检查和待处理持久化 |
| `P0-06`~`P0-09` 数据保护/更新 | 表单、决策门槛、错误展示和流程导航 | 备份/恢复/导出文件、真实路径、签名校验、安装、重启和失败回滚 |

本指南已有条目按上表范围分流；新增或改写验收条目时，必须在标题或条目开头标注上述标签。涉及两类行为时使用 `[混合]`，并把“浏览器自动化证据”和“桌面人工证据”拆成两个明确的通过条件。验收记录也分别填写“自动化结果”和“人工结果”。

- 始终在 `feat/v0.2.0-product-completion` 分支验收，不要先合并 `main`。
- 此轮记录的验收基线必须是 `18bcccc`；如提交变化，先更新本文件和验收矩阵。
- 尽量使用新建的临时集中库、临时 Skill 和临时目标目录。删除、恢复、解除部署不得针对个人真实资料。
- 对每项只填写“通过 / 失败 / 未验证”。失败需记录操作步骤、界面文案、错误详情和截图（如有）。
- “文件出现在目录中”只代表文件写入结果，不代表 Agent 已加载、调用或验证可用。

启动应用：

```powershell
pnpm --dir apps/desktop tauri dev
```

在应用打开后，先确认当前 Git 提交：

```powershell
git rev-parse --short HEAD
```

## 1w. AR-025 标准导出重设计（2026-09-07 批次，待人工复验）

前提：库内至少两个可导出 Skill（其中一个含 SKILL.md 之外的文件更佳）。

1. 数据保护 → 导出所选 Skill → "选择输出目录"：弹出系统目录选择器；选择后页面显示所选路径。
2. 不选择输出目录时导出：包落在集中库 `.skillhub/management/exports`（诚实回显路径）。
3. 文件夹模式导出：得到一个外层 `skillhub-export-*.zip`，解压后为以 Skill 显示名命名的完整文件夹（含 SKILL.md 与全部附属文件）；不应再出现内部 UUID 目录名。
4. ZIP 模式导出：外层 ZIP 解压后是若干独立 `<显示名>.zip`，每个内层 ZIP 根目录即 SKILL.md——可直接被 Trae/Cline 等 IDE Agent 导入。
5. 含敏感内容的 Skill：仍需逐个决策（先处理/排除/包含并标记），被排除的 Skill 不出现在外层包中。
6. 显示名相同的两个 Skill 同时导出：目录名自动区分、互不覆盖。

## 1q. N5b 批量操作统一汇总（`79fa7d9`，尚未人工验收）

1. 批量部署多个 Skill（至少制造一个失败场景，如把某目标目录设为只读）：提交后出现"批量操作汇总"，顶部为成功/跳过/失败分组计数，下方逐项列出每条结果与原因。
2. 批量删除多个 Skill，其中一项提交失败（如文件被占用）：不再整体报错终止——汇总中已删除项记为成功、失败项单独列出原因，且技能列表已刷新（不再显示已删除的行）。
3. 全部成功时汇总只出现"成功 N"，不出现空的冲突/失败分组。
4. 单 Skill 部署页的旧结果列表保持不变（汇总仅用于批量场景）。

## 1r. N6 概览按标签下钻（`c7eef74`，尚未人工验收）

1. 库中至少两个 Skill 打上同一标签、另一标签只打一个：概览页侧栏出现"按标签的 Skill 数量"清单，条目按数量降序，显示各标签 Skill 数。
2. 点击某标签条目：跳转到技能库页且标签筛选已生效（URL 含 tag=<名称>，列表只显示该标签的 Skill）。
3. 库中无任何标签时：概览不出现该清单（诚实空态）。

## 1s. N7a 仓库导入上游来源记录（`6e0b9c5`，自动化覆盖，人工可抽验）

1. 从仓库发现下载并导入一个 Skill：导入完成后该 Skill 的来源为长期 git 来源（数据库 sources 表 kind=git，metadata_json 含 branch/directory）——UI 来源栏仍显示原信息，此为数据层变化。
2. 同一 Skill 再次从同一仓库导入：不产生重复来源行。
3. 本地目录导入的 Skill：不产生 git 来源记录。

## 1t. N7b 远端来源更新检测（`6bdfc98`，需联网人工验收）

前提：Skill 来自仓库发现导入（1s 已确认其来源为 git+坐标）。

1. 未改动远端仓库：Skill 详情"检查更新"显示为最新（UpToDate）。
2. 在远端仓库修改该 Skill 目录内 SKILL.md 后再检查：显示有更新（UpdateAvailable），走既有"来源更新决策"流程（采纳上游/保留本地/取消）。
3. 断网后检查：诚实提示来源不可用（SourceUnavailable），不显示"最新"。
4. 手动 Relink 到 git URL（无 branch/directory 坐标）的 Skill：检查显示来源不可用——不伪造结果。

## 1u. N8 批量来源更新检查（`d46019f`，需联网人工验收，建议与 1t 同场景）

前提：库内至少有一个仓库发现导入的 Skill（git 坐标来源）和一个本地导入 Skill。

1. 技能库多选若干 Skill（含 git 来源与本地来源），批量栏出现"检查来源更新"按钮。
2. 点击后显示结果汇总：分组为"已是最新 / 可升级 / 来源不可用 / 需要认证"，每个 Skill 一条，不出现整体失败。
3. 断网后重复：git 来源 Skill 落入"来源不可用"，本地路径来源不受影响——批次不掩盖单条结果。
4. 结果区提示"升级需逐个进入 Skill 详情确认应用"，批量栏本身不提供一键批量升级按钮。
5. 更换筛选或清除选择后，上一轮汇总应消失，不残留旧结果。

## E. 核心流程（P0-02~P0-09）

## 2. P0-02 发现与导入（尚未人工验收）

1. 在临时目录创建一个测试 Skill 文件夹，并放入最小 `SKILL.md`。
2. 打开“发现 → 本机”，点击“选择本地目录”，选择该目录；界面不应显示 `\\?\` 前缀。
3. 读取候选、选择一个或多个候选，进入冲突审阅；没有冲突时不应要求无效决策。
4. 提交导入，确认界面显示逐项进度和成功/跳过/失败结果；失败项应显示错误详情。
5. 到集中库 `C:\Users\<用户名>\SkillHub\skills`（或当前实际库）确认成功导入的 Skill 有可见内容目录；原始临时目录仍保留。
6. 再导入同名或相同内容，确认“跳过 / 建立关联 / 独立导入”等可用决策可以提交，且不会出现 `input.invalid; field=decision`。

通过标准：目录选择、候选解析、冲突决策、提交结果和集中库物化均可解释且可重复；远程来源尚未接入时必须明确提示边界。

## 3. P0-03 技能库与详情（尚未人工验收）

1. 在技能库搜索刚导入的 Skill，打开快速抽屉和完整详情。
2. 查看 Markdown、版本、关系、元数据和安全区域；确认没有预览数据伪装为真实数据。
3. 修改允许编辑的元数据或生命周期，刷新页面确认结果保持。
4. 选择一个或多个 Skill，确认批量删除入口先展示影响，再要求 `FORCE DELETE` 二次确认；此步仅使用临时 Skill。

通过标准：真实数据可读取，错误或暂不支持能力明确显示，不因失败显示虚构状态。

## 4. P0-04 部署、解除部署与删除（尚未人工验收）

1. 只使用临时 Agent 或项目目录作为部署目标。
2. 发起部署预检，确认目标、版本、文件方式和变化摘要正确；Agent 默认链接、项目默认复制时应有清晰说明。
3. 提交后确认目标目录结果与界面一致；不要将其记录为 Agent 已调用。
4. 发起解除部署或删除预检，确认会显示影响；在目标中放入无关文件，确认不会被静默删除。

通过标准：每次写入前均有预检；集中库原件、共享目标和未知内容受到保护。

## 5. P0-05 安全、待处理与恢复（尚未人工验收）

1. 对临时 Skill 运行基础安全检查，查看状态和发现项。
2. 对高风险发现确认、忽略或取消，确认高风险动作需要显式确认。
3. 打开待处理与恢复页面，确认仅对当前事项提供对应动作；不执行不理解的删除或归档动作。
4. 在设置创建一条“精确待处理事项”规则后完全退出并重启应用：规则应仍存在。若规则有暂缓截止日期，在截止日前对应事项不显示；截止当天应自动重新出现。此步只使用临时 Skill/事项。

通过标准：状态、原因和结果可见；取消不产生意外写入。

## 6. P0-06～P0-08 备份、恢复与导出（尚未人工验收）

1. 在设置创建备份预检；如存在敏感内容，逐项选择处理方式后再创建。
2. 记录界面返回的备份路径并确认文件存在。
3. 在“管理数据保护”中校验备份；仅对临时库执行恢复预检和冲突决策。
4. 导出一个或多个临时 Skill，确认导出路径存在，且不包含本机绝对路径或明文凭据。

通过标准：预检或决策缺失时提交按钮不可用；失败不损坏原集中库。

## 7. P0-09 应用更新（尚未人工验收）

仅当存在与当前候选提交对应的真实签名 Release 资产时才执行。检查、下载、签名校验、安装、自动重启和失败回滚均需独立取证；“没有更新”或“打开官方发布页”均不能标记通过。
