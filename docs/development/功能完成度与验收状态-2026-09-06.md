用途：作为后续开发与人工验收的唯一进度口径；不把“有页面”“有接口”“自动化通过”表述为“产品已完成”。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现 | 有受测代码路径，但尚未完成真实桌面验收。 |
| 部分实现 | 只有部分子能力接通，或存在明确的原生/交互缺口。 |
| 待开发 | 需求已经确认，但尚无可用实现。 |
| 待人工验收 | 已实现能力需要在真实 Windows/macOS、真实目录或真实网络条件下取证；不等于已通过。 |
| 已人工通过 | 在指定候选提交、平台和步骤下取得了可复核证据。 |

## 验收执行分流

| 标签 | 先执行 | 仍需补充 |
| --- | --- | --- |
| `[浏览器自动化]` | DOM、路由、表单、键盘、布局、文案、前端状态和固定 fixture | 无真实桌面副作用的项目可直接以自动化结果为证据 |

## 0.2.0 收口已确认决策（2026-09-09）

以下决策已由产品确认，本轮开发全程遵守；执行中如与代码契约冲突，先报告再调整。

1. **批量升级**：维持 N8 记录决策"只检查不批量升级"，不开发批量应用；升级仍逐 Skill 在详情页显式确认。
2. **库根自动迁移**：移出 0.2.0，与下一大版本 NAS/SMB 网络存储同批；0.2.0 维持"备份→导入"指引。
3. **i18n**：0.2.0 只做 zh-CN/en-US 双语全覆盖；更多语言属后续版本，不进入 0.2.0 范围。
4. **UI 收口**：纳入 0.2.0 **开发阶段**执行。此项倒置了下节表格原文"先完成影响页面的真机验收，再以问题为依据做最小视觉收口"的实施顺序——先按借鉴报告完成 UI 收口开发并补组件测试，最终人工验收统一验证效果；开发期不阻塞在真机截图上。
5. **发布路径**：开发 → 全量自动化冻结 → 用户人工验收 → 修复 → 重跑受影响自动化 → 复验；循环到发布门槛全绿才创建 tag。人工验收由用户本人执行，不阻塞开发交付。

## 已知降级项复核结论（2026-09-09）

1. **Agent 重新定位**：自定义 Agent 可经"编辑 → 重新选择目录"完成重定位（grant 链路 `eb72ba5e` 已修复），详情页提示已改为指引导语；识别到的内置 Agent 目录来自发现快照，应用内重定位无契约，维持诚实降级并展示原因。
2. **Agent 级忽略**：`IgnoreSubject` 仅有路径/精确 Skill/精确待处理三变体，Agent 级忽略需新增契约并改忽略评估语义，不属于"低成本小契约"，维持诚实降级（`agents.limits.ignoreUnsupported` 在 UI 可见），记入后续版本候选。
3. **AI 输出语言**：译文按语言键控存储（`TranslationRecord.language`），AI 输出实际跟随界面语言；独立的"AI 输出语言"偏好需改 prompt 组装契约，维持诚实降级并记录，属后续版本评审。
4. **减少动效**：应用已通过 `MotionConfig reducedMotion="user"`、抽屉 `prefers-reduced-motion` 探测与 CSS 媒体查询承接系统"减少动态效果"设置；不重复提供应用内开关（避免与系统偏好双轨），视为已覆盖而非降级。

## 发布门槛

在下列条件全部满足前，不创建 `v0.2.0` tag：

1. 上表 P0 工作流达到“已实现”，且剩余限制在 UI 中诚实可见。
2. 当前候选提交重新执行完整质量检查，并记录实际命令、提交和计数。
3. Windows 与 macOS 均完成真实初始化、导入、部署/解除、备份、恢复、导出和安装启动取证。
4. 真实签名更新资产完成检查、安装、重启与失败回滚取证。
5. i18n 不再只覆盖局部页面，或将未覆盖语言明确从发布范围移除。
