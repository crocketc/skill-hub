# SkillHub 功能完成度与验收状态

更新时间：2026-09-08
代码验收基线：`feat/v0.2.0-product-completion` / `eaee655`（本轮浏览器 E2E 已扩展至 22/22；后续同步提交只更新验收/状态文档）
用途：作为后续开发与人工验收的唯一进度口径；不把“有页面”“有接口”“自动化通过”表述为“产品已完成”。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现 | 有受测代码路径，但尚未完成真实桌面验收。 |
| 部分实现 | 只有部分子能力接通，或存在明确的原生/交互缺口。 |
| 待开发 | 需求已经确认，但尚无可用实现。 |
| 待人工验收 | 已实现能力需要在真实 Windows/macOS、真实目录或真实网络条件下取证；不等于已通过。 |
| 已人工通过 | 在指定候选提交、平台和步骤下取得了可复核证据。 |

## 验收执行分流

| 标签 | 先执行 | 仍需补充 |
| --- | --- | --- |
| `[浏览器自动化]` | DOM、路由、表单、键盘、布局、文案、前端状态和固定 fixture | 无真实桌面副作用的项目可直接以自动化结果为证据 |
| `[混合]` | 页面流程、错误展示、确认交互和可注入数据 | Tauri IPC、数据库、真实网络、文件产物、权限和重启后的持久化需桌面取证 |
| `[桌面人工]` | 不作为浏览器自动化通过项 | 系统目录选择器/浏览器、真实文件系统、Agent 目录、签名更新包和双平台安装 |

- 当前工作区状态以 `git status --short` 为准；本轮同步不触碰用户未提交改动。

## 0.2.0 收口已确认决策（2026-09-09）

以下决策已由产品确认，本轮开发全程遵守；执行中如与代码契约冲突，先报告再调整。

1. **批量升级**：维持 N8 记录决策"只检查不批量升级"，不开发批量应用；升级仍逐 Skill 在详情页显式确认。
2. **库根自动迁移**：移出 0.2.0，与下一大版本 NAS/SMB 网络存储同批；0.2.0 维持"备份→导入"指引。
3. **i18n**：0.2.0 只做 zh-CN/en-US 双语全覆盖；更多语言属后续版本，不进入 0.2.0 范围。
4. **UI 收口**：纳入 0.2.0 **开发阶段**执行。此项倒置了下节表格原文"先完成影响页面的真机验收，再以问题为依据做最小视觉收口"的实施顺序——先按借鉴报告完成 UI 收口开发并补组件测试，最终人工验收统一验证效果；开发期不阻塞在真机截图上。
5. **发布路径**：开发 → 全量自动化冻结 → 用户人工验收 → 修复 → 重跑受影响自动化 → 复验；循环到发布门槛全绿才创建 tag。人工验收由用户本人执行，不阻塞开发交付。

## 0.2.0 可纳入的借鉴 UI 收口

借鉴报告中的功能按版本已拆解到《后续版本借鉴功能范围-2026-09-08.md》。在不改变现有领域模型、绑定契约和文件写入语义的前提下，0.2.0 可纳入以下 UI 收口；它们不取代本节“发布门槛”的真实桌面验收。

| 范围 | 允许的当前版本改动 | 明确不做 | 完成条件 |
| --- | --- | --- | --- |
| 技能库 | 调整统计摘要、筛选工具栏、卡片信息层级和批量操作栏视觉；仅消费现有查询字段 | 新增聚合查询、批量操作语义或新的持久化偏好 | 现有列表/卡片/矩阵测试保持通过；键盘操作、窄窗口和中英界面人工复验 |
| 在线发现 | 优化搜索结果卡片的来源、安装状态、加载/空态和进入既有导入向导的入口 | 精选远端清单、缓存、下载协议或绕过导入安全检查 | 现有在线搜索、下载和导入契约不变；网络失败文案准确 |
| 本机发现 | 用现有发现快照强化“发现待导入”提示、扫描中状态和审查入口 | 扫描来源持久化开关、自动重扫或后台常驻扫描 | 候选进入原有审查与冲突处理；不改变扫描范围 |
| 高风险操作 | 统一既有预检、执行中、完成、失败的视觉反馈和结果摘要 | 新建通用冲突中心、通用回收站或跨流程事务模型 | 继续复用 `prepare → commit` 契约；失败不暗示已成功或可自动恢复 |

实施顺序：先完成影响页面的真机验收并记录问题，再以问题为依据做最小视觉收口；每项 UI 改动都需补前端测试、运行 `pnpm --dir apps/desktop check`、构建和对应人工截图。若需要新增 Rust（Rust）模型、TypeScript（TypeScript）绑定或改变文件写入流程，则移入后续版本范围，不在 0.2.0 扩项。

## 发布门槛

在下列条件全部满足前，不创建 `v0.2.0` tag：

1. 上表 P0 工作流达到“已实现”，且剩余限制在 UI 中诚实可见。
2. 当前候选提交重新执行完整质量检查，并记录实际命令、提交和计数。
3. Windows 与 macOS 均完成真实初始化、导入、部署/解除、备份、恢复、导出和安装启动取证。
4. 真实签名更新资产完成检查、安装、重启与失败回滚取证。
5. i18n 不再只覆盖局部页面，或将未覆盖语言明确从发布范围移除。
