6. **新发现缺陷（非发布阻塞，建议发布前修）**：`tauri.conf.json` 的 CSP `"default-src 'self'; script-src 'self'"` 未显式给 `connect-src`，`connect-src` 回落到 `default-src`，导致 Tauri IPC 自定义协议被 CSP 阻断、每次启动回退 postMessage，并常驻 2 条控制台 CSP 错误。Tauri 官方 CSP 参考值含 `"connect-src": "ipc: http://ipc.localhost"`。**修法（一行）**：`"csp": "default-src 'self'; script-src 'self'; connect-src 'self' ipc: http://ipc.localhost"`。本轮只报告未改动。取证见《人工验收清单-2026-09-18》R-3 末条。

7. **新发现缺陷（Windows 专属，发布阻塞）**：`crates/skillhub-application/src/lib.rs` 的 `materialized_source()`（约 347-361 行）把物化目录拼成 `.skillhub/deployment-trees/<skill_id>/<version_id>`，其中 `version_id` 是 `sha256:<hex>` 原文。Windows 不允许路径分量含 `:`，`create_dir_all` 必然失败 → 整个部署以 `operation.conflict` / `io_kind: NotADirectory` 中止。**实测**：`C:\skillhub-test\.skillhub\deployment-trees\<skill>\sha256:b356b6…` 建目录报 `WinError 267 目录名称无效`（`NotADirectoryError`），与 App 报出的 `io_kind` 逐字一致；同形探针 `…\sha256:abc` 同样失败。macOS/Linux 上 `:` 合法，故 mac 侧测试全绿也照不到。**影响面**：所有需要物化的部署——即全部「受管复制」，以及「可见库目录缺失或当前版本不一致」时的符号链接/目录联接。**修法**：物化目录名去掉 `sha256:` 前缀（`version_id.as_str().trim_start_matches("sha256:")`，与 `VersionStore::manifest_path_for_test` 同一口径），补一条 Windows 用例如实反映路径可创建。
8. **新发现缺陷（发布阻塞）**：`deployments.target_id` 有硬外键 `REFERENCES targets(id)`，而 `targets` 在**生产代码里没有任何写入方**（`INSERT INTO targets` 只出现在测试中；新的逻辑目标模型把目标持久化在 `settings.agent_discovery_snapshot` 的 JSON 里）。部署后端写入的 `target_id = target.physical_target_id`（`lib.rs` 约 458 行，形如 `fs:volume-…`），`targets` 里不存在该行 → 外键失败 → `internal.error`。**实测（在库文件副本上做，不动 App 数据库）**：开启 `PRAGMA foreign_keys=1` 后插入该 `deployments` 行报 `IntegrityError: FOREIGN KEY constraint failed`；先补一行 `targets` 再插同一行则**成功**。**后果（比失败更严重）**：真机实测一次目录联接部署——文件系统上 `~/.claude/skills/find-skills` **已经建成**且为真 reparse point、可读透 `SKILL.md`，但 `deployments`/`deployment_relations` 仍为 0，操作落成 `needs_recovery`；即**产物已落到用户 Agent 目录、SkillHub 却无记录**，UI 既看不到也无法按正常路径移除。这也是四个关系页面（图谱/冲突工作台/治理清单）在本机永远为空的直接原因。
9. **新发现缺陷（发布阻塞）**：Agent profile 里每个 client 声明的 `deployment{ copy / symlink / junction / limitations }` 在**部署路径上完全未被消费**（全仓检索：非测试代码零引用，只有 `skillhub-adapters/tests/builtin_profiles.rs` 断言它）。`list_deployment_targets` 与规划器都只取宿主全局 `available_capabilities()`。因此本机对 Claude Code 的目标给出的可选模式是 `directory_junction + managed_copy`，规划器默认选中 **目录联接**；而 `anthropic.json` 明写该客户端 `"junction": false`（限制 `junction_support_unconfirmed`）、`symlink: true`，且 `link_capabilities_are_true_only_when_officially_documented` 断言**所有**客户端 `!deployment.junction`。即产品自己的不变量被部署路径绕过。**修法**：目标能力取「profile 声明 ∩ 宿主探测」，并让 UI 的模式列表遵循同一口径。
