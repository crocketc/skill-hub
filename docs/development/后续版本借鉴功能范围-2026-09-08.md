# 后续版本借鉴功能范围

更新时间：2026-09-08
用途：将《外部项目Skills-Hub借鉴报告-2026-09-07.md》的调研结论转为版本边界。本文不是需求实现授权；每个版本开始前仍需补充需求、验收标准和实施计划。

## 定位约束

- SkillHub 当前是面向普通用户的纯本地 Skill（技能）管理工具；用户不需要理解 Git（版本控制）、软链接或 Agent（智能体）目录结构。
- 当前版本只支持本地路径。网络存储是下一大版本的独立方向，优先研究 NAS（网络附加存储）/SMB（服务器消息块）挂载目录；不以跨设备 Git 同步作为前置方案。
- 任何发现、推荐或网络功能均不能绕过现有来源校验、导入检查、安全检查、冲突决策和用户确认。

## 版本划分

| 阶段 | 纳入范围 | 不纳入范围 | 进入条件 |
| --- | --- | --- | --- |
| v0.2.0 收口 | 已有功能的 UI 视觉与反馈优化 | 新读模型、新持久化、新文件写入语义 | 不影响发布门槛；先有相应真机验收问题或明确可用性证据 |
| 下一小版本 | 精选发现、扫描来源控制 | 网络存储、跨设备同步、通用事务/冲突中心 | v0.2.0 本地闭环和双平台验收完成 |
| 后续本地可靠性版本 | 由验收数据驱动的局部预览/冲突/恢复增强 | 一次性抽象全部本地操作 | 已确认多个流程存在相同的真实缺口 |
| 下一大版本 | NAS/SMB 等网络存储支持 | Git 跨设备同步默认方案 | 独立需求、兼容性矩阵、断连与恢复策略完成评审 |

## v0.2.0：只做 UI 收口

### 可做的页面级借鉴

1. 技能库：提高统计摘要、筛选、卡片与批量操作栏的信息层级；继续使用当前列表、卡片和矩阵视图的数据。
2. 在线发现：在已有 `skills.sh` 搜索结果上优化来源、已导入状态、加载、空态和进入导入向导的动作层级。
3. 本机发现：用已有发现快照呈现“发现待导入”横幅、扫描进度和审查入口；候选仍进入原有选择和冲突流程。
4. 高风险流程：在导入、来源更新、备份恢复、导出和部署中统一显示“预检、进行中、完成、失败”四类既有状态；不伪造事务性或可撤销能力。

### 不可做的扩项

- 不增加精选目录的远端拉取、缓存、签名或新下载接口。
- 不增加扫描来源开关、自动重扫、后台常驻扫描或新的扫描设置数据。
- 不创建通用 `LocalChangePreview`、`LocalConflict`、回收站或跨流程原子事务。
- 不引入 NAS、SMB、Git、OAuth（授权）、设备、远端仓库或同步调度。

### 验收要求

- 沿用现有绑定与 `prepare → commit` 语义；若需要改绑定，任务自动转入后续版本评审。
- 覆盖键盘焦点、窄窗口、加载、空态、失败和中文/英文文案；不得以纯视觉改动删除或弱化安全提示。
- 每个页面改动补相应组件测试，并完成前端检查、构建和真机截图取证。

## 下一小版本：发现体验闭环

### F1：精选优先的在线发现

目标是降低普通用户的第一步选择成本，而不是建立新的安装通道。

- 提供仓库内、可审查的精选清单：名称、简介、来源 URL、分类、维护日期和排序。
- 搜索页分为“推荐匹配”和“在线结果”，按规范化来源与 Skill 标识去重；已导入项显示状态并跳转详情。
- 清单读取采用“验证过的远端更新 → 本地缓存 → 内置清单”回退；网络故障不能阻塞现有在线搜索或本地管理。
- 所有安装继续经过既有下载、导入、安全检查与冲突决策。

验收重点：离线、远端失败、缓存过期、清单字段错误、重复项、已导入项和恶意/非受支持 URL。

### F2：扫描来源控制与待导入提醒

目标是让用户明确决定哪些本机目录参与发现，并保持发现范围与部署目标完全分离。

- 定义持久化 `DiscoverySource`：稳定键、显示名、脱敏路径提示、来源类型、启用状态、上次扫描摘要。
- 设置页提供“来源名称 + 路径 + 开关”列表及“保存并重新扫描”；关闭来源不删除已导入 Skill，也不改变部署目标。
- 库页仅在有新候选时显示待导入横幅，入口仍进入既有审查和冲突处理。
- 继续使用真实目录、路径边界、符号链接和权限检查；重复路径按规范化真实路径去重。

验收重点：跨重启保存、权限失败、失效路径、符号链接越界、重复目录、关闭来源后不扫描，以及读屏器与键盘操作。

## 后续本地可靠性版本：按证据收敛，不预建框架

只有当 v0.2.0 验收显示多个流程重复出现同类问题时，才考虑抽取局部公共能力：

- 预览必须列出受影响 Skill、文件增删改与风险项。
- 有共同基线的文本才允许三方合并；二进制、过大文件、混合换行、哈希不一致和路径异常一律要求人工处理。
- 写入使用暂存目录、校验和原子替换；失败保留原内容和可读诊断。
- 删除或覆盖的恢复能力优先复用已有备份、版本和操作记录，避免并行维护第二套回收站。

进入条件：至少两个独立本地流程出现相同缺口，并已由真机验收或操作记录证明；先为具体流程写失败测试，再决定是否提取公共模型。

## 下一大版本：网络存储

### 初始边界

- 优先支持已由操作系统挂载的 NAS/SMB 目录；应用只把它识别为受约束的路径，不负责发现设备、保存网络密码或配置路由器。
- 集中库仍是单一来源；网络路径不可用时，本地缓存、备份和受管部署不得被静默覆盖。
- 首版必须明确显示挂载、可读、可写、断连、权限不足和路径变化状态；不把“能看到路径”描述为“可安全写入”。

### 必须在立项前确定的问题

1. 离线时的只读、禁止写入、队列重试或显式恢复策略。
2. 网络文件系统上的锁、原子替换、大小写、权限和符号链接语义。
3. 备份位置、恢复点、空间统计、迁移和断连后的可回滚路径。
4. Windows 与 macOS 的挂载路径规范化、凭据归属和真实兼容性矩阵。

Git 跨设备同步不在本范围内。如未来用户研究证明存在独立需求，必须作为另一份产品提案重新评估，不能搭载在 NAS 支持中进入实现。
