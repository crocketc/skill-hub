### 四层契约（本轮核心变更）

一次请求的行为由四层共同决定，任一层不再单独决定“用什么参数发请求”：

1. **传输协议**：`open_ai` / `open_ai_compatible` / `open_ai_responses` / `anthropic` / `gemini` / `azure_open_ai`，只描述 HTTP 线形状（URL 后缀、认证头、响应信封）。
2. **供应商/产品线兼容档**：20 个内置档 + `generic`，描述同协议下不同产品的差异（结构化机制、推理开关、模型目录、凭据策略）。
3. **结构化输出策略**：`json_schema_strict` / `json_schema` / `json_object` / `prompted_json` / `gemini_schema`。
4. **推理策略**：`provider_default` / `disable_for_structured` / `effort_none_for_structured`。

核心事实：**OpenAI 兼容 ≠ 可下发 strict Schema**（DeepSeek Chat 只接受 `json_object`）；DeepSeek Chat 与 Responses 对推理控制不同；GLM 普通 API 与 Coding Plan 是两条独立产品线，Coding Plan 内部又分 Chat/Responses/Anthropic 三端点。因此矩阵按**产品线**而非按协议列能力。完整表见《LLM 供应商兼容矩阵-2026-09-13》。

### 三层连接测试语义

- **服务可达**：地址是否有任何 HTTP 响应（任意状态码均算可达），附耗时。
- **模型可调用**：一次低 token 的**纯文本**探测，证明认证、模型存在与信封可解析。
- **结构化输出兼容**：按当前兼容档策略发一次真实结构化请求。
- 未执行的层级显示“未验证”（info），不是失败也不是成功；模型级未通过时结构化级不下探；**模型可调用 ≠ 结构化兼容**；每级均有图标+文字，不单靠颜色；保存配置不要求测试成功。

### 状态语义（清除凭据 / 启用 / 部署标签）

- **清除凭据**：仅删除 OS 凭据存储中的密钥，保留供应商配置；**启用状态不变**（仍“已启用”），凭据显示“未配置凭据”；清除后模型级返回 `llm.auth_failed`/`credential.unavailable`，不伪装成健康状态。
- **启用/停用**与凭据相互独立；停用供应商不参与解析（`object_not_found`）。
- **部署标签**“云端/本地”表达部署类型（是否走网络、是否通常需凭据），不因连接测试结果改变；本地部署（Ollama/LM Studio）豁免凭据，允许 `http` 但仅限 loopback/私网/链路本地地址。

## 本轮设计决策（裁决记录，详见 SDD 台账）

1. **通知 Provider 归属**：`AppNotificationsProvider` 位于 AppShell 内、Router 之内（生产结构）；测试宿主必须同样把 Provider 放在 Router 内层，否则带跳转动作的 toast 因无 Router 上下文崩溃。
2. **返回入口唯一化**：壳层仅在存在子路由 fallback 时显示返回（`showBack = backFallback !== null`）；移除页内返回前先补 fallback。技能详情页页内返回**保留**——沉浸式详情无壳层返回，且其 Link 承载库内回跳状态语义，不是重复入口。
3. **概览两行指标取代 P1-07 单行指标带**：M-20 用户明确"窗口化两行布局为准，只缩放不换结构"；宽容器 hero 跨 4 列独占第一行，紧凑统计 `display:contents` 落到第二行。
4. **后端偏好同步延后**：reduced-motion 维持 localStorage 模式（与外观偏好一致），native `get/set_ui_preference` KV 留作未来同步通道。
5. **锁中毒语义**：凭据存储 mutex 中毒 `expect` 维持现状（桌面应用惯例，审查认可）。
6. **文档本地化策略修正**：四份当前文档与归档记录保持版本化（AGENTS.md 协作入口），其中个人本机路径脱敏为 `C:\Users\<本地用户>`；`github.com/crocketc/*` 为公开仓库 URL 非个人信息。
