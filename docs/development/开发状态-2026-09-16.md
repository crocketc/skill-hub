## 已完成（2026-09-16）

### Task 5：单/批量导入的关系分组确认

- 核心层按设计 §4.1 实现六类确定性分组：完全重复、内容一致的复制副本、同名不同内容、通用目录直接读取、通用目录链接引用、识别未知或共享影响未确认；判定顺序固定（同名冲突 → 已验证观察副本 → 完全重复 → 共享目录引用/读取 → 已知来源不建组 → 识别未知）。关系完全明确的普通导入不再生成治理组，避免待办噪音。
- 分组携带结构化影响事实（来源路径、受影响 Agent）；界面文案（数量/受影响 Agent/回退方式）全部由客户端按 i18n 渲染，core 不产出散文。治理待办类型按分类一一映射，持久化稳定 detail 键。
- 导入向导在冲突分析之后插入治理阶段（无分组时跳过）；分组确认 + 单项覆盖，未显式确认不能提交；修复了流程步骤计算在无治理分组时的错位。经两轮独立复审（第二轮 APPROVE）。

### Task 6：复制副本/共享引用转管理链接

- 核心纯函数转换计划 + 体积精确链接能力探针（在关系父目录内做创建→校验→清理探针，零残留）+ 同卷/跨卷事实（无法取卷身份时 fail-closed）。
- prepare 增加可行性闸门：链接不可用/跨卷 junction/需动共享本体时明确失败并生成治理待办，原入口不动、不产生备份；绝不静默降级为复制覆盖。
- commit 严格按「重扫 → 指纹比较 → 备份 → 暂建链接 → 验证 → 移除原入口 → 原子换入 → 再验证 → 关系落库 → 审计」执行；失败路径要么保留原入口，要么从恢复点回退；不存在双入口残留路径；外来同名条目拒删。顺带修复两个既有缺陷：关系影响范围漏 `link_target_directory_id`、备份路径校验穿透符号链接误判。
- 独立复审两轴均 MINOR 无阻断；Windows junction 执行器为既有桩（探针诚实报不可用），真机 junction 行为留给人工验收。

### Task 7：Agent 页目录矩阵与 Skill 详情关系视图

- Agent 详情新增目录矩阵：目录路径/角色/识别状态（supported/unknown/unsupported；绝不表述"已加载/一定会调用"，常显否定式免责句）/优先级证据/Skill 数/共享消费者/每 Skill 关系行（用户语义标签 + 移除影响入口 + 技术详情折叠）。
