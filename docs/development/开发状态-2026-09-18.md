- **DEV-66 未通过 Windows 人工复验，不新增重复编号。** 当前 release 在物理 `2560×1600`、Windows 缩放 `175%` 的最大化窗口中，应用实际 client area 为 `1462×866`（`168 DPI`）；概览页出现页面级纵向滚动条。用户反馈 macOS 最大化时正常，但尚未留下可复核的 macOS 有效内容区尺寸，因此不能把平台差异写成通过证据。

## 2026-09-23 Windows DEV-66 第二次人工复验

- **未通过，不再尝试第三次阈值微调。** 新版已消除滚动条，但最大化和窗口化都出现大面积底部空白；窗口化原本应保留自然排列和页面滚动，现也被不当地压缩。

## 2026-09-23 Windows DEV-66 第三次复验反馈

- 页面和模块滚动条已消失，但截图显示两项**已修复后的边界遗漏**，登记为 **DEV-77**，不回退 DEV-66 的“最大化状态识别/根滚动”修复：① 最大化指标区固定为 5 列，实际只有 4 张次级指标卡，右侧留下整列空白；② 左侧部署图的 SVG 在 fill 网格切换后未随最终容器尺寸重测，越过面板边界并视觉压到右侧标签卡。
- 当前代码事实：`overview.css` 最大化规则使用 `grid-template-columns: repeat(5, ...)`，而数据模型固定为“1 张 hero + 4 张 compact stat”，hero 已跨整行；`DeploymentBarChartRuntime`/标签图运行时仅订阅 `window.resize`，没有 `ResizeObserver` 追随图表容器的最终几何尺寸。现有 E2E 只测模块外框与滚动高度，未测指标带的列占用、SVG 边界或左右卡片内容交叠。
- DEV-77 建议方案（待用户批准后开发）：最大化指标带改为四列次级指标轨道，hero 仍跨整行；图表运行时改用 `ResizeObserver` 在容器完成布局后重测，并补 E2E 断言“4 张指标共同填满指标带”“两个 SVG 均不越出各自图表容器”“左右模块内容矩形不相交”。
- 复现补充：离开概览页再返回后图表溢出消失，但仅切换到其他桌面应用再回来仍溢出。这排除了数据内容和页面根滚动作为主因，确认是**首次挂载/异步最大化布局/图表初始化的时序竞态**：重新进入会卸载并在最终容器几何下重建图表；失焦/回前台不重建也不触发容器观察。DEV-77 的 `ResizeObserver` 必须覆盖部署图和标签图，并在观察回调中安排布局稳定后的 resize，不能继续只依赖一次性 `window.resize`。
