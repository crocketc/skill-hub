### 7. DEV-94 操作记录条目要素统一（含两处真缺陷）

背景（2026-09-25 验收反馈截图）：「最近操作记录」条目显示 `deploy_skill` / `import_skill` 裸技术名 + 一串数字，与本会话后台操作（有本地化 label + 结果摘要）观感割裂。`OperationsList.tsx` 现状与诊断：

**两处真缺陷（TDD 红灯先行）**：

1. **时间显示损坏**：`created_at` 为 epoch 秒字符串（如 `1789890340`），`formatTimes` 用 `new Date(value)` 解析 ISO 失败得 NaN 后原样回显——截图里那串数字就是时间解析失败的 fallback。修复：识别 epoch 秒（10 位数字）按秒转 Date；解析失败不得回显原始值。
2. **技术名裸奔进界面**：`row.kind`（`deploy_skill`/`import_skill`）直接渲染为标题与详情链接文本，违反「技术标识不进界面」约定。修复：kind → 本地化操作名映射（部署技能 / 导入技能 / …），未知 kind 回退中性文案；详情链接文本同步本地化。

**要素统一设计**（与本轮 DEV-92 通知五要素同风格，操作记录为持久事实所以字段更稳定）：

- **标题** = 本地化操作名 + 对象名（如「部署技能：tdd」）。对象名需要契约支持：`RecentOperationRow`（BootstrapSnapshot.recent_operations）目前只有 operation_id/kind/state/phase/error_code/created_at，需扩展行结构携带对象摘要（对象名或短摘要）；涉及原生契约变更，绑定必须由生成工具更新，不手写。
- **状态徽标**：沿用 `phase`（已提交/进行中/成功/失败…）。
- **时间**：修复解析后规范展示（Intl 本地化）。
- **内容行**：成功/进行中显结果摘要（对齐本会话后台操作的「成功 N、失败 M」形态）；失败显人读错误（error_code 人类化，不裸错误码）。
- **深链**：保留进入 `/operations/:id` 详情页，入口文案用「查看详情」或标题本体，不用技术名。

实现顺序：先修两处缺陷（纯前端，`OperationsList` 测试红灯先行）；要素扩展涉及快照契约（Rust 侧 recent_operations 组装 + schema + 生成绑定 + 前端消费），作为第二步独立提交。验证：OperationsList 组件测试（kind 映射、epoch 解析、对象名/摘要渲染、未知 kind 回退）；Rust 侧快照组装测试；E2E 操作记录页回归。
