### Plan 04：来源与导入（Task 1–8 已完成）

- 来源描述、输入解析和来源模型。
- 隔离获取工作区、归档路径安全和受限提取。
- 受边界控制的 HTTP/Git 获取。
- 多 Skill 检测、本地所有权分类和导入候选识别。
- 确定性重复和同名冲突分析：规范化运行时名称、来源定位、版本树哈希和 FTS/BM25 候选按固定顺序判定。
- 精确内容默认提供复用/建立关联/独立复制/跳过；内置或插件 Skill 只允许独立复制。
- 同名不同内容必须明确选择；决策枚举不包含覆盖已有目标的动作。
- SQLite 只读投影读取现有 Skill、当前版本树哈希、来源和所有权，并通过 `AnalyzeImport` 查询契约提供给上层。
- 统一导入准备/提交/取消流程：准备阶段保存不可变分析快照，提交阶段只接受快照中提供的决策。
- 本地复制保留原文件；接管流程先复制并验证集中库副本，验证成功后才移除原文件；失败会保留准备会话以便重试或显式取消。
- 导入命令、结果和 TypeScript bindings 已冻结为 `PrepareImport`、`CommitImport`、`CancelImport` 及对应结果类型。
- 来源重连会替换 Skill 的活动来源关系但保留版本历史；来源更新检查和更新提交通过明确决策区分保留本地、采用上游、创建独立分支和取消。
- 检测到本地修改时，采用上游决策会被确定性阻止，避免未经选择覆盖本地内容；保留本地和取消不会触发写入。
- 来源重连/更新命令、结果及 TypeScript bindings 已冻结为 `RelinkSource`、`CheckSourceUpdate`、`ApplySourceUpdate` 及对应结果类型。
- skills.sh 在线搜索使用官方 `/api/v1/skills/search` JSON 接口，映射稳定 ID、来源、安装链接、页面链接、安装量和重复标记；不抓取网页，不把第三方审计结果当作 SkillHub 检查结果。
- 在线搜索遵守查询最小长度、limit/owner 参数、Cache-Control、429 Retry-After、401 认证不可用和全局网络关闭边界；搜索响应可持久化并按明确 TTL 读取缓存。

### Plan 05：部署与操作（Task 1–9 已完成）

- 部署计划、运行时名称冲突规则和目标校验。
- 跨平台软链接/受管复制执行器，以及基础安全检查门禁。
- 单目标和批量部署编排：提交前重新校验计划，按物理目标去重执行，逐目标返回成功/失败结果，并保留批量部分失败信息。

- 外部变化处理必须由用户明确选择收集为新版本、恢复所选版本、保留独立副本或忽略；收集动作带基本预检并返回新版本 ID，保留独立副本不删除目标文件。

- 支持移除受管目标、保留共享部署并解除关系、仅解除关系、解除管理但保留文件；解除一条共享关系不会误删共享文件，解除部署不会删除集中库 Skill。

- 增加确定性的健康检查发现、逐项修复计划和提交流程；修复只处理可验证的元数据/目标事实，不猜测或生成内容。
- 增加崩溃恢复候选查询和显式完成/回滚决策，只接受候选项声明过的恢复动作。
- `RunHealthCheck`、`PrepareRepair`、`CommitRepair`、`ResolveRecovery` 和 `ListRecoveryCandidates` API 合约已冻结并生成 bindings。
- 增加 Agent 调用策略能力识别、预览、应用和恢复原值；仅对明确可编辑的 profile 目标允许修改，只读/不支持目标不写入。
- `PrepareCallPolicyChange`、`CommitCallPolicyChange`、`RestoreOriginalCallPolicy` 和 `GetCallPolicy` API 合约已冻结并生成 bindings。
- 增加精确、可逆的忽略规则：仅支持精确路径、精确 Skill ID 和精确待处理项 ID；拒绝通配符、正则和脚本式规则。

- `CreateIgnoreRule`、`RemoveIgnoreRule` 和 `ListIgnoreRules` API 合约已冻结并生成 bindings。

## 重要技术边界

- `crates/skillhub-core` 不依赖桌面 UI。
- `apps/desktop/src-tauri` 负责本地后端桥接；真实 ApplicationFacade 执行和原生文件选择器接入仍需后续 Task 完成。
- `apps/desktop/src/api/bindings.ts` 和 Rust bindings 必须由 Specta 生成，不能手工维护接口副本。
- `PathGrant` 只传 opaque grant ID；实际目录必须由 `PathGrantResolver` 解析。
- Windows 路径比较按不区分大小写处理；macOS 保留观察到的大小写。
- 发现和兼容性模块只记录文件与目录事实，不声称 Skill 一定能被 Agent 执行。
- 基础安全检查必须是确定性的；LLM 检查只能作为独立增强。
