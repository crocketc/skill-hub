## 能力守卫：从「静默 pass」到可观测、可反证的跳过

**原问题（已修复）**：`crates/skillhub-application/tests/facade_relationship_governance.rs` 中 17 处 `available_capabilities().symlink` 守卫在命中时**提前 `return`**。libtest 没有运行时 skip，会把这种早退记为 `passed`；更糟的是它还会捕获通过用例的 stderr，所以连 `eprintln!("skipping: …")` 也看不见。结果是：在无链接能力的宿主上，17 项链路**没有执行任何断言**，却出现在「1098 通过 / 0 忽略」里。

**现在的机制**（`7853ae0f`）：

- 统一的 `skip_or_continue_for_missing_capability(available, requirement, location)`，由 `missing_symlink_capability()`（17 处：夹具自己建符号链接的场景）与 `missing_directory_link_capability()`（1 处：RC-16，只要符号链接或 junction 之一可用就应执行）调用；跳过时打印 `SKILLHUB-TEST-SKIP; 文件:行; 缺少什么能力`。
- 该标记**直接写入进程 stderr 的文件描述符**，绕开 libtest 的逐用例捕获，因此普通 `cargo test` 日志即可计数：`grep -c '^SKILLHUB-TEST-SKIP;' <日志>`。
- `SKILLHUB_REQUIRE_SYMLINK_CAPABILITY=1`：任何跳过都变成硬失败。**在这个开关下全绿，才证明守卫场景真的执行了**。
- `SKILLHUB_TEST_FORCE_NO_LINK_CAPABILITY=1`：负向对照，强制走跳过路径，使这套接线在具备链接能力的主机上也能被验证，不需要改代码。

**本机（macOS）实测**：默认 59 通过 / 0 跳过；负向对照 18 条标记；`REQUIRE` 下 0 跳过；两者叠加 18 失败。因此 Task 12 不再存在「未执行但记为通过」的情形。

