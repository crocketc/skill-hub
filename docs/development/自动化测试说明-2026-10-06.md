### 本轮记录的执行注意

- **npm audit 公告漂移**：audit 实时查询 npm 注册表，上次绿跑后也可能出现新公告导致 ci:local 第 9 项失败。处置：核对公告对应的依赖位置，优先用 `pnpm-workspace.yaml` `overrides` 按最小修复版本收窄强制升级（如 `"katex@<0.18.2": ">=0.18.2 <0.19"`），不用 ignore 压制。
- **收紧 override 后必须整树重装**：增量 `pnpm install` 不会清除 node_modules/.pnpm 里被换掉的旧版本目录，生命周期检查扫描物理目录会撞上残留包（本轮 katex 0.19.0 残留触发失败）。处置：`rm -rf node_modules apps/desktop/node_modules && pnpm install` 后重跑检查；新版本若带 prepare 等 lifecycle 脚本，同步补 [依赖与供应链策略](../dependency-policy.md) 表。
- **workspace clippy 是整合门禁**：每批整合后立即 `cargo clippy --workspace --all-targets --all-features -- -D warnings`（历史教训见归档）。
- **E2E 与用户 5174 预览服务共存**：端口被用户 vite dev 占用时，使用仓库外会话临时配置复用现有服务，不杀用户进程、不改正式配置。
- **并行负载偶发**：并行 cargo/vitest 首轮偶发失败；隔离重跑全绿即定性环境负载，不降低断言、不增加任意延时。负载竞态若根因是用例自身的同步查询撞上重渲染窗口，应修用例而非靠重跑放过——本轮 SkillLibraryPage「清除遗留归档过滤」一例把行选择框查询改为 findByRole 等待提交完成（`31bf5d7b`），断言意图不变。
- **断点语义修改先对齐既有契约用例**：markdown 堆叠断点从视口 40rem 改容器度量属过度修改，全量 E2E 中 markdown-workspace-preview 的 640px 契约用例将其拦下；回退视口断点、只保留真实缺陷的选择器覆盖修复（`27dfe15d`）。
- **i18n 校验与 vitest 必须从 `apps/desktop` 运行**；E2E 必须用根目录 `pnpm test:e2e`（直接 `npx playwright test` 不加载 baseURL）。

## 自动化命令

| 用途 | 命令与注意事项 |
| --- | --- |
| Rust 单元／集成 | 定向 `cargo test -p <crate> --test <测试文件>`；全仓 `cargo test --locked --workspace` |
| Rust lint 门禁 | `cargo clippy --workspace --all-targets --all-features -- -D warnings`（每批整合后必跑）；`cargo fmt --all -- --check` |
| 前端单测 | 全量 `pnpm test:frontend`；定向 `pnpm --dir apps/desktop exec vitest run <受影响测试>`。必须在 `apps/desktop` 下运行 vitest |
| 前端检查与构建 | `pnpm check:frontend`（ESLint 与 TypeScript）、`pnpm build:frontend`、`pnpm --dir apps/desktop check` |
| 浏览器 E2E | 根目录 `pnpm test:e2e <spec>`（带 `--config=tests/e2e/playwright.config.ts`）；retries=0，须一次通过 |
| 发布检查 | `pnpm verify:release`、`pnpm test:release`、`node scripts/verify_atomic_test_catalog.mjs`、`node scripts/verify_frontend_lifecycle_scripts.mjs` |
| 依赖审计 | `pnpm audit --json --registry=https://registry.npmjs.org`；公告按"执行注意"处置，overrides 记录在 `pnpm-workspace.yaml` |
| 生成绑定 | 临时设置 `SKILLHUB_WRITE_BINDINGS=1` 运行 `cargo test -p skillhub-desktop generate_bindings`，完成后移除该临时变量并核对生成差异；绑定只能由生成工具更新，不手写 bindings.ts |
| Windows release 构建 | `pnpm --dir apps/desktop tauri build --no-bundle`（产物 `target/release/skillhub-desktop.exe`，不提交 Git，供真机验收使用） |
| 本地 CI | `pnpm ci:local` 十项：fmt、deny、clippy、Rust 全仓、冻结安装、生命周期、audit、check、前端单测、构建（保留既有 chunk 提示；通过步骤静默，失败才输出） |
| 空白检查 | 最终整合提交前 `git diff --check` |

## 覆盖范围与验证边界

自动化覆盖：

- Rust core／application／storage 的领域、facade、存储与迁移测试；K1—K6 与六项裁决新增的行为测试（历史清单见[归档快照](archive/2026-10-06-验收反馈改造前快照/自动化测试说明-2026-10-05.md)，结论不回退）。
- 本轮改造的行为测试：安全扫描器遍历对齐、product_level 门禁与聚合呈现、警告去重与批量跳过（含预览场景）；导入向导四步拆分、候选分级徽标、安全决策变化弃置冲突处置；冲突卡独立组件（六场景动词）；评审详情六区与转正抽屉的生产路由呈现。
- 前端组件与 nativeApi 契约单测；DEV 预览路由与 mock 门面下的浏览器 E2E 已整体重锚定到转正布局。
- 发布检查、原子测试目录一致性与生命周期脚本策略校验。

自动化不能证明：

- 真实桌面通过。浏览器预览、预览 HTTP 200、自动化通过均不代表 Windows/macOS 桌面通过；人工验收只按[人工验收清单](人工验收清单-2026-10-06.md)执行并记录。
- 原生文件与权限事实、真实窗口／主题视觉、长路径与批量耗时不在自动化覆盖内；Windows 目录联接与 macOS 符号链接的真实落盘需真机取证。
- mock 与真实持久化分开记录：E2E 使用 DEV 预览路由与 mock 门面，只证明前端契约与几何；生产链路由真实应用域＋临时库持久化测试分别验证；两者都不替代桌面人工验收。
- katex 0.16→0.18 升级后 mermaid 数学图渲染无专项自动化（现有 markdown 套件覆盖图表渲染管线，未覆盖数学语法）；真实渲染效果在流程 T／O2 桌面验收中顺带核对。
- 评审详情中"重新翻译""AI 相似性"等 AI 入口在当前基线仅为说明框或禁用态（见[开发状态](开发状态-2026-10-06.md)缺陷处置表待裁决项 #4、#6），自动化如实呈现该现状，不代表 AI 流程已接通。

## 验证纪律

- 行为变更采用 TDD：先写失败测试，再实现最小行为，最后重构；不降低断言、不删除测试、不假成功、不增加任意延时；真实缺陷用 `test.fixme` 登记，不得为绿掩盖。
- 开发阶段按影响范围定向验证；每批整合后立即跑 workspace clippy 与 fmt。
- 相关测试通过且代码未再变化时，不重复运行同一套测试；回报写明本轮测试范围、结果与尚未验证的边界，定向通过不得写成全量通过。
- 发布前必须在最终整合提交上执行全量验证：`pnpm ci:local`、`pnpm test:e2e`、发布检查与 `git diff --check`，并处理失败。缺陷修复轮在 `27dfe15d` 执行（结果见上表）；后续任何代码变更都必须重新执行，不得继承本轮结果。
