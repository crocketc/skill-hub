# SkillHub LLM 供应商兼容矩阵（2026-09-10 核验）

状态：现行有效。支持级别定义（与目标一致）：

- **已支持**：契约自动化测试 + 真实服务验证均通过。
- **兼容**：契约自动化测试通过，真实服务验证未完成。
- **实验性**：部分能力通过或存在已知差异。
- **未验证**：证据不足，不宣传支持。

当前无任何真实凭据环境，故 v0.2.0 发布时所有供应商最高级别为**兼容**；"已支持"必须由真实服务人工验收记录（`人工验收清单`）回填后升级。真实供应商验证不能替代契约自动化测试。

## 已知限制与边界

1. **"未找到"清单**（官方文档核验无此端点，均如实标注，不猜测）：Azure 推理面 /models、DeepSeek /models、智谱 /models、MiniMax /models、火山方舟 /models。这些供应商模型列表自动获取不可用，UI 直接提供手动输入（需求 5.42"获取失败时允许手动填写"）。
2. **结构化输出分级**（实现侧统一策略：无论供应商能力如何，输出一律经本地 JSON Schema 严格校验，`deny_unknown_fields` + 枚举/长度/引用校验）：
   - 原生 json_schema：OpenAI、OpenRouter、Kimi、xAI、LM Studio、Azure（strict）、Ollama（format）。
   - beta：Anthropic（未启用，走提示词约定）、火山方舟。
   - 仅 json_object：DeepSeek、智谱。
   - 未记载：MiniMax。
   - 原生但形态不同：Gemini（responseSchema，当前实现经系统指令传递 Schema + responseMimeType，可后续升级为原生 responseSchema）。
3. **不宣称兼容即兼容**：OpenAI-compatible 供应商的"兼容"级别只代表契约测试通过；字段级差异（如 MiniMax 无 response_format）以矩阵行为准。
4. **Azure 部署名**：Azure 的 model 字段填部署名（deployment name），UI 有说明。
5. **流式**：所有供应商均支持流式，但 SkillHub 的任务（检查/翻译/重复分析/查询）为短请求，统一使用非流式，简化取消与错误处理；流式不在 v0.2.0 范围。
6. **核验方法**：官方文档直读或服务端抓取（platform.openai.com/developers.openai.com/platform.claude.com/ai.google.dev/docs.x.ai 直连受地区或 DNS 限制，经服务端抓取官方页原文取证；docs.volcengine.com 为 JS 渲染站，以官方页面目录与官方域名限定检索佐证）。核验日期统一为 2026-09-10，供应商 API 变更时应复核本表。
7. **测试夹具密钥**均为明显虚构值（`sk-test`、`sk-ant`、`az-key`、`g-key`），不含真实凭据。

## 契约测试覆盖

每个协议族契约测试（`crates/skillhub-adapters/tests/llm_protocol_contract.rs`、`llm_runner_contract.rs`，mock HTTP 服务）至少覆盖：正常响应、结构化响应、认证失败（401/403）、模型不存在（404）、限流（429 + Retry-After 有界重试）、超时、取消、服务端错误（5xx）、非法 JSON、Schema 不匹配、响应中断、凭据缺失、凭据读取失败、日志脱敏、自定义地址、自定义请求头、本地服务（http loopback）、网络总开关关闭。批量部分失败在业务层（翻译批量、导入批量）测试中覆盖。
