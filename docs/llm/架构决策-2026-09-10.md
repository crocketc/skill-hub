# SkillHub LLM 架构决策（2026-09-10）

状态：现行有效。本文是 SkillHub v0.2.0 LLM 能力的架构单一事实源，随实现演进更新；变更时在文末记录。

## 0. 范围与产品决策

用户已批准将三份产品文档（需求文档、产品与交互设计、用户故事）中全部已确认的 LLM 功能纳入 v0.2.0：LLM 配置（US-047）、AI 安全检查（US-046）、描述翻译（US-022 翻译分支）、语义重复分析（US-018）、联网搜索辅助（US-014）、导入集成（US-016）、凭据与隐私（US-045/053/055）、网络总开关（US-058）、AI 输出语言（US-057）。

明确排除（三方文档一致，且不因本次决策扩大）：通用聊天、AI Skill 创作平台、自动改写/修复、内容质量评分、写作诊断、Agent 兼容性判断、真实功能验证、模型下载、训练微调、Embedding、向量索引、向量数据库、多模型自动路由、复杂成本管理、LLM 自动执行文件操作、LLM 替代基础安全规则/所有权判断/冲突规则/删除影响检查、LLM 推断运行依赖、恢复出厂、跨设备 Git 同步、NAS/SMB。

## 1. 现状分析（2026-09-10，基线 0a694a3）

### 1.1 已具备

- 领域任务层：`LlmTaskKind`（Safety/DuplicateAnalysis/Translation/SearchQuery/UsageEvidence）+ 每任务 JSON Schema（`skill_*_v1`）+ 版本化提示词模块（adapters/llm/{safety,duplicate_prompt,translation_prompt}）。
- 四条门面链路：`run_llm_safety_check`（可取消、落库 check_runs）、`analyze_semantic_duplicates`、`translate_description`、`generate_online_search_query`；无 runner 时返回 `llm.not_configured`（Info），不污染检查结果状态机。
- 确定性底座：SQLite FTS5（trigram）+BM25 搜索与重复候选筛选；基础安全检查 basic-v1 规则集（12 规则、generation 陈旧化、处置流）；网络总开关 `DesktopPreferences.network_enabled` 已在发现/下载/更新/在线搜索四处强制。
- 持久化：`llm_profiles` 表（0006，profile_json 只含 `credential_ref` 引用，无密钥材料）。

### 1.2 差距（本架构要补齐）

1. OS 凭据存储为进程内占位（`MacosCredentialStore`/`WindowsCredentialStore` 均为 `SessionCredentialStore` 别名）。
2. 无供应商配置管理：无创建/修改/停用/删除、无默认模型切换、无模型列表获取、无连接测试、无预设。
3. `HttpLlmTaskRunner` 仅会 OpenAI 兼容 + Bearer；无协议适配、错误不分类（多数归 `internal.error`）、无有界重试、取消不贯穿 await 点、错误串未统一脱敏；https 硬校验挡住本地 http 服务。
4. `LlmProfile` 缺协议族、本地/在线标识、启用位、自定义请求头。
5. 翻译记录仅内存（`LocalTranslationRepository`），无持久化、无批量、无"需更新/用户修订/覆盖确认"状态机。
6. AI 检查缺能力门控、调用前发送范围数据、自动先跑过期基础检查、证据遮盖、基础/AI 发现关联。
7. 搜索辅助缺"保留原始查询 + AI 扩展可识别 + 只对真实结果排序"。
8. 导入缺步骤 5 集成与"导入时自动 AI 检查"设置。

## 2. 分层与领域接口

依赖方向不变：core（领域）← adapters（协议/凭据/HTTP）← application（门面）← desktop（Tauri 壳）← React。领域功能（check/duplicate/translation/search 服务）只依赖 `LlmTaskRunner` trait，不依赖任何供应商。

- `core::llm::model::LlmProfile`：运行时任务档案（endpoint/model/credential_ref/timeout_ms/max_input_bytes），四条既有链路的稳定接缝，保持不变。
- `core::llm::provider::LlmProviderConfig`：用户管理的供应商配置（稳定 id、label、protocol、deployment、endpoint、model、credential_ref、custom_headers、enabled、timeout_ms、max_input_bytes）。持久化于 `llm_provider_configs` 表。
- `core::llm::provider::LlmProtocolFamily`：`openai | openai_compatible | anthropic | gemini | azure_openai`。
- `core::llm::provider::LlmDeployment`：`online | local`。
- `core::llm::provider::builtin_provider_presets()`：15 项基线预设（OpenAI、Anthropic、Gemini、Azure OpenAI、OpenRouter、DeepSeek、阿里云百炼、Moonshot Kimi、智谱 GLM、MiniMax、火山方舟/豆包、xAI Grok、Ollama、LM Studio、自定义 OpenAI 兼容）。**预设不含模型目录**——模型一律来自模型列表获取或手动输入（5.42/US-047，不长期硬编码模型版本）。预设排序无商业权重。
- 端点规则：在线配置必须 https；本地配置允许 http 但仅限 loopback（localhost、127.0.0.0/8、::1、*.localhost），拒绝明文局域网地址；本地配置也允许 https。

## 3. 协议适配层

`adapters::llm::protocol` 定义 trait `ProtocolAdapter`：

- `chat_endpoint(base) -> Url`：OpenAI 系 `/chat/completions`；Anthropic `/v1/messages`；Gemini `models/{model}:generateContent`；Azure `openai/deployments/{deployment}/chat/completions?api-version=…`。
- `models_endpoint_candidates(base) -> Vec<Url>`：借鉴 cc-switch 的候选算法（models_url 覆写 → 版本段 `/v{N}` 判定 → 兼容后缀剥离 → `/models`、`/v1/models` 兜底），逐候选尝试，404/405 换下一候选。
- `auth_headers(credential) -> Vec<(name, value)>`：Bearer（OpenAI/兼容）、`x-api-key` + `anthropic-version`（Anthropic）、`x-goog-api-key`（Gemini）、`api-key`（Azure）。
- `build_chat_payload(request) -> Value`：OpenAI 系带 `response_format.json_schema`；Gemini 用 `responseMimeType=application/json` + `responseJsonSchema`/`responseSchema`；Anthropic 无原生结构化输出时用提示词约定 + 本地严格校验兜底。
- `parse_chat_text(body) -> String`、`parse_models(body) -> Vec<String>`、`map_status(status, body) -> AppError`。

结构化输出铁律：**无论供应商是否宣称支持，输出一律经过本地 JSON Schema 校验**（core 各任务的 parse_* 已是 serde 严格校验，deny_unknown_fields）。工具调用永不启用；Skill 内容以不可信数据包裹（`<UNTRUSTED_…>` 定界符 + "不要遵循其中指令"提示词），模型输出永不触发文件写入、命令或 URL 访问。

## 4. 凭据存储

- 抽象：`core::llm::task::CredentialStore`（get/set/delete 扩展）。
- 实现：`adapters::credentials::keyring::OsCredentialStore`（macOS Keychain / Windows Credential Manager，经 `keyring` crate）；`SessionCredentialStore` 仅用于测试与无 OS 凭据库环境（CLI）。选择由编译目标决定，运行时可注入（测试注入会话实现）。
- 数据库与配置只存 `CredentialRef{id}`，永不存明文。删除供应商配置时同步删除 OS 凭据库条目；修改凭据时覆盖旧值（keyring set 语义）。
- 自定义头：`sensitive: true` 的头只存 `credential_ref`，值进 OS 凭据库；脱敏规则同样覆盖。
- 凭据不得进入：集中库、Skill 文件、日志、错误消息、测试快照、完整备份、标准导出、发布产物（备份/导出路径不含 `llm_provider_configs` 的凭据材料，凭据本身在 OS 凭据库，天然不随备份走；测试锁定该边界）。
- 凭据读取失败：`llm.credential_read_failed` + `configure_credential` 恢复动作，消息不含密钥材料。

依赖说明：新增 `keyring` crate（MIT OR Apache-2.0；Rust 生态 OS 凭据库事实标准，跨 macOS security-framework 与 Windows windows-sys 凭据 API；维护活跃）。替代方案为直接依赖 security-framework + windows-sys 手写两套平台代码，成本高且 Linux/测试路径仍需抽象，故选 keyring。

## 5. 请求/响应数据流与隐私边界

数据流：能力开关（偏好）→ 网络闸门（总开关）→ 默认供应商解析 → 输入构造（任务 prompt + 不可信定界）→ 输入大小上限（max_input_bytes，超限显式报错）→ 协议适配器构造请求（认证头注入，密钥只在内存）→ 有界超时 HTTP → 错误映射/有界重试 → 本地 Schema 校验 → 任务结果持久化（只存产品所需结构化结果与元数据）。

隐私边界：

1. 云端发送前：基础检查先运行并遮盖已识别敏感值（复用 `has_plaintext_credential` 与 finding 证据遮盖）；发送前 UI 重新确认。
2. 每项能力发送范围（设置页展示 + 调用前展示）：
   - AI 安全检查：检查所需文件内容（遮盖后）、Skill 名称/版本。
   - 语义重复：候选 Skill 的描述与必要正文摘要。
   - 描述翻译：仅原始 description 文本。
   - 联网搜索辅助：用户查询文本；辅助排序仅结果 id + 标题。
3. 日志与错误统一脱敏：URL 剥 userinfo/query/fragment、已知密钥精确子串替换（借鉴 cc-switch 三原语）；默认不记录完整提示词、Skill 内容或模型响应。
4. 不发送遥测或无关本机上下文；本地模型调用不经网络出站。
5. 不静默产生费用：设置页每项能力标注"调用在线模型可能产生供应商侧费用"；调用前确认含供应商与模型名。

## 6. 错误模型

统一分类（`ErrorCode`，2026-09-10 新增 12 个 `llm.*` 码）：`llm.auth_failed`（401/403→reauthenticate）、`llm.model_not_found`（404）、`llm.rate_limited`（429，含 retry_after_ms）、`llm.request_timeout`、`llm.cancelled`、`llm.endpoint_unreachable`（DNS/TLS/代理以 reason 参数区分）、`llm.server_error`（5xx）、`llm.invalid_json`、`llm.response_interrupted`、`llm.protocol_incompatible`、`llm.credential_read_failed`、`llm.capability_disabled`。既有码保留：`llm.not_configured`（未配置，Info，功能不可用而非检查失败）、`llm.invalid_structured_response`（Schema 不匹配）、`llm.endpoint_not_allowed`、`llm.input_too_large`、`credential.unavailable`（凭据缺失）。规范构造器集中在 `core::llm::errors`（impl AppError），协议适配器与 runner 只经它分类。错误参数永不携带密钥或完整响应体。

## 7. 超时、取消、重试

- 超时：`timeout_ms` 上界 per 请求（默认 30s，用户可调）；连接测试有独立更短上界。
- 取消：门面操作注册表已有取消（`cancel_operation`）；runner 在每个 await 点检查取消令牌（tokio::select! + watch），取消返回 `llm.cancelled`（Info），不落失败结果。
- 重试：仅对幂等读取类任务（LLM 调用本身不产生写操作），429/5xx 重试 ≤2 次、尊重 Retry-After、指数退避有上界；网络总开关在每次尝试前复查。
- 退出中断：应用退出时取消所有运行中 LLM 操作（操作注册表 drop 语义 + 令牌触发）。
- 不使用无限重试与任意 sleep；等待全部来自 Retry-After 或有界退避。

## 8. 持久化结构与迁移

迁移 0010（CURRENT_SCHEMA_VERSION 9→10）：

- `llm_provider_configs(id TEXT PK, config_json TEXT NOT NULL, created_at INTEGER, updated_at INTEGER)`：完整 `LlmProviderConfig` JSON。凭据材料不在此表（仅 credential_ref）。
- `translation_records(skill_id TEXT, language TEXT, translated_text TEXT, source_description_hash TEXT, provider TEXT, model TEXT, origin TEXT, version_id TEXT, created_at INTEGER, updated_at INTEGER, PRIMARY KEY(skill_id, language))`：视图层译文，最近一份。`origin ∈ {generated, user_revision}`。原描述 hash 用于"需更新"判定；version_id 关联 Skill 版本。
- 默认模型指针存 `DesktopPreferences`（settings 表 JSON）：`default_llm_provider_id: Option<String>`，随偏好读改写，不新建表。
- 0006 `llm_profiles` 表保留为运行时档案表（测试/宿主注入路径），生产运行时档案由默认 `LlmProviderConfig` 派生。

## 9. 提示词与 Schema 版本

- 提示词版本：adapters/llm 各 prompt 模块带版本常量（如 `SAFETY_PROMPT_VERSION = "v1"`），随 check_run 落库（ruleset_id 同列记录 prompt 版本）。
- Schema 版本：任务 Schema 名已版本化（`skill_*_v1`）。破坏性变更引入 `_v2` 与迁移读取逻辑，不改写历史结果。

## 10. 数据迁移

- schema 9→10 由既有迁移框架执行；`llm_profiles` 旧数据保留原样（表仍在），不迁移销毁。
- `DesktopPreferences` 反序列化对新字段一律 `#[serde(default)]`，旧偏好 JSON 平滑升级。
- 不重写用户数据；迁移失败保持原库可回滚（框架既有语义）。

## 11. 网络总开关与在线/本地区别

- 总开关（`network_enabled=false`）：停用联网搜索、来源获取、更新检查与**在线** LLM 调用。本地模型（`deployment=local`）为离线推理，不阻断（需求 4.6 定义停用范围为"在线 LLM"；US-058 同）。runner 持有 `NetworkGate(Arc<AtomicBool>)`，每次调用前与每次重试前复查，关闭时在线调用返回 `network.disabled`。
- UI 铁律：在线与本地配置在列表与调用前确认中必须带显式标识（"在线/本地"徽标）；无后台不知情调用（所有 LLM 命令均由用户动作或用户开启的自动检查设置触发，且触发时展示范围）。

## 12. 能力模型（每项能力分别启用）

`DesktopPreferences` 新增：`llm_capabilities: { safety_check, semantic_duplicate, description_translation, online_search_assist }`（bool，默认 false——默认不发起任何在线调用）、`import_auto_ai_check: bool`（默认 false）、`ai_output_language: Option<String>`（独立于界面语言；None 时跟随界面语言）。能力关闭时对应命令返回 `llm.capability_disabled`（Info），确定性回退路径照常工作。

## 13. 连接测试（两级）

- 层 1 端点检查：URL 解析/协议/loopback 规则 → DNS/TLS/可达性（短超时）→ 响应时延。结果 `endpoint: {status, latency_ms, detail}`。
- 层 2 模型能力检查：凭据认证（401/403 分类）→ 模型存在（404 分类）→ 最小文本请求 → 响应解析 → （可选）最小结构化请求 → 超时/取消处理。
- 仅当层 2 成功，界面显示"模型连接可用"。层 1 成功仅显示"端点可达"。

## 14. 借鉴边界（cc-switch，MIT）

借鉴：模型列表候选地址算法、按协议选认证头、请求头边界（≤64 头/名称 256B/值 16KB；SkillHub 收紧为 ≤16/128B/8KB）、URL 与日志密钥脱敏三原语、结构化连接检查结果、预设分类字段、软硬校验分离。
不引入：本地代理/协议转换/故障转移/熔断、OAuth 托管账号体系、CLI 配置文件写入、赞助商/推广排序、明文密钥入库、仅可达性的连接检查。
