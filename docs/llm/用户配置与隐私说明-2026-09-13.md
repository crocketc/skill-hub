# SkillHub LLM 用户配置与隐私说明（2026-09-13）

状态：现行有效。本文面向用户说明 v0.2.0 中 AI 能力的配置方式、数据发送范围和凭据保护机制；技术架构见《架构决策-2026-09-10.md》，供应商支持级别与四层证据见《供应商兼容矩阵-2026-09-13.md》。

## 1. 总原则

- **AI 全部可选且默认关闭**：四项 AI 能力（安全检查、语义重复分析、描述翻译、联网搜索辅助）出厂均为关闭状态；不开启就不产生任何模型请求。
- **本地功能不依赖 AI**：扫描、导入、部署、备份、基础安全检查、确定性搜索与重复提示全部在本地完成，与 LLM 配置无关。
- **网络总开关优先**：设置中的"关闭所有网络功能"打开时，即使 AI 能力开关是开的，也不会发出任何模型请求。
- **费用透明**：SkillHub 不代理、不经手你的 API 密钥对应的账户费用；用量与计费发生在你与供应商之间，应用不会隐藏任何调用。
- **不猜厂商**：供应商行为只由你显式选择的"产品线"决定，绝不按名称、地址或模型名推断；也不会在运行期自动改用其它协议重试。

## 2. 配置 LLM 供应商（设置 → 网络与 AI → LLM 供应商）

### 2.1 新增供应商

1. 点击"新增供应商"。
2. 从预设选择（25 个内置预设，例如 OpenAI、Anthropic Claude、Google Gemini、Azure OpenAI、OpenRouter、DeepSeek（OpenAI/Anthropic 两个面）、阿里云百炼 Qwen、Kimi 开放平台、Kimi Code（OpenAI/Anthropic）、智谱 GLM 普通 API、GLM Coding Plan（Chat/Responses/Anthropic 三个端点）、MiniMax、火山方舟 Doubao、xAI Grok、Groq、Mistral、百度千帆（OpenAI/Anthropic）、Ollama、LM Studio，以及"自定义 OpenAI 兼容服务"）。
3. 填写 API 地址（预设会自动带入默认地址，可改为自定义 Base URL）、模型名和（在线服务所需的）API 密钥。
4. 保存。密钥立即写入操作系统凭据存储（macOS 钥匙串 / Windows 凭据管理器），数据库只记录 `llm-provider:{配置ID}` 这样的引用，不含明文。

**产品线决定行为**：选择预设会同时确定"产品线兼容档"，它决定结构化输出方式与推理开关（例如 DeepSeek Chat 用 `json_object` 而非严格 Schema；GLM Coding Plan 与普通 GLM API 是两条互不混用的产品线）。**同一个协议、不同产品线会得到不同的请求参数**，这是有意的。

**接口格式跟随产品线**：选择内置预设后，"接口格式"下拉只列出该产品线**已确认**的协议；只有"自定义"配置才列出全部六种，并额外提供"高级选项 → 结构化输出策略"由你显式选择（内置产品线隐藏该实现细节，由系统按其兼容档决定）。**切换接口格式只改变请求协议**，不会修改你已填写的 Base URL、模型或密钥。

**模型列表失败不阻塞**：点击"获取模型列表"可从服务拉取模型名；若服务不提供模型列表接口或请求失败，直接手动输入模型名即可。模型名以你实际获取到的目录为准（供应商目录会变化）。

### 2.2 三层连接测试

"测试连接"分三层展示，三层回答**不同**的问题，绝不合并：

| 级别 | 含义 | 展示 |
|---|---|---|
| 服务可达 | API 地址是否有任何响应（任何状态码都算可达） | "服务可达 (延迟 ms)" 或 "服务不可达" |
| 模型可调用 | 一次低 token 纯文本探测：凭据有效、模型存在、信封可解析 | "模型可调用" 或本地化失败原因（如"模型服务拒绝了凭据…"） |
| 结构化输出兼容 | 按当前产品线的结构化策略发一次真实结构化请求 | "结构化输出兼容" / "结构化输出不可用（能力警告）" / "结构化输出未验证" |

规则：

- **未执行的层级显示"结构化输出未验证"**（中性图标），不冒充成功；模型级未通过时不会继续下探结构化级。
- **模型可调用 ≠ 结构化兼容**：模型能返回纯文本、但结构化输出失败时，只提示"结构化输出不可用"的能力警告，**不会**说成"模型协议不兼容"，也不会把该供应商标记为不可用（普通文本任务仍可用）。
- 每一级都带图标与文字，状态不单靠颜色区分。
- **保存配置不要求测试成功**；测试只是诊断动作。

### 2.3 管理动作

- **启用/停用**：停用的供应商不参与默认供应商解析，也不发起任何请求。
- **设为默认**：AI 功能使用默认供应商；删除默认供应商时默认标记自动清除。
- **清除凭据**：只删除操作系统凭据存储中的密钥，保留供应商配置；**启用状态保持不变**（仍显示"已启用"），凭据状态显示"未配置凭据"。清除后模型测试会返回凭据错误，不会伪装成健康状态。
- **删除**：同时删除配置与操作系统凭据存储中的密钥。
- **部署标签**："云端" / "本地"表达**部署类型**（是否走网络、是否通常需要凭据），不是健康状态；它不会因连接测试结果而改变。本地部署（Ollama、LM Studio 等）请求不出本机，无需密钥。

## 3. AI 能力开关与数据范围（设置 → 网络与 AI → AI 能力开关）

| 能力 | 默认 | 发送范围 | 说明 |
|---|---|---|---|
| AI 安全检查 | 关 | Skill 文件内容（先遮盖已识别的明文凭据再发送） | 在基础检查之外提供语义层风险提示 |
| AI 语义重复分析 | 关 | 候选 Skill 的名称与描述 | 只分析确定性筛选出的少量候选 |
| 描述翻译 | 关 | Skill 描述文本 | 只翻译 description 字段 |
| 联网搜索辅助 | 关 | 搜索关键词 | 只做查询改写/扩展与辅助排序 |

- 每个开关旁展示该能力的发送范围说明；界面上发起任何 AI 调用前也会显示"当前发送范围"。
- **AI 输出语言**独立于界面语言，可选"跟随界面语言"、中文或英文。

## 4. 凭据保护机制

凭据遵循一条硬边界（有对应自动化测试约束）：

1. 密钥只保存在操作系统凭据存储；应用数据库、Skill 文件、日志、错误消息、完整备份、标准导出和发布产物中都只有引用或遮盖形式。
2. 设置表单里尚未保存的草稿密钥只在内存中暂存（覆盖层），不写入磁盘；关闭表单即清除。保存配置时密钥只通过专用凭据字段传输，**不进入被持久化的供应商 JSON**。
3. 发送给 LLM 的证据文本先经敏感值遮盖（私钥块、`sk-`/`ghp_`/`github_pat_`/`xoxb-`/`xoxp-` 前缀令牌、键值形连接串）。
4. 删除供应商会同时删除凭据存储中的密钥；清除凭据只删密钥、保留配置。

## 5. 各功能中 AI 的角色

### 5.1 AI 安全检查（Skill 详情 → 检查）

- 先运行（必要时先刷新）基础检查 basic-v1，再发起 AI 检查；两次检查**分别展示**结果，不合成第三个结果或分数。
- AI 只读分析：无工具授权、不包含无关本机上下文、不评价写作质量/功能/兼容性、**不会自动修改或删除内容**。
- 提示词版本化（`safety-prompt-v1`），版本号随检查记录保存。

### 5.2 描述翻译

- 只发送 description 字段；保存语言、供应商、模型、时间与提示词版本。
- 描述后续变更时该翻译标记"需更新"；重新生成**不会**静默覆盖你的手工修订，会先要求确认。
- 批量翻译逐项报告成败，单项失败不影响其他项。

### 5.3 语义重复分析

- 候选先由本地全文检索（SQLite FTS5 + BM25）确定性筛出，AI 只对少量候选做语义判断。
- LLM 失败或返回异常时回退为纯确定性结果并标注失败码，不会展示空白或阻塞你管理 Skill。
- 是否认定重复始终由你确认，AI 结果只是建议。

### 5.4 联网搜索辅助

- AI 只参与查询改写/扩展与结果辅助排序；你的原始查询始终保留并可用。
- AI 扩展命中的结果带"扩展查询"来源标记；不会生成虚假来源。
- 辅助失败时直接回退普通搜索。

### 5.5 导入流程 AI 预检

- 在导入第 5 步由你发起，或在设置中开启自动预检；批量结果展示数量、文件范围、供应商与模型。
- AI 预检**不绕过任何确定性门**（安全规则、路径边界、所有权判断照常生效）；AI 只是叠加的建议性发现。
- 部分对象失败时逐对象展示原因，其余对象结果不受影响。

## 6. 明确不提供的能力

聊天对话、AI Skill 创作、自动改写/修复、质量评分、Agent 兼容性判断、模型下载、训练微调、Embedding/向量索引/向量数据库、多模型自动路由、代理/熔断/故障转移、复杂成本管理、LLM 自动执行文件操作或替代确定性安全规则。v0.2.0 的命令契约与界面都没有这些入口。

## 7. 常见错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `llm.not_configured` | 未配置供应商（提示级，不算失败） | 在设置中新增并启用供应商 |
| `llm.capability_disabled` | 对应 AI 能力开关未打开 | 在"AI 能力开关"中显式开启 |
| `network.disabled` | 网络总开关关闭 | 打开网络功能后再使用在线能力 |
| `llm.auth_failed` | 密钥无效或过期 | 重新保存凭据 |
| `llm.model_not_found` | 模型名不存在或无权限 | 核对模型名（可先获取模型列表） |
| `llm.rate_limited` | 供应商限流 | 稍后重试 |
| `llm.request_timeout` | 请求超时 | 检查网络或服务状态 |
| `llm.endpoint_unreachable` | 服务不可达 | 检查 Base URL 与网络 |
| `llm.protocol_incompatible` | 产品线与接口格式不匹配（保存或请求前拦截） | 改为该产品线支持的接口格式 |
| `llm.invalid_structured_response` | 返回不符合本地 Schema 校验 | 重试；若持续出现换用其他模型 |
| `credential.unavailable` | 凭据已被清除或不可读 | 重新输入 API 密钥 |
| `translation.user_revision_requires_confirmation` | 存在你的手工修订 | 确认是否覆盖 |

## 8. 支持级别与真实验证

供应商能力按"四层证据"判定：cc-switch 参考实现取证 → 官方文档核验 → SkillHub mock 契约测试 → 真实服务验证。**cc-switch 仅作参考实现证据，不等于 SkillHub 已支持**；实际能力以本仓库的兼容档与契约测试为准。

2026-09-13 已完成 DeepSeek（Chat 面）、GLM Coding Plan（Chat 面）与 LM Studio（本地）的真实服务验证，三者服务可达、模型可调用、结构化探测均通过；其余供应商与其余面保持"契约通过、真实未验证"。清除凭据后的行为也在真实服务上验证：模型级返回 `llm.auth_failed`，结构化级不下探。真实服务验证不替代真机按钮验收，详见《供应商兼容矩阵-2026-09-13.md》与《人工验收清单-2026-09-13.md》。
