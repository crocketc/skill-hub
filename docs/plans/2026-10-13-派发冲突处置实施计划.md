# 派发冲突处置与单项/批量统一实施计划

> **执行说明：**按 `superpowers:executing-plans` 在当前分支逐任务实施。每项先写失败测试、确认 RED，再实现、定向验证、更新开发快照、自审差异并独立提交；不创建工作树或新分支。

**目标：**为派发同名冲突交付默认跳过的替换/换名/跳过流程，并让单项、批量入口的资格、提交与结果一致且可恢复。

**架构：**服务端预览记录精确占用事实、消费者、允许动作及指纹；提交端重验后调用同一逐目标处置服务。受管目标复用现有关系和恢复模式；未知目标原件进入可恢复备份；React 两个入口共用动作模型、处置组件和 facade。

**技术栈：**Rust（系统编程语言）、SQLite（嵌入式数据库）操作日志、Tauri（桌面应用框架）/Specta（类型绑定生成）生成绑定、React（前端框架）、Vitest（前端测试）、Playwright（浏览器自动化）。

**规格：**[派发冲突处置与单项/批量统一设计方案](2026-10-13-派发冲突处置设计方案.md)

## 全局约束

- 冲突决策默认“跳过该项”；未提交或取消时文件和关系均不变。
- 客户端不得授权自身构造的目标或占用者；服务端签发预览、重新验证并绑定每项处置。
- 替换必须核验目标身份和原件所有权；原件无法恢复时不得执行替换。
- 换名必须改主体 `SKILL.md` 的 `name`；仅影响所选目标时另存新主体并建立“复用修改”关系，来源与其他关系保持原样。
- 共享目录变更须显示全部可确认消费者并显式确认；消费者集合不完整或变化时阻止旧预览。
- 逐目标报告成功、跳过、失败和待恢复；重复提交幂等，部分成功不得伪装为全部成功或全部失败。
- Rust API 绑定只能通过 `SKILLHUB_WRITE_BINDINGS=1 cargo test -p skillhub-desktop generate_bindings -- --exact` 生成。
- 前端编码前加载 `frontend-design` 与 `vercel-react-best-practices`；自动化通过不得标记为 macOS/Windows 桌面人工验收通过。
- 每项只在其文件范围运行受影响测试、格式、静态检查和构建；实现或测试范围变化后更新开发状态、自动化测试说明及完成度矩阵。

## Review Focus（重点审查）

1. 预览后目标被替换：旧预览提交必须被拒绝，磁盘与关系账本均不变；由 Task 2 的漂移集成测试覆盖。
2. 未知占用是符号链接：备份移动链接本身，不跟随或改动链接所指的外部目录；由 Task 5 的恢复集成测试覆盖。
3. 共享目录消费者变化或发现不完整：不执行任何物理修改；由 Task 6 的消费者漂移测试覆盖。
4. 备份后、关系记账前中断：恢复端只能完成或回滚到一个经校验的终态；由 Task 3/5 的写入边界故障注入覆盖。
5. 改名面对“来源仅用于所选目标”与“另有其他使用者”：前者更新原主体和全部所选关系，后者创建派生主体且不改原关系；由 Task 4 的两组集成测试覆盖。
