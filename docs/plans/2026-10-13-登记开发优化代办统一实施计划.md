# 登记开发优化代办统一实施计划（2026-10-13）

**目标：**按当前产品裁决逐项完成已登记的开发优化代办，以任务级测试、代码核查、自动化浏览器验收、文档记录和独立提交收口，并生成下一轮真实桌面人工验收构建。

**方案：**仅在当前分支串行工作。先收口会阻断其他流程的操作恢复与主体身份问题，再完成导入、派发、跨页面状态和导航，之后接通批量操作与 Agent 适配，最后处理已确认的界面精修。每项先补失败测试、按影响范围实现和验证、独立检查差异、更新四份当前开发快照并提交；所有项完成后执行全量发布验证，合并为下一轮人工验收入口并推送远端。

**技术栈：**Rust（后端与桌面命令）、React/TypeScript（前端）、Tauri（桌面壳）、Vitest（单元/组件测试）、Playwright（浏览器自动化）。

**依据：**用户已确认产品规则及当前实现核查，见 `docs/product/业务决策模型.md`、`docs/product/界面呈现与操作入口.md`、`docs/product/关系体系与生命周期.md`、`docs/product/AI能力可用性与刷新规范.md`；跨流程恢复与派发的原有详细方案分别见 `docs/plans/操作记录与恢复统一收口-2026-10-12.md` 和 `docs/plans/派发流程统一优化-2026-10-12.md`。这些既有计划是本计划的具体实现依据；发生规范冲突时先停下并回到已确认产品裁决，不自行扩大行为。

## 执行约束

- 只使用当前分支 `feat/v0.2.0-product-completion` 和当前工作区；不创建其他分支或工作树，不并行派发。
- 依赖顺序：OPR → REL-ID → IMP → DEP → NAV → AI/BAT/ADP → UI。表内按编号依序实施；有独立边界的任务仍串行提交。
- 每项采用 TDD（测试驱动开发）：先写能表达用户行为的失败测试并确认失败，再实现最小代码、运行受影响验证、检查实现与产品规范、`git diff --check`，更新开发状态/自动化说明/人工验收清单/验收矩阵后提交，再开始下一项。
- 前端任务实施前加载 `frontend-design`（前端设计）技能；React 实现同时遵循 `vercel-react-best-practices`（React 最佳实践）技能。交互任务必须有生产组件的 Playwright（浏览器自动化）验收，不以只读样式文本断言代替页面行为。
- 危险文件操作只能用隔离测试目录和测试数据库。不可验证唯一身份、权限或恢复路径时必须阻断写入，不通过弱化门禁换取成功率。
- 自动化/E2E（端到端）通过和人工桌面验收分开记录。所有开发任务完成后停在新的人工验收状态，不替用户宣告人工通过。
- 不把构建产物、用户技能内容、个人绝对路径、凭据或缓存写入提交。
