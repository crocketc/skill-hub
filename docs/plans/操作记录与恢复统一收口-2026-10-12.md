# 操作记录与恢复统一收口实施计划

> 执行方式：待方案确认后串行实施，每项先补失败测试、修复、按影响范围验证、审查和提交。实施时使用 superpowers:executing-plans（计划执行）技能；沿用用户已确认的串行方式，不自行派发子智能体。

**目标**：只读准备不阻断正常使用；真正中断的写入可按真实影响恢复；候选数量与详情加载失败不使恢复入口失效。

**架构**：统一操作阶段、写入影响和恢复能力的判定，由启动门禁与恢复候选共用。详情按操作标识查询完整日志。恢复按操作种类调用真实恢复实现并验证结果，禁止通用改标签冒充恢复。

**技术栈**：Rust、SQLite（数据库）、React（界面框架）、TypeScript（类型语言）、Vitest（单元测试）、Playwright（浏览器自动化）。

**依据**：[关系体系与生命周期](../product/关系体系与生命周期.md)的取消、失败与恢复契约；[产品规范索引](../product/README.md)；[界面呈现与操作入口](../product/界面呈现与操作入口.md)。

## 现场与历史归类

- 2026-10-12 macOS 当前构建 `a68e709a`，用户批量扫描导入、处置冲突时出现“上次操作尚未完成”；恢复页显示 `operation was not found`（未找到操作）。进程仍在运行，尚无原生崩溃证据；当前确定是全局门禁与恢复页面形成死路，不能将其写成已确认的操作系统级卡死。
- 只读查询实际运行数据库：238 条 `import_skill / running / prepared`，创建时间为北京时间 21:28:05—21:28:06；没有本轮导入的 applying/verifying/needs_recovery 记录。数据库快速一致性检查为 ok。仅说明这些记录未进入写入阶段，不推断整个用户素材均无变化。
- 历史 R-10 已修复“提交前安全阻断错误进入 needs_recovery”；本次是分析预备记录漏结算、门禁误拦截与恢复详情查询缺陷，归类为旧问题修复后的边界遗漏，不能仅凭相似提示宣布 R-10 原修复回归。
- 今日 Windows 删除预览已有修复和真实验收通过；该通过仍成立于其实际覆盖范围。本次暴露其他预览种类未统一及共用恢复链路缺陷，不改写 Windows 已通过记录。
- 未修改用户数据库、操作记录、Skill 内容；本轮未修程序或重建产物。

## 已核实的共用缺陷

| 编号 | 当前源码事实 | 影响与证据 |
| --- | --- | --- |
| REC-01 | 导入 `analyzeConflicts` 对每个候选调用 `prepare_import`，不保存准备标识用于收尾；提交重新 prepare；`cancel` 仅清空前端候选 Map（映射表） | 分析、返回、取消和重复分析可遗留 prepared。现场 238 条同秒记录符合该路径；AI 预检的部分准备失败也需覆盖补偿 |
| REC-02 | bootstrap 查询将除 `delete_skill/prepared` 外的未完成 prepared 一律拦截 | 准备阶段尚未写入也可阻断全局使用；不应继续给每个种类添加零散特例 |
| REC-03 | 完整候选按创建时间升序，`nativeOperationFacade.get` 却只在 bootstrap 最近 10 条降序摘要中找详情；找不到抛截图原文 | 现场首个候选不在最近 10 条中，可确定失败链；所有操作种类在数量超过 10 或记录被新操作挤出后均受影响 |
| REC-04 | 恢复详情错误与列表错误共用 error；任一详情失败使整个候选区替换为错误占位 | 可恢复候选与按钮同时消失，无法切换或继续处理；需隔离错误、清除过期错误和异步竞态 |
| REC-05 | 候选排除 `subject_runtime_rename/prepared`、`usage_duplicate_cleanup/prepared`，门禁不排除 | 可在内存 SQLite（数据库）中按当前门禁 SQL（查询语句）验证“拦截=true、候选=false”；软件被挡但没有处置入口 |
| REC-06 | 共享迁移候选只允许 complete，但后端该恢复分支返回 unsupported；页面又固定发送 rollback。其他大多数种类进入通用 pending_targets 清理/改状态分支 | 恢复能力宣告、实际执行和界面动作不一致。需逐种核验磁盘、数据库、版本指针和备份恢复，不能将改标签称为恢复完成；此项为源码缺陷，未在真实素材执行破坏性验证 |

## 流程覆盖清单

| 流程 | 当前核实的准备记录/门禁问题 | 实施时必须覆盖的中断恢复 |
| --- | --- | --- |
| 批量/单项导入、冲突分析、AI 预检 | import_skill，现场确认 prepared 遗留 | 安全阻断、跳过、取消、重新分析、批量部分失败、提交清理失败 |
| 派发、原目录迁移 | deploy_skill、migrate_original 的 prepared 会拦截 | 取消、权限变化、目标冲突、部分目标写入、重新启动 |
| 来源更新、切换/回滚版本 | prepare_source_update、set_current_version 的 prepared 会拦截 | 预览过期/漂移、取消、指针/可见目录/关系同步部分失败 |
| 另存副本并替换关系、标准导出 | save_as_copy_replacement_preview、standard_export 的 prepared 会拦截 | 返回/取消、目标失效、产物写入中断、关系替换部分失败 |
| 释放、主体/派生改名、受管关系变更、重复清理、共享迁移 | usage_release、subject_runtime_rename、usage_derived_rename、managed_usage_change、usage_duplicate_cleanup、shared_usage_migration；其中主体改名/重复清理候选与门禁明确不一致 | 逐种核验专用恢复实现与允许动作，含共享目录、备份、数据库/磁盘不一致 |
| 删除 | 今日 delete_skill/prepared 已过滤且 Windows 取消/重启覆盖通过 | 真正执行中断的恢复、批量部分失败、历史记录不在最近 10 条 |
| 创建/保存、组合操作、卸载、来源重连、环境核对处置、搜索候选保存/确认/忽略 | 存在 planned 日志；不是已确认的预览遗留故障 | 逐个核对成功/失败结算和进程中断点；通用恢复不能无条件视作已恢复 |
| 备份/恢复及其他未接入统一日志的磁盘写入 | 尚不能据此次日志证明安全或故障 | 作为覆盖审查项核对独立事务/补偿契约，不为了覆盖盲目新增第二套日志 |

## 全局约束

- 禁止直接清库、批量改终态、移除全局安全拦截或吞掉恢复错误来绕过现场。
- 只读预览、当前会话正在执行与需要恢复的持久化写入必须区分；在写入前持久化足够恢复事实。
- 失败恢复需确认磁盘/数据库/版本事实一致；保留原文件、共享影响、备份与可回滚路径。
- 前端修改前加载 frontend-design（界面设计）和 vercel-react-best-practices（React 最佳实践）；按既有风格设计清晰的恢复入口。
- 本次统一方案确认后更新产品规则，再实施。当前报告不是实现已完成或人工通过证据。

## 审查重点

1. 超过 10 条候选及旧记录被新记录挤出——任务 1。
2. 批量准备部分失败、取消与再次分析——任务 2。
3. 当前会话执行中与上一会话残留不同——任务 2。
4. 恢复许可只有完成、只有回滚、无安全自动动作——任务 3。
5. 权限受限、共享路径、恢复失败和再次启动——任务 3、4。
