# 派发流程统一优化（2026-10-12）

## 目标

把安全判定、目标可用性和同名冲突处置收敛到现有派发流程中，让用户看懂每个目标能否派发、受什么限制以及将如何处理冲突。派发明确分成两个独立步骤：“选择目标”与“预览结果并处置”；预览不得藏在目标选择长页面底部，用户不能依靠滚动整页寻找下一步。它仍是同一派发流程，不新增重复入口或另一套执行契约。

安全门禁以[业务决策模型第四节](../product/业务决策模型.md#四安全分级与预警模型)为准：危险结果在完成“完全信任”前不可派发；警告结果保留风险记录与说明，但无需“完全信任”即可派发。检查结论及信任决定仍绑定具体内容版本，人工智能不参与分级或放行。

## 当前代码核查

- **实施前源码基线**：安全派发门禁曾通过 `ensure_no_security_alert` 检查活动预警，警告和危险结果都可能被阻止；DEP-1 已改为只阻止危险且未完全信任的精确版本。
- **实施前源码基线**：派发计划允许缺少基础检查记录。现已确认缺失、运行中、失败或规则集过期的检查事实应显示为未检查/未完成，不得伪装成通过，也不据此新增隐式阻断；精确版本上的危险预警仍按危险规则处理。
- 目标可选状态与可写权限分别计算，派发资格检查未一致要求目标具备可验证的写入能力。只读内置目录不得作为派发目标。
- 当前同名占用可能以通用 `TargetExists` 结果返回；现行产品规则要求在既有派发预览内提供“替换目标里的／换个名字派发／跳过该项”，缺省跳过，并按关系与冲突规范处理名字及消费者影响。

## 实施范围

1. **安全结果与派发门禁**：按精确内容版本读取基础检查、预警和信任事实。危险结果在完全信任后才开放派发；警告结果不要求信任即可派发，仍展示警告说明并保留原始发现与待处理记录；无发现结果按当前规则派发。检查结果运行中、失败、过期、缺失或无法核验时如实展示事实，不得映射为“通过”，也不据此扩大阻断范围；精确版本仍有危险未信任预警时继续阻止。
2. **目标可用性预检**：统一派发目标的发现状态、目录角色、派发模式支持情况和实际可写能力。只读内置目录不可选；不可派发目标显示具体原因和可行的下一步；逐目标执行仍需处理权限变化与文件系统失败，并给出真实结果。
3. **同名冲突闭环**：在同一预览中呈现占用对象与影响，提供已裁定的替换、换名派发、跳过三种选择，默认跳过。换名处理遵循现行冲突与技能主体规则，不得只静默改目标文件名；批量派发对每个目标逐项列出执行、跳过和失败结果。

三个部分都属于派发流程的预检和逐目标决策，不改变关系治理分类，也不增加“必须先转为集中管理”的额外前置条件。单项和批量入口复用同一套规则及执行契约。

## 开发任务

| 任务 | 内容 | 完成条件 |
| --- | --- | --- |
| DEP-1 安全门禁 | 修正安全事实到派发资格的映射，保留版本绑定和信任审计 | 危险未完全信任时被阻止；危险完全信任后可派发；警告未信任仍可派发且可见风险说明；版本变更后不会继承旧决定 |
| DEP-2 目标资格 | 统一目标可用性、模式能力、目录角色和写权限判断 | 内置只读目标不可选；可写目标可用；权限不足、目标变化和模式不支持均说明具体原因，执行结果准确 |
| DEP-3 冲突决策 | 将既有三选冲突模型接入预览和执行 | 默认跳过；替换、换名和跳过都作用于正确对象；取消/失败不造成未告知改动；批量逐项汇总真实结果 |
| DEP-4 单项/批量联调 | 两种入口共享同一规则、预览、提交和结果映射 | 同一素材从单项和批量入口得到一致资格与处置结果；无重复提交或过期页面状态 |
| DEP-5 两步交互与预览可达性 | 将目标选择和预览/处置设计为清晰的前后步骤；单项与批量入口遵循同一信息层级；在预览步骤集中呈现安全结论、目标资格、冲突影响及处置选择 | 有明确的“下一步/上一步”；预览步骤进入后无需滚动目标清单到末尾即可查看；返回时保留目标选择；窄窗口、长目标列表和键盘操作可用 |
