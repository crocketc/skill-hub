## 统一实施方案

**目标：** 将第一批遗漏与本轮关系规范按同一事实契约实施，覆盖后端执行、持久化、前端所有消费点与验证；不改用户已确认布局，不引入依赖升级。

**依据：** [关系体系与生命周期](../product/关系体系与生命周期.md)、[统一术语与命名总表](../product/统一术语与命名总表.md)、[业务决策模型](../product/业务决策模型.md)、[界面呈现与操作入口](../product/界面呈现与操作入口.md)。

**执行建议：** 主代理在本会话按依赖顺序实施，不自行并行派发。Rust core／application／storage 提供共享事实和真实动作，TypeScript presenter 只映射展示；历史技术枚举通过兼容投影读取，新动作写入明确的使用关系与决定历史。接口绑定由仓库生成命令更新。

**全局约束：** 六类关系职责分开；链接／完整拷贝与已管理／未管理独立；Agent 内置目录只读且不可派发；Agent 用户／工作区目录不与独立 Project 混同；回收选择按 Agent／共享目录／项目三组；解除拷贝提供保留独立拷贝或同步移除拷贝；解除决定不能被普通重扫撤销；来源登记不能冒充可操作使用关系；所有迁移先建并核验替代入口再清旧文件。

**特别复核：** Windows junction／符号链接与大小写别名；只读内置和普通原件的保护；共享多消费者及未知消费者；预览后文件变化及部分执行失败；历史保留记录重扫和同路径新技能。下列任务分别覆盖这些条件。

## 跨任务契约（由 T01／T02 定义，其余任务按归属扩展）

以下是新增领域类型设计，既有物理技术枚举仍可用作底层证据。跨任务使用同一份 Rust 类型和生成绑定，不手工维护另一套 TS 契约。

- `UsageRelationView`：relation_id、skill_id、target（Agent／共享目录／Project 身份及目录角色）、entry_key、form（Link／FullCopy）、management（Managed／Unmanaged）、health_reasons、decision_history_ids、active、file_representation、link target 证据、`physical_source_ids_evidence` 与 `evidence_relation_ids`。物理 ID 集合只保留核验线索；多 ID 是显式冲突证据，不成为稳定键或单一动作目标。无法确认形式时允许缺省，不得猜测可操作链接目标。
- `UsageEntryKey`：已确认目录实体 ID＋规范化入口相对路径；物理文件 ID 作为核验证据，不把可因替换改变的 inode／文件 ID 当作唯一长期身份。技能主体 ID 和该 key 共同限定解除决定；未确认身份不得仅凭名称恢复或套用决定。
- `UsageDecisionRecord`：decision_id、skill_id、entry_key、原 relation_id／物理证据、decision（Released／RetainedIndependentCopy）、决定时指纹与时间、操作 journal ID。普通重扫更新发现事实而不改决定；明确派发／转入管理建立新的活动关系且保留历史。
- `UsageEnvironmentKey`：真实 Agent 身份＋可选独立 Project ID；不以 Agent 工作区 scope 自动创建 Project。`EnvironmentProblemView`：problem_id、kind（SameSkill／NameConflict）、所有受影响环境、实际入口证据、消费者、核验 revision、逐环境关闭结果；未知身份保留证据而不猜分类。
- `PrepareUsageChange`／`CommitUsageChange`：准备请求包含 operation_id、选中关系或问题、动作、拷贝处理／保留位置／内容基准；返回 prepared_id、relationship_revision、主体版本、入口身份／指纹、全消费者及逐目标影响。提交使用 prepared_id；范围变化必须失效，不能直接拿前端路径执行。
- `ImportCandidateUsageHistory`：None／PreviouslyReleased／PreviouslyReleasedChanged，另给 retained_independent_copy 和证据；前端默认选择由这份事实确定。用户重新勾选仅允许导入，不等于恢复管理。
- 统计和图谱读同一活动使用投影及识别环境；导入 provenance、当前更新 source、lineage 是独立输入。FactsChanged 后相关治理、待办、详情、统计与图谱缓存一起失效；重新查询确认后才更新完成状态。

兼容策略：新增结构化决定仓库和迁移；旧技术类型按事实投影，不批量改历史 JSON 值。显式用户决定必须有操作历史证据；自动 Retained／健康原件标记不迁移成解除。无法区分的旧行保留历史并重新核验使用事实，既不猜用户授权、也不修改原文件。迁移可重复执行，跨重启保持决定与唯一活动槽位；主体删除和派生孤立追溯沿既有独立契约，不混用单条解除。
