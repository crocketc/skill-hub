# 产品定位与模型边界

> 2026-10-08：技能库内统一管理对象定名“技能主体”；使用关系的形式、管理责任、当前位置角色与历史来源分别表达。转入管理允许链接或维护同步的完整拷贝，共享目录按拷贝方式。当前关系边界见[关系体系与生命周期](关系体系与生命周期.md)，其明确修订优先于旧链接唯一终态表述；本轮未实施。

从原AGENTS.md迁出的已确认产品定位与模型约束。拆分只调整文档职责，不撤销规则。具体关系与主体动作契约按[产品规范索引](README.md)路由；实现状态见当前开发文档。

本软件以技能库统一管理技能主体的内容、版本、元数据与生命周期，尽量由技能库直接连接各 Agent／项目目标。支持链接的目标使用链接，只能复制的目标使用维护同步的完整拷贝；共享目录按完整拷贝方式。不能将主体称为“主副本”。该定位不代表自动接管所有目录，仍须遵守授权、识别、权限、内置只读、共享影响和原文件保护边界。

“已导入”是主体事实。关系形式、管理情况、健康、用户决定分开，治理分类为待处理／无需处理。保留独立拷贝后解除关系、进入历史；外部删除或替换只更新事实，不自动解除。当前完整关系契约见[关系体系与生命周期](关系体系与生命周期.md)。

导入不等于原位置已转入管理。转入管理先预览、确认、备份，建立链接或管理中的完整拷贝并核验后记账；失败保留或恢复原文件。不把复制成功冒充链接成功，也不将仅解除记录当作重复已消除。展示由统一 presenter 映射，保持悬浮与键盘说明一致。

编辑后创建新Skill须记录原主体/起始版本到新主体的上游“复用修改”关系，在统一模型和图谱可追溯，成功落账显示已完成/复用修改；不套用下游目标使用关系的未接管/已接管语义，不自动继承网络更新来源。派发继承仅替换继承/不继承，不提供复制继承；须执行真实目标操作与名称/所有权/共享影响核验，不能仅复制账目或以显示别名绕过同目标唯一名称。普通派发目标同名占用须预览阻断并说明，未建立关系的派发意图不生成虚构使用关系，也不使已有正常关系变异常。先确定操作模型，再决定抽屉和详情入口；内容/版本操作不在技能抽屉展示。

Skill主体操作与具体使用关系治理必须分别建模：主体的画像、内容/版本、更新来源、检查、试用、组合/导出和删除由对应主体流程负责；转入管理、链接修复、拷贝同步与解除使用关系由统一关系流程负责；主体侧回收技能编排同一流程。技能详情可提供具体关系快捷入口，派发可从技能发起创建关系，删除主体及新建替换继承可编排关系安全操作，但须共用同一权威事实、预览、执行与恢复，不能另建主体“已接管/待治理”状态或第二套关系动作。跨模块影响合并预览确认，不要求用户手工跑重复流程。复用修改保留独立上游追溯语义，网络更新仍归生命周期；主体试用/检查与各目标健康分别呈现。

本项目是技能（Skill）全生命周期管理软件，同时覆盖向 Agent 派发、向项目派发、回收及关系治理等全链路功能。整体产品以外包企业（乙方）的人力资源管理软件作为理解模型：

- **技能库**相当于乙方的岗位资源库。每个 Skill 相当于一个岗位，具有自己的画像、擅长领域（技能标签），并经历登记、注册、安全检查、培训（版本升级）、派发与回收等生命周期。
- **Agent 模块**相当于多个甲方企业。每个企业可配置多个岗位员工，按需要增加或删减岗位；在软件中对应 Skill 与 Agent 的派发和回收关系。
- **项目模块**相当于甲方企业中的具体项目，承接项目级技能配置、派发、回收和关系管理。

页面设计和交互应围绕资源画像、能力匹配、去向、当前状态和可执行操作展开，帮助用户理解技能从登记到使用、升级和回收的全过程。以上类比用于指导产品设计，不把未实现的人事业务引入范围，也不改变现有 Skill、Agent、项目及共享目录的实体身份、安全边界和数据契约；界面继续使用用户熟悉的技能、Agent、项目、派发与回收等名称。
