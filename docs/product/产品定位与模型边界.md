# 产品定位与模型边界

从原AGENTS.md迁出的已确认产品定位与模型约束。拆分只调整文档职责，不撤销规则。具体关系与主体动作契约按[产品规范索引](README.md)路由；实现状态见当前开发文档。

本软件的终极目标是由集中库统一管理本地所有 Skill 主体，Agent 与项目通过指向集中库的链接使用 Skill，目标目录最终只保留使用入口，不各自维护独立内容副本。集中库管理 Skill 的内容、版本、元数据及生命周期，不能将 Skill 主体称为“主副本”。该目标是产品演进方向，不代表所有本地目录已自动纳入管理或所有 Agent 已验证支持链接；实施仍须遵守明确授权、目标识别、兼容性、权限、内置只读、共享目录实体及源文件保护边界。

“已导入”是 Skill 主体事实，不是关系管理状态。当前使用关系的管理状态只有“未接管”“已接管”，前端分别展示为“待集中管理”“已集中管理”；关系治理最上层分“待处理”“已完成”，“全部”是汇总入口，下一层为管理状态，再下一层说明具体原因。明确保留独立副本且无新问题可完成治理，但不能冒充已接管；健康事实与用户处置决定分别记录。外部删除或替换入口只改变健康事实，不自动结束关系，必须明确回收或结束后进入历史。上游来源与版本升级属于 Skill 生命周期，操作失败与恢复属于执行/恢复模块，不新增为关系类型。

内容进入集中库不等于原 Agent/项目入口完成集中管理；原位置仍为独立副本时，必须明确提示待接管，并在关系治理中提醒和引导闭环。完成接管须以正确受管链接、验证后的目标事实及持久化关系为依据。前端通过统一 presenter 映射为用户可理解的名称，增加鼠标悬浮说明，并提供等价的键盘可访问说明；不得直接展示内部状态枚举。接管前先预览影响、确认、备份和验证，失败保留或恢复原文件，不静默覆盖、删除或以复制回退宣称链接接管完成。

编辑后创建新Skill须记录原主体/起始版本到新主体的上游“复用修改”关系，在统一模型和图谱可追溯，成功落账显示已完成/复用修改；不套用下游目标使用关系的未接管/已接管语义，不自动继承网络更新来源。派发继承仅替换继承/不继承，不提供复制继承；须执行真实目标操作与名称/所有权/共享影响核验，不能仅复制账目或以显示别名绕过同目标唯一名称。普通派发目标同名占用须预览阻断并说明，未建立关系的派发意图不生成虚构使用关系，也不使已有正常关系变异常。先确定操作模型，再决定抽屉和详情入口；内容/版本操作不在技能抽屉展示。

Skill主体操作与具体使用关系治理必须分别建模：主体的画像、内容/版本、更新来源、检查、试用、组合/导出和删除由对应主体流程负责；接管、保留/撤销、链接修复、回收/结束由统一关系流程负责。技能详情可提供具体关系快捷入口，派发可从技能发起创建关系，删除主体及新建替换继承可编排关系安全操作，但须共用同一权威事实、预览、执行与恢复，不能另建主体“已接管/待治理”状态或第二套关系动作。跨模块影响合并预览确认，不要求用户手工跑重复流程。复用修改保留独立上游追溯语义，网络更新仍归生命周期；主体试用/检查与各目标健康分别呈现。

本项目是技能（Skill）全生命周期管理软件，同时覆盖向 Agent 派发、向项目派发、回收及关系治理等全链路功能。整体产品以外包企业（乙方）的人力资源管理软件作为理解模型：

- **技能库**相当于乙方的岗位资源库。每个 Skill 相当于一个岗位，具有自己的画像、擅长领域（技能标签），并经历登记、注册、安全检查、培训（版本升级）、派发与回收等生命周期。
- **Agent 模块**相当于多个甲方企业。每个企业可配置多个岗位员工，按需要增加或删减岗位；在软件中对应 Skill 与 Agent 的派发和回收关系。
- **项目模块**相当于甲方企业中的具体项目，承接项目级技能配置、派发、回收和关系管理。

页面设计和交互应围绕资源画像、能力匹配、去向、当前状态和可执行操作展开，帮助用户理解技能从登记到使用、升级和回收的全过程。以上类比用于指导产品设计，不把未实现的人事业务引入范围，也不改变现有 Skill、Agent、项目及共享目录的实体身份、安全边界和数据契约；界面继续使用用户熟悉的技能、Agent、项目、派发与回收等名称。
