# 关系体系与生命周期

状态：2026-10-08 本轮关系术语与产品边界已确认并落库，未授权代码实施，未表示实现或验收完成。本文是关系定义、生命周期与跨模块边界的当前实施依据；与既有规范冲突时，以下明确修订的规则优先，未涉及规则继续有效。

阅读优先级：本轮后续补录见第十一节，其明确纠正的状态、目录及来源措辞优先于前文阶段性表述；旧“自有目录”统一理解为下方既有目录分类中的对应目录，不新增实体角色。

## 一、统一关系体系

“关系”是全软件总概念。同一事实在各模块、页面使用同一名称、解释和操作含义；各页面按职责选择展示，不要求全部关系出现。关系定义不以现有内部枚举数量为约束，旧“8 种关系、6 种连线、7 类状态”不再作为产品分类的固定结构。

| 关系名称 | 定义 | 自然展示句式 |
| --- | --- | --- |
| 使用关系 | Agent、项目或共享目录存在获取该技能的入口；不证明实际执行过技能 | 使用去向、可用技能；异常与限制须同时说明 |
| 导入来源 | 某次导入时内容从哪里取得，属于历史事实 | 导入自、导入位置、导入时间、导入版本 |
| 更新来源 | 当前从哪里检查和获取后续版本 | 更新来源 |
| 复用修改 | 新技能基于哪个技能的哪个版本创建；之后独立演变 | 基于、基于此技能创建的新技能 |
| 目录归属 | 技能文件或链接入口位于哪个目录 | 所在目录、目录内的技能／入口 |
| 目录识别 | 根据规则或配置，Agent／项目能够从哪个目录发现技能；不保证加载或执行 | 可识别的技能目录、能识别此目录的 Agent／项目 |

关系治理以使用关系为独立治理对象；目录归属、目录识别、来源与共享影响按需要作为背景，不生成重复治理条目。技能详情展示相关关系；Agent／项目详情展示使用、目录识别及位置；目录视图展示归属、识别与共享；图谱可按关系种类筛选展示全体系。冲突继续归冲突模型，不因图谱画线成为新增关系种类。

## 二、主体、形式与位置角色

“技能主体”是技能库内统一管理内容、版本、元数据与生命周期的技能。当前位置的文件实体、对应技能身份与位置角色分别表达。

同一位置可以同时承担使用关系和导入来源：前者维护当前使用事实，后者保存导入时事实。页面合并位置呈现，不合并两种语义；同一位置只计一条实际使用关系。

| 原位置处理 | 当前实体与角色 | 导入来源 |
| --- | --- | --- |
| 转为链接 | 原文件先备份，再由指向技能主体的链接替换；使用关系保留，形式改变 | 保留历史，说明原件已被替换 |
| 转为管理中的完整拷贝 | 可以保留完整文件目录，核对或同步内容；管理身份改变，不另造技能主体 | 保留历史 |
| 原文件被外部删除 | 使用关系登记入口缺失，不自动解除 | 保留历史，说明原件不存在 |

转换为派发入口后不再展示“技能原件”标识，需要追溯时查看导入记录。尚未转换的 Agent 目录原件仍说明原件与管理情况；内置只读原件保留“技能原件（只读）”。用户普通来源目录中的原件可展示，但不建立使用关系或产生转换待办；用户目录后来成为真实使用目录时按实际用途判定，不按路径名称分类。

“转入技能库管理”不再仅指改为链接：支持链接或 SkillHub 维护同步的完整拷贝。共享目录与技能库之间本轮按完整拷贝方式管理，不通过链接派发；Agent 实际仍读取共享目录当地文件，不能说成直接读取技能库。

## 三、关系属性、状态与核验

| 维度 | 定义 |
| --- | --- |
| 形式 | 链接／完整拷贝；拷贝派发后显示“完整拷贝 · 管理中” |
| 管理情况 | 管理中：SkillHub 承担维护入口和同步当前版本的责任；未管理：不承担维护责任 |
| 当前状态 | 按适用事实表达正常、入口缺失、链接异常、内容变化、待同步、同步失败等；不是固定七类 |
| 用户决定 | 与健康事实分开保存，包含解除及保留独立拷贝的决定 |
| 核验情况 | 自动核验结果直接呈现；待用户确认＝需要用户判断；无法核验说明具体限制；不设“待核验／正在检查”关系状态 |

管理中的拷贝同步失败仍为管理中，须显示未同步事实与重试入口。未管理的链接若指向技能主体也可能随内容变化，不能断言所有未管理入口均不跟随。“发现的”描述识别来源，不等于管理情况。

治理分类改为“待处理／无需处理”，“全部”为汇总入口；分类表示当前是否需要行动，不表示关系结束。“等你处理”“请选择使用内容”是行动提示，“原件保留（只读）”是来源与权限说明，不冒充健康状态。

“待用户确认”移出关系种类，具体指出技能对应、指向、管理归属等哪项需要用户判断。能确认的事实照常呈现；对象或文件影响未确定时不执行文件修改。来源信息不完整不应使正常使用关系整体成为异常。

## 四、共享目录与操作范围

当前只有一个共享目录对象；Agent 页面保留其独立卡片，用户可像操作 Agent 一样操作它。回收选择按“Agent／共享目录／项目”三组组织。共享是影响事实，目录识别是正式关系；共享目录的物理入口只治理、同步、回收一次。

真实 Agent／项目回收其对应可写目标目录中的派发关系；Agent 内置目录不执行回收。通过共享目录获得技能的 Agent 展示“通过共享目录使用”，该关系的回收指向共享目录对象；不能选择一个真实 Agent 却删除共享文件并暗中影响其他消费者。预览汇总全部真实消费者；图谱呈现“技能 → 共享目录 → Agent”路径，不复制成多条派发。

## 五、回收与解除使用关系

技能操作模型保留“回收技能”：用户选择 Agent／共享目录／项目，系统解析真实关系与目录。关系侧操作叫“解除使用关系”，针对当前关系；两者共用预览、执行与恢复流程。路径仅在区分入口、说明影响时辅助展示。

| 管理中的派发形式 | 解除结果 |
| --- | --- |
| 链接 | 删除目标位置链接，解除使用关系 |
| 完整拷贝 | 用户选择“保留为独立拷贝”或“同时移除拷贝”，随后解除使用关系；移除遵循备份、恢复要求 |
| 入口已缺失 | 只解除关系，说明无需处理文件 |

未管理关系可解除：只清理活动关系记录，不动原文件，说明 Agent 仍可能读取、SkillHub 不再跟踪。技能主体、其他使用关系、导入来源不受解除影响；其他关系种类不套用此操作。

保留独立拷贝后当前使用关系进入历史，不再作为活动关系中的“无需处理”条目；保留决定与结果留痕。再次希望管理时用“转入技能库管理”，重新核验后建立管理关系；取消独立“撤销保留”入口，不自动恢复旧关系。

Agent 内置只读原件没有经过派发，也不是“已保留独立拷贝”。不改文件、不转换、不参与派发清理或回收；使用事实与导入来源可展示，技能库主体可独立编辑、版本化并派发到可写目录。

## 六、扫描、导入与解除决定联动

解除决定针对某技能的具体入口，不排除整个 Agent 目录，不影响其他技能。系统须结合身份与入口核验，不能只按截断路径或显示名称匹配。

| 再次发现 | 处理 |
| --- | --- |
| 同技能、同入口未变化 | 不恢复活动关系、不重复生成治理待办；候选标“曾解除使用关系”，默认不勾选 |
| 原入口内容变化 | 标“曾解除，内容已变化”，仍默认不勾选，用户决定重新导入或管理 |
| 原入口换成另一个技能 | 新发现，不继承旧技能解除决定 |
| 同技能出现在新位置 | 新使用事实，不继承其他入口的决定 |
| 明确重新派发或转入管理 | 核验成功后建立管理关系，保留旧历史 |

扫描继续保留真实发现结果；导入候选可按“曾解除使用关系”分类，并说明是否已保留独立拷贝。用户可以重新勾选导入；导入本身不撤销解除、不自动恢复管理，转入管理单独确认。外部变化更新事实，不替用户撤销决定。

未管理、已确认对应技能主体且位于使用目录、尚无用户决定的使用关系进入待处理；曾解除或明确保留不重复催促转换。普通来源目录不产生使用关系待办；内置只读原件健康时无需处理，异常按权限边界说明。

代码核实：现行治理通常将未接管且无保留决定的台账关系列为 pending；健康导入原件及保留项有 completed 例外。发现页已有确认后写精确路径忽略规则、当前页面隐藏；候选支持勾选／全选，冲突支持本次跳过。未核实到精确路径排除在扫描／导入中的完整消费链；候选展示尚无上述解除历史分类。以上为静态阅读事实，不代表新联动已经实现。

## 七、来源边界

导入来源保存某次取得内容时的位置、版本、时间等真实证据；更新来源可关联、更换、解除。同一对象可以同时承担两种关系，改变更新来源不改写导入来源。解除更新来源不删除技能内容。

统一操作句式：关联更新来源／更换更新来源／解除更新来源／检查更新。本地目录可为导入来源；能否成为更新来源须实际契约支持，记录路径不代表具备自动更新能力。

## 八、统计视角

| 视角 | 口径 |
| --- | --- |
| 单个真实 Agent 技能数 | 包含其已确认可识别的自有、共享、内置只读及其他配置目录；例如“技能 8 条，其中共享目录 2 条、内置目录 3 条” |
| 共享目录技能数 | 独立展示其目录技能数 |
| Agent 对象统计 | 包含共享目录对象，单独说明；例如“3 个，其中 1 个为共享目录” |
| 项目对象 | 与 Agent 分开统计和展示 |
| 使用关系数 | 按实际入口，共享入口仅计一次；一个 Agent 多个入口可有多条关系 |
| 技能主体数 | 按技能库主体，不因多次派发或多个消费者增加 |
| 共享消费者 | 单独说明，不能重复当作物理使用关系 |

同一技能计入不同 Agent 各自数量是合理的；各 Agent 数量相加只能称按 Agent 累计数量，不冒充全局技能总数。统计表达可发现／可获取，不保证实际执行。概览必须明确每项统计视角，涉及的 Agent 汇总若包含直接使用与共享消费者须去重。

## 十、多目录重复与重名治理（2026-10-08 后续确认）

### 发现范围与归属

判定单位是具体 Agent 使用环境：Agent 自身，或“Agent × 项目”。联合检查该环境可识别的自有、共享、内置、项目及其他已确认目录；项目内不同 Agent 的目录不能全部混合判断。目录规则及平台证据统一维护在[Agent 平台兼容性调研](../Agent平台兼容性调研.md)，适配器实际覆盖与调研结论分别核实，不把目录存在推定为实际加载。

同一环境中，同一技能或重名技能存在多个实际入口就进入待处理，暂不考虑目录优先级。内容一致按“同一技能”，名字相同、内容不同按“重名”。同一物理入口被多路径／重复扫描识别不算多个入口；多个 Agent 共用同一共享入口也不算该异常。

前端标题用“同一技能出现在多个目录”或“多个目录中存在重名技能”，列明 Agent／项目、目录角色和内容事实，不用“多入口／多技能入口”，不宣称实际发生加载冲突。

关系治理持续发现和跟踪事实，需要选择时进入共用冲突处置流程，结果回写关系事实；只形成一个待处理事项，不由两个模块重复建待办。Agent、项目页面均可进入同一问题，技能详情展示关联影响。既存异常发现是新增场景，不能声称现有导入／派发冲突流程已覆盖。

### 同一技能的治理完成条件

目标是尽量减少重复，不以保留多份为常规完成方式。有内容一致的内置项时保留只读内置技能，解除并清理自有／项目目录重复项；没有内置项时由用户选择保留位置。内置与用户内容不同则归重名，不能因内置同名就默认删除用户内容。

闭环顺序：列出全部事实与共享影响 → 确定保留方式 → 备份并安全处理冗余链接／完整拷贝 → 重新扫描受影响环境。只在重复实际消除后归无需处理。只解除记录、完整拷贝仍留在可识别目录时不算完成；希望保留文件可保存到该环境不会识别的目录，需核验范围。未管理文件清理必须明确授权；取消、权限失败或仍重复继续待处理，不自动修改用户文件。

该异常的完成条件优先于第六节“不重复催促已解除关系”的一般规则：解除历史保留，但不能据此隐藏仍存在的多目录重复／重名事实。

### 共享目录重复的迁移闭环

优先由技能库直连各目标。列出共享技能全部消费者：有同一内置技能的保留内置项；仍依赖共享项的 Agent／项目从技能主体直接派发，支持链接用链接，只能复制用管理中的完整拷贝，已有正常直连关系复用。

先建立并核验全部替代使用方式，再备份并移除共享目录中的该技能、解除对应关系，最后复查所有受影响环境。任一目标失败、消费者范围未知或出现待处置重名时保留共享项，继续待处理；共享目录对象及其他技能保留。临时同时存在新旧入口不能提前记为治理完成。

### 重名改名与影响范围

改名要修改技能文件 `SKILL.md` 的 `name`，不能只改展示名称；目标文件夹名称是否同步按 Agent 命名规则核实。管理中的派发不能只在目标拷贝私自改名，否则后续同步会覆盖并偏离技能主体。

| 用户选择 | 结果与推荐 |
| --- | --- |
| 仅调整这些 Agent／项目 | 默认推荐：另存新技能主体、设置新运行名称，替换本次所选目标的使用关系，原主体与其他关系保留 |
| 修改技能主体，应用到所有使用目标 | 修改原主体运行名称、形成新版本，预览全部影响并同步管理中的目标 |

原主体仅用于本次涉及目标时，推荐直接修改主体，避免无必要的新主体。确认页说明 `name` 修改、新主体是否创建及全部受影响对象。用户未管理文件须明确选择转入管理或授权修改原文件；内置技能不改。重新扫描确认重名消除才闭环。

另存新技能必须建立“复用修改”关系，记录原技能及起始版本；新旧主体此后独立维护，不自动同步，新主体不自动继承更新来源。创建主体、追溯建档、所选目标派发替换需原子或可恢复，失败不报告完成。

### 实施与未决边界

本节仅已确认产品规则，未改代码或执行新行为验证。仍需核实使用环境集合、身份及物理入口归并、全消费者覆盖、共享迁移失败恢复、运行名称与目录规则、改名及复用修改真实契约；技能数去重与来源贡献统计、英文词面等继续讨论。目录优先级调研仍保留，但不阻塞本轮多目录治理判定。

## 十一、展示、状态、来源与目录最终补充

### 统计及待处理导航

治理前保留实际发现项数，单独说明重复／重名问题，不用数字去重掩盖异常；同一物理入口重复扫描不重复计数。例如“发现技能 8 项，其中共享目录 2 项、内置目录 3 项；待处理：1 组同一技能、1 组重名技能”。治理后重新扫描更新数量；技能主体数独立统计。

待处理按问题组计数，不按涉及文件或关系条数累计；同一问题跨页面只形成一条待办。同一共享问题汇总所有受影响 Agent／项目环境，内部逐环境记录结果，全部闭环后才关闭。

概览、Agent、项目、技能详情与待处理工作台携带准确使用环境（Agent，必要时加项目）、问题组及相关对象跳转关系治理并直接定位。进入后重新核验、展示完整问题与共享消费者，再进入共用处置流程；不能只显示点击项局部。已解决说明已解决，范围变化重新展示与预览，不按旧上下文执行。

### 状态词

| 用户用词 | 含义 |
| --- | --- |
| 正常 | 已核验符合关系预期，不证明实际执行 |
| 文件缺失 | 应存在的文件／目录不存在；按对象说明技能文件或技能原件缺失 |
| 链接异常 | 未正确指向预期对象 |
| 内容变化 | 偏离位置预期基线；管理拷贝对照应同步版本，原件对照导入存证 |
| 待同步 | 管理中的完整拷贝尚未同步当前主体版本 |
| 同步失败 | 已尝试同步而失败，管理责任保留 |
| 无法核验 | 权限或访问等限制使事实无法确定，说明原因与下一步 |
| 待用户确认 | 已有事实仍需要用户选择，不等同于自动检查尚未完成 |

核验是自动系统行为，不新增“待核验／正在检查”前端关系状态。首次结果未返回沿用页面加载反馈，不标正常；确有长任务且契约提供进度时使用统一异步反馈，进度不是关系状态。多异常保留完整事实，摘要优先说明操作影响。

更新来源适用“有新版／当前版本已是最新／无法检查更新”，检查成功才可说最新。未管理文件或原件停留旧版本符合预期时，不仅因与主体不同就报内容变化。多目录重复／重名为治理问题；内容选择为行动提示；已解除／已保留为独立拷贝为历史结果。

### 来源记录和文件形式

导入来源针对技能主体，是登记追溯，不套回收／解除使用关系；更新来源为可关联、更换、解除的当前关联。“由 SkillHub 派发”仅为使用关系建立记录，不作为技能来源分类。目标文件展示对应技能主体与建立记录；扫描发现位置不能推定内容来源。

关系行形式只展示“链接／完整拷贝”，符号链接、目录联接放技术详情。此前候选“无法识别文件形式”及新来源分类列表未获最终确认，不作为新增已定稿分类执行；须以真实核验事实说明，不自动要求用户判断。

### 沿用既有目录角色裁定

| 普通 Agent 目录角色 | 含义 | 既定徽标 |
| --- | --- | --- |
| Agent 内置目录 | Agent 自带，随软件更新；v0.2.0 只读、不可派发 | 琥珀色“内置” |
| Agent 用户目录 | 用户范围内技能目录，按实际文件权限读写 | 蓝色“用户” |
| Agent 工作区目录 | Agent 工作空间内技能目录，包括既有 profile 的 project scope 路径 | 紫色“工作区” |

共享目录是独立目录实体和卡片语义，不属于三种角色，不因用户／工作区差异重复成卡；是否支持共享目录是独立能力维度。项目目录属于独立注册 Project 模型，不作为 Agent 卡片，不与 Agent 工作区混同。

Hermes 的 `{project_root}/.hermes/skills`、OpenClaw 的 `{project_root}/skills` 归工作区；不能因 scope 为 project 排除，也不能因路径含 workspace 归内置。使用环境按真实识别关系确定，不能据 scope 自动生成 Project 身份。

不新增“用户来源目录／空间目录／Agent 自有目录”正式角色。普通文件夹导入在来源记录中显示“导入位置”与原件现状，不自动成为使用对象；是否另属 Agent／Project／共享目录按真实识别关系判断。

### 收口进度

中文核心定义已确认；用户授权英文由维护者按中文含义统一，当前英文见术语总表。旧八种关系、七类状态和操作表已重写，旧来源／技术枚举不再直接充当产品分类。后续发现具体契约遗漏继续核对，不代表实现与验证已完成。

## 十二、旧七类覆盖核对与保留细则

以下按讨论前业务模型正文核对；已替代规则不继续执行，未改动的保护和恢复要求明确保留。

| 原七类 | 当前对应 | 覆盖结论 |
| --- | --- | --- |
| 正常受管链接 | 使用关系＋链接＋管理中＋正常；完整拷贝另有同步事实 | 保留并扩展形式，不只覆盖链接 |
| 明确保留且无新异常 | 解除后独立拷贝与决定进入历史，扫描尊重决定 | 替代旧活动关系保留及撤销；实际重复优先治理 |
| 尚未作决定 | 未管理、待处理，需要选择时待用户确认 | 保留；退出或稍后处理不等于完成 |
| 两边内容不同 | 内容变化与内容选择、转入管理或同步 | 保留；不把保留旧版的预期行为误报异常 |
| 原独立文件缺失 | 文件缺失、恢复使用方式或解除使用关系 | 保留；不自动结束记录 |
| 已接管但链接异常 | 链接异常、修复或解除；外部文件占用须核对备份 | 保留；拷贝异常另有内容变化／同步失败 |
| 只读目录技能原件 | 原件／来源、只读及当前使用事实；健康无需处理 | 保留保护边界，不与退出管理的独立拷贝混同 |

### 内容选择及全目标影响

转入管理时原位置与主体内容不同，保留旧二选一契约：以技能库当前内容为准（推荐），或以原位置内容为准。选择原位置内容须先保存为主体版本，保留原主体版本和检查依据，然后执行管理转换。因为改变主体当前版本，其他管理中的目标会跟随，必须一次汇总预览；不能让用户以为只改变这一处。重名局部另存主体的流程归第十节，不等同于这里改原主体内容。

链接直接指向主体、完整拷贝实际同步，执行失败分别报告，不伪称全目标已更新。版本采用／恢复不自动结束或重建正常使用关系；更新来源、试用和检查状态与关系健康保持独立。

### 缺失、外部替换与恢复

文件缺失保留恢复使用与解除两条路径；恢复按目录真实能力建立链接或完整拷贝，先核验目标身份、权限及重名，不自动重建。已有链接被普通文件替换时不直接覆盖，先选择内容并备份，再修复。外部删除／替换只更新事实；恢复经核验后回到正常，不自动抹除历史。

无法核验不当作已确认文件缺失；动作受限须说明原因、如何解除限制和重新核验路径。未知目标、只读限制或不满足安全条件的修改动作不能提交。

### 只读原件异常与上游追溯

只读原件按导入存证核对：主体升级而原件停在旧版本不是异常，原件本身变化或缺失才更新事实。异常时保留重新检查和明确解除记录的出口；解除只动记录、不动内置文件，扫描尊重决定，但多目录治理不因此隐藏实际重复。普通导入来源是历史记录，不能用解除使用关系删除导入事实。

复用修改不产生接管待办。原技能删除后新技能与使用关系保留，追溯说明原技能已删除，不保留已删正文；新技能删除不自动重新派发原技能。

### 确认、失败与恢复通用要求

预览后文件、主体版本、目标身份、关系或共享消费者变化，旧预览失效，重新汇总并确认。一次明确意图一次必要确认，内部备份／执行／核验步骤不逐项确认。

取消不修改事实；失败保留或恢复原文件，核验恢复成功后才报告已恢复。恢复未确认则进入恢复流程，不伪装成新的关系种类或已完成。批量逐项记录成功、失败和仍需处理，部分成功不关闭全部问题。共享迁移先核验替代关系后清原项；重复／重名问题只在实际消除后关闭。

主体删除沿用业务模型第三节的独立汇总确认与级联规则，不要求先逐条回收，也不因单条解除的拷贝选项改变主体删除默认保留原件／拷贝的裁决。

覆盖结论：旧七类的基本场景均有对应，新模型明确替代了保留仍活动、撤销保留、链接唯一终态和解除一律不动文件。以上为规范覆盖核对，不表示现有代码已支持，也不表示所有跨模块契约已核验完毕。
