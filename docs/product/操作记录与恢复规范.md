# 操作记录与恢复规范

本文规定操作日志、准备阶段与恢复入口的共同边界。操作记录用于追踪真实写入及其中断；只有可能留下需要处理的外部状态时，才要求用户先进入恢复流程。

## 准备阶段

`prepared`（已准备）表示操作正在展示预览和收集决定。它可以写入操作日志、影响快照或检查观察值，但不得据此认定 Skill 内容、文件路径、使用关系或版本指针已经发生变更。真正写入前必须先持久化 `applying`（执行中）检查点。

| 操作种类 | 准备阶段持久化内容 | 准备阶段对 Skill 文件、目标路径、关系和版本指针的影响 | 重启后的处理 |
| --- | --- | --- | --- |
| `import_skill` | 导入候选名、安全报告及操作日志；版本捕获阶段只新增未引用的不可变版本对象和清单 | 捕获成功后，先持久化新主体事实、目标版本 ID/树指纹、可移植记录及专属备份路径为 `applying`（执行中）检查点；检查点前不新增目录主体或活动消费面 | 仅 `prepared`（已准备）阶段安全结算；检查点后仅在快照、目录、指针、可移植记录和版本清单均核验通过时提供“撤销”，否则保留恢复门禁 |
| `deploy_skill` | 派发预览及会话内计划 | 无 | 结算为 `rolled_back`；重新预览目标 |
| `delete_skill` | 删除影响快照及操作日志 | 无 | 结算为 `rolled_back`；重新确认影响 |
| `undeploy_skill` | 解除派发影响快照及操作日志 | 无 | 结算为 `rolled_back`；重新确认影响 |
| `save_search_candidates` | 搜索结果页及 `planned`（已计划）操作日志 | 候选页写入和 `committed`（已完成）日志在同一数据库事务提交 | 写入事务中断或日志失败时整体回滚，候选不留部分记录 |
| `confirm_search_candidate`、`dismiss_search_candidate` | 候选状态变更请求及 `planned`（已计划）操作日志 | 候选状态和对应终态操作日志在同一数据库事务提交 | 状态与日志一起提交或一起回滚；此前的候选状态保留 |
| `reconcile_collect_changes` | 只读预检、派发目录内容捕获及 `prepared` 日志；捕获仅新增不可变版本对象和清单 | `prepared` 阶段不改数据库版本表、部署/关系事实；版本登记、部署事实和 `committed` 日志在同一数据库事务提交 | 中断或提交失败时安全结算；提交失败则数据库事实整体回滚，未引用版本清单纳入残留核查 |
| `reconcile_ignore_external_change` | 只读预检、目标观察及 `prepared` 日志 | 有目标观察值时，部署观察指纹、关系观察事实与 `committed` 日志在同一数据库事务提交；目标缺失时，在事务内重核部署事实后只结算日志 | 中断或提交失败时安全结算；数据库事实和终态日志一并回滚，不进入恢复候选 |
| `reconcile_restore_deployment` | 只读预检；目标替换前持久化部署事实、目标根身份、原目标身份/内容指纹和专属备份路径 | `prepared` 阶段不改部署目标；首次移动目标前写入 `applying` 检查点 | 仅有 `prepared` 记录时安全结算；检查点后按目标与备份事实继续完成，漂移时保留恢复门禁 |
| `migrate_original` | 原目录迁移计划及会话内状态 | 无 | 结算为 `rolled_back`；重新预览 |
| `prepare_source_update` | 上游候选观察、预览事实和确认指纹 | 不替换文件、不切换版本或关系；候选观察仅供更新状态展示 | 结算为 `rolled_back`；重新检查来源 |
| `commit_source_update` | 上游候选确认事实及旧消费面快照；捕获期间只新增不可变版本 | 目标版本身份、树指纹和可移植目标记录持久化为 `applying` 检查点后，才改变可见树、版本指针或来源状态 | 捕获期 `prepared` 可安全结算；检查点后仅在旧/目标消费面与备份均核验通过时提供“撤销” |
| `set_current_version` | 版本采用影响快照、备份目标路径及确认指纹 | 不创建备份、不替换可见目录、不切换任何版本指针 | 结算为 `rolled_back`；重新预览版本 |
| `create_skill` | 新 Skill 快照及采用前事实；目标版本身份确认前仅捕获不可变版本 | 可写入未引用版本对象和清单；不新增目录主体、指针或可移植记录 | 安全结算准备阶段；目标身份检查点后，按快照撤销新主体和目标版本 |
| `save_skill_content`、`save_markdown_content` | 旧消费面快照；目标版本身份确认前仅捕获不可变版本对象 | 可写入尚未被任何消费面引用的版本对象和版本清单；不切换指针、可见目录或可移植记录 | 结算为 `rolled_back`，不阻断启动；目标身份检查点前退出可能留下未被当前指针引用的版本清单，纳入版本残留核查 |
| `save_as_copy_replacement_preview` | 替换目标、共享消费者和确认指纹 | 无 | 结算为 `rolled_back`；重新预览 |
| `standard_export` | 导出选择、授权目标与确认指纹 | 不创建导出产物 | 结算为 `rolled_back`；重新预览 |
| `usage_release` | 关系影响、文件指纹和恢复计划 | 无 | 结算为 `rolled_back`；重新预览 |
| `subject_runtime_rename` | 主体改名计划和原始事实快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_derived_rename` | 派生主体替换计划及另存副本子操作引用 | 仅准备记录可结算为 `rolled_back`；进入 `applying` 后由子操作恢复规则处理 |
| `managed_usage_change` | 受管关系变更计划和影响快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_manage` | 关系迁移预览及校验快照 | 无；写入从 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |
| `usage_manage_batch` | 批量关系处置计划和逐项事实 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_duplicate_cleanup` | 重复关系清理计划和恢复快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `shared_usage_migration` | 共享关系迁移计划、目标快照及子操作引用 | 无；目标替换从 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |
| `migrate_relation` | 单条关系迁移计划、来源关系快照和备份路径 | 无；目标创建、来源改动从 `applying` 检查点后开始 | 检查点前失败以失败结果结算，不建恢复候选；检查点后按恢复日志处理。仅有准备记录时重新预览 |
| `relation_governance_batch` | 批次决定、逐项结果和子操作引用 | 无；子项写入各自在 `applying` 检查点后开始 | 仅有准备记录时结算为 `rolled_back`；提交或回滚尝试结束后，父记录保存最终逐项结果并结算为 `committed`。需要恢复的子项独立保留恢复候选，不重复拦截父批次 |

以上是当前已核实的可安全放弃准备种类。启动门禁、恢复候选、健康检查和启动清扫必须使用同一份分类。已知准备预览不阻断其他操作，也不出现在待恢复列表；未知种类不得自动清理，必须保留恢复闸门并展示该记录，但不提供未经该种类实现验证的通用“完成/回滚”动作。

## 真正写入与中断

- `applying`、`verifying` 和 `needs_recovery`（需要恢复）表示操作可能已经改变文件、关系或版本事实；启动时不得只改为已完成/已回滚来冒充恢复。
- `migrate_relation`（关系迁移）在首次文件写入检查点前完成关系事实、来源指纹、目标路径和权限核验；这之前的失败保留可读失败结果，但不创建 `OperationFailureRecovery`（操作失败恢复）任务、不进入恢复候选。检查点后失败仍依完整恢复日志保留恢复闸门。已提交结果证明发生过写入；兼容旧日志时，即使其阶段误记为 `prepared`，回滚仍按已写入操作处理。
- `relation_governance_batch`（关系治理批次）是逐条子操作的编排摘要。批次最终结果写入后父记录不再单独构成恢复闸门；若某个子操作仍处于 `needs_recovery`，恢复中心保留该子项及其已验证动作。
- `usage_derived_rename`（派生改名）由父操作记录用户请求结果，`save_markdown_as_copy`（另存副本）子操作负责目标文件和替换恢复。子操作处于恢复闸门时，父项不重复显示恢复动作；子操作已提交且其终态逐项结果可由操作记录核对时，父项允许根据该收据补齐结果并结算，不再重复执行文件操作。子项缺失、日志损坏或收据不一致时不提供动作，继续保留恢复闸门。子项收据仅保存技能/版本标识和逐项目标结果，不保存 Markdown 正文。
- 开始每项外部写入前，必须保存该操作所需的恢复事实。恢复动作必须检查实际目标及前置条件，执行该种类对应的补偿或继续流程，并核验结果后才能结算。
- 恢复页逐条读取候选声明的动作；“继续完成”和“撤销未完成改动”使用不同命令及结果说明。后端未实现经过验证的恢复方式时不显示通用动作，也不允许仅修改日志阶段来结算。
- 未知阶段、未知操作种类、损坏或不完整恢复材料均按需要恢复处理。没有经过验证的安全动作时保留详情与闸门，不猜测性删除文件或变更关系。
- `deploy_skill`（派发技能）回滚仅处理日志记录的残留项：恢复材料须含已登记目标根的物理身份、运行名、模式和派发条目身份；路径必须是该根目录下与运行名完全对应的直接子项。候选展示前核验注册根和现存条目身份；执行时先核验全部目标，再在每次删除前复核根与条目身份。条目已不存在可按幂等方式结算；身份缺失、路径越界、条目被替换或注册根变化时隐藏动作并保留恢复闸门。
- `subject_runtime_rename`（主体运行名改名）的恢复日志必须记录本次新建目标条目身份。继续改名或撤销时，只有条目类型、物理身份和预期内容指纹都匹配，才可继续操作或移除；缺少身份的旧日志或身份变化时保留恢复闸门，不按路径名删除。
- `managed_usage_change`（受管关系变更）的失败补偿只移除本次派发创建且身份仍匹配的目标条目，再按已验证备份恢复原条目。新日志保存执行前的部署与关系事实；中断记录只有在尚无逐项结果、无备份/新建条目检查点，且磁盘条目、部署记录和关系事实均与完整快照一致时，才可提供“撤销”并仅结算操作日志。恢复执行时重新核验全部快照并与同类变更串行。旧日志、快照缺失、事实漂移或条目身份不可核验时，不按路径名删除或覆盖，保留恢复闸门并进入人工处置。Windows 符号链接和目录联接点按链接自身的重解析点身份核验；旧日志若只保存链接目标身份，不能据此推断链接本身未被替换。
- `save_markdown_as_copy`（另存副本）替换继承出现部分失败时，若成功项已提交、失败项未写入，或失败项的补偿已验证恢复原状态，则保存逐项结果并将本次操作结算为 `committed`（已完成），不触发全局恢复闸门；仅文件、关系或数据库事实无法核实时保留恢复闸门。
- `save_markdown_as_copy` 在逐项目录替换前先持久化副本版本、完整目标事实和目标计划；每个目标改动前记录原部署/所有权快照及操作专属备份路径，并在替换后记录新部署/所有权快照。重启后仅当已开始写入的目标之来源版本、目标根、部署事实和文件所有权均与检查点吻合时提供“继续完成”：只发现原目录备份时先恢复并核验原目录，再将该目标记为失败；新目录已安装时核验新树和数据库，补齐记账并幂等写入继承历史，再清理已验证备份。未开始或预检阻塞的目标不会改文件，结算为失败且不应挡住其他目标安全恢复；已完成目标保留结果。已开始写入目标的内容/路径漂移、恢复材料缺失或权限错误不猜测处理，保留恢复闸门。
- `set_current_version`（采用版本）在 `applying` 检查点后中断时，恢复页只对可由持久化快照完全核验的状态提供“撤销”：版本库指针和数据库指针各自必须指向采用前版本或本次目标版本；可移植记录必须与采用前记录完全一致，或只将 `current_version` 改为本次目标；可见目录必须是采用前树、本次目标树，或在可信旧树备份存在时缺失。旧树备份必须位于本次操作的预定内部路径且内容指纹匹配。若应用启动时按旧指针重建了旧可见目录，且该目录与备份均匹配采用前指纹，恢复先将已验证的重复备份原子移出本次操作路径，再清理该目录；执行前还要核验派生隔离路径不存在，若路径已占用则隐藏“撤销”并保留闸门。清理中断后，仍以旧树指纹匹配的可见目录完成重试，隔离目录只有仍匹配旧树时才尽力清理，残余清理失败不阻断恢复。版本采用与恢复共享串行锁，恢复取得锁后重新读取操作阶段；只有 `applying` 或 `needs_recovery` 可补偿，已提交操作不得被旧记录撤销。恢复执行后再次核验四个消费面均恢复到快照且操作备份路径已消失，才结算为 `rolled_back`（已撤销）。恢复失败保留 `needs_recovery`（需要恢复）并允许重试；指针、元数据、目录、备份或快照出现其他漂移时隐藏动作并保留闸门。
- `create_skill`（新建技能）在目标版本捕获期间保持 `prepared`（已准备）；目标版本 ID、树指纹和目标可移植记录持久化为 `applying`（执行中）检查点后，才新增技能主体或修改活动消费面。新建技能的恢复快照保存主体事实，因此即使补偿已删除目录行，重启后仍能核对并撤销本次新增目录、指针、可移植记录及版本清单。目标清单仅在所有消费面恢复并验证后清理；目录补偿失败时保留版本清单和可执行恢复动作。旧版缺少目标身份的日志不提供自动动作并保留恢复闸门。
- `import_skill`（导入技能）对新建主体采用与 `create_skill` 相同的捕获边界和恢复快照：版本捕获成功后，先保存新主体事实、目标版本、树指纹、可移植目标记录和操作专属备份路径，再写入目录主体、版本指针与可见树。最终提交时，来源存证、批次结果、来源/观察关系、治理待办、冲突组和 `committed`（已完成）操作日志在同一数据库事务中写入；任一步失败都会一起回滚，操作仍保留 `applying`（执行中）检查点供补偿。`Skip`（跳过）将跳过结果、治理待办与终态日志原子提交；复用已有主体将来源存证、批次成功结果、来源关系、治理待办、冲突组与终态日志原子提交。重启只能看到整组结果已提交或未提交，不留下互相矛盾的成功标记。新建主体重启后只有主体与各消费面均处于快照允许的旧/目标状态、目标版本内容匹配且备份路径未被替换时提供“撤销”；主体删除会一并撤销本次导入的关系、批次、存证及检查记录。仅能核实部分事实、发生内容漂移或恢复材料缺失时不自动删除，继续保留恢复门禁。旧版缺少目标身份的导入日志不提供自动动作。
- `commit_source_update`（提交上游更新）与内容保存共用捕获边界：捕获期间保持 `prepared`（已准备），目标版本 ID、树指纹及目标可移植记录先持久化为 `applying`（执行中）检查点，再替换可见树或切换消费面。恢复中心只提供已经通过同一内容采用快照校验的“撤销”；上游来源状态在成功提交后更新。目标检查点前中断不会阻断启动，已落盘但未引用的版本清单仍须由残留核查识别。
- `save_skill_content`（保存技能内容）和 `save_markdown_content`（保存 Markdown 内容）在捕获目标版本期间保持 `prepared`（已准备）：捕获只能增加未引用的不可变版本对象和清单，不改变当前指针、可见目录、可移植记录或数据库指针，因此中断后可安全结算且不阻断启动。目标版本 ID、树指纹、是否由本次新建及可移植目标记录持久化为 `applying`（执行中）检查点后，才允许替换可见目录或切换消费面。重启后只在技能身份、旧/目标指针、旧/目标可移植记录、可见树及操作专属备份均与快照匹配时提供“撤销”；先恢复并核验旧目录及所有消费面，再移除本次新建且指纹匹配的目标版本清单。旧目录原本缺失时，只能删除指纹与目标版本完全一致的可见目录；内容漂移、备份被改动或旧日志缺少目标身份时隐藏动作并保留恢复门禁。若进程在目标检查点前退出且版本清单已落盘，未引用清单可能留存，不能将其当作当前版本。
- 操作详情按稳定操作标识读取完整持久化记录；首页最近操作摘要只用于展示，不能作为恢复数据源。
- 关系迁移只有在日志中保存且能解析为 `PreparedRelationMigration`（已准备的关系迁移）恢复事实时，才允许从恢复中心执行“撤销”；该动作调用关系迁移自身的回滚校验流程。记录不完整或事实不符时继续保留恢复门禁，不提供通用处置。
- `shared_usage_migration`（共享关系迁移）在重启后只允许通过应用层专用续做流程“继续完成”。恢复候选必须处于 `needs_recovery`（需要恢复），且操作标识、操作类型、准备结果和迁移预览均可从完整日志核验；日志不完整或损坏时保留候选和恢复闸门，不提供自动动作。续做逐项复核替代关系，全部替代目标确认后才移除共享源；任何子操作或复核失败均保留恢复状态。
- `delete_skill`（删除技能）已确认删除决定并开始写入后，只允许恢复中心“继续完成”，不提供伪造回滚。仅当影响快照、逐关系决定、已完成/待处理分区及安全运行名均完整一致时才声明该动作；恢复时逐项重核关系身份、目标目录物理身份和文件所有权。已经删除的目标或结算过的关系不重放；身份漂移、事实缺失、共享删除确认不足或中央技能状态不一致时保留恢复门禁并隐藏动作。中央可见目录、版本清单、portable（可移植）元数据、主体目录投影和草稿采用稳定操作备份名并按幂等步骤续做；存在未完成删除时启动不执行写权限探测，也不从不完整版本清单重建可见目录，让恢复页面先打开。
- `undeploy_skill`（解除派发）在用户决定后，先重新核对完整影响快照；“取消”或目标所有权预检失败不会推进到 `applying`（执行中）。真正写入前保存用户决定、待处理关系和目标项物理身份。恢复中心只对安全运行名及关系身份匹配的记录提供“继续完成”；目标根仍存在时其物理身份须匹配，目标项仍存在时还须通过所有权核验；目标根或目标项已不存在时可只对账关系。被替换的目标、所有权变化或不完整事实隐藏恢复动作并保留门禁，绝不按路径名删除后来出现的文件。正常操作拼接目标路径前也校验数据库中的运行名，避免损坏记录指向已登记目标根之外。
- `reconcile_restore_deployment`（恢复受管派发）在只读预检阶段记为 `prepared`（已准备），启动时可安全结算；目标替换前保存原部署事实、目标根身份、原目标物理身份/内容指纹及同级唯一备份路径。原目标先原子移入备份，再安装目标版本并更新观察指纹。重启后仅当目标根、部署事实和当前目标/备份身份与指纹可核验时提供“继续完成”；恢复会补装目标版本、更新数据库并清理已验证备份。目标漂移、备份缺失或材料损坏时不自动覆盖或删除，并保留恢复门禁。
- `reconcile_collect_changes`（收集派发后的修改）在读取和捕获阶段保持安全 `prepared`（已准备）；捕获的新版本对象可能在数据库提交失败时成为未引用清单。成功提交时，版本登记、部署版本/指纹、关系观察事实与 `committed`（已完成）日志必须在同一数据库事务内完成。事务失败则这些数据库事实全部回滚，操作结算为 `rolled_back`（已撤销），不进入恢复候选。
- `reconcile_ignore_external_change`（忽略派发后的外部变更）只记录当前观察结果，不改已选版本。目标存在时，部署观察指纹、关系观察事实和 `committed`（已完成）日志必须同事务提交；目标缺失时在事务内再次核对部署版本事实后结算日志。数据库提交失败时观察事实和终态日志一起回滚，操作安全结算，不留下恢复拦截。
- 搜索候选的保存、确认和移除在一个 SQLite（轻量数据库）事务中提交候选数据与操作终态。操作开始记录仍处于 `planned`（已计划）时，事务提交失败会整体回滚；进程中断后启动清扫可安全结算未提交的计划，不会出现候选已变更却日志记为已撤销。

## 当前实施边界

已知 `prepared` 种类表由 `skillhub-core` 的统一策略维护，产品文档同步说明每种准备内容及其写入边界。恢复候选的已知操作种类登记也由核心策略维护；未知种类保留记录和恢复闸门，不提供未经验证的通用处置动作。被登记为已知只确认操作来源，不代表其恢复动作已经逐种核验；具体可用动作仍须按对应实现与开发计划验证。新加操作种类时，先确认其准备是否会改变外部事实、补充策略与中断测试，再接入启动、健康检查和恢复列表。关系迁移、`delete_skill`、`undeploy_skill`、符合上述快照条件的 `set_current_version`、新建技能、上游更新及内容保存的已知中间态，已分别接入经过验证的回滚/续做路径；其他真实写入后的逐种恢复能力仍按对应实现与开发计划核验。
