# 操作记录与恢复规范

本文规定操作日志、准备阶段与恢复入口的共同边界。操作记录用于追踪真实写入及其中断；只有可能留下需要处理的外部状态时，才要求用户先进入恢复流程。

## 准备阶段

`prepared`（已准备）表示操作正在展示预览和收集决定。它可以写入操作日志、影响快照或检查观察值，但不得据此认定 Skill 内容、文件路径、使用关系或版本指针已经发生变更。真正写入前必须先持久化 `applying`（执行中）检查点。

| 操作种类 | 准备阶段持久化内容 | 准备阶段对 Skill 文件、目标路径、关系和版本指针的影响 | 重启后的处理 |
| --- | --- | --- | --- |
| `import_skill` | 导入候选名、安全报告及操作日志；候选提交数据另存会话内存 | 无 | 结算为 `rolled_back`（已撤销）；需要时重新分析 |
| `deploy_skill` | 派发预览及会话内计划 | 无 | 结算为 `rolled_back`；重新预览目标 |
| `delete_skill` | 删除影响快照及操作日志 | 无 | 结算为 `rolled_back`；重新确认影响 |
| `undeploy_skill` | 解除派发影响快照及操作日志 | 无 | 结算为 `rolled_back`；重新确认影响 |
| `migrate_original` | 原目录迁移计划及会话内状态 | 无 | 结算为 `rolled_back`；重新预览 |
| `prepare_source_update` | 上游候选观察、预览事实和确认指纹 | 不替换文件、不切换版本或关系；候选观察仅供更新状态展示 | 结算为 `rolled_back`；重新检查来源 |
| `set_current_version` | 版本采用影响快照、备份目标路径及确认指纹 | 不创建备份、不替换可见目录、不切换任何版本指针 | 结算为 `rolled_back`；重新预览版本 |
| `save_as_copy_replacement_preview` | 替换目标、共享消费者和确认指纹 | 无 | 结算为 `rolled_back`；重新预览 |
| `standard_export` | 导出选择、授权目标与确认指纹 | 不创建导出产物 | 结算为 `rolled_back`；重新预览 |
| `usage_release` | 关系影响、文件指纹和恢复计划 | 无 | 结算为 `rolled_back`；重新预览 |
| `subject_runtime_rename` | 主体改名计划和原始事实快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_derived_rename` | 派生主体替换计划 | 无 | 结算为 `rolled_back`；重新预览 |
| `managed_usage_change` | 受管关系变更计划和影响快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_manage` | 关系迁移预览及校验快照 | 无；写入从 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |
| `usage_manage_batch` | 批量关系处置计划和逐项事实 | 无 | 结算为 `rolled_back`；重新预览 |
| `usage_duplicate_cleanup` | 重复关系清理计划和恢复快照 | 无 | 结算为 `rolled_back`；重新预览 |
| `shared_usage_migration` | 共享关系迁移计划、目标快照及子操作引用 | 无；目标替换从 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |
| `migrate_relation` | 单条关系迁移计划、来源关系快照和备份路径 | 无；目标创建、来源改动从 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |
| `relation_governance_batch` | 批次决定和逐条准备结果 | 无；子项写入各自在 `applying` 检查点后开始 | 结算为 `rolled_back`；重新预览 |

以上是当前已核实的可安全放弃准备种类。启动门禁、恢复候选、健康检查和启动清扫必须使用同一份分类。已知准备预览不阻断其他操作，也不出现在待恢复列表；未知种类不得自动清理，必须保留恢复闸门并展示该记录，但不提供未经该种类实现验证的通用“完成/回滚”动作。

## 真正写入与中断

- `applying`、`verifying` 和 `needs_recovery`（需要恢复）表示操作可能已经改变文件、关系或版本事实；启动时不得只改为已完成/已回滚来冒充恢复。
- 开始每项外部写入前，必须保存该操作所需的恢复事实。恢复动作必须检查实际目标及前置条件，执行该种类对应的补偿或继续流程，并核验结果后才能结算。
- 恢复页逐条读取候选声明的动作；“继续完成”和“撤销未完成改动”使用不同命令及结果说明。后端未实现经过验证的恢复方式时不显示通用动作，也不允许仅修改日志阶段来结算。
- 未知阶段、未知操作种类、损坏或不完整恢复材料均按需要恢复处理。没有经过验证的安全动作时保留详情与闸门，不猜测性删除文件或变更关系。
- `deploy_skill`（派发技能）回滚仅处理日志记录的残留项：恢复材料须含已登记目标根的物理身份、运行名、模式和派发条目身份；路径必须是该根目录下与运行名完全对应的直接子项。候选展示前核验注册根和现存条目身份；执行时先核验全部目标，再在每次删除前复核根与条目身份。条目已不存在可按幂等方式结算；身份缺失、路径越界、条目被替换或注册根变化时隐藏动作并保留恢复闸门。
- `subject_runtime_rename`（主体运行名改名）的恢复日志必须记录本次新建目标条目身份。继续改名或撤销时，只有条目类型、物理身份和预期内容指纹都匹配，才可继续操作或移除；缺少身份的旧日志或身份变化时保留恢复闸门，不按路径名删除。
- `managed_usage_change`（受管关系变更）的失败补偿只移除本次派发创建且身份仍匹配的目标条目，再按已验证备份恢复原条目。旧日志未保存新目标条目身份时，不按路径名删除，保留恢复闸门并进入人工处置。Windows 符号链接和目录联接点按链接自身的重解析点身份核验；旧日志若只保存链接目标身份，不能据此推断链接本身未被替换。
- `save_markdown_as_copy`（另存副本）替换继承出现部分失败时，若成功项已提交、失败项未写入，或失败项的补偿已验证恢复原状态，则保存逐项结果并将本次操作结算为 `committed`（已完成），不触发全局恢复闸门；仅文件、关系或数据库事实无法核实时保留恢复闸门。
- `save_markdown_as_copy` 在逐项目录替换前先持久化副本版本、完整目标事实和目标计划；每个目标改动前记录原部署/所有权快照及操作专属备份路径，并在替换后记录新部署/所有权快照。重启后仅当已开始写入的目标之来源版本、目标根、部署事实和文件所有权均与检查点吻合时提供“继续完成”：只发现原目录备份时先恢复并核验原目录，再将该目标记为失败；新目录已安装时核验新树和数据库，补齐记账并幂等写入继承历史，再清理已验证备份。未开始或预检阻塞的目标不会改文件，结算为失败且不应挡住其他目标安全恢复；已完成目标保留结果。已开始写入目标的内容/路径漂移、恢复材料缺失或权限错误不猜测处理，保留恢复闸门。
- `set_current_version`（采用版本）在 `applying` 检查点后中断时，恢复页只对可由持久化快照完全核验的状态提供“撤销”：版本库指针和数据库指针各自必须指向采用前版本或本次目标版本；可移植记录必须与采用前记录完全一致，或只将 `current_version` 改为本次目标；可见目录必须是采用前树、本次目标树，或在可信旧树备份存在时缺失。旧树备份必须位于本次操作的预定内部路径且内容指纹匹配。若应用启动时按旧指针重建了旧可见目录，且该目录与备份均匹配采用前指纹，恢复先将已验证的重复备份原子移出本次操作路径，再清理该目录；执行前还要核验派生隔离路径不存在，若路径已占用则隐藏“撤销”并保留闸门。清理中断后，仍以旧树指纹匹配的可见目录完成重试，隔离目录只有仍匹配旧树时才尽力清理，残余清理失败不阻断恢复。版本采用与恢复共享串行锁，恢复取得锁后重新读取操作阶段；只有 `applying` 或 `needs_recovery` 可补偿，已提交操作不得被旧记录撤销。恢复执行后再次核验四个消费面均恢复到快照且操作备份路径已消失，才结算为 `rolled_back`（已撤销）。恢复失败保留 `needs_recovery`（需要恢复）并允许重试；指针、元数据、目录、备份或快照出现其他漂移时隐藏动作并保留闸门。
- 操作详情按稳定操作标识读取完整持久化记录；首页最近操作摘要只用于展示，不能作为恢复数据源。
- 关系迁移只有在日志中保存且能解析为 `PreparedRelationMigration`（已准备的关系迁移）恢复事实时，才允许从恢复中心执行“撤销”；该动作调用关系迁移自身的回滚校验流程。记录不完整或事实不符时继续保留恢复门禁，不提供通用处置。
- `shared_usage_migration`（共享关系迁移）在重启后只允许通过应用层专用续做流程“继续完成”。恢复候选必须处于 `needs_recovery`（需要恢复），且操作标识、操作类型、准备结果和迁移预览均可从完整日志核验；日志不完整或损坏时保留候选和恢复闸门，不提供自动动作。续做逐项复核替代关系，全部替代目标确认后才移除共享源；任何子操作或复核失败均保留恢复状态。
- `delete_skill`（删除技能）已确认删除决定并开始写入后，只允许恢复中心“继续完成”，不提供伪造回滚。仅当影响快照、逐关系决定、已完成/待处理分区及安全运行名均完整一致时才声明该动作；恢复时逐项重核关系身份、目标目录物理身份和文件所有权。已经删除的目标或结算过的关系不重放；身份漂移、事实缺失、共享删除确认不足或中央技能状态不一致时保留恢复门禁并隐藏动作。中央可见目录、版本清单、portable（可移植）元数据、主体目录投影和草稿采用稳定操作备份名并按幂等步骤续做；存在未完成删除时启动不执行写权限探测，也不从不完整版本清单重建可见目录，让恢复页面先打开。
- `undeploy_skill`（解除派发）在用户决定后，先重新核对完整影响快照；“取消”或目标所有权预检失败不会推进到 `applying`（执行中）。真正写入前保存用户决定、待处理关系和目标项物理身份。恢复中心只对安全运行名及关系身份匹配的记录提供“继续完成”；目标根仍存在时其物理身份须匹配，目标项仍存在时还须通过所有权核验；目标根或目标项已不存在时可只对账关系。被替换的目标、所有权变化或不完整事实隐藏恢复动作并保留门禁，绝不按路径名删除后来出现的文件。正常操作拼接目标路径前也校验数据库中的运行名，避免损坏记录指向已登记目标根之外。

## 当前实施边界

已知 `prepared` 种类表由 `skillhub-core` 的统一策略维护，产品文档同步说明每种准备内容及其写入边界。恢复候选的已知操作种类登记也由核心策略维护；未知种类保留记录和恢复闸门，不提供未经验证的通用处置动作。被登记为已知只确认操作来源，不代表其恢复动作已经逐种核验；具体可用动作仍须按对应实现与开发计划验证。新加操作种类时，先确认其准备是否会改变外部事实、补充策略与中断测试，再接入启动、健康检查和恢复列表。关系迁移、`delete_skill`、`undeploy_skill` 与符合上述快照条件的 `set_current_version` 已分别接入经过验证的回滚/续做路径；其他真实写入后的逐种恢复能力仍按对应实现与开发计划核验。
