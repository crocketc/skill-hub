本文件维护全项目前端产品约定；通用开发流程见根AGENTS.md。原AGENTS中的展示细则迁入下方第1节，具体按钮分工与样式已由用户确认，收于第2节。统一样式/组件/执行流程，抽屉与详情仍各自承担不同内容。

## 1. 全项目呈现规则

- **少选择、合并确认**：内部流程规则不能逐条转成用户选择/确认。只读查询和已授权范围内检查不加写入确认；轻量字段保存或明确元数据操作即提交。更新、回滚、接管、修复、回收技能、删除等同一用户意图，系统自动准备检查/影响，一次汇总必要确认后完成备份、执行、核验与刷新，不按内部步骤或每个目标重复确认。来源给可核验推荐，沿已有明确设置，高级配置可收纳；未知身份/同名冲突、真实风险或实际影响变化仍明确选择并重核验，不能借简化绕过安全/共享/权限/源文件保护或扩大网络/AI授权。关键影响直接可见，普通路径不强迫用户逐项决定技术参数。

- **用户视角与解释**：所有前端名称、说明和按钮按用户需要理解的事实、影响和下一步设计，前端修改必须使用 `frontend-design` skill，React 同时遵循 `vercel-react-best-practices`。状态用简短可读名称，悬浮/键盘聚焦展示具体原因、含义和处理建议；关键决策信息也应在预览或详情中直接可见，不能仅藏在 tooltip 中。
- **稳定布局与内容框**：列表、看板、卡片内容区的大小和位置在同一视口下尽量固定；筛选、展开次要操作和显示说明不得明显移动或挤压内容区。深层条件/操作优先用有边界的下拉、浮层、弹窗或独立步骤，限制高度并在内部滚动，支持关闭和焦点恢复。视口改变或显式设置布局时可响应调整；不能用固定尺寸掩盖溢出、遮住内容或破坏可访问性。保留用户已确认的布局样式，不因内容调整全面重做。
- **重点提示与批量闭环**：需要用户重点阅读的风险、影响、受限原因及下一步，用主题高亮/差异色和图标、文字形成明确层级，不只靠颜色。可合并的同类事项尽量提供一键类别操作或批量按钮；一键仍须有真实范围、影响预览和必要确认，受限项分别说明，结果按项记录，不能绕过安全、共享影响或版本一致性检查，不能把部分成功写成全部完成。
- **长内容收纳**：路径、名称等较长值使用有限宽度的固定前段展示并省略尾部，悬浮/键盘聚焦可查看完整的用户可读值，必要时在详情中提供完整文本和复制入口。保留完整数据，不按截断文本做判断或操作；规范化路径后再呈现，内部标识不能借完整 tooltip 进入界面。验证长内容不会撑大卡片/列或产生根级横向溢出。
- **图谱与治理一致**：技能图谱中的目标使用关系必须复用关系治理的权威事实和统一 presenter，治理分类、管理状态、具体原因及操作权限不得另行判定；内容匹配或线型不能冒充接管完成。上游来源、共享目录识别关系与目标使用关系分开说明和计数，前两者不套用接管状态。外部链接异常仍保留目标节点与关系，解除关系才进入历史；图谱详情提供精确处理入口并保持画布稳定。
- **路径展示**：任何面向用户的路径不得出现 `\\?\`、`\??\` 等 Windows 内部前缀，也不得出现同一目录因斜杠拼写（`\` 与 `/`）不同而重复展示；同一物理目录只展示一条，展示前按文件系统身份归并并统一斜杠风格。新增任何展示路径的界面必须遵守，存量界面发现违例一并修。
- **Agent 呈现**：**项目所有前端展示面**涉及 Agent 工作台厂商与类型时，统一使用「品牌厂商 logo + 用户可理解的展示类型徽标」组合呈现，不允许只在某个页面接入，也不允许纯文本 `client_id`/技术 ID 裸奔；例如 `codebuddy.code` 只展示为 CodeBuddy +「终端」，`codebuddy.workbuddy` 只展示为 CodeBuddy +「桌面端」。前端展示类型必须由统一 presenter 按用户视角归类，不能直接照搬后端 `ClientKind`：`cli/tui` 显示「终端」、`desktop` 显示「桌面端」、`ide_extension` 显示「IDE 插件」、`web` 显示「网页端」、`mobile` 显示「移动端」、`bot` 显示「机器人」、`headless` 显示「后台服务」、`acp` 显示「协议接入」、`shared_directory` 显示「共享目录」。同品牌、同 Skill 目录、不同展示类型的条目合并为一张卡片并标注类型，不得重复出卡；新增或修改 Agent 展示面时必须做全项目消费点检查。
- **共享 Agent 目录语义**：共享目录本身视为一个独立的 Agent 目录实体，在目录列表、技能关联和部署目标中只展示一份“共享目录”；支持/识别该目录的各品牌 Agent 作为该目录的关联方，不复制共享目录卡片。关系图谱必须把“Skill → 共享目录 → 可识别共享目录的 Agent”画成可区分的节点与关系，不能用 Skill 直接连多个 Agent 来替代共享目录拓扑。
- **技能库同名与部署命名边界**：技能库以 `SkillId` 作为实体身份，允许存在同名但内容、来源或用途不同的 Skill；当前可读目录名采用“原运行时名称 + 稳定识别后缀”的形式，不能据此把名称后缀写回 `SKILL.md`。Agent/项目的同一目标目录内，用户可见的有效 Skill 名称必须唯一，不能把两个同名目录直接部署到同一目标。部署入口名默认仍使用 Skill 的 `runtime_name`，并必须与拷贝/连接所呈现的 `SKILL.md:name` 一致。技能库内部目录后缀不参与 Agent/项目识别：软连接/目录联接的目标目录 basename 可以不同，Agent 看到的是目标位置上的连接入口名；实现上还必须确保连接目标中的 `SKILL.md:name` 与入口名一致。若产品允许用户为部署关系指定别名，别名必须是“该目标上的部署名称”，不是修改技能库 Skill；仅在受管复制模式下生成隔离拷贝，并同步改写拷贝 `SKILL.md` 的 `name` 以保持文件夹名与声明一致，记录原名/部署名/来源版本并支持回滚。符号链接、目录联接不得静默改写源文件；没有安全的别名部署能力时必须在预览阶段阻断并说明可选目标/处理方式，不能自动重命名或覆盖原 Skill。
- **技术标识不进界面**：前端展示以用户视角设计，不从技术角度出发。内部标识（SkillId、UUID、内容哈希、operation id、pairId、client_id 等）**一律不得出现在任何用户可见界面**——包括页面标题、图谱节点标签、列表与详情，也包括「技术详情/诊断信息」这类折叠区域：折叠只能用于收纳次要的**用户可读**事实（实现方式、能力说明、时间、规范化路径），不得成为展示原始 ID 的豁免通道。需要标识语义时用名称、版本、时间等用户可读信息。错误码/枚举值（`delete_skill`、`object.not_found` 等）不得作为独立的标签、标题或字段值出现；唯一例外是既有失败文案约定：本地化失败说明后括注错误码（如「操作失败（xxx）」）用于支持对账，且该说明必须先于码值、独立可读。技术对账与原始错误参数属于日志和导出诊断文件的职责，不属于界面。存量界面发现违例一并修。
- **前后端文案分层**：后端可以保留精确的状态枚举、失败原因、实现方式和字段名；前端必须通过统一 presenter（展示转换层）映射为用户可理解的名称、状态和操作说明。卡片、详情页、派发流程和通知不得直接展示后端枚举、字段名、内部阶段名或实现术语；技术原因仅可转化为用户可理解的事实与处理建议，原始技术信息保留在日志或诊断导出中。冲突处置动词（跳过/复用/接管/覆盖/另存/合并/回收）是后端语义词汇，界面文案必须场景化大白话转译，不得直接展示动词术语。
- **多步流程分步呈现**：向导类多步流程的每一步必须是独立的呈现单元（子页面、弹窗或步骤面板），禁止把后续步骤的内容追加到长列表末尾靠滚动条发现；步骤切换由明确的「上一步/下一步」驱动，当前步骤内容应处于首屏可视范围。
- **操作入口先整体梳理**：先明确每个操作的归属、主入口、快捷入口、出现条件、单项/批量支持及确认方式，再决定按钮层级与是否收进“更多”。“更多”是可选收纳方式，不是所有非主操作的预定位置；不得因此隐藏关键闭环入口、绕过抽屉的内容/版本边界或另建重复流程。
- **派发与快捷区域用语**：面向用户的Skill使用动作统一称“派发”，入口/流程/进度/结果/通知保持一致；后端deployment命令及普通配置、标签或组合成员添加不因文案改名。安全区直接展示基础/AI各自真实短结果，悬浮/键盘聚焦给长说明，不加独立查看结果按钮；发现项仍可读可处理，关键决策风险/影响在预览中直接说明。网络来源查找/关联/更换及检查/采用统一在“来源更新”区域，导入存证与网络更新来源仍分别说明。抽屉提供组合成员加入/移出快捷操作，完整详情同步可达，内容/版本执行仍不入抽屉。
- **安全结果图标统一**：全项目安全短结果通过统一组件/presenter展示，真实检查通过用绿色圆形对勾，不通过/有风险发现用黄色盾牌内红色叹号。基础/AI明确区分，悬浮和键盘聚焦长说明，图标含可读无障碍名称，不只靠颜色。未检查、检查中、运行失败分别表达，不冒充风险结论；运行成功枚举、零待处理或用户已处置不等于无原始风险，旧版本结果不冒充当前检查通过。此呈现不改变安全门禁或自动信任规则。
- **关系摘要与精确导航**：详情及抽屉展示用户可读的关系摘要、品牌logo标签与悬浮/键盘说明，携Skill/具体关系/真实目标及返回上下文跳关系治理或对应Agent/项目，不复制治理动作面板。共享多品牌是同一目录的关联方；+N等折叠品牌入口用于有界查看，不误触父链接。避免嵌套交互，路由参数构建/解析一致，失效上下文给可读说明，不用错误边界掩盖坏跳转。
- **抽屉与完整详情页的包含关系**：技能抽屉是快捷展示与快捷操作入口，但不是能力的唯一入口。抽屉中的所有内容和操作必须在技能完整详情页中同步可达；完整详情页可以提供抽屉没有的更多内容或操作。新增或优化抽屉能力时，必须同步检查详情页的字段、操作、状态反馈、权限边界和持久化结果，避免两处行为漂移。
- **调用方式只读边界**：Skill 的“调用方式/运行要求”在 SkillHub 内只展示声明与当前可读事实，不提供编辑或切换入口。模型调用、用户调用等开关由各家 Agent 自己管理；除非后续明确改变产品裁决，不得在抽屉或完整详情页新增修改调用方式的操作。
- **Skill 无归档功能**：产品已决定移除 Skill 归档入口、批量动作、状态、过滤与专属偏好；旧归档 Skill 迁回常规状态，不删除主体/版本或改变使用关系，不能以“停用/隐藏”等新名字重新引入。关系结束历史、恢复依据、文档归档和 ZIP 导入/导出仍按原职责保留，不属于 Skill 归档功能。
- **试用与复核保留**：支持技能试用与复核日期，到期只产生提醒，由用户决定后续动作；不能自动删除主体、回收链接或把技能归档。归档功能移除时保留真实试用日期和复核事实，生命周期与检查结果、来源更新、关系健康分别呈现。

## 2. 已确认的抽屉、详情和列表分工

2026-10-03 用户补充实施次序：抽屉和完整详情先基于已提交前端分支画原型并共同调整，原型确认后再实施新增界面方案。既有代码修复成果保留，画原型不要求先合并到验收分支。产品规范确认不等同于界面原型或实际代码已验收。

沿用已有页面风格与主题，不全面换布局。只为已确认入口安排呈现方式，未具备真实契约的能力仍排队，不以样式调整提供假执行。用户已明确同意整体设计；统一的是视觉样式与真实流程，抽屉和详情的内容/能力仍有分工。

### 2.2 完整详情与列表

完整详情沿现有内容分区：画像字段编辑在字段旁；安全区短结果和检查；“来源更新”区按无来源/已有来源/可更新事实呈现查找、关联、检查、采用；正文编辑及保存模式仅内容区，版本命名/变化/恢复仅对应历史版本；试用与组合均在相应字段区。关系区只可读摘要及上下文跳转，不摆治理动作；详情主体操作可发起派发、导出、删除。次要设置用有界浮层，保留内容区，不将所有操作塞到页头。

列表保持浏览和比较优先：单击现有入口打开抽屉，状态摘要可定位对应详情区；派发等单项快捷位置不铺成每行多按钮。选中后批量栏按真实契约提供派发、标签、基础/AI检查、检查更新、组合、导出、删除等动作分组，准确所选范围、可执行/受限数、同意图一次汇总、逐项结果；未接批量契约的动作不显示可执行按钮。具体批量栏排序/哪些常驻哪些收纳待本节讨论，不默认把全部非主动作隐藏。

详情/批量样式：来源更新“更新”及正文最终“保存”用主题实色强调，查询/更换等轻描边或透明字段图标；历史版本“恢复此版本”用轻描边并进入影响确认，不和当前更新混成一个按钮；详情治理跳转为差异色可读入口，不复制治理动作。批量栏派发为主强调、同类检查/标签/组合等低强调图标+文字，危险删除单独分组；列表批量栏具体排序/收纳仍需按真实能力收口，不因确认样式伪称所有批量均已支持。


### 2.3 抽屉与详情不是同一套内容布局

| 能力 | 快捷抽屉 | 完整详情 |

## 10. 关系治理页页签、细分桶与筛选（2026-10-06，本轮裁决）

用户验收关系治理页后逐轮确认：页面以治理待办为主视角，进页直接看待处理；治理分类保留页签形式；桶内按关系分类细分；只读内置目录的导入原件是无动作的正常终态。裁决如下；模型依据同轮写入[业务决策模型](业务决策模型.md)（判定三层、七类基本情况、内置与只读目录边界）。

- **页签**：保留「待处理 / 无需处理 / 全部」三个页签按钮，顺序改为待处理、无需处理、全部；进入页面默认选中「待处理」。「全部」按治理分类拆双桶并排呈现（待处理桶在左、无需处理桶在右，列序固定，不随数量互换位置）。
- **桶内分组**：按适用问题与事实组织，形式、管理情况和状态分开表达，不保留旧七类混合分类；多目录重复／重名按问题组计数，涉及项数另说明。无需处理显示正常活动关系，只读健康原件按边界展示；已解除、保留独立拷贝在历史，不混入活动桶。批量只能执行所选对象共同可用的动作，权限限制如实说明。
- **筛选条常驻内联**（不再用浮窗）：只保留搜索（Skill、目标或路径）与视图切换（看板/表格）；删除「来源副本/派发」关系范围 chips 与「待集中管理/已集中管理」管理状态 chips——导入来源与派发的区分由分类细分桶自然承载。深链 `?governance=`、`?scope=`、`?management=` 参数保留解析兼容，映射到对应页签或细分桶（导入完成等既有跳转方继续可用）。

- **无需处理桶动作语义**：正常使用关系可查看或解除，主体侧回收选择对象并调用共用流程；已保留独立拷贝进入历史，不提供撤销保留。健康只读原件只展示关系与来源、不参与文件操作或批量；异常可重新检查或解除记录，不动文件。
