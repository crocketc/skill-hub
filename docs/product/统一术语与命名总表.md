# 统一术语与命名总表

**状态：裁决词表（2026-10-08 用户逐项确认；同日用户划定实施边界——冲突与操作动词、全局改名已定稿可实施；关系域暂缓实施，待用户对关系体系再讨论确认后统一执行，见第八节）。本表为全项目用户可见词汇的唯一权威。**

## 定位

- 本文收口全项目用户可见词汇：关系、图谱连线、冲突、状态词、操作动词、禁用词。
- **命名铁律：用户一看就懂。** 优先使用用户已经在用的词（技能、链接、完整拷贝、派发、导入、目录）；不造四字复合术语（受管、托管、观察、纳管、副本这类词一律弃用）；一层信息一个短词，两层信息拆成两个标识分开呈现。
- **前端展示为规范**：每条词条以「用户看到的称呼」为准（中英文同时定名）；内部枚举名、表名、键名只是开发对账映射，不得出现在任何用户可见界面。
- **全局改名裁决（2026-10-08）**：「集中库」全项目改叫「**技能库**」（界面与产品规范文案；代码内部标识如 `CentralLibrary`、`central_library` 不动，仅作对账映射）；「副本」一律改叫「**拷贝**」。

## 先说清楚三个数字（7 类状态、8 种关系、6 种连线）

- **关系状态：7 类**——一条关系**现在怎么样、要不要你处理**。词面见第五节状态词表。
- **关系种类：8 种**——一条关系**是什么**（链接还是完整拷贝、管理中还是发现的、导入来源、共享目录、待确认）。见第一节。
- **图谱连线：6 种**——图谱上画的不止使用关系一种线，还有上游来源、复用修改、目录归属、共享目录识别、冲突。见第二节。

## 一、关系种类命名总表（全枚举 8 种）【关系域——暂缓实施，待关系体系再讨论确认后统一执行】

**呈现模型（裁决 1、8）**：每条关系行主词是「技能」（或具体技能名），旁边最多两个小标识：

- **形式**：「链接」／「完整拷贝」／「导入来源」／「共享目录」／「待确认」
- **管理**：「管理中」／「未管理（发现的）」

**跟随更新规则（裁决 8）**：「跟随技能库更新」是「管理中」的固有属性，由管理标识表达，形式标识不重复；不跟随的只有只读原件（内置目录等只读目标）、已保留独立拷贝、发现的未管理技能三种。受管拷贝同样跟随——技能库采用新版时一并更新（现有实现未做到，#15 修复后生效）。

空间受限必须合成一个标签时用带括号写法，如「链接（管理中）」。

内部枚举为 `RelationshipType`（8 种，skillhub-core/src/relationship/mod.rs:97），全部列出；「待确认」也是正式种类，不是兜底垃圾桶。

| --- | --- | --- | --- | --- |

**种类与状态分层**：种类回答"是什么"，状态（7 类，第五节）回答"现在怎么样、要不要你处理"。徽标与筛选不得跨层混贴。只读目录里的技能原件健康时：种类＝导入来源，状态＝已入库·原件保留（只读）。

**文件形态词**（描述目标位置上是什么物理形态，非关系）：目录／符号链接／目录联接／完整拷贝／看不清的形态。现行后端写法「目录联结」「未知表示」「复制副本」实施时替换。

**来源分类词**（治理页"来源"列，描述关系从哪来；随本表一并更名）：扫描发现／导入来源（原「导入登记」）／Agent 本地拷贝（原「Agent 本地副本」）／用户本地拷贝（原「用户本地副本」）／项目登记拷贝（原「项目登记副本」）／在线导入拷贝（原「在线导入副本」）／技能库拷贝（原「集中库副本」）／未分类来源。

## 三、冲突命名表（类型 2 ＋场景 6；裁决 9 定稿）

**冲突类型——冲突只有「名字×内容」两种撞法，判定靠确定性事实（名字相等、内容指纹相等），不依赖 AI：**

| 类型（zh / en） | 判定 | 处理 |
| --- | --- | --- |
| 同一技能 / Same skill | 内容完全一样（名字相同是常态；名字不同的极少数也照此办理） | 留一份、复用已管理的 |
| 重名 / Name taken | 名字相同、内容不同 | 换个名字，或替换 |

- **相似技能 / Similar skill（不是冲突）**：名字不同、内容相近，接了大模型判断才出现的提示；这种情况很多、属正常，只提示不打断。同名但内容相近时，名字相撞本身是确定事实，按重名走，「相近」只作卡内参考说明。
- **实现对账**：后端 `ConflictKind` 五项——`duplicate_same_content`→同一技能；`same_name_different_content`→重名；`same_source_fork`→重名卡内证据说明（「同一来源、内容分叉」，不作独立类型）；`shared_directory_duplicate`→场景词（在共享目录发现），类型仍按内容判同一技能或重名；`unknown_directory_recognition`→权属情形，按导入流程既定呈现。前端现行四词映射：完全重复→同一技能、名称重复→重名、可能匹配／搜索匹配→相似技能提示；「Agent 管理的目录」这类权属情形不画冲突卡，沿用导入既定按钮措辞（该词目前仅存在于前端演示夹具，后端从未产生）。

**场景表（什么时候要你决策，全枚举 6 场景）**——场景枚举以[业务决策模型](业务决策模型.md)第五节为准；导入场景按钮五句为既定裁决措辞，逐字使用不得改写。

| 场景 | 界面标签（裁决） | 既定按钮措辞（照抄） | 状态 |
| --- | --- | --- | --- |
| 导入时库里已有相同/同名的技能 | 导入重名 | 「复用已管理的 Skill」「保留当前位置并纳入管理」「复制到 SkillHub」「独立导入」「跳过此候选项」 | 已实现 |
| 派发时目标目录已有同名技能 | **派发重名** | 待实现时按本表执行，不另起名 | 待实现 |
| 删除技能牵连其他记录 | 删除冲突 | 同上 | 已实现（删除影响/级联） |
| 恢复备份/历史时与现状相撞 | 恢复冲突 | 同上 | 待实现 |
| 改名后与其他技能撞名 | 改名冲突 | 同上 | 已实现 |
| 升级影响使用位置 | 升级冲突 | 同上 | 窄口径待开发 |

冲突条目呈现沿用四件事纪律：什么情况、涉及哪两边、能做什么、不管它默认怎样。

## 四、技能操作动词表（裁决）

动词一对一：一个动作一个动词，近义动词按宾语硬性区分。

| 动词（zh / en） | 定义（用户视角） | 界面用词细则与禁用判例 |
| --- | --- | --- |
| 导入 / Import | 把某个位置的技能收进技能库，技能库里多了一个可管理的技能 | 只用于入库动作；「导入来源」是关系名词，不作按钮 |
| 导出 / Export | 把技能库里的某个版本打包成目录或压缩包拿走 | 不建立使用关系；禁用「下载」「另存为」指此动作 |
| 派发 / Dispatch | **在目标目录创建链接或完整拷贝，让 Agent 用上技能库里的技能**（既定动词；技术上叫部署，本软件统一叫派发） | 创建使用关系的唯一入口动词；禁用「部署」「安装」 |
| 接管 / Take over | 把目录里已有的技能改为链接、本体交给技能库管理（先备份原文件） | 仅治理动作；禁用「纳管」「收编」 |
| 转入技能库管理 / Manage via skill library | 对没接管的位置发起接管（既定裁决词；"管理"二字保留，避免误解为搬移文件） | 原「转为集中管理」 |
| 采用新版 / Adopt | 来源有新版，决定把新版设为当前版本 | 仅来源更新域；禁用「升级」「更新到最新」 |
| 保持当前 / Keep current | 来源有新版但决定不换 | 不冒充"已是最新" |
| 恢复此版本 / Restore this version | 把某个历史版本设为当前版本 | 宾语必须是版本；「恢复」在恢复页指完成上次没做完的操作，按宾语区分 |
| 回滚 / Roll back | 来源更新后退回更新前的旧版本 | 仅来源更新域 |
| 删除 / Delete | 删掉技能库里的技能主体，它名下的关系一并清理（2026-10-07 裁决口径） | 宾语只能是技能库技能主体；「删除标签」是错用——集合成员用「移除」 |
| 移除 / Remove | 从集合或列表里拿掉一个成员，成员本身没事 | **必须带具体宾语**（裁决 7）：移除标签、移除组合、移除候选项；禁止裸「移除」按钮——不带宾语易与删除混淆 |
| 回收技能 / Reclaim skill | 把这条使用关系在目标目录建的入口拆掉（链接或完整拷贝），把这个技能从这个目录收回来 | 治理动作按钮定名「回收技能」（裁决 7）：宾语是当前行技能，不是删除技能本体；入口已经不在了就只解除关系；禁用「卸载」「拆除」作按钮 |
| 解除关系 / Release relation | 把这条使用关系解除、记入历史，位置上的文件留着不动 | 与回收技能、删除严格区分：解除只动关系记录（裁决 7，「结束」含义不清弃用）；禁用「断开」「结束」作按钮 |
| 保留为独立拷贝 / Keep as independent copy | 不再管理这个位置，文件留在原地继续可用（原「保留为独立副本」，2026-10-08 随"副本→拷贝"更名） | 简称「保留独立拷贝」；「独立拷贝」是状态词，不与「完整拷贝」（形式词）混用 |
| 撤销保留 / Undo retention | 把"决定长期保留"撤回，回到等你处理 | — |
| 覆盖保存 / Overwrite save | 编辑后存回原技能，旧版本自动保留 | 与「另存新技能」二选一呈现 |
| 另存新技能 / Save as new skill | 以当前内容存成一个新技能，记住它是从哪个技能改出来的 | — |
