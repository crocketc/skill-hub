- 正式关系名称：使用关系、导入来源、更新来源、复用修改、目录归属、目录识别。不同页面按职责展示；待确认不是关系种类，冲突归冲突模型。
- 技能库中管理的对象叫“技能主体”；“技能原件”仅描述仍承担原件角色的文件，转为派发入口后不再显示原件标识，历史导入来源保留。

- “转入技能库管理”支持链接和维护同步的完整拷贝，不再仅指改为链接。
- “解除使用关系”替代单条使用关系的“解除关系”：管理中的链接删除链接；管理中的拷贝选择保留为独立拷贝或同时移除拷贝；未管理关系只清记录、不动文件并保留解除决定。废止旧“一律不动文件”的定义。

- 来源操作：关联更新来源／更换更新来源／解除更新来源／检查更新；导入来源为历史、更新来源为当前关联，不互相改写。
- 共享目录当前仅一个，保留独立卡片及统计，回收选择单独成组；消费者技能数包含共享及内置目录贡献，须单独说明。

英文定名、完整状态适用表、来源分类与文件形态对账尚待讨论；不得沿用旧英文推定新定义已经定稿。全局改名与冲突裁决中未受本轮修订影响的部分仍有效。

## 定位

- 本文收口全项目用户可见词汇：关系、图谱连线、冲突、状态词、操作动词、禁用词。
- **命名铁律：用户一看就懂。** 优先使用用户已经在用的词（技能、链接、完整拷贝、派发、导入、目录）；不造四字复合术语（受管、托管、观察、纳管、副本这类词一律弃用）；一层信息一个短词，两层信息拆成两个标识分开呈现。
- **前端展示为规范**：每条词条以「用户看到的称呼」为准（中英文同时定名）；内部枚举名、表名、键名只是开发对账映射，不得出现在任何用户可见界面。
- **全局改名裁决（2026-10-08）**：「集中库」全项目改叫「**技能库**」（界面与产品规范文案；代码内部标识如 `CentralLibrary`、`central_library` 不动，仅作对账映射）；「副本」一律改叫「**拷贝**」。

## 一、关系统一名称与属性

| 中文 / English | 定义 |
| --- | --- |
| 使用关系 / Usage relationship | Agent、项目或共享目录获取技能的关系，不证明实际执行 |
| 导入来源 / Import origin | 技能主体某次导入时的来源记录 |
| 更新来源 / Update source | 当前检查和获取后续版本的来源关联 |
| 复用修改 / Derived from | 新技能基于原技能及起始版本创建，之后独立维护 |
| 目录归属 / Directory location | 技能文件或链接所在目录 |
| 目录识别 / Directory recognition | Agent／项目可从该目录发现技能的关系 |

各页面按职责选用，不要求全部出现；关系治理只将使用关系作为独立治理对象。具体生命周期见[关系体系与生命周期](关系体系与生命周期.md)。

| 维度 | 中文 / English |
| --- | --- |
| 管理对象 | 技能主体 / Skill entity |
| 尚承担原件角色的文件 | 技能原件 / Original skill files |
| 来源记录的位置 | 导入位置 / Import location |
| 形式 | 链接 / Link；完整拷贝 / Full copy |
| 管理情况 | 管理中 / Managed；未管理 / Unmanaged |
| 治理分类 | 待处理 / Needs attention；无需处理 / No action needed；全部 / All |

管理中的拷贝跟随主体版本同步；失败仍为管理中。未管理链接也可能随指向内容变化。“发现的”不是管理状态。退出管理并保留文件的结果叫“独立拷贝”，解除后关系进入历史，不作为活动状态。

目录沿用：Agent 内置目录 / Built-in skill directory（内置 / Built-in）、Agent 用户目录 / User skill directory（用户 / User）、Agent 工作区目录 / Workspace skill directory（工作区 / Workspace）。共享目录 / Shared directory为独立实体；项目目录 / Project skill directory属于独立 Project。不新增用户来源目录或空间目录角色。

符号链接 / Symbolic link、目录联接 / Directory junction只在技术详情说明，不构成新的关系种类。来源分类不照搬内部枚举：“由 SkillHub 派发”属于使用关系建立记录；导入来源、更新来源针对主体分别表达。

内部 managed_link、managed_copy、observed_link、observed_copy 映射使用关系的形式与管理情况；import_copy 映射导入来源事实并另核实当前使用；共享直接读取／引用映射目录识别、使用路径与形式；unknown映射具体无法核验或待用户确认事项，不是正式种类。实施须核实契约，不以枚举强行覆盖事实。

## 二、图谱与页面关系表达

图谱沿用第一节六种关系名称，不另建业务分类。实际画线方式由节点与关系事实决定，旧 deployment/source/related_skill/located_in/shared 分别对账使用、更新来源、复用修改、目录归属、目录识别；导入来源须有独立事实表达，不能混入更新来源。conflict 是冲突标记，不算新增关系种类。

共享路径展示“技能 → 共享目录 → Agent”，共享物理使用关系只计一次。技能详情可合并同一位置的使用与导入来源，但保留不同语义。位置转换为派发入口后不再标原件，历史来源可追溯。

治理问题用“同一技能出现在多个目录 / Same skill in multiple directories”或“多个目录中存在重名技能 / Same name in multiple directories”。不展示“多入口／多技能入口”。问题按 Agent 自身或 Agent × 项目使用环境判定，不以目录优先级为前提；共享问题汇总消费者、只建一条待办。
## 三、冲突命名表（类型 2 ＋场景 6；裁决 9 定稿）

**冲突类型——冲突只有「名字×内容」两种撞法，判定靠确定性事实（名字相等、内容指纹相等），不依赖 AI：**

| 类型（zh / en） | 判定 | 处理 |
| --- | --- | --- |
| 同一技能 / Same skill | 内容完全一样（名字相同是常态；名字不同的极少数也照此办理） | 留一份、复用已管理的 |
| 重名 / Name taken | 名字相同、内容不同 | 换个名字，或替换 |

- **相似技能 / Similar skill（不是冲突）**：名字不同、内容相近，接了大模型判断才出现的提示；这种情况很多、属正常，只提示不打断。同名但内容相近时，名字相撞本身是确定事实，按重名走，「相近」只作卡内参考说明。
- **实现对账**：后端 `ConflictKind` 五项——`duplicate_same_content`→同一技能；`same_name_different_content`→重名；`same_source_fork`→重名卡内证据说明（「同一来源、内容分叉」，不作独立类型）；`shared_directory_duplicate`→场景词（在共享目录发现），类型仍按内容判同一技能或重名；`unknown_directory_recognition`→权属情形，按导入流程既定呈现。前端现行四词映射：完全重复→同一技能、名称重复→重名、可能匹配／搜索匹配→相似技能提示；「Agent 管理的目录」这类权属情形不画冲突卡，沿用导入既定按钮措辞（该词目前仅存在于前端演示夹具，后端从未产生）。

**场景表（什么时候要你决策，全枚举 6 场景）**——场景枚举以[业务决策模型](业务决策模型.md)第五节为准；导入场景按钮五句为既定裁决措辞，逐字使用不得改写。

| 场景 | 界面标签（裁决） | 既定按钮措辞（照抄） | 状态 |
| --- | --- | --- | --- |
| 导入时库里已有相同/同名的技能 | 导入重名 | 「复用已管理的 Skill」「保留当前位置并纳入管理」「复制到 SkillHub」「独立导入」「跳过此候选项」 | 已实现 |
| 派发时目标目录已有同名技能 | **派发重名** | 待实现时按本表执行，不另起名 | 待实现 |
| 删除技能牵连其他记录 | 删除冲突 | 同上 | 已实现（删除影响/级联） |
| 恢复备份/历史时与现状相撞 | 恢复冲突 | 同上 | 待实现 |
| 改名后与其他技能撞名 | 改名冲突 | 同上 | 已实现 |
| 升级影响使用位置 | 升级冲突 | 同上 | 窄口径待开发 |

冲突条目呈现沿用四件事纪律：什么情况、涉及哪两边、能做什么、不管它默认怎样。

## 四、技能操作动词表（裁决）

动词一对一：一个动作一个动词，近义动词按宾语硬性区分。

| 动词（zh / en） | 定义（用户视角） | 界面用词细则与禁用判例 |
| --- | --- | --- |
| 导入 / Import | 把某个位置的技能收进技能库，技能库里多了一个可管理的技能 | 只用于入库动作；「导入来源」是关系名词，不作按钮 |
| 导出 / Export | 把技能库里的某个版本打包成目录或压缩包拿走 | 不建立使用关系；禁用「下载」「另存为」指此动作 |
| 派发 / Dispatch | **在目标目录创建链接或完整拷贝，让 Agent 用上技能库里的技能**（既定动词；技术上叫部署，本软件统一叫派发） | 创建使用关系的唯一入口动词；禁用「部署」「安装」 |
| 接管 / Take over | 转入技能库管理的执行语义，先备份再建立管理中的链接或完整拷贝 | 用户操作入口使用“转入技能库管理”，不再限定必须链接 |
| 转入技能库管理 / Manage through skill library | 经核验将使用位置改为管理中的链接或完整拷贝 | 共享目录按完整拷贝方式；预览、备份、执行核验后记账 |
| 采用新版 / Adopt | 来源有新版，决定把新版设为当前版本 | 仅来源更新域；禁用「升级」「更新到最新」 |
| 保持当前 / Keep current | 来源有新版但决定不换 | 不冒充"已是最新" |
| 恢复此版本 / Restore this version | 把某个历史版本设为当前版本 | 宾语必须是版本；「恢复」在恢复页指完成上次没做完的操作，按宾语区分 |
| 回滚 / Roll back | 来源更新后退回更新前的旧版本 | 仅来源更新域 |
| 删除 / Delete | 删掉技能库里的技能主体，它名下的关系一并清理（2026-10-07 裁决口径） | 宾语只能是技能库技能主体；「删除标签」是错用——集合成员用「移除」 |
| 移除 / Remove | 从集合或列表里拿掉一个成员，成员本身没事 | **必须带具体宾语**（裁决 7）：移除标签、移除组合、移除候选项；禁止裸「移除」按钮——不带宾语易与删除混淆 |
| 回收技能 / Withdraw skill | 从技能出发选 Agent／共享目录／项目，解除对应使用关系 | 属技能操作模型，调用同一关系流程；位置为辅助信息 |
| 解除使用关系 / Remove usage relationship | 解除当前使用关系并按形式处理文件 | 管理链接删除；管理拷贝选择保留或同时移除；未管理文件不动；不存在则只清记录 |
| 保留为独立拷贝 / Keep as independent copy | 留下完整文件，解除使用关系，不再维护同步 | 结果记入历史；文件仍重复时不算重复治理完成 |
| 同时移除拷贝 / Also remove the copy | 解除使用关系时一并移除目标完整拷贝 | 明确确认、备份并可恢复 |
| 覆盖保存 / Overwrite save | 编辑后存回原技能，旧版本自动保留 | 与「另存新技能」二选一呈现 |
| 另存新技能 / Save as new skill | 以当前内容存成一个新技能，记住它是从哪个技能改出来的 | — |
| 命名版本 / Name version | 给当前版本起个好认的名字 | 禁用「打标签」指版本命名（标签是另一个东西） |
| 整理画像 / Edit profile | 编辑描述、标签这些"这个技能是干什么的"信息 | — |
| 设为试用 / Mark trial · 转常规 / Promote | 试用期管理；到期只提醒，不会自动删也不会自动回收 | — |
| 检查更新 / Check for updates | 去关联的来源查一查有没有新版 | 查不到或没网就如实说，不假称"已是最新" |

| 待同步 / Sync pending | 管理中的完整拷贝未同步主体当前版本 |
| 同步失败 / Sync failed | 已执行同步但失败 |
| 无法核验 / Unable to verify | 权限或访问限制阻挡核验，说明原因 |
| 待用户确认 / Awaiting your decision | 需要用户选择，说明具体事项 |
| 有新版 / New version available | 成功检查后发现可采用版本 |

| 已解除使用关系 / Usage relationship removed | 历史结果，不是活动关系健康状态 |
| 已保留为独立拷贝 / Kept as an independent copy | 历史结果，文件保留且不再同步 |

不新增“待核验／正在检查”关系状态；自动核验结果尚未返回使用页面加载反馈。多异常可并存，详情保留完整事实。未管理文件或原件停留旧版符合预期时不因与主体不同报内容变化。治理前显示实际发现项数及重复／重名问题组，不去重隐藏问题；待处理导航携使用环境与问题组并重新核验。
