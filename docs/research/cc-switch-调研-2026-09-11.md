## 2. 发现与仓库模式

### 2.1 本机工具配置的发现方式

- cc-switch 按已知默认目录定位各 CLI 工具的配置：Claude Code `~/.claude/`、Codex `~/.codex/`、Gemini CLI `~/.gemini/`、OpenCode `~/.config/opencode/`、OpenClaw `~/.openclaw/`、Hermes `~/.hermes/`。手册逐工具列出目录内关键文件（settings.json、auth.json、config.toml、.env、config.yaml 等）。来源：手册 5.1。
- 每个 CLI 目录均可在设置中改为自定义路径（设备级设置，含 `claudeConfigDir` 等字段），修改后应用与对应 CLI 需重启并保持一致。来源：手册 1.5、5.1。
- 手册未描述"扫描安装位置自动探测工具是否安装"的细节，自动探测逻辑**未证实**；可证实的最小事实是"按默认/自定义目录读写已知配置文件"。
- 数据自身存储在 `~/.cc-switch/`（可改）：`cc-switch.db`（SQLite，SSOT）、`settings.json`（设备级设置）、`skills/`（Skill 源目录）、`skill-backups/`、`backups/`。来源：手册 5.1。

### 2.2 供应商与预设的组织方式

- 单一事实源（SSOT）优先级：数据库为 SSOT → 切换时写入实况配置文件 → 编辑当前激活供应商时从实况文件"回填"读回，用户手工改动可被捕获并保存回数据库。来源：手册 5.1"配置优先级"。
- SQLite 内含 providers、provider_endpoints（端点候选）、provider_health、model_pricing、proxy_config、proxy_request_logs、mcp_servers、prompts、skills、skill_repos、settings 等表。来源：手册 5.1。
- 预设模板按供应商组织，覆盖官方与第三方/代理服务；v3.20.2 发布说明显示预设与模型定价条目仍在持续扩充（新增腾讯云 Token Plan、QwenCloud、PPIO 等，并按月刷新定价）。来源：手册 2.1、Releases v3.20.2。
- v3.7.0 从 JSON 文件迁移到 SQLite：首次启动自动迁移，旧配置文件保留为备份。来源：手册 5.1。

### 2.3 Skill 发现与仓库组织（与 SkillHub 最相关）

- 支持五款应用的 Skills：Claude Code、Codex、Gemini CLI、OpenCode、Hermes；Skill 即"含提示词模板、工具定义与示例代码的文件夹"。来源：手册 3.3。
- 内置预配置仓库：Anthropic 官方、ComposioHQ（社区维护合集）、Community Picks（编辑精选）；内置仓库的具体指向清单**未证实**（手册未列 owner/repo）。来源：手册 3.3。
- 自定义仓库采用结构化坐标：owner + 仓库名 + 分支（默认 main）+ 可选子目录，对应 GitHub 形如 `/{owner}/{name}/tree/{branch}/{子目录}` 的路径。来源：手册 3.3。
- 集成 skills.sh 公共注册表搜索（v3.13.0 起），可在仓库管理对话框内按关键词检索社区 Skill 并一键加入仓库列表。来源：手册 3.3。
- 发现侧交互：按名称/描述/目录名实时搜索；按"已安装/未安装"状态过滤；"刷新"重新扫描仓库。来源：手册 3.3。
- 安装目标目录按应用映射：`~/.claude/skills/`、`~/.codex/skills/`、`~/.gemini/skills/`、`~/.config/opencode/skills/`、`~/.hermes/skills/`。来源：手册 3.3。
- SSOT 与分发分离：安装内容先落入源目录（默认 `~/.cc-switch/skills/`，可切换为社区约定的 `~/.agents/skills`，切换不丢状态、平滑迁移），再按同步方式分发到各应用目录——symlink（默认，省空间实时同步）或 copy（整份复制，权限受限时使用）。来源：手册 3.3、1.5。
- 更新检测：v3.13.0 起用 SHA-256 内容哈希比对本地与远端版本，远端有变化即在卡片上显示可更新标识，支持单个更新与"全部更新"批量下载。来源：手册 3.3。
- 卸载保护：删除前自动备份到 `~/.cc-switch/skill-backups/`，随后从各应用目录、SSOT 目录与数据库记录三处移除；支持"从备份恢复"（列出名称与备份日期）与删除备份（不可撤销，需确认）。来源：手册 3.3。
- 卡片信息：名称、描述、来源仓库、安装状态。来源：手册 3.3。
- 交叉印证（二手证据）：本仓库《Skill 发现模块实现规格（复用自 cc-switch）.md》基于其 v3.19.x 源码记录了实现层事实——skills.sh 走 `api/search` 接口；GitHub 发现用 `archive/refs/heads/{分支}.zip` 整仓下载后本地扫描 `SKILL.md`，不依赖 GitHub API 与令牌；分支按"指定分支 → main → master"回退；发现结果不落库、仅安装落库。来源：内部规格文档（引用时注意其非官方文档）。

### 3.2 界面组织

- 顶部导航按应用切换（Claude/Claude Desktop/Codex/Gemini/OpenCode/OpenClaw/Hermes），每应用可独立隐藏，至少保留一个；导航含 Skills、MCP、Prompts 等入口。来源：手册 1.3、1.5、3.3。
- 供应商以卡片列表呈现：激活卡"蓝色边框+标签"，代理模式下实际使用的卡"绿色边框"，普通卡默认样式。来源：手册 2.2。
- 设置分页签组织：个性化（语言/主题/窗口）、代理、高级（目录/数据管理/备份恢复）。来源：手册 1.5。
- 设置入口快捷键为 `Cmd/Ctrl + ,`；除设置入口外，是否存在切换供应商的**全局**快捷键**未证实**（手册仅记载托盘与主界面两条切换路径）。来源：手册 1.5、2.2。

### 3.3 配置切换交互

- 主界面：点目标卡"启用"→ 更新配置文件 → 卡片状态变为"当前激活"。生效方式因工具而异：Claude Code 与 Gemini CLI 热加载立即生效；Codex 需重开终端。来源：手册 2.2。
- 切换失败有明确归因提示：配置文件被占用、目录权限不足、JSON 格式非法三类，分别给出处理建议。来源：手册 2.2。
- 编辑供应商时对当前激活项执行"回填"，把用户手工改过的实况配置读回表单。来源：手册 2.3（目录）、5.1。

### 3.4 托盘与常驻

- 关闭行为可选"最小化到托盘"或直接退出；支持开机自启（Windows 注册表 / macOS LaunchAgent / Linux XDG autostart）。来源：手册 1.5。
- 托盘快速切换：右键托盘图标 → 悬停应用子菜单（标题显示当前激活供应商与用量摘要）→ 点供应商名完成切换并弹托盘通知。v3.13.0 将扁平列表重构为按应用子菜单，避免供应商过多时菜单超出屏高，且各应用切换互不干扰。来源：手册 2.2。
- 轻量模式（v3.13.0 起）：托盘独占运行态，主窗口被销毁（非隐藏）以释放 UI 资源，空闲占用接近零；经托盘菜单、深度链接或二次启动按需重建窗口，状态保留；该状态不持久化，下次正常启动恢复普通模式。来源：手册 1.5。
- 官方推荐组合：后台常驻 + 轻量模式 + 按应用托盘子菜单，适合高频切换用户。来源：手册 2.2。

- 未发现任何"操作系统凭据存储（钥匙串/凭据管理器）"集成的证据——**未证实**其存在。

## 5. 对 SkillHub 的可借鉴点（逐条标注证据来源）

以下每条均为"模式借鉴"，需 SkillHub 自行实现并过验收，不存在现成能力。

1. **SSOT 源目录 + 应用目录分发分离**：安装内容只落一份源目录，再 symlink/copy 分发到各应用，卸载、更新、回滚只动一处。证据来源：手册 3.3、1.5（skills 源目录切换与同步方式）。
2. **symlink 默认、copy 兜底的同步策略**：默认 symlink 省空间实时同步，权限受限场景退回整份复制；两者可在设置切换。证据来源：手册 1.5。
3. **卸载前自动备份 + 可视化恢复**：删除前强制备份（独立目录、含名称与日期），恢复入口与删除备份分离且不可逆操作需确认。证据来源：手册 3.3；与 SkillHub"复制/删除/恢复必须保留用户原文件、提供可回滚路径"的规则同向。
4. **SHA-256 内容哈希更新检测 + 批量更新**：不依赖版本号，内容变更即提示可更新，支持逐个与全部更新。证据来源：手册 3.3。
5. **结构化仓库坐标**：owner/仓库/分支/子目录四元组描述 Skill 来源，避免散落 URL 字符串；配合"来源仓库"在卡片上透明展示。证据来源：手册 3.3。
6. **发现与安装解耦、发现结果不落库**：现扫现列，只有安装才写库，规避缓存过期（实现层事实，二手证据）。证据来源：本仓库《Skill 发现模块实现规格（复用自 cc-switch）.md》。
7. **公共注册表作为附加发现源而非唯一来源**：skills.sh 搜索与用户自定义 GitHub 仓库并列，注册表不可用时本地仓库链路仍可用。证据来源：手册 3.3（故障排查一节同时承认网络失败场景）。
8. **导入前自动备份与保留策略**：任何覆盖式导入前自动备份，固定保留最近 N 份、时间戳命名。证据来源：手册 5.1。
9. **回填机制（外部变更捕获）**：用户在应用外手工改动目标文件后，工具能在编辑时读回实况并保存，降低"工具外修改被覆盖"的风险。证据来源：手册 5.1。可映射到 SkillHub 的"外部修改的 Skill 重新纳入管理"。
10. **按应用分组的托盘子菜单 + 子菜单标题显示激活状态**：解决条目增多后菜单溢出，且不展开即可见当前激活项。证据来源：手册 2.2。
11. **轻量模式（销毁窗口、按需重建）**：常驻工具的空闲资源控制范式。证据来源：手册 1.5。
12. **切换失败归因提示**：把失败原因收敛为"文件占用/权限/格式非法"等可操作类别，而非笼统报错。证据来源：手册 2.2。

SkillHub 生命周期为发现/导入/部署/版本/备份，下表将 cc-switch 可证实模式映射到各阶段，便于后续规格拆解。

### 5.2 借鉴时的边界约束

- 每条借鉴落地前须先在本仓库形成规格（含失败、取消、重复、恢复路径的测试计划），遵循 AGENTS.md 的 TDD 要求；cc-switch 手册只证明"它这样做"，不证明"这样做在 SkillHub 的边界下安全"。
- 涉及删除、覆盖、链接的操作必须保留用户原文件并提供回滚路径，cc-switch 的卸载备份模式是同类思路的参照而非免检依据。
- skills.sh 与 GitHub 属外部来源，引入时按 AGENTS.md 要求做边界校验（路径穿越、解压预算、归档内容校验），不得因其为"知名注册表"而豁免。

## 6. 明确不借鉴点

1. **明文凭据落盘的凭据处理**：cc-switch 把 API Key 明文写入 CLI 配置文件，与 SkillHub"密钥只进 OS 凭据存储"的硬边界冲突。即使做"供应商配置切换"类功能，也不得照搬。证据来源：手册 5.1、《用户配置与隐私说明-2026-09-10.md》。
2. **本地代理、应用接管、故障转移与计费用量统计**：属于流量代理产品形态，超出 SkillHub"本地 Skill 生命周期管理"定位，不引入。证据来源：手册第 4 章、1.1。
3. **改写宿主工具行为的深度侵入**：写 `skipIntroduction` 跳过引导、写 `primaryApiKey` 同步 VS Code 扩展、Codex OAuth 反向代理、接管模式下改写登录状态字段等，均是对其他工具内部状态的修改，风险与维护成本高且与 Skill 管理无关。证据来源：手册 1.5、Releases v3.20.2。
4. **供应商预设/模型定价/catalog 数据体系**：服务其代理计费与供应商切换，SkillHub 无此消费场景；仅"预设模板降低表单成本"的交互思想可参考，数据本身不搬。证据来源：手册 2.1、5.1、Releases v3.20.2。
5. **SQLite 全量 SSOT 的具体 schema**：只借鉴"SSOT 优先级 + 回填"思想，表结构按 SkillHub 自身领域设计，不照搬其 11 张表。证据来源：手册 5.1。

## 7. 风险与不假设事项

- **不得假设 cc-switch 的能力存在于 SkillHub**：本文记录的任何能力（Skill 发现、哈希更新检测、备份恢复、托盘等）在 SkillHub 中只有写入规格、实现并通过自动化与人工验收后才算具备；借鉴清单（§5）不是现状描述。
- **版本时效**：手册文档版本为 v3.16.0（2026-05-29），仓库已发布至 v3.20.3（2026-09-11）；v3.16→v3.20 之间的行为差异本文未逐项核对，引用手册结论时注意版本差。发布说明结论（如 v3.20.2 的预设与修复条目）经摘要转述，未逐条核对原始 diff。
- **未证实事项汇总**（不做任何推断）：内置三个 Skill 仓库的具体 owner/repo 指向；密钥在 SQLite 内的存储形态与是否加密；OS 凭据存储集成；切换供应商的全局快捷键；工具安装状态的自动探测逻辑；遥测/数据上传策略；自动更新完整流程。
- **品牌与素材边界**：本文不包含其 logo、截图与代码片段；交互描述为文字提炼。后续任何 UI 借鉴须自行设计实现，不得复制其视觉资产。
- **社区指标波动**：star 数、发布节奏随时间变化，本文数值仅代表 2026-09-11 查询时点。
- **交叉印证的局限**：内部规格文档基于 v3.19.x 源码，与其后版本可能存在偏差；引用其结论（如发现不落库、分支回退）时以官方手册可证实部分优先。
