# 应用内更新功能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Each Task must be completed and committed independently.

**Goal:** 在 Windows 和 macOS 上提供应用内检查、下载、校验、自动重启、启动失败回滚的更新闭环，同时保持未签名/未公证版本的安全边界。

**Architecture:** 核心层定义发布清单、资产选择、更新状态和校验结果；适配层负责 HTTPS 清单与资产下载；ApplicationFacade 编排策略、缓存、临时文件和回滚记录；Tauri 桌面层负责平台安装器启动与重启；React 设置页负责进度、确认和失败恢复交互。首次安装继续使用 NSIS/DMG，应用内更新使用 Tauri updater artifact。

**Tech Stack:** Rust workspace、skillhub-core API/Specta、reqwest、SQLite、Tauri 2 updater、React/Vite、Vitest、Node release scripts。

**Spec:** `docs/superpowers/specs/2026-08-31-应用内更新功能设计.md`

## Global Constraints

- V1 不包含静默安装、强制升级、后台常驻服务或任意第三方下载源。
- 只信任固定官方 HTTPS 发布源；不接受用户输入的下载 URL。
- 更新包必须校验版本、平台/架构、大小、SHA-256 和 Tauri 更新签名。
- 用户确认后才启动安装；系统安全提示由 Windows/macOS 负责。
- 失败只恢复应用程序，不回滚用户 Skill、数据库或其他用户数据。
- 私钥、API Key、用户路径和更新包不提交 Git、不进入日志或备份。
- 所有 Rust 行为先写失败测试；前端通过 ESLint、TypeScript、Vitest 和生产构建。
