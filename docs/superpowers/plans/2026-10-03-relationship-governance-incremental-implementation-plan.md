## 4. 具体增量锚点

### A：后端

- `crates/skillhub-core/src/relationship/governance.rs`：新增/替换统一治理分类与管理投影；readiness仅保留旧契约兼容，不再决定完成、接管或动作可行性，动作依统一action_conditions。正常来源不再自动完成。同主体同物理入口归并记录证据来源，独立副本保留决定重启稳定。
- `source_copy.rs`、`validation.rs`、application `relationship_validation_service.rs`：替换外部缺失自动归档；最近确认的管理状态与当前入口健康分别记录。历史旧归档兼容明确处理，不盲目复活旧结束记录。
- application `relationship_governance_service.rs`、`relationship_governance_batch.rs` 和相关命令：优先复用安全转换、预览/提交/回滚；补足内容选择、恢复入口、明确结束及保留撤销；读模型不能同时发出两条同物理目标待办。
- database 关系/来源/部署 repositories 与 queries：增量持久化/迁移或投影证据兼容，SkillId 身份不变，既有用户文件不删。
- pending_workspace、删除/版本门面：从新关系事实派生事项；一确认删除链接与主体，独立副本保护，操作失败/恢复仍归原模块；上游更新不加入治理。
- 使用生成工具更新 `bindings.ts`，不手改。无法复用现有执行链时向 Leader 报告确切冲突与最小方案，不自行改产品范围。

### B：前端

- governance API、projection、board/table presenter 和页面：按真实 DTO 统一判定，顶部全部/待处理/已完成，二级管理状态和具体原因明确，保留当前看板风格。过去的四列/readiness 操作映射必须按新规则替换。
- 卡片/表格共享说明与按钮，批量入口先聚合同类可执行范围，再预览/确认；多源事实不是“混合类型所以不能一键”的永久借口，必须按实际动作/安全条件分组。
- import summary 提供本批接管与稍后处理入口，不暴露 candidateId；显示受限原因、没有命令支持的动作不能伪成功。
- pending、Skill 主体删除/版本影响、抽屉与详情页面：更新精确入口和一致反馈，不复制后端状态机；更新失败不消除原事项。
- i18n 内容以用户语言表达，名称/路径/说明可读、完整 tooltip 不含技术 ID。使用 UI skills、主题 token 与已确认尺寸，不替换整体主题或视图结构。
