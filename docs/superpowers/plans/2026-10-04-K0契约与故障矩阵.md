## 2. 统一预览绑定模式（K1/K3/K6 共用）

沿用部署批次已验证的形态，禁止各包自造第二套：

```
Prepare 阶段返回：preview_id, expires_at, confirmation_fingerprint, <载荷>
Commit 阶段输入：preview_id + 用户决定
Commit 执行前重核：载荷指纹（内容身份/当前指针版本/上游头）与指纹一致；
                  预览过期（expires_at 已过）→ 拒绝，提示重新预览；
                  身份漂移 → OperationConflict，禁止继续破坏性提交。
```

- 指纹内容按包定义：K1=（skill_id, 当前 version_id, 目标 version_id）；K3=（所选 skill+version 的内容身份序列）；K6=（skill_id, 当前 version_id, 上游候选身份）。
- `expires_at` 由后端生成；前端展示过期后必须走重新预览，不得静默重试提交。
- 预览状态允许内存暂存，但**破坏性提交**（K2 删除、K3 导出落盘、K6 覆盖采纳）的已确认状态必须有持久化依据（journal 或专用表），重启后提交被拒绝而非误放行。

## 4. K1—K6 契约与故障矩阵

### K1 版本采用可恢复闭环（A 后端 + B 前端）

**命令/查询契约**

1. `SetCurrentVersion`（改造，提交增加后端生成的 `preview_id` 绑定；所有外部调用方同步迁移）：
   - 增加 `journal_begin("set_current_version")` 全程 journal。
   - 成功路径补 `database.record_current_version(request.skill_id, &version)`（对齐 `save_markdown_content_flow:5349`）。
   - 物化失败时恢复可见树（见故障矩阵），不能只恢复指针。
   - 目标版本缺少基础检查记录时触发基础检查重跑（确定性检查，非 LLM）。
   - 提交前重核预览中的主体、当前版本、目标版本和全部实际影响；过期／身份变化拒绝。不保留绕过预览的 UI／IPC／CLI 破坏性提交路径；内部版本采用服务复用安全执行，不为此创建第二套动作。
2. `ReadMarkdownFile` 增加字段 `version_id: Option<VersionId>`：None=当前版本；Some=精确读取历史版本（供历史查看与恢复核对）。所有现有调用方不传即兼容。
3. 新查询 `GetRollbackImpact { skill_id, target_version_id }` 返回 §2 的预览绑定字段及真实影响：哪些受管链接跟随当前版本、哪些独立副本保持、哪些身份异常／受限、目标版本是否缺基础检查记录。实现读取真实关系、文件身份与检查记录，禁止常量。正常产品不提供固定旧版本派发；移除要求新增 `pinned` 能力的契约及夹具。存量版本钉住记录只按兼容／异常事实显式核验，不静默删记录或把独立副本标成固定版本派发。
4. B 侧：安全面板查询键改用具体 `version_id`（来自当前版本结果），版本切换/保存/回滚后失效刷新；删除 `versionId="current"` 读取。

### K2 共享目标回收与多目标删除恢复（A 后端 + B 前端）

**命令/查询契约**

1. prepared 状态持久化：`RemovalService.prepared` 从内存 HashMap 改为基于操作日志的持久化（journal Prepared 相位 + 影响载荷），或专用表（A 在批次报告给出最终字段定义并说明迁移）；重启后 `commit_*` 对不存在的 prepared 拒绝并要求重新预览（行为与现状一致，但**已确认决定**不得因重启丢失——持久化内容含用户已给出的共享目标决定）。
2. `commit_delete` 逐项结果：不再 `?` 中断；逐项执行并收集，返回结构扩展为逐项 `applied/failed(error_code)`（形态对齐 `RelationGovernanceBatchOutcome`）；全部关系处理成功才执行 `delete_skill`；任一失败→登记恢复候选（含剩余待处理项与已处理项），prepared 保留可续作；重试必须先重新 prepare（重新核对身份），不允许盲重放。
3. `apply_decision` 前置校验：沿用现有 `RemovalDecision`，不新增未经权威规范授权的 `convert_to_copy` 复制回退。影响要求共享决定且执行 `RemoveOwnedTarget` 时，`CommitUndeploy`／相应 `RemovalChoice` 必须携带 `confirm_shared_target_removal=true`（缺省 false，拒绝执行）；显式确认仍须绑定并重核全部消费者／物理入口影响。保留共享入口等决定按真实安全动作执行，不静默默认移除；存在实际集中库链接未安全解决时阻断主体删除。
4. B 侧：`governance/nativeApi.ts` 把共享决定透传进提交载荷；`removal/nativeApi.ts` 删除影响查询失败必须可见失败并停止流程，不得回退 `target_id`。

**故障矩阵（K2）**

| 故障 | 系统行为 | 用户可见 |
| --- | --- | --- |
| prepared 丢失/过期 | 拒绝提交，要求重新预览 | 「预览已失效，请重新确认」 |
| 共享目标无显式决定 | OperationConflict，不执行任何删除 | 需补共享决定 |
| 第 N 项删除失败 | 前 N-1 项保留已执行结果，登记恢复候选；中央 Skill 不删 | 逐项结果面板：成功项/失败项+原因；提供「继续处理」入口（重新 prepare） |
| `delete_skill` 失败 | 关系决定已执行、中央仍在 → 恢复候选记录该不一致 | 明示「目标已回收，中央 Skill 未删除」及恢复入口 |
| 重启后重试 | 从持久化 prepared/journal 读取剩余项，重新核对后继续 | 同上，不重复已成功项 |

**RED 测试（A）**：共享部署+缺显式决定→OperationConflict；3 目标中第 2 项失败→结果含逐项状态、恢复候选存在、第 1 项不重放；prepared 持久化后新建服务实例（模拟重启）commit 被拒；含用户决定的 prepared 重启后保留决定。
**RED 测试（B）**：共享目标对话框决定出现在提交载荷（断言不再硬编码）；影响查询失败→确认按钮禁用+错误可见；逐项结果渲染成功/失败分列。

DTO 落点：扩展现有 `DeploymentRemovalResult` 的逐项执行结果／错误，不建立另一份互相矛盾的结果列表；`RemovalResult` 附中央删除错误及恢复引用。执行状态沿用既有批次完成／失败／受限语义，不是新关系状态。字段命名与兼容序列化由 A 交提案，经主代理复核后生成绑定。

### K3 导出全量资产扫描与预览绑定（A 后端 + B 前端）

**契约**

1. `ExportService::prepare` 扫描范围扩展为所选版本物化树全部文件（skill.content + 资产/脚本/配置/.env 等），规则保持确定性：现有内容模式 + 敏感文件名模式（`.env`、含 key/secret/token/credential/id_rsa 的文件名）；不得引入 LLM。
2. `PrepareStandardExport` 返回 §2 三件套；`CreateStandardExport` 输入仅为必需 `preview_id` 与用户决定，实际输入取后端保存并扫描的内容快照，不再接受可篡改的完整 `input`。指纹覆盖选定主体／版本、全部文件字节、格式和授权输出位置；prepare 从真实版本存储核验，不相信前端传入文件充当真实版本。提交重核版本／内容／授权，漂移或过期拒绝并重新预览。
3. B 侧：`DataProtectionPage` 预览后冻结选择（修改选择即作废预览并提示重新预览）；扫描结果按「文件+原因」呈现（内部枚举映射为用户事实文案）。

**故障矩阵（K3）**：扫描单文件失败→整体失败不静默跳过（列出失败文件）；预览过期→拒绝创建；落盘失败→清理半成品归档文件，报告失败。

**RED 测试（A）**：夹具版本含 `.env`（含 token）与脚本（含 sk-）→ sensitive_items 覆盖这两个资产文件；预览后变更选择→Create 拒绝；过期→拒绝。
**RED 测试（B）**：预览后修改选择→预览作废提示；扫描结果渲染资产文件名+原因。

DTO 落点：导出专用 `ExportSensitiveItem { skill_id, version_id, path, reason }`，`path` 为经校验的版本内相对路径；不为此污染备份共享敏感项模型。旧直接 create 调用方同步迁移，不提供缺预览或重新传入未扫描文件的绕过路径。

3. 新命令 `ValidateMarkdown { path, markdown }` → 确定性校验（路径合法、大小上限 1 MiB、非空），返回结构化问题列表；无 LLM。
4. 保存（覆盖当前）仍走 `SaveMarkdownContent`（已闭环）；成功后后端清除对应草稿；保存失败草稿必须保留（不丢用户输入）。保存（另存）走 K5 扩展后的 `SaveMarkdownAsCopy`。
5. B 侧：`MarkdownWorkspace` 切 Tab/文件前保存草稿、返回时恢复；`MarkdownEditor` 启用真实 facade；离开保护=应用内路由守卫 + 关窗前提示（有未保存草稿且内容非空时触发）；保存对话框按操作模型 §7.2 合并「覆盖/另存」与身份冲突处理。

**故障矩阵（K4）**：草稿写失败→编辑器保留内存内容+可重试；保存失败→草稿保留+错误可见；身份冲突→提供「重新加载/另存为副本」，不静默覆盖。

**RED 测试（A）**：Save→新 facade 实例（模拟重启）读到草稿；Discard 后读 None；SaveMarkdownContent 成功后草稿清除；Validate 对超限/非法路径返回确定性错误。
**RED 测试（B）**：输入→切 Tab→返回内容恢复；有草稿时路由离开被拦截且可选择留下/放弃；验证错误渲染；保存失败后草稿仍在。

### K5 复用修改与替换继承（A 后端 + B 前端；依赖 K1+K2+K4）

**契约**

1. `SaveMarkdownAsCopy` 扩展（新字段，旧调用方迁移）：
   - `origin: Option<SaveAsCopyOrigin>`：`{ source_skill_id, source_version_id }`。
   - 创建分支始终生成独立新主体和首版本；原主体、旧版本、网络来源保留，新主体不自动继承网络来源。覆盖原主体继续走 `SaveMarkdownContent`，不混入本命令。
   - `inheritance`：不继承，或替换继承预览中明确选定的受管目标。替换成功的旧使用关系结束到历史，新主体建立并核验新关系；未选择目标不变。共享物理入口只操作一次并列出全部消费者，不能仅复制账目。具体 DTO 由 A 按现有关系预览／执行契约提交，B 不自行定义第二套流程。
   - `target_display_name: Option<String>` 只作展示名称，不能改真实运行时名称来规避目标占用。集中库同名主体合法；只有具体目标的有效名称冲突才按 §9 核验和阻断／预览替换，不加集中库名称唯一约束或静默 `(copy)` 后缀。
2. 血缘：ReuseModify 经现有关系设施登记「来源 skill+version → 新 skill 首版本」有向事实；查询侧在 `SkillResult`/详情查询暴露上游谱系（MS-04）。
3. 伪独立分支入口移除（MS-06/决策 D4），已有伪分支通过编辑保存链路收回（§17.1）。
4. B 侧：保存对话框先选覆盖原技能／创建新技能；创建分支仅提供替换继承／不继承及明确目标预览。保存成功后详情/列表刷新并定位新主体、展示上游谱系，不渲染“同主体元数据继承”三模式。

**故障矩阵（K5）**：目标占用／身份漂移→核验报错，不改入口；创建／血缘失败→按 journal 补偿，保留原主体；所选目标替换中途失败→记录真实逐项结果和恢复依据，不宣称全部继承／全部回退，不重复已成功目标。只有核验能安全补偿时才回滚新主体，不删除仍被已成功替换目标使用的新主体。

**RED 测试（A）**：创建产生独立主体+首版本+可查询血缘且不继承网络来源；不继承保留原关系，替换继承只改所选真实受管入口、旧关系进入历史；集中库同名允许，目标占用／未知所有权阻断；共享目标一次物理操作；创建／血缘／第 N 个目标替换失败可恢复且不误删原主体或仍在使用的新主体。
**RED 测试（B）**：覆盖／创建两分支及创建时的两种继承选择携带真实预览与目标决定；保存后定位新主体并显示上游谱系；伪独立分支入口不再渲染。

### K6 来源身份/候选/采纳闭环（A 后端 + B 前端；依赖 K1）

**契约**

1. `RelinkSource { skill_id, source }`：`source` 为经边界校验与探测后的**已验证来源身份**（规范化 URL/本地路径），后端探测成功才落库；拒绝自由文本猜测（G-15）。本地路径执行既有边界校验（不得越出用户授权范围）。
2. 来源更新采纳改预览绑定（§2）：`PrepareSourceUpdate { skill_id }` → 候选预览（preview_id、expires_at、候选身份=上游提交标识、文件级变更摘要）；`CommitSourceUpdate { preview_id, decision }` 提交前重核当前版本与上游头未漂移；全程 journal，失败按 K1 恢复矩阵恢复可见树。

4. B 侧：采纳成功后失效版本/检查/洞察/详情查询（MS-07）；`SourceRelinkPanel`/`SourceUpdatePanel` 按上述契约改接；「忽略本次更新」收在次要操作位。

**故障矩阵（K6）**：来源探测失败→报错不落库；预览后上游漂移→拒绝并要求重新预览；采纳中途失败→同 K1 恢复矩阵+恢复候选；忽略记录过期→自动清除，不阻塞新候选提醒。

**RED 测试（A）**：非法/不可达来源→错误且 skill 来源不变；Prepare→Commit 间上游漂移→OperationConflict；Ignore 持久化并在采纳后清除；采纳成功产生新版本且四类消费方一致（复用 K1 断言）。
