### Wave 2（中体量）

#### W2-1 跟进 6：来源更新守卫式快速重试

- 行为：来源更新执行失败后，失败记录保留用户决定；重试前重核事实（本地当前内容、上游内容与原预览一致）：一致则按原决定直接重试、免重新预览；不一致（上游更新、本地改动）落回重新预览再确认。重核通过等价于原预览的事实保证。
- **勘察结论（体量下调：中 → 小-中）**：后端已具备核心机制——`commit_source_update`（`crates/skillhub-application/src/lib.rs` ~5386）物理采用失败时预览行**不结算、保持 Prepared**（`settle_content_adoption_failure` 只结算 adoption journal；取数失败注释明确"预览保留，可重试"），同一 `preview_id` 可直接重试，且每次 commit 都重核指针漂移与上游 tree hash；前端 `SourceUpdatePanel.tsx` 已区分两类失败：`SETTLED_PREVIEW_REASONS`（expired/drifted/facts_changed）落 `stale` 态撤下提交入口、其余失败保留预览原按钮重试。
- 剩余缺口（本项实际工作）：①系统核实所有失败点分类并固化为测试（哪些失败保留预览、哪些必须结算落回重新预览，当前只有取数/物理采用两类有注释）；②失败记录（adoption journal）是否保留用户决定的核实与补齐；③前端对"可快速重试"失败展示明确指引（现状仅按钮可点，无"按原决定重试"说明）；④E2E 覆盖失败→快速重试成功路径。
- TDD：后端 RED——①物理失败后同 preview_id+原决定重试成功且不要求重新预览；②失败后上游变化 → facts_changed 结算落回重新预览；③失败后本地指针漂移 → drifted 同。前端——失败提示区分"可按原决定重试"与"事实已变化需重新预览"。
- 判据：失败恢复少一步且不掩盖事实变化；三条不一致路径全部落回重新预览。

#### W2-2 FB-007：批内冲突分组与显式处置（第一期）

- 行为：冲突分析新增"批内"分组：同内容同来源（明显重复）建议合并为一个、其余跳过；同名不同内容要求用户逐个显式处置（独立命名或跳过），不给静默默认、无处置则提交被拒；提交期库或文件再变化则重新确认。第一期先做分组呈现＋同名显式处置，逐个重命名体验后补。
- TDD：后端 RED——①批内同内容同来源 → 分析产出合并建议＋跳过其余；②批内同名不同内容 → 未显式处置时提交被拒，处置（独立命名/跳过）后按处置执行；③提交期文件变化 → 既有预览绑定失效路径重新确认。前端——ConflictResolution 新增"批内"分组与逐项处置控件。
- 判据：批内重复不再静默改名复制；同名不同内容必有用户决定；库内冲突呈现不受影响。

### Wave 3（大体量，最后实施）

#### W3-1 FB-003：安全三级分级＋预警状态（修订后裁决）

裁决要点（2026-10-05 三次修订定稿）：三级分级，**无任何一级无条件硬拦**；危险级决策粒度为**单个 Skill**——导入时对该 Skill 展示具体风险明细，用户显式决策不导入/仍然导入，**不牵连整批导入任务**（其他 Skill 正常导入）；危险级"仍然导入"后进入预警状态，与警告级一致；预警=不可派发+加入待办+三选处理（**完全信任**解除并恢复可派发等操作、**留痕用户决策记录**／不信任删除／稍后处理持续不可派发）；预警与信任绑定内容版本（同版本不重复提示，版本变化重新提示），导入时"仍然导入"与待办"完全信任"的决定均留痕可追溯；分级只基于确定性规则，AI 仅辅助解释、不参与判定；伴生修复：明细完整展示、内部编号不外露、误报回归素材。

实施拆分（每步独立 RED→GREEN，顺序依赖）：

1. **分级规则表**：`security/rules.rs` 现有规则集划分三级（危险/警告/放行），确定性规则、逐条注明分级依据；`BasicScanReport` 携带分级结果。
2. **导入流改造（单 Skill 粒度）**：`enforce_import_security_gate` 现对整个导入候选抛 `CheckBlocked` 阻断整批，需改为按候选 Skill 逐个分级：放行级直接过；警告级提示导入后预警、可直接继续；危险级仅对该 Skill 挂起决策——展示完整明细（file/line/说明、可读名称不外露内部编号），用户显式选择"不导入/仍然导入"；**危险 Skill 的决策不阻断批内其他 Skill 的正常导入**（批内提交拆分为可直接导入项与待决策项，待决策项按用户决定分别导入进预警或跳过）。危险级批量决策的具体交互形态（提交流内联决策或导入完成后补决策）在规范收口时定，不改变上述语义。
3. **预警状态落地**：catalog 记录预警状态并绑定内容版本；`deployment_service` 派发前拦截预警主体（不可派发的确定性行为）；`pending/` 派生待办条目。
4. **三选处理动作**：完全信任（解除预警、恢复可派发等操作，**留痕用户决策记录**）、不信任（删除主体）、稍后处理（留待办、持续不可派发）；三个动作均记录决定与版本，导入时"仍然导入"的决定同样留痕，均可在安全页追溯。
5. **前端呈现**：导入向导风险明细与决策步骤；列表/详情预警标识（可读说明，不只靠颜色）；安全页与待办的处理入口。
6. **伴生修复**：明细完整展示不丢弃；内部编号不外露；建立误报回归素材目录（真实误报样本固化为测试素材，不含用户真实数据）。
7. **AI 边界测试**：断言分级与放行判定不依赖 AI 结果；AI 解释仅作辅助展示（既有 `facade_import_ai_checks.rs` 语义保持隔离）。

判据：任何 finding 都不再无条件堵死导入；批量导入中危险 Skill 的决策不阻断其他 Skill 正常导入；危险级"仍然导入"后不可派发且待办可见；完全信任后恢复可派发且决策记录可追溯；版本内容变化重新进入预警；同版本不重复提示；三个处理动作全链路生效；明细完整、无内部编号外露。

## 5. 顺序、依赖与风险

- Wave 1 三项相互独立，可立即并行；Wave 2 两项相互独立，可在 Wave 1 后或并行（无代码依赖）；**Wave 3 最后**——依赖 W1-3 建立的"检查记录绑定内容版本"机制（预警状态同用版本绑定），且门禁语义变化最大，规范收口先行。
- 风险与边界：
  - W3-1 改变安全门禁语义（拦 → 用户决策），是本轮最大的行为变化；实施前必须完成产品规范收口，避免代码先行。
  - 预警状态新增涉及 catalog 模型、派发门禁与生成绑定，影响面跨 core/application/desktop，需按共享契约单一写入者协作。
  - W1-2 删除级联是"不丢用户文件"边界的已裁决例外（草稿随主体删除），实施与文档表述都要明确这一点，避免被误读为数据丢失缺陷。
  - 全部波次不阻塞当前真机人工验收；人工验收反馈的相关现象按流程登记，作为实施的实例素材。

## 6. 实现对齐：源码级修改方案（2026-10-05 前后端勘察）

> 本节由两路源码勘察（后端链路、前端消费点）汇成，供实施直接对照，避免返工。契约再生成、i18n 双 JSON、nativeErrors 映射三项纪律适用于所有涉及新命令/字段/文案的包，先列共性，再按包落点。

### 6.0 全局共性（每个包都适用）

- **契约链路**：后端命令/查询全部走 `AppCommand`/`AppQuery` tagged enum（`crates/skillhub-core/src/api/command.rs`、`query.rs`）；Tauri 层仅 5 个通用命令，**不需要改 src-tauri**。契约改动后必须运行 `SKILLHUB_WRITE_BINDINGS=1 cargo test -p skillhub-desktop generate_bindings` 重生成 `apps/desktop/src/api/bindings.ts`（ drifted 不符测试会失败），随后扩展 feature 的 `api.ts`（facade 接口）+ `nativeApi.ts`（bindings 适配器）。
- **错误呈现**：新错误码在 `apps/desktop/src/api/nativeErrors.ts` 的 `keyedMessage()` 加映射，并同步 `i18n/en-US/common.json` 与 `i18n/zh-CN/common.json`（单命名空间、点路径、新增键必须两份同步，键类型由 `i18n/index.ts` 绑定 en-US）。
- **发现的两处既有债（不在本轮顺手修，实施涉及该文件时评估）**：`SecurityResults.tsx` risk-aware 分支有硬编码中文（379、412 行）；列表与详情的检查状态枚举不一致（列表 5 态 `skills/api.ts:10`、详情 4 态 `skill-detail/nativeApi.ts:176`）。

### 6.1 W1-1 备份说明

- 后端：**零改动**（`core/backup/` 现范围已不含 `root/drafts`，符合裁决 B）。

  3. core 的 `enforce_security_gate`（`deployment/planner.rs:139-164`）支持挂 `CheckRun` 拦截高风险，但 **application 层从未挂载（全仓 0 处 with_basic_check_run）**，桌面条线惰性；lifecycle（`SkillLifecycle{Normal,Deprecated}`）对派发无任何门禁。

  1. **分级规则表**：`basic-v1.json` 每条规则增加产品级字段（如 `product_level: "danger" | "warning"`，无 finding 即放行级），由 `BasicRule` 携带、`Finding` 透传；**critical/error/warning → danger/warning 的逐条映射表是规范收口的核心交付物**（12 条逐条定级＋依据，确定性规则，AI 不参与）。severity 字段保留不删（兼容既有存储与查询）。
  2. **导入流改造（单 Skill 粒度）**：扫描从 commit 提前到 `prepare_import`（`lib.rs:10326`，在 candidate_tree_hash 之后），`PreparedImport` 保存分级报告；`analyze_import` 查询结果或 prepare 结果携带分级摘要供前端在 conflicts 步骤前呈现。`CommitImport` payload 增加 `security_decision: Option<proceed|skip>`——**仅危险级候选必填**：未携带则该候选 commit 被拒（错误码 `import.security_decision_required`），**批内其他候选不受影响**（前端逐候选独立 prepare/commit 天然隔离；被拒候选在 ImportSummary 落失败行，`finalize_import_batch` 汇总）。警告级直接导入并在结果中预警提示；放行级无感。危险级选"不导入"=前端对该候选不发 commit（或显式 skip），批内其余照常。
  3. **预警状态落地**：新表 `security_alerts`（迁移）：`skill_id, version_id, level, state(alert|trusted|dismissed_later), decided_at, decision_source(import|trust)`——承载预警、版本绑定与**用户决策留痕**（导入时"仍然导入"与待办"完全信任"都写入，`decision_source` 区分；同版本不重复、版本变化新行即重新预警）。列表/详情查询投影带 alert 状态。派发门禁：`get_deployment_plan`（`lib.rs:9537`）与 commit `revalidate` 处检查 alert 表，alert 态 → 新错误码 `deployment.security_alert_blocked`（可读说明，非 planner 的 CheckRun 路径——那条惰性路径保持不动，避免牵动 K 系列已验证行为）。
  4. **三选处理动作**：新命令 `trust_skill_security(skill_id)`（写 security_alerts：state=trusted，留痕）＋复用现有删除流（不信任）＋现有 defer（稍后处理，走 `dismiss_pending_work`）。wire/绑定再生成。
  5. **前端**：导入向导在 conflicts 步骤前插入"安全决策"环节（危险级候选展示完整明细——明细已在 evidence 结构化，需补完整字段透出与可读名称；`nativeErrors.ts:182-184` 现有 import_basic_check 映射改为决策流入口而非失败文案）；列表加"预警"列（`COLUMN_IDS` 体系现成）或并入 security_status 徽标；详情 `DetailStatusRail`（473-478 行 zone-status）加预警徽标、`DetailHeader` 主操作槽加"安全处理"入口；待办 `pending_workspace` 派生 alert 类条目（新 WorkKind），动作映射三选。
  6. **伴生**：明细完整展示=前端渲染全部 findings 字段不丢弃；内部编号不外露=candidate id/finding id 不上 UI（可读名称映射）；误报回归素材=`crates/skillhub-adapters` 测试素材目录固化误报样本（不含用户数据）。
  7. **AI 边界**：既有 `facade_import_ai_checks` 与确定性扫描保持隔离的测试继续有效，新增断言分级/放行判定不读 AI 结果。
