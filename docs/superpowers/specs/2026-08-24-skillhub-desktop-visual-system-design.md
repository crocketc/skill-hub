# SkillHub 桌面端视觉系统设计

> 日期：2026-08-24  
> 状态：用户已确认整体方向，等待书面规格复核  
> 实施依据：[Plan07 桌面体验实施计划](../plans/2026-08-22-skillhub-07-desktop-experience.md)

## 1. 目标与边界

本规格补充 `docs/产品与交互设计.md` 中延后的视觉决策，不改变既有信息架构、业务流程、安全边界和页面职责。

Plan07 继续按 Task 顺序实施。Task 1 只负责设计令牌、可访问基础组件、路由、查询客户端和中英文基础，不提前实现 Task 2 的应用壳层，也不一次性实现业务页面。

## 2. Design Read

`Design Read: local Skill operations · calm, precise, quietly warm · register=product · SOUL=6 · SPECTACLE=2 · DENSITY=8 · hero-engine=none`

SkillHub 是本地生产力工具，不是营销页。界面以清晰、密度、可追溯关系和安全操作为核心。动效只用于反馈状态、层级变化和操作连续性，不使用装饰性动态背景、Hero、颗粒、暗角、巨型展示字体或 WebGL。

应主动避开的默认方案是蓝紫发光的通用 AI/SaaS 仪表盘。蓝紫渐变作为用户明确要求的一个可选主题保留，但只用于强调面，不成为所有主题的默认语言。

## 3. 共享壳层

采用用户确认的 A「平衡工作区」：

- 固定左侧导航宽度为 222px；不使用纯图标导航替代文本标签。
- 顶栏基准高度为 58px，承载面包屑、当前页面上下文操作和全局状态入口。
- 内容区使用 20px 基准内边距、12–16px 面板间距和自适应宽度。
- 默认数据表行高为 40px，属于高密度但不压迫的标准档；紧凑和舒适密度作为用户偏好保留。
- 右侧快速抽屉覆盖内容区而不改变列表布局。关闭后恢复触发元素焦点，并保留筛选、选择、滚动和列状态。
- 小窗口降低内容列数，但不缩小关键文字或交互目标；主要交互目标在触摸语境下不小于 44px。

左侧导航顺序保持权威产品设计：

1. 概览
2. 技能库
3. 发现
4. Agent
5. 项目
6. 待处理

底部固定“操作记录与恢复”和“设置”。“导入”继续作为技能库与发现页面中的主操作，不增加顶级导航项。

## 4. 信息密度与组件造型

默认密度为 8/10，面向 100–300 个技能的本地工作区：

- 字号采用固定产品级阶梯：12、14、16、18、20、24px；界面标签使用系统无衬线字体，代码、路径和数据使用等宽字体。
- 间距采用 4px 基准阶梯；面板边界使用低对比透明细线和带主题色倾向的轻阴影。
- 圆角和阴影在所有主题中保持一致。主题切换不得改变组件形态、布局或信息密度。
- 状态始终使用图标或文字配合颜色，不生成综合健康分，也不把“未知”“未检查”或“无数据”表现为失败。
- 生命周期、部署、版本、基础安全检查、AI 安全检查、所有权和待处理状态使用独立语义角色。

## 5. 多主题系统

主题是完整协调配色，不是强调色选择器。每套主题同时定义页面、表面、嵌套表面、主次文字、边界、强调色、强调色文字、焦点环和带色阴影。

| 主题 | 明暗属性 | 视觉方向 | 代表色 |
| --- | --- | --- | --- |
| 中性苔 | 明亮 | 默认；冷静、耐看、略带自然温度 | page `#eef0ec`, accent `#3f7259` |
| 春信绿 | 明亮 | 参考微信与 Tencent WorkBuddy 的明快绿色气质 | page `#edf8f1`, accent `#19a95b` |
| 陶土橙 | 明亮 | 参考 Claude 的温暖纸张与陶土气质 | page `#f5eee7`, accent `#d7653b` |
| Codex 白 | 明亮 | 暖白主面、墨黑反差，装饰色最少 | page `#f3f3f0`, accent `#151614` |
| 深海蓝 | 明亮 | 参考 DeepSeek 的理性钴蓝与冷灰气质 | page `#edf2fa`, accent `#3d63d8` |
| 樱霞粉 | 明亮 | 灰粉纸面与莓粉强调，轻盈但不幼态 | page `#f8eff2`, accent `#d45e88` |

### 5.1 外观设置兼容

保留产品设计要求的“跟随系统、浅色、深色”：

- 跟随系统：系统浅色使用“中性苔”，系统深色使用“Grok 夜”。
- 浅色：固定使用“中性苔”。
- 深色：固定使用“Grok 夜”。
- 手动主题：用户可选择上述九套固定主题；每套主题自带明暗属性，不再叠加第二个明暗开关。

主题偏好持久化。首次启动默认跟随系统；无法读取系统偏好时使用“中性苔”。

### 5.2 语义令牌

Task 1 使用三层令牌：

1. 原始值：色阶、间距、字号、圆角、时长。
2. 语义角色：page、surface、surface-muted、text、text-muted、border、accent、on-accent、focus、success、warning、danger、info。
3. 组件角色：按钮、输入框、抽屉、确认框、状态徽标和数据状态。

业务组件不得直接引用某一主题的十六进制颜色。功能状态色独立于主题强调色；当绿色或橙色主题与成功或警告状态接近时，必须通过文字、图标、明度和边界共同区分。

## 6. 动效与可访问性

- 使用系统减少动态效果设置；减少动态时抽屉和页面切换不使用位移变换。
- 普通模式只允许短时 `opacity` 与 `transform` 反馈，无弹跳、弹性或装饰性循环动画。
- 每套主题分别验证正文、辅助文字、焦点环和强调色文字的 WCAG AA 对比度。
- 所有基础组件支持键盘操作、可见焦点、辅助功能名称和正确的焦点恢复。
- 中文与英文资源键集合完全一致；切换语言立即生效，不修改原始 Skill 内容、路径或错误信息。
- Windows 与 macOS 系统缩放下保持可读，避免依赖固定窗口尺寸。

## 7. Task 1 实施与验证

Task 1 按 TDD 进行：先写失败测试并确认失败原因，再实现最小功能，最后重构。

本 Task 的可验证行为包括：

- 抽屉关闭后焦点返回触发元素。
- 系统减少动态时抽屉标记并采用无位移终态。
- 简体中文与英文资源拥有完全相同的键集合。
- 外观模式能够解析为正确的固定主题，并允许九套手动主题覆盖系统模式。
- 基础组件只消费语义令牌，不耦合具体主题色。

验收命令遵循 Plan07 Task 1：

```text
pnpm --dir apps/desktop test --run src/ui/Drawer.test.tsx src/i18n/i18n.test.ts
pnpm --dir apps/desktop build
git diff --check
```
