# SkillHub Task5 Skill 完整详情工作台设计

> 日期：2026-08-26
>
> 状态：用户已确认交互与视觉方向，等待书面规格复核
>
> 实施依据：[Plan07 桌面体验实施计划](../plans/2026-08-22-skillhub-07-desktop-experience.md)

## 1. 目标与范围

本规格定义 Plan07 Task5 的 Skill 完整详情页，包括权威元数据、生命周期、轻量试用、Agent/项目/目录关系、运行要求、安全与重复摘要、外部变化、操作历史和版本时间线。

详情页承接 Task4 的“列表 → 快速抽屉 → 完整详情”三级信息架构。它是单个 Skill 的权威信息入口，但不会提前实现后续任务：

- Task6 负责 `SKILL.md` 安全渲染、源码视图和轻量编辑。
- Task9 负责完整部署、安全问题处置、归档、删除和恢复工作流。
- 真实后端详情聚合契约需要后续经 Rust/Specta 冻结和生成，Task5 不手工维护 bindings 副本。

## 2. Design Read

`Design Read: local Skill lifecycle tool · restrained, reliable, precise · register=product · SOUL=5 · SPECTACLE=1 · DENSITY=8 · hero-engine=none`

详情页是高密度桌面工作台，不是营销页。视觉优先级依次为当前状态、对象身份、风险依据、关系和历史。页面只使用反馈性动效，不使用装饰性动画、玻璃效果、渐变文字、品牌页大标题或英雄视觉引擎。

现有九套完整主题继续只改变语义配色，不改变页面结构、组件造型、字号层级或交互方式。主题包括中性苔、明亮绿色、陶土橙、Codex 白、深海蓝、樱花粉、蓝紫渐变、咖啡和 Grok 深色。

## 3. 已确认的整体布局

采用用户选择的 B「锚点导航 + 连续主内容 + 固定状态轨」：

- 左侧为页内锚点导航，快速跳转到完整信息区段。
- 中间为连续阅读的权威详情，不用大量页签割裂跨区核对。
- 右侧为固定状态轨，展示关键状态和当前最重要的操作。
- 首屏采用用户选择的 A：优先回答“这是什么、现在是否正常”，而不是直接打开 `SKILL.md` 或版本历史。
- 主操作采用用户选择的 A：根据当前状态只突出一个主操作，低频和高风险操作进入“更多”。
- 可编辑元数据采用用户选择的 A：每个信息区独立进入编辑、保存或取消，不让整页同时变成表单。
- 版本历史采用用户选择的 A：纵向时间线默认显示变化摘要，需要时再展开或进入完整比较。
- 回滚采用用户选择的 A：在时间线中展开影响预览，确认事实和影响后再提交。

## 4. 路由和列表上下文

完整详情路由为 `/library/:skillId`。

从技能库进入详情时，保留原列表的搜索、筛选、排序、页码、滚动位置和当前 Skill。详情页顶部显示可点击面包屑、Skill 名称/别名、当前版本和相邻 Skill 导航。

“上一个 / 下一个”遵循进入详情前的筛选和排序，不重新按名称建立另一套顺序。切换相邻 Skill 时保持当前详情区段，但将滚动定位到该区段顶部，避免视觉位置落在新 Skill 的错误内容中。

返回技能库时恢复原筛选和滚动现场。直接通过链接进入详情仍能正常工作，但没有列表上下文时不显示虚假的相邻顺序。

## 5. 响应式信息架构

### 5.1 宽屏

宽屏使用三栏：

1. 左侧锚点导航。
2. 弹性主内容列。
3. 固定宽度状态轨。

主操作只出现一次，位于右侧状态轨。页面标题区不复制同一主按钮。

### 5.2 中等和窄窗口

- 中等宽度下，左侧锚点变为主内容上方的粘性区段导航，主内容和状态轨保留两栏。
- 更窄窗口下，状态轨变为标题下方的状态摘要，页面退化为单栏。
- 状态轨折叠后，主操作随状态摘要移动，不能消失或在顶部重复出现。
- 不通过压缩字体、嵌套横向滚动或同时挤压三栏来适应窗口。

## 6. 主内容区段

主内容按下列顺序连续排列：

1. 概览与“我的用途说明”。
2. 原始描述、保存的描述译文和译文状态。
3. 身份、来源、作者、许可证和版权。
4. Agent、项目和物理目录关系。
5. 调用方式、运行要求和声明适用信息。
6. 基础安全检查和 AI 安全检查。
7. 确定性重复、语义重复、相关 Skill、组合和依赖。
8. 外部变化和操作历史。
9. 版本时间线。

使用证据只有在数据可靠时才增加对应区段；没有可靠数据时完全不渲染该区段，不展示空卡片，也不暗示“未使用”。

Task6 完成后，`SKILL.md` 阅读、源码和编辑区插入描述之后。Task5 不预留一个看似可用但没有安全渲染能力的假编辑器。

## 7. 右侧状态轨

状态轨固定展示与决策直接相关的摘要：

- 生命周期和试用剩余时间/复核日期。
- 当前版本、上游更新和本地修改状态。
- 基础安全检查与 AI 安全检查的独立状态。
- 高风险和待处理数量。
- Agent、项目和实际物理部署摘要。
- 当前最重要的主操作。

状态轨不能把“声明要求”表示为“已经安装”，不能把“试用”表示为隔离或验证结果，也不能把 Agent 客户端发现表示为 Agent 已加载或可运行 Skill。

主操作按当前状态选择，例如“添加到 Agent/项目”“正式纳入管理”或“处理待确认事项”。普通次要操作位于紧邻区域，高风险和低频操作进入“更多”并使用专门影响确认，不使用含糊的通用 OK 弹窗。

## 8. 元数据和描述编辑

显示别名、我的用途说明、标签和备注均为独立编辑区。每个区段提供编辑、保存和取消，保存期间只禁用当前区段。

- 原始描述来源于 Skill 内容，只读展示。
- 描述译文是独立保存的数据，展示目标语言、模型、时间和对应版本。
- 原始描述变化后，旧译文标记为“需要更新”。
- 用户修改过的译文标记为“用户修订”，重新翻译前必须确认覆盖。
- 我的用途说明和备注属于本地管理信息，不写入 `SKILL.md`，不影响 Agent。
- 保存失败时保留用户输入并说明可执行的修复或重试方式。

任一保存成功后只刷新相关详情查询，同时使 Task4 的表格行和快速抽屉摘要失效并重新获取。

## 9. 试用和生命周期

轻量试用是标签和复核日期，不创建临时目录，也不改变更新、安全或部署规则。

- “正式纳入管理”只清除试用日期和对应待复核状态。
- “延长试用”只修改复核日期。
- 设置或修改试用日期时显示实际日期，不只显示模糊倒计时。
- 到期不自动删除、归档或解除部署，而是在待处理中心生成“试用待确认”。
- “放弃试用”进入 Task9 的归档、解除部署和安全删除流程；Task5 只产生类型化意图，不伪造删除结果。

生命周期和试用操作成功后刷新详情摘要、Task4 列表/抽屉和待处理摘要。失败时保持原事实和用户输入，不使用乐观状态冒充成功。

## 10. 版本时间线、比较和回滚

版本历史使用纵向时间线。每个节点显示版本、产生方式、日期、基础检查状态和文件变化摘要。版本较多时按月份折叠或分页，不一次渲染无限历史。

用户可以选择任意两个版本进入完整比较。Task5 显示文件级 added/removed/changed 摘要；Task6 接入安全 Markdown 能力后再补充内容级阅读和编辑体验。

点击“回滚到此版本”后，在当前时间线中展开影响预览：

- 将选定旧内容创建为新的当前版本，不删除原有后续历史。
- 列出受影响的未固定部署。
- 明确列出不受影响的项目固定版本。
- 说明回滚后将重新执行基础安全检查。
- 高风险或冲突事实未加载完成前不能提交。

提交期间防止重复操作。成功后刷新版本、详情状态、安全摘要、关系和 Task4 列表；失败时保留影响预览和选择，允许用户修正或重试。

## 11. 前端数据边界

### 11.1 当前契约缺口

现有 Specta bindings 只提供简化的 `SkillResult`、`VersionResult` 和文件级 `VersionDiffResult`，以及 `set_metadata`、`set_trial`、`set_lifecycle`、`set_current_version` 等命令。它不能直接提供 Task5 所需的完整来源、翻译、关系、部署影响、安全摘要、重复分析和操作历史视图。

Task5 不手工扩展 `apps/desktop/src/api/bindings.ts`，也不从不完整字段猜测权威事实。

### 11.2 独立 Facade

采用用户确认的方案 A：新增独立 `SkillDetailFacade`，不把完整详情方法塞入 Task4 的 `SkillLibraryFacade`。

Facade 按面板提供强类型查询和命令边界，包括：

- 首屏详情摘要。
- 元数据和描述信息。
- 关系与物理目录事实。
- 调用方式与声明要求。
- 安全和重复摘要。
- 外部变化和操作历史。
- 版本列表、版本差异和回滚影响。
- 分区元数据保存、试用和生命周期意图、回滚提交。

测试和开发预览注入确定性的 Mock Facade。正式路由在真实合约不可用时使用明确的 unavailable 实现，不能展示伪造用户数据或伪成功结果。

以后接入真实 Rust 能力时，适配器必须消费 Specta 生成类型并通过 bindings 漂移校验；UI 组件、状态模型和行为测试不依赖手写的接口副本。

## 12. 查询、缓存和更新

React Query 只保存服务端事实；用户尚未保存的字段草稿保存在对应面板本地。

- 首屏摘要优先请求，其他面板并行请求，避免串行瀑布。
- 每个面板拥有独立 query key 和独立加载/失败状态。
- 面板失败不会使其他成功信息消失。
- 更新成功后精确失效相关详情 key，同时失效 Task4 的行、快速抽屉和必要汇总。
- 组件不把大型详情对象复制到本地状态，也不使用 Effect 同步可在渲染时派生的值。
- 相邻 Skill 可以预取摘要，但不在首屏预取所有历史、差异或大型关系数据。

## 13. 组件边界

- `SkillDetailPage.tsx`：路由上下文、首屏摘要、锚点联动、相邻切换和面板编排。
- `MetadataPanel.tsx`：描述、翻译、用途说明、身份、来源、许可证和分区编辑。
- `LifecyclePanel.tsx`：生命周期状态及允许的入口。
- `TrialActions.tsx`：设置、延长和转正试用；放弃试用只产生后续流程意图。
- `VersionTimeline.tsx`：纵向历史、选择比较、回滚影响预览和提交状态。
- `RelationsPanel.tsx`：Agent、项目、逻辑目标和物理目录关系事实。
- `RequirementsPanel.tsx`：调用方式、声明要求、适用信息和未验证提示。
- 小型状态轨、安全摘要、重复/外部变化区段放在同一 feature 目录的聚焦组件中，不把所有逻辑写进页面文件。
- `api.ts`：Facade、详情前端模型、query keys、Mock/unavailable 边界和类型化意图。

详情页复用现有 Button、StatusBadge、DataState 和确认基础组件；只有高风险影响预览确实无法由现有组件表达时才新增通用原语。不能在页面内重新实现按钮、抽屉、状态徽章或主题系统。

## 14. 加载、空数据和错误

- 首屏加载使用与最终标题、摘要和状态轨相同尺寸的骨架，避免布局跳动。
- Skill 不存在时说明对象可能已删除或移动，并提供返回原技能库上下文的入口。
- 首屏摘要不可用时显示整页错误和重试。
- 单个面板失败时只在该面板显示错误、原因和重试。
- 无关系、无译文、无版本差异、未运行 AI 检查和无来源分别说明事实与下一步，不显示空白卡片。
- Facade 未接入时显示真实的功能边界，不回退到演示 Skill。
- 保存或操作成功使用 `aria-live="polite"` 的短时反馈；失败使用保留上下文的区域错误。
- 禁用按钮必须同时说明禁用原因，不能让用户猜测。

## 15. 视觉、主题和动效

- 使用现有语义主题变量，不在 feature CSS 中写某套主题的原始颜色。
- 采用紧凑桌面密度、固定产品字号和 4px 间距网格。
- 表面使用轻边界或微弱主题色阴影，不堆叠厚阴影和硬灰色卡片框。
- 一个状态必须同时提供文字/图标和颜色，颜色不是唯一信息通道。
- 动效只服务状态变化、保存反馈和锚点定位，使用短时 opacity/transform。
- `prefers-reduced-motion` 下直接进入终态。
- 九套主题逐一检查正文、辅助文字、状态、禁用态、焦点环和 accent 按钮对比度。

## 16. 可访问性和焦点

- 页面使用连续、可理解的标题层级；锚点导航指示当前区段。
- 锚点、相邻切换、编辑、版本操作和状态轨全部支持键盘。
- 打开编辑后焦点进入首个字段；取消回到原编辑按钮；保存完成回到区段标题或保存按钮。
- 切换相邻 Skill 后焦点回到新 Skill 标题，并通过 live region 说明对象已切换。
- 回滚影响展开后焦点进入影响标题；完成或失败后保持可恢复焦点。
- 不产生主页面滚动、面板滚动和状态轨滚动相互竞争的嵌套滚动陷阱。
- 所有交互目标满足至少 44px 的可操作尺寸，焦点样式在全部主题下清晰可见。

## 17. TDD 与验收

实施先写能表达行为的失败测试，再写最小实现并重构。至少覆盖：

- 原始描述、保存译文和我的用途说明保持独立。
- 分区编辑的保存、取消、失败保留输入和防重复提交。
- 试用转正只清除试用状态，不改变生命周期、内容或部署关系。
- 延长试用只改变复核日期。
- 相邻切换遵循列表上下文，返回恢复筛选和滚动位置。
- 直接路由进入时不显示虚假相邻导航。
- 单个面板失败不影响其他成功区段。
- 使用证据无可靠数据时不渲染。
- 版本时间线、任意两版本选择和文件级差异摘要。
- 回滚影响区分受影响未固定部署与不受影响固定版本。
- 回滚成功、失败、取消和重复提交保护。
- 加载、空、错误、成功、禁用和 Facade unavailable 状态。
- 键盘锚点、焦点恢复、中英文资源和减少动态效果。

Task5 验收命令：

```text
pnpm --dir apps/desktop test --run src/features/skill-detail
pnpm --dir apps/desktop test --run
pnpm --dir apps/desktop check
pnpm --dir apps/desktop build
cargo test -p skillhub-desktop generate_bindings
git diff --exit-code -- apps/desktop/src/api/bindings.ts
git diff --check
```

完成后在桌面窗口中检查中性苔、Codex 白和 Grok 夜主题，并抽查其余主题；分别检查中文/英文、宽屏三栏、中等宽度、窄窗口、键盘焦点、长描述、多版本、独立面板错误、试用到期和回滚影响预览。

## 18. 后续契约任务

真实联调前需要单独冻结并实现：

- 完整 Skill 详情和本地元数据查询。
- 翻译记录与译文保存契约。
- Agent/项目/物理目录关系查询。
- 安全、重复、依赖、外部变化和操作历史摘要。
- 回滚影响准备与提交结果模型。
- 使用证据的可靠性标记和查询。

这些接口不属于 Task5 前端 UI 提交。任何新增合约都必须以需求、本规格和 Rust 核心类型为依据，经 Specta 生成 TypeScript bindings，并通过完整漂移校验。
