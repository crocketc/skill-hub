# SkillHub Plan07 Task6 Markdown 工作区设计

## 目标与边界

Task6 在 Skill 详情中提供安全的 Markdown 阅读、源码查看和轻量编辑闭环。普通用户无需安装外部 Markdown 软件即可查看和修改 `SKILL.md`，但 SkillHub 不扩展为终端、调试器或完整 IDE。

本任务覆盖：

- `SKILL.md` 及同一 Skill 内其他 Markdown 文件的文件列表与切换。
- CommonMark、GitHub Flavored Markdown、YAML Frontmatter、任务列表、表格、引用、脚注、删除线、代码块、相对链接和本地图片的阅读体验。
- 危险 HTML、远程图片、外部链接和 Mermaid 的安全边界。
- 可编辑 Skill 的源码编辑、分栏预览、撤销重做、搜索替换、行号、基础高亮和 Frontmatter 提示。
- 本机草稿、显式校验与保存、保存后形成版本的接口边界。
- 只读内容的预览、复制接管和外部打开入口。

本任务不实现复杂多文件重构、脚本和非 Markdown 编辑、升级冲突合并、代码执行、终端、调试或 AI 内容生成。真实文件系统命令尚未接入时，生产路由必须明确显示不可用状态；可交互样例只存在于隔离的开发预览中。

## 产品布局

Markdown 工作区嵌入 Skill 详情的“说明”章节，位于描述和译文信息之后。它保持现有详情页的左侧章节导航、连续内容区和右侧状态栏，不改变全局组件造型。

工作区采用高密度产品界面：

- 顶部工具栏左侧显示当前文件和 Markdown 文件选择器，右侧显示“阅读”“源码”“编辑”模式及外部打开菜单。
- 阅读与源码模式使用单栏，编辑模式默认左右分栏，窄窗口收敛为“编辑 / 预览”切换。
- 编辑器上方只保留保存状态、搜索替换和显式保存等高频操作，不堆叠 IDE 工具。
- 草稿、校验问题、只读原因和保存结果靠近操作位置展示，不依赖瞬时通知表达关键状态。

## 组件与职责

### `MarkdownWorkspace`

负责文件选择、模式切换、权限状态、查询状态和各子组件编排。它只通过 `MarkdownFacade` 读取或改变数据，不直接访问 Tauri、文件系统或浏览器全局对象。

### `MarkdownRenderer`

将 Markdown 解析为安全 React 节点。解析和展示不修改原始 Markdown；未知扩展语法在源码与编辑模式中保持原样。渲染器不执行脚本、事件属性或代码块内容。

### `MarkdownEditor`

使用 CodeMirror 提供源码编辑能力。编辑值首先写入本机草稿接口；显式保存前调用校验接口，只有没有阻断问题且用户确认保存时才写入正式 Skill。保存成功后刷新文件内容、版本和安全检查摘要。

### 安全子组件

- `ExternalLink` 展示真实外部地址，用户确认后才交给系统浏览器。
- `RemoteImage` 默认只显示被阻止的域名，用户单次确认后才加载；确认不形成全局永久白名单。
- `MermaidBlock` 动态加载 Mermaid，使用严格安全模式，渲染失败退回普通代码块；图表链接仍经过统一外链确认。
- `sanitize.ts` 负责 URL 分类、Skill 内相对路径约束和允许的 Markdown/HTML 安全策略。

## 数据契约

前端定义独立强类型 `MarkdownFacade`：

- `listMarkdownFiles(skillId)`：列出 Skill 内可查看的 Markdown 文件。
- `readMarkdownFile(skillId, path)`：读取内容、可编辑性、只读原因和内容身份。
- `saveDraft(skillId, path, markdown)`：保存本机草稿，不建立版本。
- `discardDraft(skillId, path)`：丢弃本机草稿。
- `validateMarkdown(skillId, path, markdown)`：返回 Frontmatter、格式和引用问题。
- `saveSkillContent(skillId, path, markdown, expectedIdentity)`：显式保存并返回新版本标识。
- `openDefaultApplication`、`chooseExternalApplication`、`openSkillFolder`：发出外部打开意图。
- `requestTakeover`：只读或外部 Skill 的复制导入/接管意图。

保存携带读取时的内容身份，避免静默覆盖外部变更。身份冲突返回明确错误并保留草稿，由后续外部变更流程处理。

## 安全策略

- 原始 HTML 默认不作为可执行 DOM 注入；白名单之外的标签和所有事件属性均不渲染。
- `javascript:`、`data:` 等危险 URL 被拒绝。外链必须为允许的 `http` 或 `https` 地址并显示完整目标。
- 相对资源解析后必须仍位于当前 Skill 根目录内；越界路径显示为不可用引用。
- 远程图片默认不发起网络请求。用户确认只影响当前图片、当前视图会话。
- 本地图片由受控资源解析接口提供，不直接拼接不可信文件 URL。
- 代码块只展示和复制，永不执行。
- Mermaid 采用动态导入、严格模式和失败回退，不允许绕过外链策略。

## 草稿、校验与保存流程

1. 打开文件时并行读取正式内容和可用草稿；存在草稿时明确提示恢复或丢弃。
2. 编辑仅更新 CodeMirror 状态，并通过去抖后的 `saveDraft` 保存本机草稿。
3. 用户点击“保存并创建版本”后调用校验；阻断问题留在编辑器内并聚焦问题摘要，警告可由用户明确继续。
4. 正式保存携带内容身份。成功后清除草稿并精确刷新 Markdown 内容、Skill 版本与安全摘要。
5. 网络、权限、身份冲突或保存失败均保留编辑内容和草稿，不显示虚假成功。

## 性能与可访问性

- Markdown 解析器和编辑器直接按模块导入；较重的 Mermaid 运行时只在出现 Mermaid 代码块并请求图表时动态加载。
- 独立文件查询并行启动，避免模式切换产生串行请求。
- 长代码块横向滚动并支持折叠，长文档使用 `content-visibility` 降低非可视区域渲染成本。
- 模式切换使用选项卡语义，文件选择和工具操作支持键盘；焦点在保存错误后回到问题摘要，在确认对话框关闭后返回触发元素。
- 编辑器与预览具备明确名称，状态使用适当的 `status` 或 `alert`，颜色不作为唯一状态标识。
- 主题全部复用现有语义令牌，只改变配色，不改变组件形状。

## 测试策略

严格按 TDD 分阶段实现：

1. URL 分类、路径约束和危险内容过滤的纯函数测试。
2. GFM、Frontmatter、代码块、远程图片、外链确认和 Mermaid 回退的渲染测试。
3. 草稿不建立版本、显式保存才建立版本、校验阻断、失败保留草稿和身份冲突的编辑器测试。
4. 阅读/源码/编辑切换、文件切换、只读状态和外部打开意图的工作区测试。
5. Skill 详情集成、生产不可用与开发预览隔离测试。
6. 中英文键一致性、ESLint、TypeScript、Vitest、生产构建和差异检查。

## 验收标准

- 不可信 Markdown 不能执行脚本、事件处理器或危险 URL。
- 远程图片在确认前不产生请求，外链在打开前展示真实目标。
- 编辑过程不会修改正式 Skill；只有显式保存才形成新版本。
- 只读 Skill 不提供原地保存入口。
- 保存失败、校验失败和身份冲突不会丢失草稿。
- 阅读、源码和编辑模式可通过键盘完成核心操作，中英文文案完整。
- Markdown 工作区集成到 Skill 详情，Mock 预览与生产数据边界清晰。
