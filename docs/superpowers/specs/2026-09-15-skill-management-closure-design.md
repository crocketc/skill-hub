# Skill 管理闭环设计（2026-09-15）

状态：用户已确认设计范围，待拆分实施计划；当前不包含 v0.3.0 图谱画布实现。

## 1. 目标与版本边界

当前版本必须完成 Skill 管理闭环：

```text
发现目录/Skill → 导入集中库 → 识别关系与冲突 → 用户决策
→ 部署/替换部署方式 → 移除部署或收敛共享关系 → 回退与审计
```

当前版本包含：

- Agent 原生目录、通用 `.agents/skills`、项目目录和集中库之间的关系识别；
- 单 Skill 和批量导入的关系治理；
- 原生部署、通用目录直接读取、通用目录链接引用、复制部署和 SkillHub 管理链接的区分；
- 部署、移除部署、复制转管理链接、共享关系收敛和回退；
- 同名不同内容的确定性冲突分组、用户批量裁决和可选 AI 分析；
- 未决冲突、识别未知和共享影响的持久化待办。

v0.3.0 只负责基于本版本关系数据构建 Skill 图谱的视觉展示与图谱交互，不重新设计或重新扫描关系模型。

## 2. 核心语义

### 2.1 目录角色

SkillHub 集中库是顶层管理库。其他目录均是下属目录节点：

- Agent 原生目录：某个 Agent 自己声明并读取的目录；
- 通用共享目录：例如 `~/.agents/skills`，作为独立的“通用 Agent/共享目录”卡片展示；
- 项目目录：项目范围内的 Skill 目录；
- 集中库目录：SkillHub 的权威管理副本。

`.agents/skills` 的“目录存在”与“Agent 是否能读取”必须分开建模。每个 Agent 需要有目录识别能力和优先级证据：

- `supported`：已由官方资料或真机确认；
- `unknown`：尚未确认，不得推断；
- `unsupported`：已有证据表明该 Agent 不读取该目录。

### 2.2 关系类型

文件复制和部署链接不能混为一种关系：

- `import_copy`：Agent/共享目录 → 集中库的导入快照。导入后源目录继续保留；
- `shared_directory_read`：Agent 直接读取通用共享目录；
- `shared_directory_reference`：Agent 自有目录中的链接指向通用共享目录；
- `managed_copy`：集中库 → Agent 目录的 SkillHub 管理复制；
- `managed_link`：集中库 → Agent 目录的 SkillHub 管理链接；
- `observed_copy`：扫描发现的非 SkillHub 创建复制副本；
- `observed_link`：扫描发现的非 SkillHub 创建链接。

文件系统表示还要单独记录“复制副本”，不能仅依赖关系类型推导；链接的文件系统表示分为符号链接和 Windows 目录联结，但用户界面统一显示为“链接部署”，详情中保留技术类型。

### 2.3 部署关系的用户语义

Agent 页面和导入页面都必须明确显示以下三类来源：

- **Agent 原生部署**：当前 Agent 自有目录直接存在 Skill；
- **通用目录直接读取**：Agent 直接识别 `.agents/skills` 中的 Skill；
- **通用目录链接引用**：Agent 自有目录通过链接引用 `.agents/skills` 中的 Skill。

移除操作先计算影响范围，再给出动作：

- 原生部署：默认只影响当前 Agent；
- 通用目录直接读取：可能影响所有识别该目录的 Agent；
- 通用目录链接引用：默认只移除当前别名，但通用目录本体和其他引用保持不变；
- 已有复制副本：可保留，或备份校验后替换为集中库管理链接；
- 已有非 SkillHub 链接：可保留，或在确认影响后替换为集中库管理链接。

将通用目录引用收敛到集中库时，必须是“建立集中库 → Agent 的新链接、验证 → 移除旧的通用目录入口”的替换操作，不能留下两个同名入口。通用目录本体只有在没有其他消费者且用户明确确认时才允许清理。

## 3. 关系数据模型

当前版本建立可供 v0.3.0 直接读取的规范化关系数据，但不实现图谱画布。

### 3.1 目录节点与识别能力

新增目录节点概念，至少包含：

- 稳定 ID、规范化路径和平台路径键；
- 目录角色：集中库、Agent 原生、通用共享、项目；
- profile/client 实例归属；
- 是否存在、最近观察时间和扫描来源。

新增 Agent 目录识别记录，至少包含：

- Agent/client ID；
- directory node ID；
- 识别状态 `supported / unknown / unsupported`；
- 目录优先级 `preferred / lower_priority_copy / may_coexist / unknown`；
- 官方/真机证据引用和研究日期；
- 适用平台和范围。

### 3.2 多来源导入存证

现有 `ImportProvenance` 不能继续以 `skill_id` 作为唯一主键，因为一个 Skill 可能来自多个 Agent、共享目录和项目目录。改为一 Skill 多来源：

- 独立 provenance ID；
- skill ID；
- source directory node ID；
- Agent/client ID（可为空）；
- 原始路径和路径键；
- 导入时的关系类型和文件表示；
- 链接目标路径/目标目录（如适用）；
- 来源快照、所有权、内容指纹和导入时间。

`import_copy` 只表示集中库获得了自己的副本，不代表可以删除源目录。

### 3.3 观察部署关系

现有 `ObservedDeployment` 扩展为可解释的路径实例，至少包含：

- source/directory node ID；
- Agent/client ID；
- Skill ID（只有内容已验证时必填，匹配不可靠时为空）；
- 观察路径和路径键；
- 文件表示：真实目录、符号链接、目录联结、复制副本、未知；
- 链接目标路径、目标路径键和目标目录 ID（如适用）；
- 关系类型；
- `skillhub_managed / observed_unmanaged / shared_reference` 所有权状态；
- 内容指纹、匹配状态、观察来源和生命周期。

SkillHub 已创建的部署继续使用现有 `DeploymentRecord`，但前端和关系查询返回统一的关系视图，避免两套用户语义分裂。

### 3.4 冲突组、AI 分析与治理待办

新增冲突组：

- conflict ID；
- 冲突类型：完全重复、同名不同内容、同源分叉、共享目录重复、识别未知；
- 成员：Skill、版本、provenance、目录和路径实例；
- 确定性证据：哈希、运行时名称、来源、作者、版本字段、目录优先级等；
- 当前判定：`same_skill_version / distinct_skill / uncertain`；
- 用户裁决和裁决时间。

AI 分析记录至少包含：

- 分析范围：全部、分类、冲突组、单 Skill；
- 输入内容指纹；
- 确定性基线结论；
- AI 结论、推荐保留版本、推荐动作、证据摘要和置信度；
- 分析来源、时间、失败码和是否已被用户采纳。

AI 结果只提供面向用户的短结论和决策建议，不能自动执行合并、删除或替换。

治理待办至少覆盖：

- 待选择权威版本；
- 待判断同名 Skill 是否为不同 Skill；
- 待确认通用目录影响范围；
- 待将复制副本改为集中库链接；
- 待将通用目录引用改为集中库链接；
- Agent 目录识别未知；
- 操作失败待回退。

## 4. 用户操作链路

### 4.1 单 Skill 导入

导入结果按关系类别分组，不要求用户逐路径点击确认：

1. 完全重复；
2. 内容一致的复制副本；
3. 同名不同内容；
4. 通用目录直接读取；
5. 通用目录链接引用；
6. 识别未知或共享影响未确认。

用户可以对整组执行默认动作，再展开调整单项。每组都显示影响数量、受影响 Agent、源/目标路径和回退方式。

### 4.2 批量导入

批量导入使用同一套关系分类和治理动作：

- 可安全批量转链接的复制副本集中确认；
- 同名冲突按冲突组确认；
- 通用目录关系按共享消费者集合确认；
- 识别未知和未决冲突自动生成待办；
- 批量操作逐项记录结果，支持部分成功、失败重试和回退。

### 4.3 部署和更换链接类型

用户可在 Agent 页面、Skill 详情页和导入结果页进入关系治理组件：

- 集中库 → Agent：优先选择链接部署；符号链接/目录联结由平台能力决定；
- 复制部署 → 管理链接：备份、验证目标、移除原复制入口、建立管理链接、记录审计；
- 通用目录链接引用 → 管理链接：验证 Agent 原生目录优先级和识别能力后进行替换；
- 不能确认优先级或会影响其他 Agent 时，先生成治理待办，不做静默替换。

### 4.4 移除部署

移除前必须返回 `RemovalImpact`：

- 当前关系类型和所有权；
- 当前 Agent 是否直接读取通用目录；
- 其他识别该目录的 Agent；
- 同一 Skill 的其他路径和复制副本；
- 推荐的最小影响动作；
- 可回退内容和备份位置。

只有用户确认后才执行文件变更。共享目录本体不得因单个 Agent 的移除操作被自动删除。

## 5. 前端范围

当前版本不是只补一个迁移按钮，而是实现两个层面的前端改造：

### 5.1 关系治理组件

提供复用组件，至少支持：

- 目录/Agent/Skill 关系矩阵；
- 关系类型和所有权标签；
- 共享影响摘要；
- 冲突分组和批量决策；
- 可选 AI 分析按钮；
- 待办入口；
- 操作预览、确认、进度、结果和回退。

### 5.2 实际页面与操作链路

- 导入向导：导入后关系分类、冲突治理和批量确认；
- Agent 页面：目录识别能力、通用目录关系、每个 Skill 的部署状态和移除影响；
- Skill 详情页：跨 Agent/目录关系和来源存证；
- 通知/任务中心：批量操作、失败项、待办和回退结果。

图谱画布不属于当前版本，但这些页面必须使用统一关系 DTO，避免 v0.3.0 再次改写页面契约。

## 6. 安全与一致性约束

- AI 不替代确定性哈希、路径、所有权和目录识别检查；
- AI 不自动合并、删除、替换或选择权威版本；
- 外部共享目录默认保留，除非影响范围清楚且用户明确确认；
- 替换链接不得留下双入口；
- 删除/替换前必须备份或保留可回退证据；
- 部分成功必须逐项记录，不得用整体成功覆盖失败项；
- 生成的 TS 绑定必须由生成工具更新；
- 所有新增行为按 TDD 覆盖成功、冲突、未知、取消、部分失败、回退和权限受限路径。

## 7. 验收标准

- 能区分 Agent 原生部署、通用目录直接读取和通用目录链接引用；
- `.agents/skills` 导入集中库不会破坏它对其他 Agent 的共享关系；
- 复制副本可以在确认后替换为集中库管理链接，且不留下重复入口；
- 同名不同内容可以分为同一 Skill 的版本或不同 Skill，并进入可回退的用户裁决流程；
- AI 可按全部/分类/冲突组/单 Skill 分析，结果短、明确、可追溯且不自动执行；
- 未知识别关系和共享影响会进入待办；
- 单 Skill、批量导入、部署、移除、替换和回退均有 UI 闭环；
- v0.3.0 图谱可以只通过关系查询读取完整节点和边，不需要重新扫描历史文件系统。
