# 技能关系模块与统一执行体验设计（2026-09-16）

## 目标与范围

本设计在不改变 SkillHub「集中库管理 Skill 全生命周期」定位的前提下，将跨 Skill 的关系事实、冲突确认和关系变更收敛到一级模块「技能关系」。同时，为所有会等待、会改数据或会改文件的功能定义统一的异步执行、通知和审计约束。

本轮只记录已确认的产品与交互设计；不代表已实现，也不替代发布前的 Windows/macOS 人工验收。

## 模块边界与导航

侧边栏新增一级入口「技能关系」，位于「技能库」之后、「发现」之前。

```text
概览
技能库
技能关系
发现
Agent
项目
待办
```

- 技能库：管理集中库中的单个 Skill，包括内容、版本、元数据、标签、安全、导出和删除。它保留「部署」快捷入口，但不维护独立的关系执行流程。
- 技能关系：管理 Skill 与 Skill、来源、Agent、项目、目录、未确认冲突之间的关系事实、确认和变更。
- Agent、项目：各自管理对象配置与本对象的使用情况；关系摘要可深链到技能关系，但不复制关系治理功能。
- 通用待办：仍只处理试用到期、安全发现、恢复等既有类型；不承载关系冲突或关系治理。

技能关系下有三个页面：

```text
/relationships                 技能图谱（默认）
/relationships/decisions       冲突处理
/relationships/governance      关系治理
```

## 技能图谱

### 定位

技能图谱是以一个 Skill 为中心的有限深度异构关系图，不是可无限展开的全系统拓扑图。图谱用于理解关系和跳转到明确操作，不在画布中直接修改文件、部署或删除关系；AI 分析也不在图谱中出现。

### 节点、连线与深度

节点：Skill、来源、Agent、项目、目录、未确认冲突。

连线：来源于、部署到、位于、共享、冲突、已关联等。关系类型与状态必须同时使用颜色、线型和文字标签表达，不能只靠颜色。

每次聚焦一个中心 Skill：

1. 显示中心 Skill；
2. 显示与中心直接关联的 Skill；
3. 显示中心 Skill 与这些直接关联 Skill 的来源、Agent、项目、目录、未确认冲突上下文；
4. 上下文节点可查看详情，但不能沿它们继续展开到其他 Skill；
5. 点击关联 Skill 是「以该 Skill 重新聚焦」，替换当前画布，不是在原图上继续扩展。

因此禁止从 `Skill A → Agent → Skill C` 或来源、项目、目录继续无限钻取。

### 进入、搜索与筛选

- 图谱始终明确显示当前中心 Skill，并将 `skillId` 写入 URL。中心节点在画布和右侧详情中有明确样式。
- 没有 `skillId` 的首次进入，从存在可展示关系的 Skill 中随机选择一个，立即绘图，并把结果写入 URL；刷新、返回和深链不再次随机。提供「换一个 Skill」主动随机切换。
- 库中没有可展示关系时，不渲染空画布，改为引导用户前往本机发现。
- 顶部保留「搜索 Skill 名称或别名」。搜索匹配主名称与别名，支持前缀、包含、忽略大小写；多结果展示主名称、命中别名、标签和关系数量，用户必须明确选择一个中心 Skill。
- 标签筛选只筛选可作为图谱中心的 Skill 候选，不会把多个 Skill 合并进同一张图。一个图谱始终只有一个中心 Skill。
- 关系类型和状态作为图谱显示筛选。Agent、项目不作为独立浏览筛选器；它们是当前 Skill 的上下文和影响说明。
- 不设置常驻左侧筛选栏。顶部使用搜索、标签、关系、状态控件；「显示设置」按需展开小型浮层，控制来源、Agent、项目、目录、未确认冲突等上下文节点与关系类型的可见性。
- 图谱按鼠标优先设计：拖拽、缩放、点选节点/边。搜索、筛选和详情面板保留基础键盘可达性，但不实现键盘遍历节点、拖动画布或缩放画布。

### 性能、生成与新鲜度

图谱不是静态图或独立图数据，而是关系事实的查询投影：

- 持久化 Skill、版本、来源、部署、关系边、冲突、治理事项及其状态、证据、首次发现/最后验证/失效时间和操作记录；
- 图谱读取「中心 Skill + 筛选条件 + 关系版本」对应的小范围关系事实，前端只负责稳定分层布局；
- 不因打开图谱扫描磁盘；查询结果按关系版本缓存；节点超过上限时按关系簇或分类折叠；
- 初始化/重新扫描、导入、部署、解除部署、纳入集中库管理、删除/恢复、关系确认等操作更新关系事实；AI 分析本身不更新图谱结构；
- 外部变化由用户显式的关系刷新/重新扫描发现。0.2.0 不做常驻目录监控。图谱显示最后验证时间及不可访问/待校验状态。

## 冲突处理

### 定位与界面

页面名称保持「冲突处理」，但不设计为待办列表。它是逐组事实对比工作台：一次聚焦一组未确认的 `uncertain` 冲突，核心是两侧 Skill、来源、指纹、部署、目录、影响和历史证据对比。

顶部只提供冲突类别导航及数量，例如「同名内容不同」「共享引用待确认」「其他待确认」，并提供「分析当前类别」「分析全部」。用户通过上一个/下一个浏览同类冲突；已处理项默认不混入当前工作台。

AI 是可选建议：仅分析未确认的 `uncertain` 冲突；不配置模型不阻碍导入或人工处理；分析可按单项、当前类别/筛选范围或全部范围执行。批量仅用于 AI 分析，不批量自动确认关系。

### 具体处理动作

AI 必须提供「结论 + 可执行处理方案」，按钮使用明确动作，例如：

- 按建议：保留为独立 Skill；
- 按建议：确认同一 Skill；
- 按建议：纳入集中库管理。

不保留只给分析记录写入 `adopted` 状态、却没有业务结果的「采纳」按钮。

- 仅写关系结论的动作会保存用户处理结果、关闭当前冲突，并写入操作记录；不改文件。
- 涉及文件、部署或链接变更的动作会跳转关系治理的影响预览、确认和执行链路。
- AI 无法可靠判断时，不显示伪造的采纳按钮，只提供手动处理或暂不处理。

所有未确认冲突处理完后，页面显示：

```text
干得漂亮，当前冲突已全部处理完毕。

你已累计处理 N 条冲突，
技能关系现在更清晰、更可控。

[查看已处理冲突] [查看技能图谱]
```

累计数只统计用户已明确处理完成的冲突记录，不统计部署、解除部署或纳入集中库管理。没有历史处理记录时，不显示不实表扬；改为「目前未发现需要你确认的关系冲突」。

冲突没有独立「刷新」操作。关系刷新/重新扫描更新事实后，新的 `uncertain` 冲突自然进入本页；相关 AI 分析会因关系指纹改变而过期。

## 关系治理

### 定位与清单

关系治理管理已建立或已明确的关系边：部署、解除部署、纳入集中库管理、重新检查和回退。它不是待办页，也不承载 AI 分析或未确认冲突。

主体是一张以关系边为单位的清单，而非重复的 Skill 列表：

```text
[Skill A] ── 托管链接 ── [Codex / 项目 X]
目标：…  已验证：今天  影响：1 Agent、1 项目
```

每行显示两端对象、关系类型、目标路径、验证状态、最后验证时间、影响范围和一个最恰当的主操作。顶部的「全部 / 可纳入集中库管理 / 待校验 / 受阻」是同一清单的快捷筛选，而非多页签。用户开始勾选关系时才显示批量工具栏。

### 命名与操作入口

用户文案使用「纳入集中库管理」，不使用技术色彩强的「转托管链接」。它的说明是「保留此位置的可用入口，改为使用集中库中的统一版本」；技术预览中才说明会用管理链接指向集中库主副本。

- 技能库、Skill 详情保留「部署」快捷入口，带入 `skillId`；
- Agent、项目页保留「部署到此处」快捷入口，带入目标对象；
- 图谱、Skill、Agent、项目的关系摘要可带入具体 `relationId` 进入治理预览；
- 实际部署计划、确认、执行、验证和关系记录统一在关系治理流程中完成。

### 部署、解除部署与纳入集中库管理

部署：选择 Skill 与 Agent/项目目标，生成计划，逐条展示将建立的 `Skill × 目标` 关系，确认后执行和验证。既有批量部署保留，但预览必须列出每个组合。

解除部署：针对一条已记录部署关系，预览目标路径、影响、保留内容和回退条件后确认；只移除 SkillHub 创建且仍匹配记录的目标入口。集中库主副本和用户原始来源不会被删除。

纳入集中库管理：前提是集中库已有经确认的主副本。对等同于该主副本的复制部署或安全共享引用，按以下路径执行：

```text
重扫与指纹校验 → 备份当前部署副本 → 创建管理链接
→ 验证链接与目标内容 → 原子替换旧副本 → 再验证并写入关系记录
```

Windows 根据能力使用符号链接或 junction。原始导入来源不因该操作删除。共享用户来源目录、跨卷、权限不足、链接能力不可用、指纹变化或外来同名文件等情况必须阻止执行，不能静默降级为复制或覆盖。

批量解除部署和批量纳入集中库管理支持，但每条关系必须有独立计划、备份、验证和操作记录。批量流程为选择 → 批量生成计划 → 汇总预览（可执行/受阻）→ 用户按项查看或取消 → 确认 → 逐项执行/验证 → 成功、失败、回退明细。失败项不破坏其他成功项，可单项重试或回退。

关系治理完成态使用：

```text
管理得很到位，N 条关系已纳入集中库管理。
```

当没有可治理或受阻关系时，使用中性状态「当前关系状态良好，没有需要处理的关系变更」，不与冲突处理的鼓励文案重复。

## 概览页

概览页保留原有基础规则：所有关键内容在应用可用视口内填满一页，页面外层不产生滚动条；需要展示更多数据时，只有面板内部列表滚动。

现有核心指标重新命名为：

1. 技能总数；
2. Agent（小字：已配置 N 个 · 已发现 N 个）；
3. 管理项目；
4. Skill 部署关系（小字：部署到 Agent N 条 · 项目 N 条）；
5. 待确认的关系冲突。

部署关系表示一条 `Skill → Agent/项目目录` 部署边，而不是 Agent 或项目对象数量。

概览主体按「使用、结构、组织」重组：

```text
核心指标（原有位置）                                      待办 N 项

┌────────────────────────────────┬─────────────────────────────┐
│ Skill 使用分布                   │ 技能关系                    │
│ Agent / 项目切换                 │ 关系图谱缩略预览            │
│ 柱状图 + 内部明细                │ [打开技能图谱]              │
│                                │ 待确认冲突 N · 可治理关系 N │
├────────────────────────────────┼─────────────────────────────┤
│ 标签分布                         │                             │
│ 饼图 + 标签明细                  │                             │
└────────────────────────────────┴─────────────────────────────┘
```

- 原「部署关系」面板改名「Skill 使用分布」，回答 Skill 在哪些 Agent/项目中使用；
- 「技能关系」是关系网络缩略预览，回答 Skill 之间、与来源/目录/冲突之间的结构；它不重复柱状图；
- 标签分布保留为组织维度；
- 通用待办从右侧大面板弱化为概览标题旁的状态入口，仍通往原待办页；
- 关系图谱、冲突处理、关系治理可从技能关系缩略区直接进入；无关系数据时显示稳定的发现引导，不造成布局跳动。

## 跨页面返回上下文

Skill 详情页不得永远返回技能库。所有进入详情的入口要携带独立返回上下文：

- 技能库：恢复搜索、标签、排序、页码和滚动位置；
- 关系治理：恢复筛选、关系行、批量选择和滚动位置；
- 技能图谱：恢复中心 Skill、显示筛选、选中节点/边以及画布缩放和位置；
- Agent/项目：恢复原对象与滚动位置。

可复现状态放入 URL；画布位置、滚动位置、批量勾选等会话状态保留在路由返回上下文。数据变更后只刷新受影响数据；原选中关系/节点消失时留在原位置并说明已更新或不存在，不跳转到技能库。

## 统一执行、通知与操作记录

### 分类

- 浏览、搜索、筛选、切换图谱中心、拖拽缩放：立即完成，不创建操作记录；
- 图谱读取、本地轻量查询：页面内加载，不进入顶栏执行状态；
- 重新扫描、刷新关系、AI 分析、安全检查、在线搜索：异步执行，进入顶栏状态和通知中心；
- 导入、部署、批量部署、解除部署、纳入集中库管理、关系确认、删除、恢复、备份、导出、应用更新：异步执行并持久化操作记录。

统一状态机：

```text
排队中 → 执行中 → 成功 / 部分成功 / 失败 / 已取消 / 等待用户处理
```

涉及文件变更时使用：准备计划 → 等待确认 → 执行中 → 验证 → 最终结果。

### 顶栏执行状态

顶栏居中提供固定 360px 宽度、无边框无底色的执行状态。没有在途任务时完全不显示。

```text
单项：正在重新扫描技能关系                         68%
多项：1 / 3 · 正在重新扫描技能关系                  68%
```

- 序号和进度固定；仅过宽的任务摘要横向滚动；
- 多项任务按顺序向上翻页显示，一次显示一项；
- 点击状态展开其下方的小型执行状态窗口；
- 窗口每页一项任务，显示任务名称、进度、阶段、开始时间和可用动作，支持上一项/下一项并以向上动效切换；
- 点击任意其他区域或 Escape 关闭窗口；
- 完成任务从分页移除，全部完成后中央状态消失。

用户可离开当前页面继续工作。只锁定同一 Skill、同一关系或同一目标目录的冲突操作，不阻塞整个应用。

### 通知中心与审计

异步操作完成、失败、部分成功或需要用户处理时，均生成可在通知中心查看的简短结果和深链。快速完成的写操作同样保留结果，但不让顶栏短暂闪烁。

通知中心用于查看结果、失败原因、重试、恢复和跳转对应页面；通知可标记已读或清除显示。操作记录用于完整审计，保留操作类型、时间、状态、影响对象、计划、备份/回退点、逐项结果、错误原因以及重试/恢复入口。清除通知不删除操作记录。

任何异步操作结束后，仅刷新受影响数据，保持用户所在页面、筛选、图谱中心、滚动位置和返回上下文。

## 后续实施边界

实现前需先把上述关系投影、关系版本、冲突 AI 指纹过期、批量执行计划、通知读状态和现有操作迁移契约明确为 Rust/SQLite/前端绑定与测试计划。所有行为变更遵循 TDD，并在实施后更新当前开发状态、自动化测试说明、人工验收清单和完成度矩阵。
