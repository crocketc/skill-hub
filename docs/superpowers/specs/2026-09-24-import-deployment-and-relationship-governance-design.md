# 导入、部署与关系治理边界设计（2026-09-24）

## 文档状态与适用范围

本设计基于 `feat/v0.2.0-product-completion` 当前已实现代码，收口导入、部署、来源信息、可管理关系与治理历史之间的产品边界。

本设计仅覆盖与本次边界调整直接相关的行为。现有导入向导、部署预览、统一执行状态、应用内通知、备份回滚、安全检查、技能图谱主体结构及其他已经实现的前后端能力，除非被本设计明确点名，否则保持原有实现。

当本设计与 `2026-09-16-skill-relationship-module-and-execution-experience-design.md` 中“部署必须进入关系治理执行”或“来源关系直接等同治理关系”的描述冲突时，以本设计为准。部署是独立流程；来源关系属于 Skill 来源信息；关系治理只管理可操作关系。

本设计不代表功能已经实现，也不能替代自动化验证和 Windows/macOS 真实桌面人工验收。

## 核心产品模型

导入和部署是两条独立业务流程，关系治理是管理已经存在且可由 SkillHub 安全操作的本地关系，不是导入或部署的必经步骤。

```text
Agent / 本地目录 / 在线来源
             │
             │ 导入
             ▼
          集中库 Skill
             │
             │ 部署
             ▼
        Agent / 项目目标

导入保存来源信息
部署建立部署关系
关系治理管理可操作的本地来源副本和部署关系
技能图谱展示完整关系拓扑
```

四个概念必须分开：

1. **来源信息**：回答“这个 Skill 从哪里来”，属于 Skill 自身信息。
2. **部署关系**：回答“集中库 Skill 当前部署到哪里”。
3. **可管理关系**：回答“哪些本地文件或部署入口可以由 SkillHub 安全操作”。
4. **治理历史**：回答“过去对可管理关系执行过什么操作，以及关系何时因已确认的外部变化退出当前列表”。

来源信息不因为“属于关系”就自动进入关系治理。只有来源对应一个仍存在、由用户持有且属于 SkillHub 管理范围的本地副本时，才投影为可管理的来源副本关系。关系投影后仍可能因证据过期、内容变化或权限受限而暂时阻止写操作。

导入冲突选择与来源关系的职责也必须分开：

- 冲突分析和用户选择决定候选最终对应哪个集中库 Skill，或决定跳过；
- 来源分类、物理路径身份、文件是否仍存在及是否属于用户持有目录，决定是否产生可管理来源副本；
- 只有导入成功并得到确定的集中库 Skill，同时来源满足可治理条件时，才建立来源副本关系；
- 不能仅凭显示名称、冲突组或用户选择猜测来源关系，也不能因“复用已有 Skill”而丢失本次新增的来源事实。

## 当前实现基线

### 导入

当前 `ImportWizard` 已实现来源选择、候选扫描、冲突分析、可选 AI 预检、导入提交、进度跟踪、结果页和应用内通知。导入提交会将内容写入集中库，并保存来源存证；导入不会删除原始文件。

当前缺口：

- 导入结果中的“现在整理 Agent 副本”直接进入未筛选的关系治理页；
- 结果没有稳定携带“本次导入产生的可管理来源关系”上下文；
- 来源副本清理尚未接入关系治理列表；
- 文案只覆盖 Agent 来源，不能覆盖普通本地目录来源。
- 当前原始来源清理按 `SkillId` 查找单条存证，不能精确操作同一 Skill 的多个来源副本；
- 当前在线仓库下载会先落到本地临时目录再进入导入管线，不能只根据候选的本地路径判断它是用户持有来源还是在线缓存。
- 当前治理页的“重新校验”只重新读取已持久化清单，没有重新检查文件系统；初始化扫描和单 Skill 重扫能够更新观察关系，但文件监听提示尚未接入桌面运行链路。

### 部署

当前 `DeploymentDialog` 与 `BatchDeploymentPage` 已独立实现目标选择、链接或复制部署偏好、影响预览、确认提交、单项/批量结果、执行状态和应用内通知。

部署流程保持独立，不迁入关系治理页面。部署成功后不推荐用户立即治理；后续维护入口来自 Skill、Agent、项目详情或关系治理。

当前批量部署已经按 Skill 生成计划、按目标展示影响卡，并汇总可执行/受阻数量和非原子执行结果；但预览失败仍按整个 Skill 汇总，任一预览失败会阻止整个批次提交，尚不支持按 `Skill × 目标` 对链接降级项分类批量确认。

### 关系治理

当前关系治理使用以关系边为单位的清单，支持筛选、搜索、单条/批量操作、影响预览、重新校验、纳入集中库管理和移除受管部署。当前后端清单只投影部署关系事实，尚未纳入本地来源副本。

### 技能图谱

当前技能图谱已经能够同时读取部署关系、来源关系、目录节点和冲突事实。它继续承担完整关系拓扑的查看职责，不承担批量文件治理。

## 来源信息分类

### 在线来源

Git、HTTPS、GitHub、skills.sh 等在线导入属于 Skill 的来源关系，必须保存：

- 来源类型与上游地址；
- 仓库、分支和目录坐标（存在时）；
- 导入时间；
- 导入版本或内容指纹；
- 后续更新检查所需信息。

在线来源不进入关系治理，因为它没有需要用户决定保留或删除的本地原始副本。在线下载过程中产生的 SkillHub 临时目录属于缓存，不是用户来源文件，由现有缓存清理机制管理。

在线来源：

- 在技能图谱中作为来源节点展示；
- 在 Skill 详情的来源信息中展示；
- 不出现在“全部可管理关系”中；
- 不产生“待治理”或“已保留”状态；
- 不进入治理历史，因为没有发生治理动作；
- 不展示 SkillHub 临时下载路径。

在线来源的判定必须使用导入获取阶段保存的权威来源分类和上游坐标。在线 Skill 即使经过本地临时下载目录进入扫描和导入，其业务来源仍是在线来源，临时目录仍是缓存。前端不得根据路径形态推断；后端也不能仅凭 `SourceKind::Local` 或“当前存在一个本地目录”把它投影为来源副本。

### Agent 本地目录来源

从已识别 Agent Skill 目录导入后，集中库拥有完整副本，原 Agent 目录仍保留用户副本。该来源既是 Skill 来源信息，也投影为可管理的本地来源副本关系，默认状态为“待治理”。

对 Agent 来源执行“清理来源副本”就是删除该 Agent 目录中的 Skill，不在同一操作中创建链接，也不自动部署。清理后集中库 Skill 仍然保留，但对应 Agent 将不再从原入口使用该 Skill；用户以后可从集中库重新部署，并选择链接或复制方式。

清理引导不能只说明“将删除文件”，还要先解释为什么建议清理以及清理后的使用方式。面向用户的说明应表达：

- 把集中库作为唯一维护入口，可以避免同一个 Skill 在多个 Agent 目录中形成难以同步的副本；
- 用户可以随时从集中库决定哪些 Agent 需要这个 Skill，并按需部署、调整或移除；
- 只向需要的 Agent 部署需要的 Skill，可以减少重复维护和无关 Skill 带来的上下文、选择与调用成本，降低模型选错 Skill 或使用旧副本的风险；
- 集中管理有助于提高 Skill 使用的一致性和准确性，但不得承诺清理动作本身必然提升模型准确率；
- 清理后如需继续在原 Agent 中使用，可从集中库选择该 Skill，选择目标 Agent，再确认链接或复制部署。

界面将 `清理并集中管理` 作为推荐主操作，将 `保留当前副本` 作为次操作；推荐必须建立在上述可理解的收益与影响说明上，不能隐藏删除后果或强迫用户清理。

清理前的影响预览必须明确展示：

- 将被删除的 Agent、展示类型和用户可读路径；
- 清理后该 Agent 将不再从这个入口使用该 Skill；
- 集中库中的 Skill 不受影响；
- 如需继续在该 Agent 中使用，需要在清理后重新部署；
- 备份位置、回滚能力和阻断原因。

提交清理前必须要求用户确认上述影响。清理成功结果以 `部署到此 Agent` 作为推荐后续入口，同时提供“稍后部署/完成”；进入部署后仍需选择部署方式并确认最终预览，不会自动开始部署，也不会把清理与部署合并成一个事务。

### 普通本地目录来源

从用户选择的普通本地目录导入后，原目录同样可能成为重复副本，因此也投影为可管理的本地来源副本关系，默认状态为“待治理”。

普通本地来源不能因为不属于 Agent 而跳过治理，但清理前必须继续执行现有原副本迁移的安全检查、备份、明确确认和回滚链路。

### 已登记项目目录

已登记项目目录可能仍是项目运行内容。本次不自动将其列为可清理来源，不改变现有项目行为。后续如需支持项目来源迁移，应另行设计项目影响检查，不能复用普通本地目录的一键清理语义。

### 不产生治理项的来源

以下来源只保存来源信息，不进入关系治理：

- 在线 Git/HTTPS/skills.sh 来源；
- SkillHub 临时下载或解压目录；
- 集中库自身目录；
- 已登记项目目录（本次范围内）；
- 已不存在且没有可恢复本地实体的纯历史来源。

### 来源分类的权威事实

导入获取阶段必须为候选保存不可由前端猜测的来源类别：

- Agent 本地目录；
- 用户选择的普通本地目录；
- 已登记项目目录；
- 在线来源的临时下载或解压缓存；
- 集中库自身目录。

该类别与来源地址、上游坐标、物理路径身份一起进入导入提交。候选被复制到临时目录、路径字符串发生规范化或在线内容落地后，来源类别不能退化为“普通本地目录”。是否投影为可管理来源关系由后端根据该类别和提交时重新校验的文件事实决定。

## 导入流程

### 步骤

1. 选择一个或多个来源；
2. 扫描 Skill 候选，并按来源展示成功数量或失败原因；
3. 选择单个或多个候选；
4. 分析重复、同名、所有权和内容冲突；
5. 用户选择复用、复制、接管、独立导入或跳过；
6. 可选运行 AI 预检；
7. 提交导入集中库；
8. 保存 Skill、版本、来源信息与适用的本地来源副本关系；
9. 在状态栏和应用内通知中报告进度与结果；
10. 展示导入结果及后续操作。

导入流程不选择 Agent/项目部署目标，不选择链接或复制部署方式，也不建立普通部署关系。

### 冲突选择与来源关系

可以使用冲突处理后的用户选择确认来源关系所归属的集中库 Skill，但冲突选择只负责确认 Skill 身份，不单独决定来源是否可治理：

- `复用已有 Skill`：本次来源事实关联到被复用的 Skill；若它是可治理本地来源，则建立或复用该 Skill 与此物理来源之间的当前来源副本关系；
- `复制到集中库`、`独立导入`、`验证后接管`：来源事实关联到本次成功产生的 Skill；符合条件时建立当前来源副本关系；
- `跳过`、导入失败或取消：不建立新的来源副本关系；
- 旧的“建立托管关系”选择与本设计的导入/部署边界冲突，不再作为新导入界面的选项。后端收到旧请求时应明确拒绝并提示用户重新确认导入选择，不能在导入提交中修改 Agent 原目录，也不能静默改成其他决策。

同一物理来源重复导入到同一个 Skill 时，不得在当前治理列表中制造重复行；应复用当前来源副本关系，并追加不可变导入存证。同一 Skill 的不同物理来源必须保留为不同来源副本关系，能够分别保留、清理和回滚。

关系拓扑按多对多设计：一个集中库 Skill 可以有多条来源关系；一个来源容器（例如仓库、Agent Skill 根目录或普通目录）也可以包含并关联多个 Skill。治理操作始终落在具体关系边上，而不是笼统作用于整个 Skill 或整个来源容器。

为避免删除歧义，当前可治理的“来源副本关系”必须精确到一个具体 Skill 目录。一条关系边只连接一个具体来源副本与一个集中库 Skill；同一个物理 Skill 目录不能同时以有效状态指向多个集中库 Skill。发生这种身份冲突时必须先由用户裁决，不能靠批量清理自动消解。这样整体拓扑仍是多对多，但单条文件操作始终有唯一对象。

为同时满足历史追溯和当前治理，数据身份分为三层：

1. 导入批次标识：一次提交的稳定内部标识，用于恢复“本次导入”上下文；
2. 导入存证标识：每次成功导入事件的不可变记录，不以 `SkillId` 作为唯一键；
3. 来源副本关系标识：由 Skill 与规范化后的物理来源身份确定，代表当前可治理实体。

导入批次保存本次产生或命中的来源副本关系映射。技术标识只用于查询和路由，不进入用户主界面。

### 导入结果按钮

当至少有一个成功导入项产生“待治理”的本地来源副本关系时：

- 主按钮：`整理来源副本`；
- 次按钮：`稍后处理`；
- 普通入口：`查看已导入 Skill`。

当存在导入失败项时，失败修复优先：

- 主按钮：`重试失败项`；
- 次按钮：`整理已导入项的来源副本`；
- 普通入口：`查看已导入 Skill`。

当全部成功项都来自在线来源或其他无需治理来源时：

- 不显示来源整理引导；
- 主按钮为 `查看已导入 Skill`；
- 提供完成或返回入口。

### 立即治理

点击 `整理来源副本` 后进入现有关系治理页面，并自动携带：

- 入口来源：本次导入；
- 关系范围：来源副本；
- 状态：待治理；
- 对象范围：本次成功导入产生的可管理来源关系。

页面顶部显示上下文说明，例如：

> 本次导入留下 3 个本地来源副本，请确认保留或清理。

“本次导入”上下文必须使用稳定、可查询的内部批次或关系标识，不能依赖候选显示名称，也不能把技术 ID 展示给用户。

### 稍后治理

点击 `稍后处理`：

- 结束当前导入引导；
- 不改变来源关系状态；
- 本地来源副本继续保持“待治理”；
- 用户以后可从关系治理、概览、Skill 详情或来源对象详情进入；
- 在线来源不会因此产生治理项。

## 部署流程

### 步骤

1. 从集中库选择一个或多个 Skill；
2. 选择 Agent 或项目目标；
3. 选择自动推荐、链接部署或复制部署；
4. 预览每个 `Skill × 目标` 的最终方式、目标路径、入口名称、文件影响、冲突和告警；
5. 自动推荐模式下，链接不可用时可以在预览阶段推荐复制，并给出面向用户的具体原因；
6. 用户明确选择链接部署但链接不可用时，阻止提交并展示原因及“改用复制部署”选择；只有用户再次确认后，才以复制方式生成新的最终预览；
7. 用户确认最终预览后提交；
8. 在状态栏和应用内通知中显示执行状态；
9. 展示逐项成功、失败和跳过结果。

链接受阻原因必须转换为用户能理解的说明，至少区分：

- 当前系统或账号没有创建链接所需权限；
- 目标磁盘、网络目录或文件系统不支持所需链接方式；
- 目标位置已有文件或目录，SkillHub 不能安全替换；
- 来源或目标目录当前不可访问，无法验证链接安全性；
- 共享目录或其他消费者会受影响，需要先处理对应关系。

界面先展示用户可采取的处理方式；原始错误码、路径身份和系统错误只放在可展开的技术详情中。用户没有确认“改用复制部署”时，系统不得静默改变部署方式。

批量部署按 `Skill × 目标` 逐项处理链接受阻。用户可以只把选中的受阻项改为复制、移除该项或返回调整目标；未确认的受阻项不能随其他可执行项一起提交。确认改用复制后，必须重新展示包含最终部署方式和文件影响的批量预览。

### 分类批量确认

批量预览按每个 `Skill × 目标` 的最终处置分类，而不是要求用户逐项打开确认：

- `按所选方式执行`：能够按用户所选链接或复制方式执行；
- `建议改用复制`：链接受阻但复制安全可用；按用户可理解的受阻原因继续分组；
- `无需变更`：目标已经处于期望状态；
- `无法执行`：存在冲突、权限或安全阻断，且没有安全降级方式。

用户可以对“建议改用复制”的一个原因分组执行 `本组全部改用复制`，也可以展开后取消个别 `Skill × 目标` 项。确认状态保存在关系项上，不只保存在视觉分组上；重新预览后只有目标、方式、阻碍原因和文件影响均未变化的确认才继续有效。`无法执行` 项不能被批量确认，必须移除、调整目标或单独解决。

最终提交页再次按“链接部署、复制部署、无需变更、已排除、仍受阻”汇总数量和影响。仍受阻或尚未确认降级的项目不进入提交；其余已确认项目可以作为非原子批次继续执行，不因无关项目受阻而全部停下。

### 部署结果按钮

全部成功：

- 主按钮：`完成` 或 `查看 Skill`；
- 普通入口：查看目标 Agent/项目。

部分失败：

- 主按钮：`重试失败项`；
- 次按钮：`查看部署结果`。

部署完成后不自动进入关系治理，也不把“管理部署关系”作为推荐下一步。后续移除部署、解除关系、保留目标文件或重新校验时，从 Skill、Agent、项目详情、技能图谱或关系治理进入。

## 技能图谱与关系治理的职责

### 技能图谱：查看完整关系

技能图谱回答“这个 Skill 与哪些来源、Agent、项目、目录和其他 Skill 有关系”。它展示：

- 在线来源；
- Agent 和普通本地来源；
- 部署关系；
- 共享目录；
- 冲突和相关 Skill。

在线来源节点必须使用用户可理解的服务、仓库或 URL 信息，不能展示临时缓存路径。

图谱不承担批量治理。关系数量较多时，图谱仍主要用于拓扑理解和进入具体对象。

### 关系治理：管理全部当前可操作关系

关系治理回答“当前有哪些本地关系可以由 SkillHub 管理，我能执行什么操作”。它展示全部当前可管理关系，而不是只展示异常关系：

- 待治理或已保留的本地来源副本；
- 正常、需校验或受阻的部署关系；
- 可纳入集中库管理的外部观察关系；
- 当前有效的共享目录关系。

页面中的“全部”文案改为 `全部可管理关系`，避免让用户误以为在线来源等信息关系也会出现在这里。页面说明：

> 展示当前可管理的本地来源和部署关系。在线来源及完整关系拓扑请前往技能图谱查看。

从侧边栏进入时默认展示全部可管理关系；从导入、Skill、Agent、项目、冲突或图谱进入时，按入口自动携带筛选条件。

## 关系治理页面

### 主页面

主页面只展示当前可管理关系，不混入治理历史。右上角提供 `治理历史` 按钮，进入独立历史页面；历史页面提供 `返回关系治理`。

主页面支持：

- 关系范围：全部可管理关系、来源副本、部署关系；
- 快捷状态：需要处理、已保留、正常、需校验、受阻；
- Skill、Agent/项目、来源类型和关键词筛选；
- 单条选择与同类关系批量操作；
- 从入口恢复筛选、选中行和滚动位置。

来源副本与部署关系不能在一个批次中混合执行。批量操作必须限定为同一种关系范围和同一种动作。

### 列表展示

列表按关系边一行展示，桌面宽屏使用表格，窄屏转为保持同一字段顺序的关系卡片。

共同字段：

- Skill 名称；
- 关系范围；
- 来源；
- 目标；
- 状态；
- 影响；
- 最近验证时间；
- 主操作与次操作。

来源副本：

- 来源为 Agent 或本地目录；
- 目标为集中库；
- 显示目录类型、原路径、内容一致性和备份/回滚能力；
- 操作为保留、清理或重新校验。

部署关系：

- 来源为集中库；
- 目标为 Agent/项目目录；
- 显示链接部署或复制部署、目标路径、共享消费者和验证状态；
- 操作为纳入集中库管理、移除部署、解除关系并保留文件或重新校验。

所有 Agent 展示继续使用统一的品牌 Logo 与用户可理解的类型徽标。Skill ID、UUID、内容哈希、operation ID 等技术标识不进入主界面；需要对账时只允许出现在折叠的技术详情中。

### 来源副本状态与操作

来源副本使用两个正交维度，不能把用户决策与文件健康状态混为一个状态。

用户决策状态只有：

- `待治理`：尚未决定是否保留；
- `已保留`：用户明确决定继续保留本地副本。

当前健康状态包括：

- `正常`：路径、目录类型和内容指纹仍与存证一致；
- `需校验`：证据已过期，尚不能执行清理；
- `内容已变化`：原目录仍存在，但内容与导入存证不同；
- `权限受限`：路径可能存在，但当前无法完成读取、身份确认或写入；
- `受管目录占用`：该路径当前属于受管部署或其他不可直接清理的关系；
- `操作失败`：最近一次清理未完成，原副本仍需继续处理。

页面快捷状态“需要处理、已保留、正常、需校验、受阻”由上述两个维度投影；例如“已保留但内容已变化”仍保留用户决定，同时可以提示重新校验。

待治理操作：

- `清理来源副本`；
- `保留来源副本`；
- 证据过期时提供 `重新校验`。

已保留操作：

- 查看详情；
- 改为清理；
- 重新校验。

清理前必须复用现有原副本迁移安全链路：

1. 从来源存证取得路径；
2. 重新校验路径身份、目录类型和内容指纹；
3. 阻止符号链接、目录联接、内容变化或受管部署目录；
4. 展示影响和备份位置；
5. 要求用户明确确认所有权；
6. 先备份，再清理原目录；
7. 记录结果并提供回滚；
8. 失败时保持可恢复状态，不伪报成功。

清理成功后，该关系从当前列表移除并进入治理历史。

### 路径缺失

“路径缺失”是指来源路径在导入时真实存在，之后在其父目录和所在文件系统均可正常访问的前提下，重新校验确认该目录已经不存在。常见原因包括用户手动删除或移动目录、Agent 卸载时清理目录，或外部工具改名。无法读取不等于缺失：权限不足、移动磁盘未挂载、网络目录离线或路径身份无法确认时，必须标记为“权限受限”或“需校验”，不能擅自判定文件已删除。

路径缺失按发生时点处理：

- 列表加载或主动重新校验时确认缺失：不再存在可执行“清理”的本地实体，因此从当前可管理关系列表移除；来源存证继续保留，并记录“外部移除”历史，不伪装成 SkillHub 清理成功；
- 用户已打开清理预览、但提交前路径消失：按并发状态变化阻止提交，重新校验后转为“外部移除”历史；
- 路径只是移动且用户希望继续管理：通过来源重新关联能力确认新路径，不能自动猜测或按名称匹配；
- 路径缺失但存在 SkillHub 备份：历史中可以提供恢复入口；恢复后根据真实文件重新投影当前来源副本关系。

确认路径缺失后自动归档，不再要求用户确认，因为此时没有文件删除或覆盖动作。归档只把当前来源副本关系标记为非活动状态，保存原因、确认时间和校验证据，并推进关系修订；不可删除来源存证或历史。若以后同一路径重新出现，必须重新校验其物理身份和内容，不能仅因路径字符串相同而自动恢复旧关系。

### 关系检查的触发条件与时机

关系检查分为轻量存在性检查和完整安全校验，避免每次打开页面都对所有 Skill 计算内容哈希。

当前已经存在的触发包括：

- 初始化向导或重新扫描向导执行目标扫描时，更新观察到的部署关系；
- 单 Skill 重扫时，更新该目标范围的观察关系；
- 导入、部署、移除、关系迁移和回滚等 SkillHub 写操作完成时，直接更新对应关系事实；
- 关系清单查询只读取持久化事实；当前页面“重新校验”也只是重新查询，并不检查文件系统；
- 核心层已有文件变化提示和确认能力，但尚未形成桌面端持续监听与关系刷新闭环。

本设计采用以下触发策略：

1. **应用启动后的轻量检查**：界面可用后，在后台对全部活动本地关系检查路径是否存在、路径类型和所在文件系统是否可访问；不计算全量内容哈希，不阻塞启动。
2. **进入治理上下文时的范围检查**：打开关系治理、Skill、Agent 或项目关系视图时，只检查当前范围内尚未在本次会话验证的关系；先展示持久化结果，再异步更新状态。
3. **用户主动重新校验**：真正执行该关系或当前筛选范围的文件检查，不再只是刷新查询；用户可以看到检查进度和逐项结果。
4. **写操作后的定向检查**：导入、部署、清理、移除、解除、恢复和回滚完成后，只检查受影响关系并更新事实。
5. **提交写操作前的强制校验**：任何删除、替换、转链接或恢复操作在提交前都重新确认路径身份、类型、内容指纹、权限和关系修订；页面上较新的检查结果不能替代此门禁。
6. **文件变化提示后的确认检查**：桌面端接入文件监听后，监听事件只作为提示，经过合并去抖后对受影响路径执行确认检查；监听事件本身不能直接归档关系或改写事实。
7. **不采用固定周期全量扫描**：本版本不按分钟轮询或反复计算所有内容哈希；通过启动轻检、上下文检查、明确写操作和文件变化提示覆盖主要变化。

轻量检查只有在确认父目录和文件系统可访问时，才能把不存在判为路径缺失并自动归档。权限错误、离线卷、网络中断和超时只更新为“权限受限”或“需校验”，保留当前关系。

### 部署关系状态与操作

现有部署治理行为保持：

- 外部复制关系可纳入集中库管理；
- SkillHub 受管部署可移除；
- 需要保留文件时可解除关系并保留目标文件；
- 证据过期时重新校验；
- 共享目录或其他消费者影响必须显式展示并确认；
- 受阻关系不能静默降级或覆盖。

## 治理历史

治理历史是独立页面，不与当前关系列表混排。它既记录 SkillHub 执行的治理操作，也记录经重新校验确认、导致关系退出当前列表的外部变化；两类记录必须明确区分，不能把外部删除描述为 SkillHub 操作成功。

历史记录包括：

- 已清理的本地来源副本；
- 被用户或外部工具移除、经重新校验确认缺失的来源副本；
- 已移除的部署；
- 已解除但保留文件的部署关系；
- 已回滚的治理操作；
- 已失败并终结的治理操作。

每条历史显示：

- Skill 与来源/目标对象；
- 原关系范围和操作；
- 操作时间与结果；
- 原路径和目标路径；
- 备份与回滚状态；
- 失败原因和恢复入口（存在时）。

执行回滚后，根据真实文件和持久化事实重新投影当前关系，不能简单把旧列表行恢复出来。

## 入口与跳转

| 入口 | 目标与自动筛选 |
|---|---|
| 导入结果“整理来源副本” | 来源副本 + 待治理 + 本次导入 |
| 导入结果“稍后处理” | 不进入治理，状态保持待治理 |
| 概览待治理数量 | 需要处理的可管理关系 |
| Skill 详情 | 当前 Skill 的全部可管理关系 |
| Agent 详情 | 当前 Agent 的来源副本和部署关系 |
| 项目详情 | 当前项目的部署关系 |
| 技能图谱具体边 | 对应可管理关系；在线来源只看详情，不出现治理按钮 |
| 侧边栏关系治理 | 全部可管理关系 |
| 关系治理“治理历史” | 独立历史页面 |
| 部署结果 | 不自动进入治理 |

图谱对在线来源不显示无效的“去治理”按钮。只有选中的边能够映射到可管理关系时，才提供治理深链。

## 数据与接口边界

### 来源信息与治理投影

来源存证继续作为不可变导入事实保存。治理状态不能改写导入历史，而应作为来源关系的独立当前状态或决策记录保存。

现有以 `SkillId` 为主键的单条导入存证不足以表达多个来源。新模型必须允许一个 Skill 对应多条不可变导入存证，并为当前来源副本关系单独保存用户决策、健康状态和最近验证事实。旧数据迁移时保留原存证内容，为其生成稳定存证标识和来源副本关系标识；不得用新一次导入覆盖旧来源历史。

统一治理读取模型只投影可管理关系，并至少包含：

- 关系范围：来源副本或部署；
- 稳定内部关系标识；
- Skill 展示信息；
- 来源与目标展示信息；
- 当前状态；
- 用户决策状态与当前健康状态；
- 可执行动作；
- 安全阻断原因；
- 影响、备份和回滚事实；
- 最近验证时间。

来源是否可治理必须由后端确定，前端不能根据路径文案猜测。在线来源、缓存目录、集中库目录和本次排除的项目目录不能被投影为来源清理项。

### 导入批次上下文

导入提交结果需要提供稳定的治理上下文，用于精确恢复“本次导入”的可管理来源关系。上下文必须可查询、可跨路由恢复，不能使用显示名称拼接，也不能把大量关系 ID 直接暴露在用户界面中。

该上下文由持久化导入批次及其来源关系映射提供。冲突组 ID 只表示冲突问题，不能代替导入批次或来源关系身份。

### 绑定生成

新增或调整 Rust/TypeScript 契约后，继续使用项目绑定生成工具更新，不手工维护重复接口。

## 错误、进度与通知

沿用现有统一执行桥：

- 导入、部署和治理分别使用自己的操作类型；
- 长时间单项和批量操作显示在状态栏；
- 成功、部分成功、失败和需要用户处理均产生应用内通知；
- 通知深链返回对应结果或治理上下文；
- 页面离开后任务继续执行；
- 失败原因必须结构化并翻译为用户可理解的说明；
- 清理、移除和回滚继续保留持久化操作记录。

来源副本清理失败时，该关系保留在当前治理列表，并显示失败原因、重新校验、重试或恢复入口。

## 实施约束

- 所有行为变更遵循 TDD，先写失败测试；
- 只调整本设计直接涉及的前端、应用层、核心模型、存储与生成绑定；
- 不顺带重构现有导入、部署、图谱或通知模块；
- 不降低既有断言或删除测试；
- 不使用 UI 状态代替持久化治理结果；
- 不把在线临时目录当作用户原始目录；
- 不绕过已有原副本迁移和关系迁移安全链路；
- 不在前端自行判定是否允许删除；
- 不把自动化通过写成人工验收通过。

## 验证范围

自动化至少覆盖：

- Agent 来源和普通本地来源产生待治理关系；
- 在线来源、缓存目录、集中库目录和项目目录不产生来源治理项；
- 在线内容经过本地临时目录导入时仍保持在线来源分类，且不展示缓存路径；
- 冲突选择正确决定来源关系关联的集中库 Skill，跳过、失败和取消不产生关系；
- 同一物理来源重复导入不产生重复当前关系，不同物理来源可以独立治理；
- 一个 Skill 的多条来源关系和一个来源容器中的多个 Skill 可以独立展示和治理；同一物理 Skill 目录不能同时有效映射到多个 Skill；
- 在线来源仍出现在 Skill 来源信息和技能图谱中；
- 导入结果按是否存在可治理来源显示正确按钮；
- 立即治理准确带入本次导入筛选；
- 稍后处理后关系仍可从治理页查询；
- 保留来源持久化为已保留；
- 清理成功进入历史并从当前列表移除；
- 路径缺失转为外部移除历史；内容变化、链接/联接、权限不足和受管部署占用时拒绝清理；
- 启动轻检、上下文范围检查、主动重新校验、写后定向检查和提交前强校验按各自边界更新关系；
- 文件变化提示必须经过确认检查，离线或权限异常不能触发自动归档；
- 备份失败、提交失败和回滚路径；
- 来源和部署关系不能混合批量执行；
- 部署成功不自动引导进入治理；
- 明确选择链接但链接受阻时禁止静默降级，只有用户确认并复核复制预览后才能提交；
- 链接受阻原因以用户可理解的分类呈现，技术错误只进入折叠详情；
- 批量部署可按受阻原因整组确认改用复制，并允许逐项排除；无法执行项不拖住其他已确认项；
- 图谱只对可管理关系提供治理深链；
- 技术标识与临时缓存路径不进入用户主界面；
