# Agent 识别、卡片归并与派发能力展示设计（2026-09-28）

## 文档状态与适用范围

本文档是 Agent 识别、Agent 卡片归并、共享目录卡片和派发能力展示的产品设计边界。本文档基于当前分支的代码事实、`docs/Agent识别与派发场景梳理-2026-09-28.xlsx`，以及 `docs/Agent平台兼容性调研.md` 中的逐平台目录资料形成。

本文档只收口识别与展示模型，不代表相关功能已经实现，也不包含实施计划。现有部署执行、关系治理、Skill 扫描、文件保护和平台适配能力，除非本文明确调整，否则保持原有边界。

本文档不把 Agent 软件运行时是否加载或执行 Skill 纳入 SkillHub 的确定性职责。SkillHub 管理可观察的本地目录和文件关系；Agent 是否识别、刷新和执行 Skill，由对应 Agent 产品负责。

## 设计目标

1. 用 Agent 根目录识别本机是否存在可管理的 Agent 目录，不增加应用安装包、命令行、注册表或扩展扫描。
2. 以品牌和 Skill 目录路径归并 Agent 卡片，同品牌共用一个实际目录的客户端类型合并展示。
3. 将共享目录建模为独立目录实体和独立卡片，不复制成多个品牌卡片。
4. 让卡片只承担信息展示和详情入口，不直接执行派发或收回。
5. 将后端精确事实与前端用户文案分离，技术枚举和内部标识不直接进入界面。

## 核心概念

### Agent 根目录

Agent 根目录是 profile（配置档案）声明的、可用于识别某个 Agent 客户端存在的本地目录。不同 Agent 的根目录规则必须依据调研资料和实际 profile 声明处理，不能假设所有 Agent 都使用同一层级结构。

例如 DeepSeek Harness 的用户级和项目级目录规则、`.dsh/skills` 与 `.agents/skills` 的作用域，必须分别按调研文档建模，不能把所有候选压缩成一个通用路径。

### Skill 目录

Skill 目录是 Agent 根目录下、profile 声明的实际 Skill 目标目录。部分 Agent 的 Skill 目录也可能是独立候选路径，是否属于根目录或共享目录由 profile 声明决定。

### 共享目录

共享目录是品牌无关的独立目录实体。支持或识别该目录的品牌只是关联方，不拥有该共享目录的品牌副本。

共享目录卡片只展示一份。关系图谱和详情页必须保留：

```text
Skill → Agent 共享目录 → 支持且已识别 Agent 根目录的品牌
```

### 物理身份

物理身份是后端用于判断两个路径是否实际指向同一文件系统实体的安全事实。它不进入用户界面。

物理身份用于：

- 合并路径拼法不同但实际相同的目录；
- 同一物理目录只生成一次派发写入；
- 收回时确认目标仍是原目录；
- 识别目录删除后在原位置重建的身份变化。

已存在且成功读取文件系统身份的目录拥有已验证身份。待创建目录没有物理身份，只有候选路径；创建后必须重新读取身份。

## 识别规则

### 基本识别流程

每个 profile 通过调研文档和适配配置声明：

- Agent 根目录候选；
- Skill 目录候选或根目录到 Skill 目录的相对规则；
- 用户级、项目级、内置和共享目录作用域；
- 是否支持共享目录；
- 支持的部署方式及其优先级。

扫描只读取和验证候选路径，不创建目录。

### Agent 卡片出现条件

对于以 Agent 根目录作为识别依据的 profile，普通自动发现遵循以下规则：

| 识别结果 | Agent 卡片 | Skill 路径展示 |
| --- | --- | --- |
| Agent 根目录不存在 | 不显示 | 不显示 |
| Agent 根目录存在，Skill 目录不存在 | 显示 | 待创建 |
| Agent 根目录和 Skill 目录均存在 | 显示 | 显示实际路径 |
| Agent 根目录存在但无法访问 | 显示异常状态 | 详情页说明原因 |
| 用户主动登记了自定义 Agent 根目录 | 显示待确认或待创建卡 | 根据实际状态展示 |

如果某个 profile 明确把 Skill 目录本身声明为独立识别路径，则该路径存在时可以直接产生 Agent 卡片。对于固定的“根目录 + Skill 子目录”规则，不存在“父目录不存在但子目录存在”的正常状态；非法或断链情况作为路径异常处理。

### 识别语义

用户界面统一使用“已识别 Agent 目录”，不使用“已安装 Agent”。

目录识别只能证明 SkillHub 发现了可观察目录，不能证明 Agent 软件一定会加载或执行 Skill。

详情页可以说明：

> SkillHub 根据 Agent 目录结构识别本机目标，不检测 Agent 软件本体，也不保证该 Agent 会加载或执行 Skill。

## Agent 卡片模型

Agent 卡片表示一个品牌在一个 Agent Skill 目录上的展示实体。

### 归并键

优先使用：

```text
品牌 + 已验证物理目录 + 目录角色
```

待创建时使用：

```text
品牌 + profile 候选路径 + 目录角色
```

归并规则：

- 同品牌、同一物理目录：合并客户端类型；
- 同品牌、不同物理目录：分别展示多张卡；
- 同品牌的用户目录、项目目录和内置目录按目录角色保持边界；
- 同一路径的终端、桌面端等类型显示为多个类型徽标；
- `client_id` 不参与用户可见归并；
- 仅有候选路径时，不能把候选身份当作永久派发或收回主键；
- 共享目录不进入品牌卡归并，始终进入共享目录卡。

### Agent 卡片展示字段

卡片只展示以下信息：

- 品牌 Logo 和品牌名称；
- 用户可理解的 Agent 类型徽标；
- Skill 路径，或“待创建”；
- 目录角色；
- “支持共享目录”能力标记；
- 派发状态图标；
- 复制、符号链接、目录联接三种部署方式图标。

卡片不展示：

- Skill 数量；
- 安装状态和安装证据；
- 部署摘要；
- 物理身份、UUID、`client_id` 或其他内部标识；
- 直接派发、收回或切换部署方式的操作。

点击卡片只进入 Agent 详情页。派发、收回和部署方式选择均在详情页中完成。

### 路径展示

路径和路径状态合并为一个展示位置：

- 已存在：显示规范化路径；
- 未创建：显示“待创建”；
- 异常：显示路径和用户可理解的异常图标，具体处理建议进入详情页。

路径必须按文件系统身份归并，并统一斜杠风格。不能同时展示同一物理目录的不同路径拼法。

### 部署方式展示

所有可派发的 Agent 目标显示三个部署方式图标：

1. 复制；
2. 符号链接；
3. 目录联接。

图标规则：

- 支持方式高亮；
- 不支持方式置灰；
- 推荐方式增加推荐标记；
- 鼠标悬浮显示用户可理解的方式名称和说明；
- 图标同时提供无障碍标签。

复制是普通可写 Agent 目录的通用兜底方式。符号链接和目录联接由操作系统、目录角色和 profile 决定。内置只读目录不参与派发，三个方式均不可用。

后端保存：

```text
supported_methods
preferred_method
```

派发默认使用推荐方式；多个方式都支持时，用户可在 Agent 详情页的派发流程中切换。

## 共享目录卡片模型

共享目录卡片标题固定为：

> Agent 共享目录

### 展示字段

- 共享目录 Logo；
- 规范化路径；
- 支持品牌的 Logo 列表；
- 派发状态图标；
- 复制、符号链接、目录联接三种部署方式图标。

共享目录卡片不直接展示 Agent 类型文字、不展示 Skill 数量、不展示安装状态，也不执行操作。

### 支持品牌列表

品牌 Logo 同时满足两个条件才展示：

1. 该品牌 profile 声明支持或识别该共享目录；
2. 当前设备上存在该品牌的 Agent 根目录。

品牌根目录不存在时，即使 profile 声明支持共享目录，也不在共享目录卡片上展示该品牌。

品牌 Logo 悬浮时显示品牌名称和支持类型。共享目录存在但没有任何已识别品牌时，仍可作为独立共享目录卡片显示，品牌列表为空。

共享目录暂时使用 Vercel 黑色三角标识作为视觉标识。界面文案仍使用“Agent 共享目录”，不暗示与 Vercel 存在产品归属关系。

## 路径状态与异常

后端可以保留精确状态，前端只显示用户可理解的名称和建议。

### 后端状态

```text
existing
missing
non_directory
inaccessible
broken_link
identity_changed
```

含义：

- `existing`：目录存在；
- `missing`：目录尚未创建；
- `non_directory`：预期目录位置实际是普通文件；
- `inaccessible`：无法读取或写入；
- `broken_link`：符号链接或目录联接目标失效；
- `identity_changed`：原目录被删除后在相同路径重建，物理身份发生变化。

前端不直接展示这些枚举值。前端展示“待创建”“无法访问”“路径位置被文件占用”“链接目标已失效”“目录已发生变化”等用户可理解文案，并提供处理建议。

## 自定义 Agent

自定义 Agent 使用通用 Agent Logo，不要求用户提供 Logo。

用户可以填写：

- 品牌名称；
- Agent 名称；
- Agent 类型；
- Agent 根目录；
- Skill 子目录或 Skill 路径；
- 是否支持共享目录；
- 可选官方链接。

系统自动判断：

- 根目录和 Skill 目录是否存在；
- 路径是否可读写；
- 物理身份；
- 与其他目录是否相同；
- 部署方式支持情况；
- 是否需要在派发时创建目录。

用户声明不能直接变成系统事实。用户填写的共享能力和路径应保留为用户配置，实际存在性、可读写性和物理身份仍由系统验证。

## 前后端文案分层

后端可以保留精确的状态枚举、失败原因、实现方式、profile 字段和内部标识。

前端必须通过统一 presenter（展示转换层）转换为用户可理解的：

- 品牌名称；
- Agent 类型；
- 目录角色；
- 路径状态；
- 派发状态；
- 部署方式；
- 异常说明和处理建议。

卡片、详情页、派发流程和通知不得直接展示后端枚举、字段名、内部阶段名、错误码或实现术语。原始技术信息只保留在日志和诊断导出中。

## 派发和创建边界

发现、初始化和重扫阶段只读，不创建目录。

当用户在 Agent 详情页选择“待创建”目标并确认派发时：

1. 再次验证父目录和目标路径；
2. 创建所需目录；
3. 读取并保存新目录的真实物理身份；
4. 验证目录访问能力；
5. 执行派发；
6. 失败时按现有回滚和恢复规则处理。

候选路径不能直接用于永久收回或安全删除。只有创建并验证后的物理身份，才能作为部署和收回安全依据。

## 非目标

本文档不定义：

- Agent 软件安装包或命令检测；
- Agent 是否实际加载或执行 Skill；
- Skill 调用方式编辑；
- Agent 运行时刷新和重启行为；
- 共享目录的品牌所有权转移；
- 新增部署执行器或关系治理流程；
- 用户自定义 Logo 上传；
- 卡片内直接派发操作。

## 验收边界

后续实现至少需要覆盖：

- Agent 根目录存在、缺失和不可访问；
- Skill 子目录存在和待创建；
- 同品牌同物理目录多类型合卡；
- 同品牌不同目录分卡；
- 用户目录和内置目录分卡；
- 共享目录独立成卡；
- 共享目录只展示 profile 支持且设备根目录存在的品牌 Logo；
- 三种部署方式的支持、置灰和推荐状态；
- 路径冲突、断链、权限不足和物理身份变化；
- 自定义 Agent 通用 Logo 和待创建路径；
- 卡片只进入详情页，不直接执行派发；
- 前端不出现后端枚举、内部标识和技术错误文案。
