# 关系治理完整闭环与增量开发产品裁决（2026-10-03）

## 状态、依据与使用方式

本文件汇总用户在 2026-10-02—03 验收讨论中逐项确认的产品规则，作为统一开发依据，替代“原 FB-009”未收口的讨论口径。产品规则已确认，代码尚未据此完成，不能把本文件作为自动化或人工通过证据。实施分工与依赖见同日期实施计划；当前进度仍由 `docs/development/` 四份当前文档汇总。

基于当前源码、数据库事实、执行器、测试和安全边界做增量修改。保留既有看板风格、来源存证、Skill 身份、生成契约流程、日志、备份和恢复执行链。旧投影、分类或命令的局部规则与本裁决冲突时替换该规则，不进行模块级重构、依赖升级或数据库全量重建。

用户补充：**增量开发不是禁止修改已有代码，尤其前端必须按新规则调整。** 上述“保留”只针对仍正确的基础设施与已确认视觉样式，不保护旧分类、旧状态、旧文案和旧按钮行为。新增正确模型字段却继续用旧投影、仅改标签不改判定、保留与新闭环冲突的动作都不合格。确需改变既有契约、持久化或流程时做范围明确的增量修改与兼容迁移，不能把“不重构”作为不完成新规则的理由。

## 1. 主体与模块职责

- 集中库统一管理本地 Skill **主体**：内容、当前版本、元数据和生命周期，不称为“主副本”。目标是 Agent/项目通过链接使用 Skill；现有兼容复制能力不因目标声明被直接删除。
- “已导入”属于主体事实。关系管理状态只有**未接管/已接管**，不能把已导入当作第三种关系状态。
- 上游来源、来源版本、更新检查、升级/回滚属于 Skill 生命周期管理。发现上游更新可进入待办，入口跳转版本管理，不进入关系治理列。
- 关系治理负责主体与已识别 Agent/项目/共享目录使用位置之间的接管、链接使用、回收及真实异常修复。普通本地导入来源仅有来源记录，不自动变成使用目标。
- 未入库的本地 Skill 先进入“待导入”待办，进入导入流程；入库成功后才产生可治理的目标关系。不能用虚构主体或名称匹配生成关系。
- 操作失败归通知/操作记录；现场未明确的中断归恢复中心。失败不是关系类型，恢复锁不是新的管理状态。
- 用户新增并确认“复用修改”为独立的上游主体关系：从原Skill编辑后创建新Skill时记录原主体/原版本→新主体/首个编辑版本，成功落账显示已完成/复用修改，纳入治理模型和图谱。不是下游Agent/项目使用位置，也不是继承网络更新来源；派生事实与实际继承结果分开。第10节说明新增边界与待收口事项。

## 2. 统一三层模型

| 层 | 后端判定语义 | 前端展示 | 规则 |
| --- | --- | --- | --- |
| 治理分类 | 待处理 / 已完成 | 待处理 / 已完成；全部为汇总入口 | 所有当前目标关系均可查询；已结束关系进入历史 |
| 管理状态 | 未接管 / 已接管 | 待集中管理 / 已集中管理 | 最近确认的接管状态与实际健康事实分别保存 |
| 具体情况 | 健康事实 + 用户决定 + 可执行条件 | 用户短名、实际原因、说明和按钮 | 多个异常可并存，不额外增加固定层级 |

治理分类优先级：未解决的真实健康异常或无法核验的事实优先进入待处理；否则有效受管链接正常为已完成；未接管且明确长期保留、没有新问题也为已完成；其他未接管关系为待处理。保留决定不屏蔽新异常。暂缓/不操作不算治理完成，也不产生独立“暂缓”关系状态。

Agent、项目、共享目录为目标类型，Skill、导入批次为范围筛选；目录路径、版本、核验时间、操作历史为详情，不新增治理状态层级。操作条件不足仅作为具体原因，不能把健康正常的受管链接因不支持某个可选操作而标成待处理。

同一 Skill 与同一物理目标位置只呈现一条使用关系。来源存证和观察/部署事实可继续分别保存，但须以主体身份、已验证目录身份、目标入口及明确映射归并呈现和计数；不同 Skill 或不同物理目标不能仅按名称合并。共享消费者不复制关系行。历史迁移不能抹掉已确认关系或用户决定。

上述三层表的管理状态适用于下游目标使用关系。上游“复用修改”不能套用未接管/已接管或发接管按钮；成功创建后已完成/复用修改已获用户确认。统一模型按上游/下游关系类型提供适用事实，不增第四层或伪装Agent/项目关系。上游网络更新仍由生命周期处理，复用修改不代表网络更新依赖；派生历史/异常和动作依第10节继续梳理。

## 3. 前后端判定与用户操作表（从正常到复杂）

下表为语义契约，不预设现有 Rust 枚举命名；执行者优先复用事实，必要增加可生成的投影字段。按钮由当前真实预检查能力决定，不能仅靠前端标签放行。

| 情况 | 后端语义 | 前端短名 | 悬浮/聚焦说明 | 操作与闭环 |
| --- | --- | --- | --- | --- |
| 正常受管链接 | 已完成、已接管、链接/主体正常 | 已集中管理 | 此位置通过受管链接使用集中库 Skill，始终跟随当前版本 | 查看关系、回收；主体升级/删除到主体入口统一处理 |
| 明确保留且无新异常 | 已完成、未接管、保留决定 | 已保留独立副本 | 此位置继续使用独立文件，不跟随集中库升级，接管提醒已关闭 | 转为集中管理；撤销保留后回到待处理；可重启持久化 |
| 尚未作决定或暂未操作 | 待处理、未接管、无保留决定、内容可核验 | 待集中管理 | Skill 已入库，此位置仍是独立副本，请选择接管或保留 | 转为集中管理、保留独立副本；稍后处理仅退出当前流程，仍待处理 |
| 独立副本内容不同 | 待处理、未接管、内容差异 | 请选择使用内容 | 原位置和集中库内容不同，请明确将哪一份作为集中库内容 | 使用集中库内容 / 使用原位置内容；影响确认与检查后完成接管，不强迫进入独立差异流程 |
| 未接管原副本缺失 | 待处理、未接管、原入口缺失 | 原文件缺失 | 原独立文件已不存在，关系仍等待你的处理决定 | 在原位置建立链接 / 结束关系；不自动归档 |
| 受管链接缺失、错误/断开或被普通文件替换 | 待处理、最近确认为已接管、对应具体健康原因 | 使用链接异常 | 根据真实原因说明入口缺失、指向错误、主体不可读取，或已变成普通文件及下一步 | 恢复集中管理 / 结束使用关系；被文件替换时先选择内容并备份，不覆盖外部文件 |

附加条件：权限、兼容性、目标身份变化、内容核验过期以“具体原因 + 如何解除 + 重新核验”说明；受限动作不能提交，仍允许执行已验证安全的其他合法动作。普通文件选择长期保留成功后，管理状态才由已接管变为未接管并记录保留决定，不能检测到普通文件就自动降级。

主体缺失/不可读取是使用链接异常的具体原因：先进入主体恢复或修正可达性，再重新核验；不能盲目创建链接指向不存在主体，也不能未经授权从外部文件覆盖主体。

## 4. 接管与内容选择

1. 导入完成页提供本批次“转为集中库管理”入口，明确可接管、已保留和受限数量。仅指向实际入库主体与其目标，不对普通本地来源提供任意替换。
2. 确认主体/目标身份、目录兼容性、权限和名称；强校验原位置内容与集中库当前内容。名称相同不等于同一主体。
3. 内容一致时直接进入统一影响预览；不一致时提供“使用集中库内容”“使用原位置内容”。查看差异/完整路径可辅助，但不是必经步骤。
4. 使用集中库内容：备份原文件后，以集中库当前内容重建受管入口。
5. 使用原位置内容：保存为该 Skill 主体的新版本，执行既有版本与基础检查边界，再转为链接。若其他链接使用该主体，预览明确它们会一同跟随新版本；集中库数据不在无确认时覆盖。
6. 备份原副本、暂存链接、验证指向及声明/入口名一致、安全替换、落账/历史/待办更新。成功核验才改为已接管/已完成。失败保留或恢复原文件；取消不产生完成事实。
7. 预览后文件、版本、目标身份或关系变更使旧预览失效，重新确认；禁止把批次中的内容选择变成最后写入者胜出。多个目标为同一 Skill 提供不同“原位置内容”时按主体分组明确唯一版本选择，不能自动覆盖。

符号链接/Windows 既有受管目录联接采用现有跨平台适配与能力验证；不静默降为复制并宣称接管完成。内置只读、未知/不可写目录、共享本体保护保持；具体 Agent 能否执行 Skill 不由存在链接推定。

## 5. 升级、回收、删除与共享目录

- 所有有效目标链接始终跟随集中库当前版本，暂不提供固定旧版本。升级/回滚列出全部受影响目标与共享消费者；复用不可变版本、当前可见主体更新及备份恢复机制，完成后核验结果。正常随主体升级不误报为独立副本内容漂移。
- 回收只移除已验证属于 SkillHub 的受管链接，保留主体及其他目标。未接管原副本不能通过回收删除；长期保留独立副本是合法决定。
- 明确回收/结束成功后关系退出当前清单，保留历史；再次派发重新建立有效关系并保留关联历史。
- 外部删除/替换只更新健康事实，不能自动结束/归档。恢复链接成功后回正常；明确确认回收/结束后才归档。保留已有历史证据，不自动复活所有旧归档记录；旧系统曾自动归档的条目须在读取/迁移策略中显式处理并报告。
- 删除主体提供一次确认页，明确主体、全部受管链接、Agent/项目和共享影响；用户无需先逐项回收。确认后安全移除受管链接与主体，保存恢复依据、统一更新关系/待办/历史。链接核验/移除失败时不继续破坏主体，不留悬空链接，不报全部成功；按现有恢复链回退。
- 未接管或已长期保留的独立副本不随主体删除。主体明确删除后它们的当前主体关联结束，来源/历史保留；以后重新导入重新建立关系，不制造指向被删主体的治理项。
- 共享目录是一个独立物理目标，接管/回收只执行一次，图谱为 Skill → 共享目录 → 可识别的 Agent。预览列全体影响，不提供从共享入口只回收某一品牌的伪操作；品牌专属目录是另一条关系。

## 6. 执行异常、受限与跨模块闭环

| 情况 | 权威事实/入口 | 下一步 | 完成条件 |
| --- | --- | --- | --- |
| 失败且已安全回退 | 通知/操作记录，原关系保持 | 查看原因，修正后重试原动作 | 动作与文件/关系核验成功；原本正常关系不因失败新增治理异常 |
| 中断且现场未明 | 恢复中心/恢复锁 | 按恢复预览恢复原状或安全继续 | 文件和关系账目一致；恢复原状不自动完成原接管事项 |
| 权限/兼容性受限 | 关系的可执行条件 | 修正权限/配置后重新核验；可选合法保留/结束 | 条件解除完成动作，或明确完成合法替代决定；不靠重复点击或关闭提示完成 |
| 真实链接异常 | 治理待处理 | 恢复集中管理或结束使用关系 | 链接/主体核验正常，或关系明确结束 |

执行中/恢复锁为临时操作提示而非关系类型。待办从真实事实派生，同一目标同一事项去重；保留决定只消除接管提醒，异常仍提醒。上下游更新、发现待导入、恢复中心均有精确跳转；读失败不显示假零、过期目标不跳到无关关系。

## 7. 前端呈现与稳定布局

- 使用 `frontend-design`，React 遵循 `vercel-react-best-practices`，依据用户事实、影响和下一步设计名称/说明/按钮，保留现有看板列头、卡片、配色、间距风格与表格视图。
- 顶部“全部/待处理/已完成”为汇总筛选；默认看板按这两个治理分类组织内容，当前筛选后的数量降序、同数稳定排序。二级管理状态、三级原因放卡片/局部筛选与说明，不要求连续展开三层才能操作，也不按每个错误新增列。
- 复用 FB-008 的固定内容画布、每列独立滚动、透明火箭回顶、右侧搜索与单图标视图切换。筛选/深层操作通过有限高浮层、下拉、弹窗或独立步骤，不参与主内容高度分配；宽窄/短屏布局均检查。
- 状态短名配 hover/键盘说明；具体原因、影响与建议不能只藏 tooltip，关键风险在预览高亮。异常分类用主题差异色、图标和文本，非只靠颜色。
- 同类事项提供“本类转为集中管理/保留/恢复/结束”等明确批量入口；预览实际候选、可执行与受限数，逐项结果和恢复可追溯。同一共享物理入口只操作一次，冲突内容不能合并成无确认的一键。
- 较长路径/名称固定宽度前段省略、完整可读值悬浮/聚焦/详情可查看，规范化路径；不能截断数据进行操作，不能在 tooltip 展示原始 ID/枚举/哈希/候选键。
- 与 Skill 抽屉、完整详情、Agent/项目页面、图谱和待办的字段、操作和持久结果一致，沿用品牌 Logo + 类型和共享目录身份约束。

### 7.1 技能图谱同步规则（用户 2026-10-03 补充）

技能图谱是同一关系模型的拓扑呈现，不保留第二套旧治理语义。用户明确要求随本方案调整，纳入 A 的 R1 查询契约和 B 的 F1/F2，不单独等待下一轮重构。

- **目标使用关系**：Skill → Agent/项目/共享目录的使用关系共用治理查询的治理分类、最近确认管理状态、真实健康原因、保留决定和动作条件。治理页、图谱悬浮说明及选中详情同一事实必须一致；不能把 `active`、内容相同或旧实线“已验证”推断为已接管/已完成。
- **展示层级**：目标关系可按待处理/已完成与待集中管理/已集中管理筛选；线条和主题强调帮助定位异常，选中详情明确展示三层含义与下一步。长期保留展示已保留独立副本，可已完成但仍未接管；颜色/线型不是唯一说明。具体处理动作复用治理流程或精确深链，不在图谱另建文件执行逻辑。
- **上游来源**：继续保留来源节点、导入追溯和只读来源事实，但明确为“导入来源/上游来源”，不套用目标接管状态。来源更新进入主体版本管理；同一原 Agent 路径既有导入存证又有使用关系时，追溯信息不重复算作另一条待接管使用关系。
- **共享结构**：Skill → 共享目录是实际使用关系，共享目录 → 可识别的 Agent 是识别/使用范围说明，不是多个独立部署。保留三类节点、一次物理操作及全体消费者影响，不给识别连线套上已接管徽标或重复关系数。
- **异常与历史**：外部删除、错误指向、断开、普通文件替换后仍展示原目标和当前关系，以“使用链接异常”及真实原因提示；不能因为目标不存在而从图谱消失或画成已结束。明确回收/结束的关系退出默认当前拓扑，历史通过既有历史入口追溯，不能盲目复活旧归档记录。
- **计数与筛选**：目标使用关系按已验证主体/物理目标身份归并，来源存证、共享识别线和冲突线分别说明，不与使用关系数混算。图谱页签若继续统计有关系事实的 Skill 数，保留清晰单位，不要求其与治理关系条数相等。查询失败不显示假零；筛选可隐藏展示但不能改事实或把异常消除。
- **交互与安全**：保持既有图谱引擎、节点布局/缩放/选择和主题风格，筛选用浮层，详情在有边界的面板内展示，开关不挤压画布。当前关系可精确跳转处理，普通来源跳来源/生命周期，结束记录跳历史；选中或核验过期时说明并重新加载，不能跳错同名目标。节点、连线、详情及 tooltip 禁止显示原始 ID/哈希/技术修订标识，长值规范化后省略并提供完整可读提示。
- **验证**：相同关系在治理和图谱三层状态/原因/按钮一致；覆盖长期保留、外部异常目标仍可见、共享单次及结构计数、上游不误纳入治理、归并和跨页刷新、深链过期、筛选画布稳定、长路径/键盘/主题。浏览器素材不能代替原生命令成功证据。

## 11. 派发同名目标占用（新增问题核查与闭环建议）

用户指出普通派发Skill到Agent也可能同名。已有目标占用校验和预览阻断，不代表存在完整替换处理链；模型须明确同名占用是动作条件/派发冲突，不能因失败建立虚构使用关系，不能把已有正常受管关系标异常。详细事实/展示/动作表见操作模型第9节。

- 同主体正常受管：已在目标使用，无需重复派发；同主体链接异常：既有使用链接异常，走恢复。
- 另一主体正常受管：预览“目标已有同名技能”，建议保留现有并跳过或明确替换；成功后旧关系明确结束到历史、新关系核验生效，保留旧主体及其他目标。
- 可识别独立副本：按精确主体/目标核验接管或保留，不凭同名把它关联本次技能；采用另一主体需单独明确替换内容及备份影响。
- 内置/插件/其他工具/未知占用：保持保护，查看/选择其他目标/跳过或先核验，不做强制覆盖。
- 同批多同名主体到同物理目标：预览选择唯一使用主体，不顺序覆盖；按目标文件系统大小写语义检查，共享物理入口一次确认全消费者。
- 尚未建立的派发意图由现有派发预览/冲突处理承接；只有实际既有关系的待接管/异常进入治理待处理。替换/接管执行安全链细节仍共同梳理，不在前端显示当前后端不支持的可执行假按钮。
