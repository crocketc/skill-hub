## 3. FB-010 抽屉设计与边界

- 沿用主题、宽度三档及拖动记忆、模块配置、详情入口；整体增加可感知的浮层留白、边界与阴影。修改作用于技能抽屉，不能使项目/删除等其他抽屉无授权地改变动效。
- 仅轻量工具栏、名称与必要状态固定，摘要其余字段、描述、用途/备注、关联关系及模块放入有充分高度的主体滚动区。采用紧凑网格、减少重复分隔与大留白；不要仅把字号缩小或裁掉信息来达标，也不要同时造多个窄滚动框。
- 常规 800×600、900×600、1440×900 浏览器客户区下，默认打开时正文阅读区目标至少占面板可用高度 60%，无重要内容被固定层压盖。高 DPI/长描述/标签增多不能扩大固定区吞掉阅读区；极短视口记录降级方案，不能用最低 140px 代替本轮标准。
- 开关均应有完整横向滑入/滑出，初始建议约 360ms 入场、320ms 退出，按截图与实际观感微调；关闭后卸载不能截断动画。减少动效遵循现有 SkillHub 设置，快速开关、遮罩、Esc、关闭焦点恢复保持正常。
- 别名、标签、用途、备注的编辑/添加入口改为透明笔形图标，hover/键盘聚焦有准确操作说明、accessible name 和足够命中区；标签移除仍保留独立可读操作。编辑确认/取消、失败保持原值，不改 Skill 原声明或调用方式。
- 配置、翻译提示、查看发现项等深层内容用有边界的局部面板/浮层，不重新挤压主体区；抽屉新增能力完整详情页同步可达。

## 4. FB-011 检查与翻译

- 抽屉直接显示当前版本的基础/AI 检查各自状态，已运行时间与发现摘要可按空间收纳；未知/未运行如实显示，不能因导入成功就伪造基础通过。导入记录缺失依 FB-006 修复，旧记录需要实际重查。
- 常规执行入口改为两个独立按钮：“重新检查”（基础）和“AI 检查”。不再把“打开安全检查”作为必经操作页。复用既有 SecurityFacade 和执行桥，保留原安全页路由兼容旧通知/深链，不在本次修复删除其查询能力。
- 安全发现具体内容在抽屉展开或完整详情中可达；仅有风险数量不能替代原因。处置高风险仍按原确认边界，AI 不替代基础检查，也不因整合入口降低门禁。
- 基础与 AI 独立在途/失败/取消状态，防重复；AI 未就绪说明原因与去配置入口。复用既有数据范围/网络授权边界，未配置或能力关闭不冒充运行成功。
- 检查成功写入真实结果后刷新对应版本检查、技能库列表/抽屉 quickView、完整详情 summary/findings、风险摘要及派生待办；不是在通知点击/已读/关闭时刷新。完成时用户可能关闭抽屉或切技能，仍刷新正确目标，不把旧版本结果写成新版本通过。失败不改成通过；取消或产生部分事实时以真实查询结果为准。
- 翻译失败保留真实结构化原因并本地化，至少区分未配置、凭据不可用、能力关闭、网络或模型错误。无可用模型时提供小号透明“配置大模型”入口，精确定位现有设置网络与 AI 区域并保留返回上下文；不裸显枚举/密钥。提示直接可见，hover 是补充。
- 原有翻译草稿确认/取消与持久化保留，不自动覆盖原始描述或用户已编辑信息。本次不改变“我的用途/翻译描述”存储语义，若发现二者契约冲突报告 Leader 后再处理。

## 5. FB-012 通知结构

- 通知标题、说明/详情和“去处理”都放在同一个带背景、边界的卡片容器内；最新卡与展开列表复用同一结构。入口采用小号透明按钮/链接并清晰可见，不悬在卡片外。
- 卡片视觉容器不是一个包住全部内容的 button；标题/标已读、展开堆叠和处理入口是独立合法交互元素，禁止 button 内嵌 Link/button。入口点击只执行精确导航及现有读/关闭行为，不能顺带触发展开/收起父点击。
- 堆叠装饰层跟随整张卡片高度，不把处理入口当作另一层。保留最多两层、玻璃样式、未读计数、全部查看、按模块分组、Esc/外点/焦点、过期入口提示。
- 长内容在既有最大高度内可读，不撑出屏幕；通知只是操作结果/业务入口，不承担数据刷新或事项完成判定。
