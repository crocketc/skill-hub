## 1. 文档说明

本文将 SkillHub 的功能范围转换为可规划、可开发、可验收的用户故事。`需求文档.md` 决定功能范围、业务规则和明确不做的内容，`产品与交互设计.md` 补充入口、页面职责、流程和反馈方式；如两者存在歧义，以需求文档为准。

优先级沿用需求文档第 11.1 节：

- P0：基础前置，其他核心能力依赖本项。
- P1：核心闭环，构成主要本地管理流程。
- P2：增强管理，提高自动化、分析和批量效率。
- P3：后置能力，依赖可靠运行数据。

优先级只表示开发依赖与先后，不代表删减已确认范围或划分发布版本。

## 2. 用户角色

- 普通用户：不熟悉 Git、命令行、软链接或 Agent 目录，希望通过桌面界面安全管理 Skill。
- 多 Agent 用户：在多个 Agent 客户端之间管理、部署和更新 Skill。
- 项目开发者：需要为不同项目维护精确的 Skill 与版本关系。
- 高级用户：需要批量操作、自动化策略、CLI 和可追溯的技术详情。
- 隐私敏感用户：要求数据本地保存，并明确控制网络、凭证和发送给 LLM 的内容。

## 3. 全局验收规则

以下规则适用于所有相关用户故事：

1. 所有权与数据保护：扫描发现默认只读；不得静默移动、覆盖、删除或改写用户、Agent、插件及其他工具的内容。
2. 期望与实际状态：管理记录和文件系统事实分开表达；未知、无数据和未检查不得显示为失败、零或确定结论。
3. 风险分级：只读操作可直接执行；影响版本或部署的操作先预览；删除、覆盖、强制导入和高风险批量操作必须明确确认，高风险项逐项处理。
4. 可恢复性：重要写操作先建立恢复点；取消、中断、重试和部分失败不得产生无法识别的半成品，且必须准确展示成功、跳过、失败和待处理对象。
5. 文件边界：只读写集中库、用户明确选择的来源和已注册目标；不遍历全盘，不执行 Skill、网页或 README 中的代码和命令。
6. 本地优先：核心管理功能离线可用；联网搜索、来源获取、应用更新和 LLM 调用分别受控。
7. 平台事实：文件已添加到目标目录不等于 Agent 已加载、调用或验证可用；不得将推测表达为运行时事实。
8. 跨平台：核心功能正式支持 Windows 和 macOS，并正确处理路径、权限、链接、大小写和换行差异。
9. 国际化与可用性：提供完整简体中文和英文界面；状态不只依赖颜色；核心查看、筛选、选择、确认和取消支持键盘与清晰焦点。
10. 性能：约 100 个 Skill 且无数据库迁移时，目标为 2 秒内进入可交互缓存首页；以 300 个 Skill 作为设计与自动化性能测试基准。

## 4. 史诗一：首次使用与集中库

### US-001 初始化集中库

**优先级：P0**  
**用户故事：** 作为首次使用的普通用户，我希望通过短向导新建、选择已有集中库或从备份恢复，以便在不理解底层目录结构的情况下开始使用 SkillHub。

**验收标准：**

- Given 用户首次启动应用，When 进入初始化向导，Then 首步提供“新建”“使用已有集中库”“从备份恢复”三种方式。
- Given 用户选择推荐位置或自定义位置，When 继续，Then 系统完成路径安全检查并展示最终位置。
- Given 推荐目录已经存在，When 系统完成检测，Then 无论是否兼容都必须让用户确认，不自动接管、覆盖或清空。
- Given 用户在确认集中库前关闭向导，Then 不写入任何内容；确认后中断则可继续且不留下未知半成品。

**来源：** 需求 4.1、5.1；交互 4.1～4.4。

### US-002 跳过可选初始化步骤

**优先级：P0**  
**用户故事：** 作为希望快速进入应用的用户，我希望跳过 Agent 发现、扫描和导入，以便先创建空集中库，之后再完成配置。

**验收标准：**

- Given 用户选择跳过初始化，When 尚未确认集中库，Then 系统仍要求确认集中库位置。
- Given 集中库已确认，When 用户跳过其余步骤，Then 只创建空集中库，不自动扫描、导入或部署。
- Given 初始化结束，Then 完成页显示集中库位置、发现结果、导入数量、跳过项和待处理事项。

**来源：** 需求 5.1；交互 4.4。

### US-003 迁移或重新关联集中库

**优先级：P1**  
**用户故事：** 作为需要更换存储位置的用户，我希望安全迁移或重新关联集中库，以便继续使用既有数据和受管关系。

**验收标准：**

- Given 集中库被移动、重命名或暂时不可访问，When 应用检测到异常，Then 暂停依赖集中库的写操作并提供重新关联或迁移入口。
- Given 用户发起迁移，When 执行前，Then 完成备份、目标路径检查、关系影响预览和用户确认。
- Given 目标路径与已知 Agent 或项目目录包含或重叠，Then 阻止迁移且不能强制绕过。

**来源：** 需求 4.1、5.34；交互 17.2。

## 5. 史诗二：导航、概览与通用工作台

### US-004 使用统一导航进入核心能力

**优先级：P1**  
**用户故事：** 作为普通用户，我希望从固定导航进入概览、技能库、发现、Agent、项目和待处理事项，以便快速找到所需功能。

**验收标准：**

- Then 左侧导航按概览、技能库、发现、Agent、项目、待处理排列，底部固定操作记录与恢复、设置。
- Then 导入作为技能库和发现中的操作入口，不单设主导航。
- Given 用户从概览或待处理事项下钻，When 返回，Then 尽量保留原筛选、选择、滚动和查看上下文。

**来源：** 需求 6.2；交互 2.1～2.3。

### US-005 查看可下钻的概览

**优先级：P1**  
**用户故事：** 作为需要了解整体状态的用户，我希望在概览看到关键数量、异常和部署关系，以便快速定位需要处理的对象。

**验收标准：**

- Then 概览显示 Skill、Agent、项目、待处理、可升级、冲突、安全问题和失联目标的真实汇总。
- Given 用户切换 Agent 或项目维度，Then 柱状图显示对应部署关系；点击柱形进入已应用筛选的列表。
- Then 概览不显示最近操作时间线、不生成健康分，也不维护独立于待处理中心的异常状态。

**来源：** 需求 7.1；交互 5。

### US-006 搜索、筛选并保存工作视图

**优先级：P1**  
**用户故事：** 作为管理大量 Skill 或项目的用户，我希望组合搜索、筛选、排序并保存视图，以便重复使用自己的工作方式。

**验收标准：**

- Given 用户在技能库或项目页设置条件，When 保存视图，Then 只保存条件、排序和列设置，不复制对象。
- Then Skill 标签与项目标签独立管理，同名标签不跨对象传播。
- Given 用户修改列、密度、默认视图或抽屉配置，Then 系统记住偏好并允许恢复默认。

**来源：** 需求 5.7、6.3、7.2、7.5；交互 3.1、6.1、9.1。

### US-007 安全执行批量操作

**优先级：P1**  
**用户故事：** 作为高级用户，我希望批量选择和处理 Skill 或项目，同时单独识别风险项，以便提高效率且不掩盖危险操作。

**验收标准：**

- Given 用户批量选择，Then 明确区分当前可见对象与全部筛选结果，并显示浮动操作区。
- Before 执行，Then 汇总可执行、跳过、冲突和需逐项处理的对象。
- Given 批次含高风险对象，Then 高风险对象退出总确认并逐项确认。
- After 执行，Then 分别显示成功、跳过、失败和仍待处理对象；部分失败不得显示为整体成功。

**来源：** 需求 6.3、6.6、6.7；交互 3.2、3.4。

## 6. 史诗三：Agent 发现与管理

### US-008 发现并区分 Agent 客户端

**优先级：P0**  
**用户故事：** 作为多 Agent 用户，我希望看到实际发现的客户端和目录证据，以便理解哪些目标可以管理。

**验收标准：**

- Then Agent 按品牌分组，但 CLI、桌面端、IDE 插件等实际客户端分别识别。
- Given 找到应用、命令或官方安装记录，Then 显示“已发现”；仅找到目录时显示“发现相关目录”并给出依据。
- Then 不展示或推断 Agent 版本、登录状态、项目可信状态、模型能力或 Skill 运行可用性。
- Given 客户端没有公开稳定的本地目录，Then 只展示能力边界、官方帮助和通用导出，不建立部署或人工安装状态。

**来源：** 需求 5.2、5.3；交互 8.1。

### US-009 管理 Agent 环境变化

**优先级：P1**  
**用户故事：** 作为 Agent 用户，我希望应用识别客户端或目录的新增、移动和失联，以便修复管理关系而不丢失 Skill。

**验收标准：**

- Given 应用运行或用户手动扫描，When 客户端或目录变化，Then 形成确定状态和待处理事项，不依赖版本号推断。
- Given 新发现 Agent，Then 提示注册但不自动部署已有 Skill。
- Given Agent 不可用，Then 提供重新定位、暂时忽略、安全解除部署或移除管理关系。
- Given 内置适配规则变化，Then 在应用变更前展示受影响范围。

**来源：** 需求 5.3；交互 8.2。

### US-010 创建自定义 Agent

**优先级：P0**  
**用户故事：** 作为使用未内置平台的用户，我希望配置自定义 Agent 及其目录，以便获得基础扫描和部署能力。

**验收标准：**

- Given 用户创建自定义 Agent，Then 可设置名称、一个全局目录和一个或多个项目目录。
- Then 自定义 Agent 支持扫描、导入、部署、解除部署、外部变化检测和基础关系展示，并标记“未验证自定义目标”。
- Then 不承诺自动发现、格式转换、调用策略映射、运行可用性判断、调用次数或完整插件观察能力。

**来源：** 需求 5.2.3；交互 8.2。

### US-011 查看和修改 Agent 专用变体

**优先级：P2**  
**用户故事：** 作为跨 Agent 使用同一 Skill 的用户，我希望管理已知格式差异的 Agent 专用变体，以便部署适合目标平台的内容。

**验收标准：**

- Given 平台存在明确且可验证的格式差异，Then 可为基础 Skill 保存 Agent 专用变体。
- Before 生成或更新变体，Then 展示文件和字段变化，不自动改写业务语义。
- After 保存变体，Then 形成相应版本记录；内容不同的变体部署到专属目录，不错误共享同一实体。

**来源：** 需求 5.2.4、5.22、5.24；交互 10.2、12.1。

## 7. 史诗四：发现、来源获取与导入

### US-012 扫描明确的本地范围

**优先级：P0**  
**用户故事：** 作为希望整理现有 Skill 的用户，我希望扫描集中库、已知 Agent、已注册项目和自己选择的目录，以便发现可管理对象而不遍历全盘。

**验收标准：**

- Then 默认扫描范围只包含集中库、通用目录、已注册 Agent/项目目录、可访问的内置或插件目录及用户明确选择的路径。
- Given 存在大小写别名、符号链接、目录联接或同一真实路径，Then 实体只识别一次并保留多项来源或使用关系。
- Then 结果区分格式正常、格式问题、疑似 Skill、链接、实体副本和无法读取对象，并展示位置、来源推测、所有权和关联状态。
- Given 用户选择上级文件夹有限发现，Then 扫描结束后不持续监控该上级文件夹。

**来源：** 需求 5.6；交互 7.2。

### US-013 搜索本地集中库

**优先级：P1**  
**用户故事：** 作为 Skill 使用者，我希望按正文、名称、说明、标签、状态和关系搜索集中库，以便快速找到已有 Skill。

**验收标准：**

- Then 本地搜索覆盖正文及管理元数据，并支持名称、别名、说明、标签、来源、所有权、Agent、项目、生命周期和部署状态等条件。
- Given 搜索命中，Then 结果显示命中原因或片段。
- Then 本地集中库搜索位于技能库，不与本机外部发现或联网发现混淆。

**来源：** 需求 5.7；交互 7.1。

### US-014 联网发现新的 Skill

**优先级：P2**  
**用户故事：** 作为希望发现新 Skill 的用户，我希望从明确适配的在线来源搜索，以便选择可信来源进入统一导入流程。

**验收标准：**

- Then “发现”页面将本机与联网分为两个页签，首个内置在线来源为 `skills.sh`。
- Given 来源缺少作者、许可证或热度，Then 不把缺失数据显示为零。
- Given 未配置 LLM，Then 基础在线搜索仍可用；LLM 只可选用于查询扩展和辅助排序。
- Given 用户选择在线结果，Then 先查看来源详情，再进入统一导入流程。

**来源：** 需求 5.7；交互 7.1、7.3。

### US-015 从多种来源安全获取 Skill

**优先级：P1**  
**用户故事：** 作为普通用户，我希望从文件夹、压缩包、仓库、网页或私有来源获取 Skill，以便不安装 Git 或 Node.js 也能导入。

**验收标准：**

- Then 支持本地文件夹、压缩包、仓库链接、Skill 页面、受支持私有来源和明确的 `npx skills add ...` 命令。
- Given 用户粘贴安装命令，Then 只解析来源、Skill 选择和目标提示，不执行 Shell；含管道、重定向、命令连接、脚本或未知命令时拒绝解析。
- Given 一个来源含多个 Skill，Then 先展示清单并允许选择单个、多个或全部；`--skill` 只作为默认勾选。
- Then 不执行网页、README 或 Skill 内容中的安装脚本和命令。

**来源：** 需求 5.8；交互 7.4。

### US-016 通过统一流程导入 Skill

**优先级：P0/P1**  
**用户故事：** 作为导入 Skill 的用户，我希望不同来源进入一致的检查、预览和确认流程，以便理解导入结果和风险。

**验收标准：**

- Then 流程依次完成来源选择、文件获取、对象选择、格式检查、确定性重复检查、基础安全检查、可选 AI 检查、预览、冲突处理和确认。
- Given 格式存在问题，Then 可导入以查看修复；Given 内容无法读取，Then 阻止依赖内容读取的操作。
- Given 未配置 LLM、AI 检查失败或用户跳过，Then 仍可依据基础检查继续导入。
- After 批量导入，Then 分别展示成功、跳过、失败和待处理对象。

**来源：** 需求 5.9；交互 7.5。

### US-017 按所有权复制、移动或接管

**优先级：P0/P1**  
**用户故事：** 作为本地 Skill 所有者，我希望按对象来源选择纳入管理、复制、移动或仅扫描，以便保护原文件并建立正确关系。

**验收标准：**

- Given 用户自有 Skill 位于已识别 Agent/项目目录，Then 优先推荐“纳入管理”，原位置转为受管部署关系，不重复显示为第二个集中库对象。
- Given Skill 位于普通自有目录，Then 推荐复制并保留原件，也可明确选择移动或仅扫描。
- Given 对象属于 Agent 内置、插件或所有权不明，Then 只能复制，不能移动、覆盖或接管原件。
- Given 用户发起接管，Then 先选择原位置成为受管部署、保留独立副本、移除原件或取消；接管未完成不得删除原件。

**来源：** 需求 4.4、5.9；交互 7.6。

### US-018 处理重复和同名冲突

**优先级：P1/P2**  
**用户故事：** 作为导入或部署 Skill 的用户，我希望系统区分内容重复、同名冲突和语义相似，以便作出明确选择而不被静默覆盖。

**验收标准：**

- Given 内容完全一致，Then 可复用、建立来源关联、保留独立对象或跳过。
- Given 同名但内容不同，Then 必须进入冲突处理；集中库可用内部身份共存，但同一 Agent 同一层级只能部署一个运行时同名 Skill。
- Given 名称不同但可能相似，Then 先用确定性文本、结构和全文检索筛选候选，再按配置交给 LLM；不得引入向量模型或 Embedding 前置依赖。
- Given LLM 提供保留或归档建议，Then 展示共同点与差异且由用户决定，LLM 不自动合并、删除、重命名或归档。

**来源：** 需求 5.15；交互 7.7、10.3。

## 8. 史诗五：Skill 内容与组织

### US-019 创建、复制或派生 Skill

**优先级：P1**  
**用户故事：** 作为 Skill 作者，我希望从空白、模板、独立副本或上游分支创建 Skill，以便开始维护自己的内容。

**验收标准：**

- Then 支持从空白或最小模板创建、复制为完全独立 Skill、创建保留上游关系的自定义分支。
- After 创建成功，Then 形成初始版本并记录身份、来源和时间。

**来源：** 需求 5.10；交互 6.3～6.4。

### US-020 安全预览 Markdown

**优先级：P1**  
**用户故事：** 作为检查 Skill 内容的用户，我希望在应用内安全阅读 `SKILL.md` 和其他 Markdown 文件，以便不依赖外部软件也能理解内容。

**验收标准：**

- Then 阅读视图与源码视图支持 CommonMark、GFM、Frontmatter、表格、任务列表、代码块、脚注及其他已确认基线语法。
- Given 存在 `mermaid` 代码块，Then 严格安全渲染并可切换源码；失败退回普通代码块。
- Then 不执行代码或脚本，过滤危险 HTML，将相对资源限制在当前 Skill 内；远程图片默认阻止，外链展示实际目标并确认。
- Given 遇到未知扩展语法，Then 保留原始文本，不因预览或保存而删改。

**来源：** 需求 5.10；交互 6.4。

### US-021 轻量编辑 Markdown

**优先级：P1**  
**用户故事：** 作为拥有 Skill 的用户，我希望通过轻量编辑器修改 Markdown 并形成新版本，以便完成常见修订而不破坏正式内容。

**验收标准：**

- Then 提供源码编辑、实时或分栏预览、撤销重做、搜索替换、行号、高亮和 Frontmatter 提示。
- Given 用户正在编辑，Then 内容先保存在本机草稿；只有显式保存才写入正式 Skill、形成新版本并触发检查。
- Given 编辑中断，Then 不把半完成草稿写入正式版本。
- Given 对象只读、内置、插件所有或尚未接管，Then 只能预览，并提供复制导入或接管入口。

**来源：** 需求 5.10；交互 6.4。

### US-022 管理个人说明、描述翻译与标签

**验收标准：**

- Then “我的用途说明”参与搜索和展示，但不写入 `SKILL.md`，随完整备份迁移，标准导出默认排除。
- Given 用户翻译描述，Then 默认只发送描述文本，并记录语言、模型、时间和对应版本；未配置或失败时继续显示原文。
- Given 原描述变化，Then 旧译文标记需更新；Given 译文经用户修订，Then 重新翻译前确认是否覆盖。
- Then 标签支持创建、重命名、删除、单个和批量设置；删除标签不删除 Skill。

**来源：** 需求 5.12；交互 6.5～6.6。

### US-023 管理组合

**优先级：P1**  
**用户故事：** 作为经常一起使用多个 Skill 的用户，我希望创建轻量组合，以便批量查看、导出或添加到 Agent/项目。

- Then 组合位于技能库的组合视图，支持创建、编辑、复制、删除、导出和部署。
- Then 组合只保存明确 Skill 清单和说明，不支持嵌套、标签表达式、预绑定目标或版本锁定。

**来源：** 需求 5.12；交互 6.6。

### US-024 管理生命周期与临时试用

**优先级：P1/P2**  
**用户故事：** 作为整理 Skill 的用户，我希望区分正常、弃用、归档和临时试用，以便清理日常列表又不误解其安全或可用状态。

**验收标准：**

- Then 生命周期只有正常、弃用和归档；弃用可设置替代项，归档默认隐藏但可搜索和恢复。
- Given 用户添加“临时试用”标签，Then 设置复核日期，默认建议 7 天且可调整；到期只生成待处理事项，不自动删除。
- Given 用户转正，Then 只移除试用标签和待处理项；Given 放弃试用，Then 复用归档、解除部署和安全删除流程。
- Then 临时试用不表示隔离、安全、已调用或验证结果，也不改变版本、更新、安全和部署规则。

**来源：** 需求 5.13、5.26；交互 6.7。

### US-025 查看来源、许可证、体积和关系元数据

**优先级：P0/P1**  
**用户故事：** 作为评估和维护 Skill 的用户，我希望查看来源、作者、许可证、体积及关联信息，以便理解内容身份与管理影响。

**验收标准：**

- Then 按版本保存来源、作者、导入时间、许可证和版权文件；许可证缺失或变化时提示。
- Then 复制、派生和导出保留来源及许可证；修改内容导出时标记已修改，但不提供法律意见。
- Then 展示文件数和体积并提示异常体积，不提供独立磁盘清理中心。

**来源：** 需求 5.12、5.14；交互 6.2～6.3。

## 9. 史诗六：项目管理与装配

### US-026 注册和组织项目

**优先级：P0/P1**  
**用户故事：** 作为项目开发者，我希望选择项目根目录并关联 Agent，以便在 SkillHub 中管理项目级 Skill。

**验收标准：**

- Given 用户选择项目根目录，Then 根据目录痕迹和已发现客户端列出候选 Agent，并由用户确认一个或多个关联。
- Given 仅存在 `.agents/skills`，Then 不据此推断具体 Agent。
- After 注册，Then 只建立管理记录，不自动导入、不写项目文件、不添加 Skill。
- Then 项目支持收藏、多标签、保存视图和批量操作，但不创建或移动本机目录，也不建立复杂文件夹树。

**来源：** 需求 5.4；交互 9.1、9.3。

### US-027 管理项目范围和失联状态

**优先级：P1**  
**用户故事：** 作为管理嵌套项目的用户，我希望看清项目、子目录、Agent 和实体文件之间的关系，以便避免重复管理或误删业务目录。

**验收标准：**

- Then 平台原生目录、`.agents/skills`、父级和嵌套范围按对应 Agent 规则处理，不统一假定固定路径。
- Given 父子项目范围重叠，Then 同一实体文件只识别一次，并分别展示项目关系。
- Given 项目移动或失联，Then 提供重新关联、暂时忽略或移除管理关系。
- Then 从 SkillHub 移除项目绝不删除项目业务目录，并允许保留 Skill、解除部署后移除关系或取消。

**来源：** 需求 5.4；交互 9.4。

### US-028 创建共享技能清单

**优先级：P1**  
**用户故事：** 作为希望共享项目配置的开发者，我希望显式启用共享技能清单，以便新设备或成员知道所需 Skill 和精确版本。

**验收标准：**

- Given 功能默认关闭，When 用户启用，Then 明确提示会向项目写入配置文件。
- Then 清单记录所需 Skill、精确版本、来源、内容身份、目标 Agent 和逻辑范围。
- Then 清单不保存本机绝对路径、凭证、使用证据、操作历史或本机部署方式。
- Given 新设备发现清单，Then 提示注册与装配，不自动获取或部署。

**来源：** 需求 5.4；交互 9.5。

### US-029 尽力装配项目

**优先级：P1**  
**用户故事：** 作为在新设备打开项目的用户，我希望按共享清单尽力装配精确版本，以便无需理解 Git 或手工复制目录。

**验收标准：**

- Then 优先复用集中库已有精确版本，缺少时从已知来源获取，不使用未声明替代版本。
- Given 来源不可用、版本不存在或认证失败，Then 逐项说明原因和下一步。
- Before 装配，Then 预览新增、复用、跳过、冲突和失败；After 装配，Then 显示期望与实际差异。
- Then 装配完成只表示文件和管理关系已建立，不表示 Agent 已加载；不主动检查或安装 Python、ffmpeg、MCP 或插件。

**来源：** 需求 5.5；交互 9.6。

### US-030 批量发现候选项目

**优先级：P2**  
**用户故事：** 作为拥有多个本地项目的用户，我希望从明确的上级目录发现候选项目，以便批量登记而不扫描隐私数据。

**验收标准：**

- Given 用户选择上级文件夹，Then 只发现含共享技能清单或已知 Agent Skill 目录的候选项目并先预览。
- Then 不读取 Agent 对话或项目历史，不遍历全盘，也不持续监控该上级目录。
- Given 用户确认候选项，Then 分别进入正常项目注册流程。

**来源：** 需求 5.4、5.6；交互 9.1、9.3。

## 10. 史诗七：添加到和移除 Agent/项目

### US-031 添加 Skill 或组合到目标

**优先级：P1**  
**用户故事：** 作为多 Agent 或项目用户，我希望把单个、多个 Skill 或组合添加到所选目标，以便建立可追踪且幂等的部署关系。

**验收标准：**

- Given 用户从技能库、Skill 详情、Agent 详情或项目详情发起，Then 进入同一添加流程。
- Before 执行，Then 选择对象、目标与版本，并检查路径、同名冲突、安全、可访问性和共享目录影响。
- Then Agent 全局部署默认跟随集中库当前版本，项目可固定精确版本；重复执行同一操作结果保持一致。
- After 执行，Then 分别显示成功、跳过、冲突、失败和待处理，不使用“兼容 Agent”或“已加载”等结论。

**来源：** 需求 5.22；交互 10.1。

### US-032 选择安全的目标目录和文件方式

**优先级：P1**  
**用户故事：** 作为不熟悉文件部署机制的用户，我希望 SkillHub 自动选择安全方式并提供可展开的技术详情，以便完成部署而不必理解软链接。

**验收标准：**

- Then 各 Agent 使用自己的已知目录；`~/.agents/skills` 仅在官方支持、用户明确选择或自定义登记时使用。
- Given 多个逻辑 Agent 指向同一物理目录，Then 只写入一次但分别保留逻辑关系。
- Then 默认优先软链接，不可用时使用受管复制；普通界面使用自然语言，技术详情显示实际路径和方式。
- Given Agent 专用变体内容不同，Then 分别部署到专属目录，不共用错误内容。

**来源：** 需求 5.22；交互 10.2。

### US-033 查看 Agent 目录关系

**优先级：P1**  
**用户故事：** 作为排查冲突的用户，我希望查看 Agent 全局、项目、内置和插件目录关系，以便理解候选优先级而不误认为运行时事实。

**验收标准：**

- Then 按 Agent 与项目合并展示名称、来源层级、版本和所有权。
- Given 官方规则明确，Then 标记优先候选、较低优先级副本、可能共存或无法判断；未经真机验证时注明规则依据。
- Given 自定义 Agent 或未知规则，Then 只提示可能共存或冲突，不声称知道优先级。
- Before 部署，Then 预览部署后的目录关系变化。

**来源：** 需求 5.23；交互 10.3、12。

### US-034 安全移除目标部署

**优先级：P1**  
**用户故事：** 作为需要停止某个部署的用户，我希望从目标安全移除受管关系，以便保留集中库和其他仍在使用的内容。

**验收标准：**

- Given 独占目录中的受管内容，Then 移除文件夹或链接本身，不沿链接删除集中库。
- Given 目标被外部修改或含非受管文件，Then 提供收集修改、保留独立副本、明确放弃或取消，且不静默删除整个目录。
- Given 多个 Agent 共用物理目录，Then 提供保留共享部署、全部移除、迁移其他 Agent 或仅解除管理关系，并准确说明文件仍可能被发现。
- Before 执行，Then 展示受影响 Agent、项目和固定版本；解除部署不删除集中库 Skill。

**来源：** 需求 5.36；交互 10.4。

## 11. 史诗八：版本、更新和外部变化

### US-035 查看版本历史与差异

**优先级：P0/P1**  
**用户故事：** 作为维护 Skill 的用户，我希望查看时间线并比较任意版本，以便了解内容、来源和许可证变化。

**验收标准：**

- Then 每个版本记录时间、来源、变更说明、内容身份及与版本绑定的声明信息。
- Given 用户选择任意两个历史版本，Then 可查看差异。
- Then 版本历史只增不减，底层是否使用 Git 不形成用户功能差异。

**验收标准：**

- Before 回滚，Then 展示受影响的未固定部署；项目固定版本保持不变。
- After 回滚，Then 用旧内容创建新的当前版本，不删除历史，并按当前规则重新执行基础安全检查。
- Then 回滚恢复版本绑定的文件、变体、来源、许可证和声明信息，但不恢复标签、别名、生命周期、备注、策略、部署、项目固定、使用证据或忽略设置。

### US-037 获取并合并上游更新

**优先级：P1**  
**用户故事：** 作为跟踪上游 Skill 的用户，我希望检查并安全合并更新，以便保留本地自定义而不被静默覆盖。

**验收标准：**

- Then 状态区分可更新、已最新、无来源、来源不可访问、本地修改和升级受阻。
- Given 存在本地修改，Then 比较原始基线、本地版本和上游版本；无冲突可合并，冲突由用户或外部编辑器处理。
- Before 升级，Then 展示来源身份、许可证、格式和安全差异；After 升级，Then 形成新版本并更新未固定部署。
- Then 不使用 LLM 自动语义重写，不静默覆盖本地修改。

**来源：** 需求 5.19；交互 11.2。

### US-038 配置更新策略

**优先级：P2**  
**用户故事：** 作为希望减少维护工作的用户，我希望分别设置自动检查和自动升级，以便在可控条件下获得更新。

**验收标准：**

- Then 默认自动检查并通知、不自动升级；支持全局默认、单 Skill 覆盖和批量修改。
- Then 优先级为项目固定高于单 Skill、单 Skill 高于全局；项目固定版本不自动变化。
- Given 自动升级将执行，Then 先创建恢复点；来源身份变化、高风险、冲突、认证失败、弃用、归档或项目固定等情况阻止自动升级并进入待处理。
- Then 自动任务只在应用运行期间执行，不创建后台服务或托盘进程。

**来源：** 需求 5.20；交互 11.3、17.4。

### US-039 重命名或重新关联来源

**优先级：P1/P2**  
**用户故事：** 作为整理 Skill 的用户，我希望设置别名、在允许时实际重命名或重新关联来源，以便修正标识和上游关系。

**验收标准：**

- Then 所有 Skill 可设置显示别名；只有用户创建或完全独立 Skill 可实际重命名，上游跟踪对象须先复制或派生。
- Before 实际重命名，Then 展示项目、组合、部署和关联影响，并只更新用户确认的受管引用；操作可撤销。
- Given 来源失效或变化，Then 先比较当前内容和候选来源，保留旧来源历史，不因内容相似自动认定同源。

**来源：** 需求 5.11、5.21；交互 11.4。

### US-040 处理外部文件变化

**优先级：P1**  
**用户故事：** 作为可能使用外部编辑器的用户，我希望检测并处理集中库或受管部署的修改、删除和移动，以便避免无意覆盖和双向同步。

**验收标准：**

- Given 应用运行或手动扫描发现变化，Then 先形成待处理变更、保存临时安全副本，并暂停相关自动升级和传播。
- Given 集中库变化，Then 可接受为新版本、恢复、暂缓或精确忽略。
- Given 用户自有部署副本变化，Then 可比较并收集为新版本、恢复目标、转为独立副本、解除部署或暂缓；非自有对象只读。
- Then 只有正式接受的新版本更新未固定部署，不提供实时双向同步。

**来源：** 需求 5.31～5.32；交互 11.5。

## 12. 史诗九：调用方式、运行要求与使用证据

### US-041 查看和修改调用方式

**优先级：P2**  
**用户故事：** 作为管理不同 Agent 行为的用户，我希望查看可追溯的调用方式并在平台支持时修改，以便控制 Skill 的声明设置。

**验收标准：**

- Before 修改，Then 预览文件和目标影响；After 修改专用变体，Then 形成新版本。
- Then 不使用“已启用”“一定会自动调用”等无法确定的表述。

### US-042 查看运行要求与声明信息

**优先级：P1**  
**用户故事：** 作为准备使用 Skill 的用户，我希望查看作者声明和可追溯的依赖引用线索，以便自行准备运行环境。

**验收标准：**

- Then 展示元数据、标准依赖文件、明确列表和固定规则发现的命令、环境变量与依赖引用，并给出文件位置。
- Given 未发现明确内容，Then 显示“未发现明确声明”，不显示“没有依赖”。
- Then 环境变量只记录名称和用途，不保存值；用户备注与原始声明分开。
- Then 不用 LLM 推断，不主动验证或安装依赖，也不生成兼容性结论或阻止部署。

**来源：** 需求 5.25；交互 12.2。

### US-043 查看实验性使用证据分析

**优先级：P3**  
**用户故事：** 作为希望整理 Agent 全局 Skill 的用户，我希望在有可靠数据时查看使用证据建议，以便参考是否保留、移入项目或归档。

**验收标准：**

- Then 模块固定标注“实验功能”和“仅供参考”，显示数据来源、统计范围和覆盖程度。
- Given 数据充分，Then 可按默认 60 天且可调整的窗口生成参考建议；Given 无可靠数据，Then 显示“暂无可用使用数据”，不显示零调用、不生成建议。
- Then 建议不自动移动、归档或删除，不解析原始会话，也不要求用户维护人工反馈。
- Then Runtime Hook 标注“研发中”，当前不提供虚假安装、连接或启用入口。

**来源：** 需求 5.29～5.30；交互 8.3。

## 13. 史诗十：安全检查与 LLM

### US-044 执行基础安全检查

**优先级：P0/P1**  
**用户故事：** 作为保护本机数据的用户，我希望用确定性规则检查敏感信息、危险命令和提示词注入等风险，以便在写操作前理解证据并作出决定。

**验收标准：**

- Then 检查覆盖需求列明的敏感信息、危险命令、下载执行、供应链、路径越界、混淆、提示词注入、外传、权限和工具诱导等固定规则维度。
- Then 检查只读内容，不执行代码或命令、不访问 URL、不验证密钥有效性；每条发现展示文件、位置、规则、证据和风险类别，不直接断言恶意。
- Then 结果只有未检查、检查通过、发现问题、检查失败，运行时临时显示检查中；内容或规则变化后恢复未检查。
- Given 高风险待处理项或检查持续失败，Then 退出自动批量流程并提供逐项确认、重试、暂缓或明确跳过；手动强制继续不篡改检查结果。

**来源：** 需求 5.27；交互 13.1～13.2。

### US-045 安全处理 Skill 中的凭证

**优先级：P0/P1**  
**用户故事：** 作为确实在自有 Skill 中使用凭证的用户，我希望保留本地内容，同时在云端发送、备份或导出前获得保护提示。

**验收标准：**

- Given 内容只声明变量名或占位符，Then 不视为真实密钥。
- Given 疑似真实密钥，Then 允许在本地导入和部署，但首次逐项确认；相同内容的本地确认可复用。
- Before 分享、标准导出或发送云端 LLM，Then 重新确认；发送 LLM 前默认遮盖已识别值。
- Then 系统不擅自删除、遮盖或改写原 Skill 文件。

**来源：** 需求 4.6、5.27、5.39、5.41；交互 13.2、15.3、16.1。

### US-046 执行独立的 AI 安全检查

**优先级：P2**  
**用户故事：** 作为需要语义风险分析的用户，我希望可选地使用 LLM 补充基础检查，以便识别多文件上下文和隐含风险。

**验收标准：**

- Then 基础检查与 AI 检查分别显示结果和明细，不合成第三个结果或安全分数。
- Given 未配置 LLM，Then 显示“AI 检查未配置”，不记为检查失败，也不影响核心功能。
- Before 在线调用，Then 先运行需要更新的基础检查、遮盖已识别敏感值并展示发送文件范围、服务和模型。
- Then AI 在只读、无工具且不包含无关本机上下文的环境分析，不评价写作质量、功能、兼容性，也不自动修改或删除内容。

**来源：** 需求 5.28；交互 13。

### US-047 配置可选 LLM 能力

**优先级：P2**  
**用户故事：** 作为需要 AI 增强功能的用户，我希望配置一个默认在线、本地或兼容模型，并了解每项发送范围，以便自主决定是否启用。

**验收标准：**

- Then 支持连接测试和一个当前默认模型；凭证保存在操作系统安全凭据存储，不进入集中库、备份或标准导出。
- Then AI 安全检查、语义重复、描述翻译和在线搜索辅助分别设置并说明数据范围。
- Given LLM 不可用，Then 回退到确定性能力或明确说明可选功能不可用。
- Then 不提供通用聊天、模型下载、训练微调、向量索引、多模型自动路由或复杂成本管理。

**来源：** 需求 5.42；交互 17.5。

## 14. 史诗十一：待处理、健康检查与操作恢复

### US-048 集中处理待处理事项

**优先级：P1**  
**用户故事：** 作为需要解决阻断和异常的用户，我希望在一个中心查看原因、影响和可执行操作，以便按风险优先处理。

**验收标准：**

- Then 汇总升级阻断、安全问题、冲突、外部变化、失联、健康问题、备份失败、装配和批量失败及试用待确认。
- Then 默认先显示阻止当前操作和高风险事项，支持按类型、Skill、Agent、项目、风险和来源筛选及保存视图。
- Given 问题解决，Then 自动移出待处理并进入历史；暂缓或忽略只绑定精确对象/问题。
- Then 不提供通用待办、系统后台通知服务或托盘提醒中心。

**来源：** 需求 5.33；交互 14。

### US-049 检查并修复集中库健康问题

**优先级：P1**  
**用户故事：** 作为维护本地数据的用户，我希望检查缺失、损坏、孤立或失联关系，以便在预览后安全修复。

**验收标准：**

- Then 检查缺失或损坏文件、无效来源/历史、失效部署、固定关系、未完成操作、孤立记录/文件、失联目标、路径重叠和异常链接。
- Then 结果分为可自动修复、需要选择、仅提示和检查失败；修复前预览并创建恢复点。
- Then 只有明确安全的问题可批量修复，未知文件不自动删除。
- Then 桌面端和 CLI 使用相同规则，不生成独立诊断报告，不以 LLM 替代确定性判断。

**来源：** 需求 5.34；交互 15.2。

### US-050 查看操作记录并撤销

**优先级：P0/P1**  
**用户故事：** 作为需要追溯变更的用户，我希望查看重要操作及结果，并在条件允许时撤销整次操作，以便恢复管理状态。

**验收标准：**

- Then 记录导入、接管、添加、移除、升级、回滚、重命名、删除、恢复和装配的时间、对象、范围和结果。
- Then 结果区分成功、部分成功、失败和已撤销，展开显示成功、跳过、失败和待处理明细。
- Given 操作满足撤销条件，Then 提供整次操作撤销；不能撤销时说明原因。
- Then 操作记录与单 Skill 版本历史分开，不提供集中库任意时间点全局回溯。

**来源：** 需求 5.35；交互 15.3。

### US-051 安全删除 Skill

**优先级：P1**  
**用户故事：** 作为确定不再需要某个 Skill 的用户，我希望先看清所有关系和替代选项，以便不破坏项目、部署或未知外部内容。

**验收标准：**

- Before 删除，Then 重新扫描 Agent/项目部署、项目配置、固定版本、组合、声明依赖、相关 Skill 和未知外部引用，并优先提供归档。
- Given 用户坚持删除，Then 可选择解除部署、保留独立副本、替换/移除受管引用或取消；不级联删除其他 Skill。
- Then 未知和非自有内容只提示、不修改；操作前创建恢复点。
- Given 任一必要关系处理失败，Then 不删除集中库原件。

**来源：** 需求 5.37；交互 15.1。

### US-052 管理精确忽略规则

**优先级：P2**  
**用户故事：** 作为希望减少已知噪声的用户，我希望忽略精确路径、Skill 或问题，以便保持待处理列表聚焦。

**验收标准：**

- Then 支持查看、创建和取消针对精确路径、精确 Skill 或已知问题的忽略/暂缓。
- Then 不支持通配符、正则、脚本条件或嵌套规则。
- Given 被忽略对象的身份或证据发生实质变化，Then 不把旧规则扩展到未经确认的新对象。

**来源：** 需求 5.38；交互 14、17.2。

## 15. 史诗十二：备份、恢复、导出与退出管理

### US-053 创建完整备份并跨设备恢复

**优先级：P1**  
**用户故事：** 作为担心本地数据丢失或需要换机的用户，我希望创建完整备份并安全恢复，以便在 Windows 与 macOS 之间迁移管理数据。

**验收标准：**

- Then 备份包含 Skill、历史版本、来源、安全记录、项目配置、组合、设置、操作历史、自定义 Agent 和逻辑关系，但不包含系统安全存储中的凭证或本机绝对部署路径。
- Before 备份，Then 检查 Skill 文件中的疑似凭证并允许先处理、排除对象或明确包含且标记敏感。
- Before 恢复，Then 在临时区域验证、备份当前状态并展示冲突，可逐项覆盖、保留两份或跳过。
- Given 恢复失败，Then 当前集中库保持不变；Given 换机恢复，Then 重新映射逻辑目标并由用户确认后再部署。

**来源：** 需求 5.39；交互 15.3。

### US-054 使用自动恢复点和滚动备份

**优先级：P2**  
**用户故事：** 作为希望降低重大操作风险的用户，我希望应用在关键操作前自动创建恢复点并清理过期备份，以便需要时恢复。

**验收标准：**

- Given 即将升级、批量部署、删除、恢复或执行其他重要操作，Then 自动创建恢复点。
- Then 自动备份只在应用运行期间工作，并按用户设置的数量或期限清理旧备份。
- Then 不创建后台服务，不提供云备份服务；备份页面显示时间、原因、范围、大小和敏感标记。

**来源：** 需求 5.40；交互 15.3、17.6。

### US-055 导出标准 Skill 内容

**优先级：P2**  
**用户故事：** 作为需要在 SkillHub 之外使用内容的用户，我希望导出标准文件夹或 ZIP，以便结果不依赖 SkillHub。

**验收标准：**

- Then 支持导出单个、多个或组合的当前/历史版本，保留来源、作者、许可证和版权，标记本地修改。
- Then 默认排除个人备注、别名、使用证据、操作历史、本机路径、部署关系、凭证和私有设置；可选附带运行要求摘要。
- Given 疑似真实凭证，Then 暂停并允许先处理、排除对象或明确强制导出，不静默修改文件。
- Then 不生成上传型平台专用包，不提供市场上传、发布通道或远程发布。

**来源：** 需求 5.41；交互 16.1。

### US-056 退出管理或卸载前安全处理

**优先级：P1**  
**用户故事：** 作为准备卸载 SkillHub 的用户，我希望决定保留、脱离或备份现有内容，以便卸载不破坏 Skill 和项目。

**验收标准：**

- Then 提供仅卸载并保留数据、将受管部署转为独立副本、解除选定/全部部署、先完整备份和取消。
- Then 默认不删除集中库、用户创建 Skill 或项目业务目录，不影响内置、插件和其他工具内容。
- Given 涉及凭证，Then 询问是否清除，默认不代替用户决定。
- Given 用户直接使用系统卸载，Then 集中库和管理数据默认保留；重新安装后可重新关联。

**来源：** 需求 5.44；交互 16.2。

### US-057 配置语言、主题和视图偏好

**优先级：P1/P2**  
**用户故事：** 作为桌面用户，我希望设置界面语言、AI 输出语言、主题、动效和视图偏好，以便适应自己的系统与工作习惯。

- Then 主题支持跟随系统、浅色和深色；系统减少动态效果时弱化非必要动画。
- Then 可配置技能库/项目默认视图、列、密度、保存视图和两类快速抽屉，并可恢复默认。

### US-058 关闭所有网络功能

- Given 用户关闭所有网络功能，Then 停用联网搜索、在线来源获取、应用更新检查和在线 LLM 调用。
- Then 本地扫描、搜索、导入已有文件、版本、部署、备份和其他核心本地功能继续可用。
- Given 任一联网功能启用，Then 在调用前或过程中说明原因、目标来源和适用的数据发送范围。

### US-059 获取诚实的桌面应用更新提示

**验收标准：**

- Given macOS 构建为 ad-hoc 且未公证，Then 只提示新版本并打开正式 Release，明确未公证，不将下载跳转包装为无感更新。
- Given 对应平台已有可信签名、公证和签名更新包，Then 才开放应用内安装。
- Then SkillHub 应用更新与 Skill 自动升级始终分开设置和表达。

**来源：** 需求 8.5；交互 17.4。

### US-060 查看网络存储后续规划边界

**验收标准：**

- Then 设置中仅提供“网络存储”次级说明入口，标注下一大版本规划和当前仅支持本地路径。
- Then 不提供连接、授权、测试、同步或“即将可用”的伪操作按钮。
- Given 用户选择同步客户端映射的本地目录，Then 当前版本只按普通本地路径处理，不承诺占位、离线、多设备锁或冲突合并。

**来源：** 需求 4.2、11.6；交互 17.2、20。

## 17. 史诗十四：轻量 CLI

### US-061 使用与桌面端一致的 CLI

**优先级：P2**  
**用户故事：** 作为高级用户，我希望通过轻量 CLI 查询、扫描、装配和管理部署，以便在自动化场景复用同一套规则与数据。

**验收标准：**

- Then CLI 支持列表、状态、扫描、项目尽力装配、添加/移除、对齐、升级、健康检查和 JSON 输出。
- Then CLI 与桌面端共用集中库、规则、互斥保护和操作历史，不形成第二套管理逻辑。
- Then CLI 随桌面应用提供，不要求 Git、Node.js 或其他开发环境，也不要求所有界面偏好都有 CLI 设置。

**来源：** 需求 2.1、5.43；交互 18。

### US-062 安全执行 CLI 写操作

**优先级：P2**  
**用户故事：** 作为在脚本中使用 CLI 的用户，我希望写操作默认预览并显式授权，以便非交互自动化不会意外破坏文件。

**验收标准：**

- Given 交互式写操作，Then 默认展示预览并要求确认。
- Given 非交互环境，Then 必须使用明确参数授权；高风险或破坏性操作缺少授权时停止。
- Given 操作失败，Then 输出原因和下一步建议，并记录部分成功明细。
- Then CLI 不执行 Skill 命令、任意脚本，不启动 Agent 或管理 Agent 会话。

**来源：** 需求 5.43；交互 18。

## 18. 明确不在本轮用户故事范围内

以下内容不作为当前实现或验收承诺：

- 多集中库、SkillHub 账号、团队权限、远程协作服务器和 SkillHub 云同步。
- 发布市场、远程发布、上传型 Agent 的专用导入包或人工安装状态。
- Git、Node.js 或其他开发工具作为普通用户前置条件，以及任意外部命令执行器。
- 自动安装运行依赖、完整代码编辑器、终端、调试器或完整 AI Skill 创作平台。
- Agent 版本、登录状态、项目可信状态、模型能力、实际调用能力或运行兼容性判断。
- Agent 自动执行测试、自动功能评分、人工“有用/无用”反馈和原始会话解析上传。
- 双向实时同步、多来源镜像或自动切换，以及当前版本的 NAS/SMB/云盘专项能力。
- 病毒扫描、动态沙箱、完整恶意代码或供应链审计、签名认证、合规及法律判断。
- 后台常驻服务、托盘监控、向量模型、Embedding、向量数据库和全库任意时间点回溯。
- Linux、Web 和移动端，以及尚未确认的品牌视觉、颜色、图标、字号、间距和具体控件尺寸。
